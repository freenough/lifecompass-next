# 指示書:繰上返済再計算ロジック 調査(新ツール企画・第8弾候補)

**このセッションの役割:** 調査のみ。実装・設計提案の確定はしないこと。

## 背景

住宅ローン+FIRE記事で使用した`calcMortgage`(または関連する住宅ローン計算ロジック。正確な関数名・所在ファイルは調査対象に含める)が、「単発の繰上返済後、期間短縮型/返済額軽減型どちらで再計算できるか」を確認したい。これは新規ツール(第8弾候補:繰上返済 vs 投資比較ツール)の企画のための事前調査であり、まだ実装フェーズではない。

## 調査してほしいこと

1. **既存の住宅ローン計算ロジックの所在・シグネチャ確認**
   - 住宅ローン記事(`housing-loan-fire`)のデータ収集時に使った関数(`calcMortgage`等、正確な名称・ファイルパスを特定)
   - `LifeEventTimeline.tsx`のモーダル内`updateMortgage()`(前回セッションで確認済み)が内部で呼んでいる計算ロジックも合わせて確認(同じ関数を共有しているか、別実装か)

2. **繰上返済(単発)対応状況の確認**
   - 現在の関数シグネチャに「ある時点で一括繰上返済額を投入する」という入力パラメータが存在するか
   - 存在しない場合、ロジック内部の計算方式(元利均等返済の月次シミュレーションか、単純な公式計算か)から見て、繰上返済ロジックを追加するのが容易か、大きな改修が必要かを判断できる範囲で報告

3. **期間短縮型・返済額軽減型、両方の再計算が可能か**
   - 期間短縮型(月々返済額は変えず残期間を短縮)・返済額軽減型(残期間は変えず月々返済額を下げる)、それぞれの計算式が現在のロジックで表現可能か
   - 一方のみ対応可能で他方が難しい場合、その理由

4. **既存テスト・検証データとの整合性**
   - この関数が他のどのツール・記事で使われているか(影響範囲の洗い出し)
   - 変更を加える場合、既存の数値(住宅ローン記事で確認済みの数値等)に影響が出ないか、関数の呼び出し方(引数追加は既存呼び出し元に影響しない設計にできるか等)

## 報告フォーマット

- 該当ファイル・関数名・行番号
- 現在のシグネチャ・計算方式の要約
- 繰上返済(単発・期間短縮型/返済額軽減型)対応の可否と、対応させる場合の改修規模感(小/中/大の目安と理由)
- 影響範囲(この関数を使っている他の箇所一覧)
- 新規ツール実装時に注意すべき点があれば追記

**実装・コミットはしないこと。調査結果をこのチャットに報告し、方針確認を経てから設計・実装指示書を別途作成する。**
