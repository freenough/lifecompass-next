# 調査指示書：資産シミュレーターLP Heroのはみ出し（1,024〜1,099px）

種別：**調査のみ**（ソースコードの変更・コミットは禁止）
対象リポジトリ：`lifecompass-next`

## 0. 目的

資産シミュレーターLP（`/asset-simulator`）のHeroで、画面幅1,024〜1,099pxのとき右側のデモカードがはみ出し、横スクロールが発生する。この不具合は以前から存在し、一人法人LP Hero再設計の作業中に見つかった。

修正方針の候補は「デモカードの幅を固定520pxではなく、狭い幅で縮むようにする」こと（一人法人LPで採用した方法と同じ）。ただし、この方針で問題ないかは、デモカードの中身が縮んでも崩れないかどうかで決まる。そこで今回は、その判断に必要な事実だけを集める。

**今回は調査のみ。ソースコードは一切変更しないこと。**

---

## 1. 調査項目

### 1.1 該当箇所の特定

- 資産シミュレーターLPのHeroを描画しているコンポーネントのファイルパスと、該当部分のコード（2列レイアウトのgrid/flex指定、左右の列幅指定、デモカード側の幅指定）を抜粋して報告する。
- デモカードの幅がどこで決まっているかを特定する（`w-[520px]`、`min-w-*`、`flex-shrink-0`、`grid-cols-[...]`、インラインstyleなど）。親子どちらにあるかも明記する。
- デモカードのコンポーネントが、LP以外（アプリ本体・一人法人LPなど）で使われていないかを確認する。使われている場合は使用箇所を列挙する。

### 1.2 一人法人LPとの比較

- `/hitori-hojin`のHero（`HitoriHojinForkDiagram`を含む2列部分）で、図の列幅を可変にしている指定（1,024pxで411px〜1,200px以上で520px）を抜粋する。
- 資産シミュレーターLP側の指定との違いを、対比表で示す（コンテナ最大幅・左右の余白・列間ギャップ・右列の幅指定・切り替え幅）。

### 1.3 はみ出しの実測

以下の各幅で、ページ全体と右側のデモカードを実測する。

- 対象幅：375・640・1,023・1,024・1,050・1,080・1,099・1,100・1,200・1,280・1,440px
- 測る値：
  - `document.documentElement.scrollWidth`と`clientWidth`（横スクロールの有無）
  - デモカードの`getBoundingClientRect()`の`left`・`right`・`width`
  - 左列（見出し側）の`width`
  - 見出しのはみ出しの有無
- 各幅のスクリーンショット（Hero部分）を撮って保存し、保存先パスを報告する。
- 結果は表にまとめる。はみ出しが始まる幅と終わる幅を実測値で示す（「1,024〜1,099px」という既知の範囲が正しいかどうかも確認する）。

### 1.4 デモカードの中身が縮めても崩れないか（重要）

一人法人LPの図と違い、デモカードには中身（数値・グラフ・表・ボタンなど）がある可能性が高い。幅を縮めたときに中身が崩れないかを確認する。

- デモカード内部の要素を列挙し、内部に固定幅・最小幅・`whitespace-nowrap`などの縮みにくい指定がないかを報告する（グラフのライブラリがあれば、その名前とサイズの決め方も）。
- **ファイルを変更せずに**、ブラウザ上で一時的にスタイルを上書きし（Playwrightの`page.addStyleTag`や`page.evaluate`など。リロードすれば元に戻る方法に限る）、デモカードの幅を411pxと460pxにした場合の見た目を確認する。1,024px幅の画面で行い、スクリーンショットを撮る。
- 文字の折り返し・はみ出し・グラフのつぶれ・ボタンの改行などがあれば、具体的に報告する。

### 1.5 修正案の候補（実装はしない）

上の結果をもとに、修正案を1〜3案に整理し、それぞれの変更箇所（ファイル・クラス名）、影響範囲、懸念点を示す。最小の変更で済む案を推奨案として明記する。判断はこちらで行うので、どれかを実装してはいけない。

## 2. 標準ルール（厳守）

- **ソースコードの変更・コミット・pushは禁止**。調査のみ。
- 指示書に書いていないファイル・フォルダ操作をしないこと。この指示書を`done/`へ移すのは、実装まで完了したあとにこちらから指示する。`docs/fixes/active/`フォルダ自体は、空になっても削除しないこと。

- 調査の最後に`git status`を実行し、作業ツリーに変更がないこと（スクリーンショットの保存先を除く）を示すこと。
