# 実装：退職延長シナリオにおける口座別積立の扱い

## 背景

KPIカードの動的境界探索機能(「あと何%支出削減/何年退職延長で届くか」を計算する新機能。以下「本機能」)を実装するにあたり、退職延長を試す際に以下の問題が確認済み。

- 各口座(`nisa`/`ideco`/`tax`)は`retAge`とは独立した`toAge`(積立終了年齢)を持つ
- `retAge`だけを延長すると、`toAge`が追従せず「延長した期間、積立が一切行われない」という実態と異なる計算になる(`retage_toage_sync_investigation.md`で検証済み)

これを踏まえ、退職延長時の設計を以下の通り確定した。

- **積立期間**:延長期間中、特定口座の`toAge`は新しい`retAge`まで延びる。NISA・iDeCoの`toAge`は元のまま変更しない
- **積立金額**:延長期間中(旧`retAge`〜新`retAge`)は、NISA分・iDeCo分・特定口座分の元の積立額を**合算した金額**を、丸ごと特定口座に積み立てる(元々の特定口座の積立額だけではない)

理由:口座別に利率を自由に設定できる以上、「NISA優先/特定口座優先」のどちらが有利かは決め打ちできない。合算して特定口座に寄せる方式なら、恣意的な有利不利の判断を伴わず、「同じペースで貯蓄を続けている」という実態を素直に表現できる。

**`simulate.ts`・`analyze.ts`は変更禁止(プロジェクトの絶対ルール)。この機能はイベント機構や呼び出し側のパラメータ加工で完結させること。**

## 実行内容

### 0. 事前確認(このタスクの最初に必ず行うこと)

1. 旧HTML版(STEP29)に存在した`con_change`イベント(`nisa_con_change`/`ideco_con_change`/`tax_con_change`。口座別に積立額を任意年齢から上書きできるイベント)が、Next.js版の`types.ts`(`LifeEvent`型)・`simulate.ts`に移植済みかどうかを確認せよ
2. 移植済みの場合:`con_change`イベントで指定した積立額が、その口座の`toAge`を超えた年齢でも適用されるのか、それとも`toAge`のゲート(`taxActive`等)によって無視されるのかを確認せよ。これは今回の実装方式に直結する重要な分岐点
3. 上記の結果を踏まえ、以下のいずれかの方式で実装すること:
   - **方式A(`con_change`が使えて`toAge`ゲートを超えて適用される場合)**:特定口座の`toAge`を新`retAge`まで延ばした上で、`tax_con_change`イベント(開始:旧`retAge`、金額:合算値)を追加し、NISA・iDeCoは`nisa_con_change`/`ideco_con_change`で0円に上書きする
   - **方式B(`con_change`が未移植、または`toAge`ゲートに阻まれて期待通り動かない場合)**:`simulate.ts`を変更せずに実現する代替方法を検討し、実装前にどのような方式を取るか一度報告すること(KENZOの確認を挟む)。目安として、本機能専用に「延長期間中の口座別パラメータ(`toAge`拡張済みの特定口座+積立0円のNISA/iDeCo)」を直接組み立てて`simulate()`に渡すラッパー関数を新設する方式などが考えられる

事前確認の結果と、採用した方式(A/B)は完了報告に明記すること。

### 1. 動的境界探索機能への組み込み

上記で確定した方式を使い、退職延長方向の探索(「あと何年延長すれば届くか」)で、延長年数ごとに正しい口座状態(特定口座`toAge`拡張・合算積立)を反映した`simulate()`呼び出しを行うようにすること。

- 探索方法:1年刻みの線形探索でよい(前回の合意通り)
- 上限:`lifeEx - 1`まで試して届かない場合は「標準的な改善では届かない水準」として打ち切る

支出削減方向の探索(二分探索、0-50%を上限)は口座構造に影響しないため、今回の合算ロジックとは無関係。既存の合意通りのまま実装してよい。

### 2. 表示ロジック

- 支出削減%の最小必要量と、退職延長年数の最小必要量を両方計算する
- 変化量が小さい方を優先表示。同程度の場合は支出削減を優先(退職延長は生活設計への影響が大きいため)
- 表示文言:
  - 届く場合:「支出を{X}%削減すると達成見込みです」または「退職を{Y}年延長すると達成見込みです」
  - 届かない場合:「標準的な改善では届かない水準です」

### 3. 配置場所

新規ファイル(例:`src/lib/improvement-search.ts`)に切り出すこと。既存の`AiPanel.tsx`の`buildAIPayload()`(固定レバー版)とは目的が異なるため、統合・置き換えはせず独立させる。KPIカード(`KpiGrid.tsx`)から呼び出す形を想定。
