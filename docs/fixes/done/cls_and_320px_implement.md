## 2. 単位ごとの内容と受け入れ条件

### 単位1：#7（資産シミュレーターLP）

- 受け入れ：
  - 320pxで、CTAの幅が272px（本文幅）になり、はみ出し0。
  - 340〜360pxで、幅304px以下、余白16px。361px以上は、現状と同じ（304px、余白32px）。
  - 横スクロールなし（`scrollWidth === innerWidth`）。
  - 他の2か所のCTAの幅が、前後で同じ。

### 単位2：#6、#13（一人法人LP）
- #6：「完全リタイア」のラベル（`HitoriHojinForkDiagram.tsx`の36行・84行付近）に`whitespace-nowrap`を足す。**文字サイズは変えない。**

- 受け入れ：
  - 320pxで、ラベルが1行。340px以上は、前後で同じ（1行のまま）。ラベルが枠から出る量（約0.2px）と、画面端までの余白を報告する。

### 単位3：CLS案A（資産シミュレーターLPのHeroチャート）
- 原因（第1段階で確認）：`page.tsx:29`の`dynamic(() => import('@/components/lp/HeroDemo'), { ssr: false })`に`loading`がなく、サーバーが返すHTMLのチャート枠が高さ0（`BAILOUT_TO_CLIENT_SIDE_RENDERING`のtemplateだけ）。1024px未満では、この枠が見出しと説明文の間にあり、後から高さ310〜424pxが現れて、下を押し下げる。
- やること：チャートが現れる前から、**同じ高さの枠をサーバーのHTMLに出す。**
  - `dynamic`に`loading`を指定する、または、枠の外側（数値の行＋チャートと同じ縦横比の領域）をサーバー側で描き、Rechartsの部分だけ後から描く。**どちらにするかは、実物で確かめて決め、理由を報告する。**
  - 高さは、固定pxにしない。描画後の枠と**同じ`aspect-ratio`・同じ構造**で確保する（幅によって、310 / 354 / 367 / 424pxと変わるため）。
  - 読み込み中の見た目は、**色・動きを足さない最小限の枠**（アニメーションなし）。枠の色・罫線を決める必要があるなら、案を報告して止まる。
  - **サーバーが返すHTMLに、枠が高さ付きで入っていること**を、`curl`で確かめる。`loading`を付けても、`ssr:false`の動的importが、Next 14で枠をサーバーHTMLに出すかどうかは、**実物で確かめる**（推定）。出ないなら、別の方法（上の2つ目）にする。
  - 1024px以上は、右の列にあり、下を押さない（現状CLS 0）。**1024・1280pxで、0のままであること。**
- 受け入れ：
  - 320 / 375 / 414 / 768pxのCLS（本番ビルド、各3回、5秒後＋最下部までスクロールした後）が、**0.02以下**。（第1段階：0.16〜0.29）残りの内訳は、フォント由来（③）の0.000〜0.064が混ざりうるので、**フォントを遮断した条件でも測り、チャート由来の分が0になったことを分けて示す。**
  - 描画前の枠の高さと、描画後の枠の高さの差が、**各幅で1px以内**。
  - 1024・1280pxで、CLS 0のまま。
  - 描画後（アニメーション終了後）のスクリーンショットが、変更前と**差0**（`/`の6幅）。Heroチャートの帯のちらつきは、これまでどおり除く。

### 単位4：CLS案B（一人法人LPのHero）
- 原因（第1段階で確認）：左の列が`lg:grid-cols-[minmax(min-content,1fr)_minmax(0,520px)]`で、列幅が見出しの実際の幅（フォントで変わる）で決まる。フォントが切り替わると左の列が狭まり、右の図の列が広がって、図が`aspect-ratio`で高くなる。同時に左の列のCTA前の文が1行増え、CTAと下のセクションが+26px動く（1024pxで0.154）。
- **先に、`hitori-hojin/page.tsx:55-58`のコメントを読み、`minmax(min-content,1fr)`を使っている設計意図を報告する。** その意図を壊さない最小の変更にする。意図を壊さずに直せないなら、**実装せずに、案を報告して止まる。**
- 変更は、**次の条件の中だけ**：
  - 1024〜1099px付近の、左右の列の幅の差が、**数px〜10px以内**。
  - 1100px以上と、1023px以下は、スクリーンショットの**差0**。
  - **見出しが本文幅からはみ出す量、折り返し、図の大きさの変化が、前後で報告できる**こと。
- 受け入れ：
  - 1024pxのCLS（本番ビルド、各3回）が、**0.02以下**。（第1段階：0.154）フォントを遮断した条件でも、0のままであること。
  - 1100・1280・1440pxで、CLS 0のまま。
  - 320〜768pxで、前後のCLSとスクリーンショットが同じ（0.001〜0.002、差0）。
  - 条件を満たせない場合は、変更を残さず、報告して止まる。

## 3. 検証（全体）

- **測定は、`next build` → `next start`（本番ビルド）。** 起動の前後に、`ps`とポートで古い`next start`が残っていないか確かめてから、PIDを指定して止める。
- **メモリ不足が前回出た。測定は、幅ごとに順番に走らせ（並列にしない）、1回ごとにブラウザを閉じる。** 止まったら、再開の前に`git status`と`git diff --stat`、動きっぱなしのシェルを確かめる。
- CLSの測り方は、第1段階と同じ（`PerformanceObserver`、`hadRecentInput === false`、初回／再読み込みは先頭に戻してから）。**前後の表**（幅 × 初回／再読み込み、各3回）を、LP2つで作る。
- スクリーンショットの比較：乱数を固定し、変更前を2回撮って差0を確かめてから比較。ビューポートをページの高さまで広げ、アニメーションが終わってから撮る。**単位ごとに、変更したLPだけでなく、もう一方のLPと、320 / 375 / 768 / 1024 / 1280pxで差0を確認する。**
- 値は、クラス名から推測せず、`getComputedStyle`・`getBoundingClientRect`の実測で。実測できなかったものは、「クラスからの換算」と書く。
- `npx tsc --noEmit`と`npm run build`の結果。**tscは、単位ごとのpatchを当てた状態でも通ること**（可能な範囲で）。
- **本番とローカルの画素比較はしない**（フォントの描画が違う）。本番の確認は、マージ後。
- `tsconfig.tsbuildinfo`が書き換わったら、`git checkout`で戻す。
