# 実装指示書:目標資産到達年齢シミュレーター フェーズ3(CTA文言・UTM・GA4)

参照: `product_spec_fire_age_tool.md`(確定版・10章)、フェーズ2完了報告
(新規ファイル一覧・`FireAgeCta.tsx`の場所は上記完了報告を参照)

## 1. CTA文言(`FireAgeCta.tsx`)

第1弾(`MonthlyInvestmentCta.tsx`)のCTA構成(本格シミュレーターへの誘導+
証券アフィリエイトリンク)をそのまま踏襲しつつ、以下の一文を
**シミュレーターへのCTAボタンの直前**に追加すること:

> 目標資産に到達した後も、その資産で生活費をまかなえるかは別の問題です。
> 本格シミュレーターでは資産寿命・年金・取崩しまで確認できます。

**この一文の目的(実装者への申し送り)**: 本ツールは蓄積フェーズのみを計算し、
取崩率(生活費)を一切考慮していない。この限界を明示しつつ、本格シミュレーター
へのCTAの説得力を高めるための文言。文言自体を変えずにそのまま使うこと。

CTA文言中に開発コードネーム「LifeCompass」が紛れ込んでいないか、実装後に
必ずgrep確認すること(第1弾で実際に発生したバグの再発防止)。公開ページでは
一貫して「資産シミュレーター」と表記する。

## 2. アフィリエイトリンク

第1弾の`AffiliateLink.tsx`をそのまま再利用する(新規実装不要)。
`<AffiliateLink provider="matsui" landing="nisa" />` と同じ形式で、
本ツールのCTA内に配置する(積立額を入力する性質上、証券口座アフィリエイトとの
親和性は第1弾と同等と想定)。`[PR]`表記も第1弾と同じ運用に揃えること。

## 3. UTM設定

第1弾と同じ形式、キャンペーン名のみ変更:

```
utm_source=tools&utm_medium=referral&utm_campaign=fire_age_tool
```

シミュレーターへのCTAリンク・アフィリエイトリンクの両方に付与すること
(第1弾の実装箇所を参照して同じ付与パターンに揃える)。

## 4. GA4イベント

**第1弾と完全に同一の3種のみ**とする(イベント名・パラメータ構造とも
新規追加は行わない。Product Spec 10章の通り、運用をシンプルに保つ判断):

- `tool_calculate`
- `tool_to_simulator_cta_click`
- `tool_to_nisa_cta_click`

第1弾の実装箇所(`MonthlyInvestmentTool.tsx`等でのgtag呼び出し)と同じ
実装パターンをそのまま複製すること。イベント名・パラメータ名も第1弾と
完全に一致させ、GA4上で両ツールの計測結果を同じ軸で比較できるようにする。

## 5. 確認事項

- `full-verify.js` がPASSすること
- 「LifeCompass」という文字列がCTA文言・アフィリエイトリンク周りに
  残っていないことのgrep確認
- UTMパラメータが実際のリンクURLに正しく付与されていることの確認
  (ブラウザの開発者ツールでリンク先URLを確認、またはgrep)
- GA4イベントが実際に発火することの確認(方法は任意。前回のPlaywright手法、
  またはGA4リアルタイムレポートでの確認のどちらでもよい)
