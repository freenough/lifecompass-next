## 0. KENZOの決定（この範囲だけ。広げない）

**案左**：`AssetProgressBadges.tsx`の1ファイルだけ、`HeroDemo`と同じ方法で、KPIの最終値の**見えない複製**を、同じマスに重ねる。**サーバーで枠を先に描く変更（案右）はしない。**

## 1. 背景（実測で分かったこと）

- ずれの原因は、`ssr:false`の空の枠ではなく、**KPIの数字のカウントアップで折り返しが変わること**。幅326〜413pxで、マウント時は「0万円」で1行、カウントアップが「11,122万円」に届くと2行になり、KPI行が64pxから81pxへ+17px。下の「資産の内訳」（`DIV.mt-4.pt-4.border-t`）が押し下げられる。フォントを遮断しても同じ（フォント由来ではない）。
- 幅324px以下は最初から2行、414px以上は折り返さない。
- KPIの値は`text-sm`（14px）×`leading-tight`＝1行17.5px（`KpiCard.tsx:49`）。
- 参考実装：`HeroDemo.tsx:33-43`（`KPI_SIZER_VALUES`）、`120-138`（見えない複製を、同じgridのマスに重ねる）。引き継ぎ資料に、`invisible [grid-area:1/1]`と`aria-hidden="true"`を使い、計算後は複製がDOMから消える、と記録がある。
- 最終値の例：「11,122万円 / 13.5% / +100万円」。`simulate`／`analyze`から出る値で、乱数は使わない（`HeroDemo`の`DEMO_STATIC`と同様に、モジュール読み込み時に固定できる見込み）。**実際の値は、コードから計算して確かめる。**

## 2. 守ること

- 作業ブランチ`fix/asset-badges-sizer`を`main`から作って作業する。**commit、push、マージはしない。**
- 変えるのは`src/components/lp/AssetProgressBadges.tsx`（実際のパスは`find`で確かめる）**だけ**。`KpiCard.tsx`、`AssetManagementPromoSection.tsx`、`AssetBreakdownDonut.tsx`、`HeroDemo.tsx`は変えない（変えないと実現できない場合は、変えずに理由を報告する）。
- **最終状態の見た目は変えない**。見えない複製は、見えない・読み上げに出ない・クリックを邪魔しない（`invisible`、`aria-hidden="true"`、`pointer-events`）。
- **改行コード（CRLF）を保つ。** 前回、`sed -i`でCRLFがLFに変わった。編集はEditツールで行い、`git diff`で、変更行だけが差分に出ることを確かめる。`tsc`・ビルドのあと、`tsconfig.tsbuildinfo`が書き換わっていたら`git restore`で戻す。
- 検証用のスクリプトやログは、リポジトリの外に置き、終わったら消す。

## 3. 実装の方針

- 計算前（マウント直後〜カウントアップ中）に、最終値と同じ文言の複製を、各KPIの値のマスに重ねる。マスの高さ・幅は、複製が決める。
- 複製の文言は、カウントアップの終点と**同じ文字列**（フォーマット含む）にする。
- カウントアップが終わったあと、複製を残すか消すかは、`HeroDemo`と同じ扱いにする。消す場合は、最終値の文言が同じなので、ずれない。**どちらにしたか、理由と一緒に報告する。**
- 初回JSを増やさない（複製のために新しいimportを足さない）。

## 4. 確かめること

### 4-1. 変更の確認
- `git diff --stat`：1ファイルだけ。CRLFのまま、差分が変更行だけであること。
- `tsc --noEmit`と`npm run build`が通ること。

### 4-2. 実測（`next build`→`next start`）
幅 **320 / 326 / 375 / 413 / 414 / 768 / 1024**で、`/asset-simulator`の資産管理プロモのカードについて、**変更前（`main`）と変更後**を比べる。

- KPI行の高さ：マウント直後→カウントアップ終了後。**変更後は、両方が同じ値**（326〜413pxで81px）であること。
- カードの中の「資産の内訳」（`div.mt-4.pt-4.border-t`）の位置が、カウントアップの前後で動かないこと（`requestAnimationFrame`で毎フレーム記録）。
- ケーススタディのセクション（`section.bg-slate-50.py-12`）の高さが変わらないこと。
- CLS：カードを画面の中央に置いて止めた場合と、小さな読み取りステップでスクロールした場合。変更前は375pxで0.0096／0.0003〜0.00075。変更後は0付近であること。（ローカルはフォントのpreloadが出ず、ページ全体のCLSは本番より悪く出る。**カード由来の分だけ見る**ため、`layout-shift`の`sources`でカードの要素に絞る。）
- 見た目（最終状態）：変更前後で、カードのスクリーンショットが**同じ**であること（`md5`などで比較）。カウントアップが終わるまで待ってから撮る。
- アクセシビリティ：アクセシビリティツリーで、KPIの値が二重に出ていないこと。
- 乱数・日付によるハイドレーションのずれがないこと（ブラウザのコンソールに、hydrationの警告が出ていないこと）。
