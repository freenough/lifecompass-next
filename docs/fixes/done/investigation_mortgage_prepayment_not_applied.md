# 指示書:繰上返済設定が本体シミュレーション結果に反映されないバグ 調査

**このセッションの役割:** 調査のみ。原因を特定し報告すること。原因が明確でその場で直せる範囲であれば修正まで行って構わないが、設計判断が必要な場合は停止して報告すること。

## 症状

`LifeEventTimeline.tsx`のモーダルで住宅ローンイベントに繰上返済(単発)を設定し保存しても、タイムラインに戻った後の本体シミュレーション結果(総資産推移グラフ・KPIカード)が、繰上返済を設定しなかった場合と変化しない。モーダル内の試算プレビュー(完済年齢短縮・返済額軽減の表示)自体は正しく計算されている(前回セッションで実機確認済み)。

## 疑うべき箇所(調査の出発点)

1. **`formToEvent`関数**(`LifeEventTimeline.tsx`)
   - チェックONかつバリデーションOKの場合、`prepayAge`/`prepayAmount`/`prepayType`が実際に返り値のイベントオブジェクトに含まれているか
   - フィールド名が`simulate.ts`側で期待している名前(`prepayAge`/`prepayAmount`/`prepayType`)と完全一致しているか(タイポ・大文字小文字違いがないか)

2. **イベント保存・state更新の経路**
   - `formToEvent`の返り値が、タイムラインのイベント配列(`events` state)に正しく追加/更新されているか
   - 保存時に別の型(`LifeEvent`型等)への変換・スプレッドが挟まっており、そこでoptionalフィールドが欠落していないか

3. **`simulate.ts`側の`hasPrepay`判定**
   - `simulate.ts`が受け取るイベントオブジェクトの`prepayAge`/`prepayAmount`の型・存在チェック方法(`!== undefined`か`truthy`判定か)を確認。特に`prepayAmount`が数値の`0`になるケースがあれば、`truthy`判定だと`false`扱いになる可能性がある(ただしバリデーションで`0 < prepayAmount`のはずなので、通常は起きないはずだが念のため確認)
   - `evAge`や`ev.years`など、他のフィールドと同じ`ev`オブジェクトから`prepayAge`等を読み取っているか(別の変数・別のオブジェクトを参照していないか)

4. **シミュレーション再計算のトリガー**
   - モーダル保存後、実際に`simulate()`が新しいイベント配列で再実行されているか(Reactの再計算トリガー・メモ化・useEffectの依存配列漏れ等でstaleな結果を表示し続けていないか)
   - ブラウザの開発者ツールでNetworkタブ・Consoleにエラーが出ていないか

5. **実際に保存されたイベントデータの中身を直接確認**
   - ブラウザのlocalStorage(または該当の保存先)から、繰上返済を設定して保存したイベントのJSONを直接取り出し、`prepayAge`/`prepayAmount`/`prepayType`が実際に含まれているかを目視確認する

## 確認してほしいこと(優先順位順)

1. まず(5)の「保存されたイベントJSONの中身」を直接確認する。ここに`prepayAge`等が入っていなければ、原因は`formToEvent`かstate更新の経路(1・2)。入っていれば、原因は`simulate.ts`側の読み取り・判定(3)かトリガー(4)。
2. 原因を1箇所に絞り込んだら、該当コードを提示し、修正が単純な typo・条件式ミスであればその場で修正して構わない。修正した場合は、前回追加した繰上返済フィクスチャ(`reference/simulation_fixtures.md`)および`full-verify.js`の該当21ケースが引き続きPASSすることを確認すること。
3. 修正が`simulate.ts`側に及ぶ場合、ロックファイルへの再度の変更になるため、変更内容を明確に報告し、コミット前にこのチャットの確認を得ること。

## 報告フォーマット

- 保存されたイベントJSONの中身(繰上返済フィールドが含まれているか)
- 原因箇所の特定(ファイル・行番号)
- 原因の説明
- 修正した場合はdiff、`full-verify.js`・`tsc`の結果
- 修正が`simulate.ts`に及ぶ場合はその旨を明記し、コミットはせず報告のみ行うこと

**原因が`simulate.ts`側の修正を要する場合、コミット・pushはこのチャット側の明示判断を待つこと。UI側の軽微な修正(typo等)のみで完結する場合も、念のためコミット前に報告すること。**
