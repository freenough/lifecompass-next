# 実装指示：「毎月の資産を、記録する。」ブロックへの資産クラス内訳ドーナツ埋め込み

作成日：2026-09-21
種別：**実装（新規追加。既存ファイルへの変更は最小限）**
関連：`claude_investigation_hero_chart_reuse.md`（調査指示・完了済み）

---

## 背景

LPトップの「毎月の資産を、記録する。」ブロック（資産管理ツール紹介）のビジュアルが静的で「張りぼて感」が強いという課題があり、ヒーローセクションと同じ考え方（見せかけではなく本物のロジック・コンポーネントを実際に動かす）で解決する方針をKENZOとの設計チャットで確定した。

### 調査で判明した前提

- ヒーロー（`src/components/lp/HeroDemo.tsx`）は、固定の`DEMO_PROFILE`／`DEMO_EVENTS`を本番の`simulate()`/`analyze()`/`runMC()`に渡して実際に計算させ、結果を自前のRechartsグラフで描画している
- 資産管理ツールの「資産クラス内訳」ドーナツ（`src/components/assetManagement/AssetAllocationChart.tsx`）は、既に完全にプレゼンテーション用として切り出されており、props（`holdings: AssetHolding[]`、`totalAmount: number`）以外の外部依存（store/localStorage/ロックファイル）が一切ない
- 「初回表示時に動く」の実体はRechartsのPieのデフォルトマウントアニメーションのみで、合計金額のカウントアップ演出はこのコンポーネントには存在しない（`HeroDemo.tsx`側にのみ同種の仕組みがある）

### 採用する設計方針

- **`AssetAllocationChart.tsx`は一切変更しない。** LP側に新規ラッパーコンポーネントを作り、そこでスクロール検知・ダミーデータの用意・カウントアップを行い、`AssetAllocationChart.tsx`自体はそのままpropsを渡して描画するだけにする
- カウントアップの仕組みは、`HeroDemo.tsx`から共通フックとして抽出し、LP側の新規コンポーネントからimportして再利用する（`HeroDemo.tsx`への変更は発生するが、複製は避ける）

---

## 1. カウントアップ用フックの抽出

- `HeroDemo.tsx`内にある数値カウントアップの実装（FIRE達成年齢等の表示に使われているもの）を、共通フックとして抽出する
- 抽出先は、既存のディレクトリ構成に合わせて適切な場所に配置すること（例：`src/hooks/`や`src/lib/lp/`など、プロジェクトの慣習に従う。迷う場合は`HeroDemo.tsx`の近くに置く程度で構わない）
- `HeroDemo.tsx`側は、抽出したフックをimportして使う形に書き換える。**`HeroDemo.tsx`の見た目・挙動は一切変えないこと**（リファクタリングのみ。動作確認で現在の表示と完全に一致することを確認する）

## 2. LP用ラッパーコンポーネントの新規作成

- 新規コンポーネント（例：`src/components/lp/AssetAllocationDemo.tsx`、命名は既存の`HeroDemo.tsx`等の慣習に合わせて調整してよい）を作成する
- 内部で行うこと：
  1. **IntersectionObserverで、このコンポーネントが画面内に入ったことを検知する**（一度発火したら以降は再発火不要。既に画面外から画面内に入った時にアニメーションが動けばよい）
  2. 画面内に入るまでは`AssetAllocationChart`を**マウントしない**（条件付きレンダリング）。画面内に入った瞬間に初めてマウントすることで、Rechartsのデフォルトマウントアニメーション（扇形が開く動き）を自然に発火させる
  3. 同じタイミングで、1で抽出したカウントアップフックを使って合計金額をアニメーションさせ、その数値を`AssetAllocationChart`の`totalAmount`propに渡す
  4. `holdings`propには、下記3で定める固定のダミーデータを渡す

## 3. ダミーデータの内容

- ヒーローの`DEMO_PROFILE`（35歳・年収750万・NISA/iDeCo/特定口座/現金の4口座）と整合する内訳にする。「LP全体で同じ架空の人物のストーリーが続いている」印象を作るのが狙い
- `AssetHolding[]`型（`id`/`owner`/`accountCategory`/`assetClass`/`amount`/`updatedAt`）に沿って、NISA・iDeCo・特定口座・現金の4区分それぞれに妥当な金額を割り振ったダミー配列を用意する。金額の内訳自体は実装側の裁量でよいが、`DEMO_PROFILE`の設定（年収750万・35歳という設定感）と乖離しない、違和感のない金額にすること
- 色分け・ラベルは`AssetAllocationChart.tsx`が内部で使っている`getAssetClassColor`/`getAssetClassLabel`（`lib/assetManagement/classColors.ts`/`categories.ts`）にそのまま乗るはずなので、追加の指定は不要

## 4. 「毎月の資産を、記録する。」ブロックへの組み込み

- 対象ブロック（LPトップの資産管理ツール紹介セクション）の右側、現在ドーナツ風の何かが仮置きされている位置に、2で作成したラッパーコンポーネントを配置する
- 周辺のレイアウト（見出し・説明文・3つの箇条書き・CTAボタン）は今回変更しない。あくまで右側の視覚要素の差し替えのみ
- モバイル幅での表示崩れが出ないか確認すること（ケーススタディの前例もあるため、375px幅での確認を必須とする）

## 5. 遵守事項

- `AssetAllocationChart.tsx`・`classColors.ts`・`categories.ts`への変更は一切行わないこと（挙動を変えずにそのまま呼び出す）
- `HeroDemo.tsx`への変更は、カウントアップフックの抽出（リファクタリング）のみに限定し、見た目・挙動を変えないこと。変更前後で目視・可能であればコードレベルで一致することを確認する
- ロックファイル（`types.ts`/`profile.ts`/`PortfolioPanel.tsx`/`simulate.ts`/`analyze.ts`/`montecarlo.ts`/`blog.ts`/`blogTopics.ts`/`concerns.ts`/`ConcernCard.tsx`）への依存・変更は一切ゼロを維持すること
- 調査で見つかった「`HojinAssetAllocationChart.tsx`のコメントに“ロック対象”と書かれているが、CLAUDE.mdの一覧には含まれていない」という点について、**今回のタスクでは`HojinAssetAllocationChart.tsx`自体に一切触れないため対応不要**。この曖昧さの整理は別途バックログとして扱う
- 本変更は見た目・装飾の主観判断を伴うビジュアル変更にあたるため、mainに直接pushせず専用ブランチで作業すること。**ブランチ名は今回のタスク固有の名前にすること**（例：`feature/lp-asset-allocation-demo`。過去に汎用ブランチ名の使い回しで事故が発生したため、汎用名は使わない）
- Vercel Preview URLで、モバイル幅（375px相当）とデスクトップ幅の両方を確認してからKENZOに完了報告し、KENZOの確認・マージ指示を待つこと（コミット・pushの自律判断は禁止）
- 完了報告には、実測に基づく証跡（スクリーンショット・該当コード抜粋）を必ず添付すること
