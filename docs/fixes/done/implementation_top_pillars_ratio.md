# 実装指示書：2本柱ブロックの左右カラム比率変更（高さバランス調整）

作成日：2026-09-30
種別：**実装指示**（対象：`freenough-main`リポジトリ、`feature/top-hero-refresh`ブランチ）
前提：Hero最小フォントサイズ・CTA幅統一・レイアウト調整（前回分）はcommit・push済み、Preview確認済み。

---

## 0. 今回の内容

01（資産シミュレーター）・02（一人法人）ブロックの左右の高さバランスをさらに改善する。

前回の対応（`align-items: center`、一人法人側の図のトリミング）により、02ブロックの高さ差は+106px→+19pxまで縮んだが、01ブロックは実際のシミュレーター画面のスクリーンショットのため中身を削れず、+151pxのまま残っている。中央揃えのため、01の図の上端がテキスト（「01」）の上端よりかなり上にはみ出して見える。

上揃え（`align-items: start`）に変えると、今度はテキスト側の下に大きな空白ができてしまい、別の形でバランスが悪くなる。

そこで、**左右カラムの幅比率を変えて画像側を縮小し、高さの差そのものを縮める**方針にする。01・02とも同じ比率に揃える。

---

## 1. 作業上の絶対ルール（これまでと同じ）

1. `feature/top-hero-refresh`ブランチで作業する。
2. 第1段階はローカル確認・報告のみ。commit・pushはKENZOの明示的な指示があってから。
3. `tsconfig.tsbuildinfo`が書き換わった場合は元に戻す。

---

## 2. 左右カラム比率の変更

- 現状の左右比率（グリッド/フレックスの列幅指定）を確認し、**テキスト側を広げ、画像側を狭める**（目安：現状ほぼ1:1のところを、6:4または55:45程度に変更。実装しながら、テキストの折返しが不自然にならない範囲で調整してよい）。
- 画像側が狭くなった分、画像は自動的に縮小される。**01側（資産シミュレーターの実画面スクリーンショット）は、文字（KPIの数値・軸ラベル）が読みにくくなるほど縮小しないこと**を確認する。読みにくくなる場合は比率を6:4寄りに戻す（テキスト側をあまり広げすぎない）。
- 01・02それぞれで、変更後の左右の高さの差（px、1440px幅で計測）を報告する。前回値（01：+151px、02：+19px）からどれだけ縮まったかを明記する。
- `align-items`は`center`のままでよい。高さの差が比率調整でどこまで縮むか次第で、center/startどちらが自然に見えるか実際のスクリーンショットで確認し、報告に両方の見え方（可能であれば両パターンのスクリーンショット）を含める。判断はKENZOが行うので、実装者側で片方に決め打ちしない。
- 375〜1920pxの全幅で、比率変更後のレイアウト崩れ（テキストの折返し、CTAの位置、800px未満の1カラム表示への影響）がないか確認する。800px未満は1カラムのため、この比率変更は800px以上のみに影響する想定。

---

## 3. 検証

375, 390, 768, 799, 800, 1024, 1280, 1366, 1440, 1920の全幅で以下を確認する。

- 01・02それぞれの左右カラム比率が変更され、画像が縮小されている
- 01側の画像内の文字が引き続き読める大きさである
- テキストの折返しに不自然な崩れがない
- 横スクロールが発生していない
