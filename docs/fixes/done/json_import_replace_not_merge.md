# 実装指示書：JSON Importを「マージ」から「置き換え」に変更

作成日：2026-08-26
種別**：設計修正（重要度：高）**
背景：ユーザー報告により、JSON Importが完全な復元になっていないことが判明。前回の完了報告で
「マージ方針の違いはCSVとJSONの役割の違いによる意図的なもの」と説明・受理したが、この判断は
誤りだったため訂正する。

---

## 0. 問題

JSONは「完全バックアップ」としてUI上案内されているにもかかわらず、現在のImport実装は
マージ方式（IDが一致すれば上書き、一致しなければ追加、**存在しないものは削除されない**）に
なっている。このため、バックアップ取得後に追加されたデータが、復元後も消えずに残ってしまう。
「バックアップから復元する」という行為は、本来「その時点の状態にすべて戻す」ことを意味するため、
これは仕様として誤っていた。

---

## 1. 修正方針：JSONペイロードに含まれる範囲は、すべて「置き換え」にする

- **保有資産（`holdings`／`hojinHoldings`）**：ペイロードに含まれていれば、既存の保有資産を
  全て破棄し、ペイロードの内容だけに置き換える（マージしない）
- **記録履歴（`snapshots`）**：同様に、ペイロードに含まれる記録履歴だけの状態に完全に置き換える
  （ペイロードに無い年月の記録は削除される）
- **設定値（目標資産額・個人化想定比率）**：ペイロードに含まれていれば、そのまま上書きする
  （これは既に置き換えの挙動になっているはずなので、変更不要。念のため確認すること）
- **移転履歴ログ（`hojinTransferLog`）**：前回はid一致でマージする実装にしたが、これも
  「復元」の一貫性のため、**ペイロードに含まれていれば全置換**に変更する（マージではなく）

- **ペイロードに含まれていない項目（個人のみのJSONに法人データが無い等）は、既存のデータに
  一切触れない**こと（これは変更しない。あくまで「ペイロードに存在する範囲」だけを完全に
  置き換える、という考え方）

---

## 2. 確認ダイアログの文言修正

- 「マージされます」というニュアンスの文言があれば、「現在のデータは、このファイルの内容に
  完全に置き換わります（ファイルに存在しない過去の記録は削除されます）」という趣旨の、
  破壊的な操作であることが明確に伝わる文言に修正すること

---

## 3. ロックファイル制約（厳守・変更なし）

`types.ts` / `profile.ts` / `PortfolioPanel.tsx` / `simulate.ts` / `analyze.ts` / `montecarlo.ts` / `blog.ts` / `blogTopics.ts` / `concerns.ts` は一切import・改変しないこと。

---

## 4. 検証ルール（引き続き徹底）

検証は本番相当の実データ環境を一切使わないこと。検証専用の隔離された環境を用いること。

---

## 5. 完了報告時に必要なもの

- 意図的に「バックアップ取得後に増えたデータ」がある状態を作り、そのJSONバックアップを
  インポートした結果、増えたデータが正しく消えて、バックアップ時点の状態に戻ることを示す、
  インポート前後のJSON・保有資産一覧のスクリーンショット
- 修正後の確認ダイアログの文言のスクリーンショット
- `full-verify.js`・`tsc --noEmit`・ロックファイル依存grepの結果
