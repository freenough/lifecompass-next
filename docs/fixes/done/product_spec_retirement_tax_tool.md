# 第5弾ツール Product Spec:退職金手取り計算

作成日:2026-07-28(v2:KENZOフィードバック反映)
関連:`investigation_retirement_tax_tool.md`(投資調査)、`fix_retirement_tax_calc_80man_floor.md`

---

## 1. 目的・位置づけ

- 既存Tools(積立額逆算・目標資産到達年齢・複利計算機・年金繰上げ繰下げ)と同じ
  「単一目的の軽量計算機」というポジション
- 本体シミュレーターの`retirementTaxCalc()`(一律20.315%の意図的簡易近似)とは
  役割分担:**ツールは一次情報(国税庁)に完全準拠した正確な累進課税計算**を提供する
- 本体との数値差は仕様であり、バグではない。ツールUI上で明示する(後述4節)

## 2. 入力項目

### 常時表示
| 項目 | 型 | 備考 |
|---|---|---|
| 退職金収入額(万円) | 数値 | |
| 勤続年数 | 数値 | 端数は切り上げ(国税庁ルール通り) |

**「退職手当等の種類」は入力項目としては設けない。** ユーザーに一般/短期/特定役員という
税法用語を意識させず、勤続年数と役員チェックボックスから内部で自動判定する(UX優先)。

### 条件付き表示(段階的開示)
- **役員等ですか?(チェックボックス)**:勤続年数 ≤ 5年の場合のみ表示
- **詳細設定(折りたたみ、初期非表示)**
  - 障害者となったことに直接起因する退職ですか?(チェックボックス、+100万円控除)

### 内部自動判定ロジック
```
if (勤続年数 > 5) {
  種別 = "一般退職手当等"
} else if (勤続年数 <= 5 && 役員 === false) {
  種別 = "短期退職手当等"
} else if (勤続年数 <= 5 && 役員 === true) {
  種別 = "特定役員退職手当等"
}
```

## 3. 計算ロジック(一次情報準拠)

### Step 1: 退職所得控除額(`calcRetirementDeduction()`)
```
if (勤続年数 <= 20) {
  控除額 = Math.max(40 * 勤続年数, 80)  // 万円、80万円下限あり
} else {
  控除額 = 800 + 70 * (勤続年数 - 20)
}
if (障害者特例) 控除額 += 100
```

### Step 2: 課税退職所得金額(`calcRetirementTaxableIncome()`)
- **一般退職手当等**:`Math.max(0, 収入 - 控除額) × 1/2`
- **短期退職手当等**(勤続5年以下・役員等以外):
  - 300万円以下部分:`× 1/2`
  - 300万円超部分:`× 1`(按分、1/2適用なし)
  - いずれも`Math.max(0, 収入 - 控除額)`を土台に計算
- **特定役員退職手当等**(役員等・勤続5年以下):
  - `Math.max(0, 収入 - 控除額)`全額、1/2適用なし

**0円下限の明記**:控除額が収入を上回るケース(例:退職金50万円・勤続3年 →
控除額80万円のため`50-80=-30`)では、課税退職所得金額は0円とする
(`Math.max(0, ...)`を必ず適用。マイナス値のまま計算しない)。

**端数処理**:課税退職所得金額は**1,000円未満切り捨て**。

### Step 3: 所得税(令和8年分源泉徴収税額速算表、`calcRetirementIncomeTax()`)
`(課税退職所得金額 × 税率 - 控除額) × 102.1%`(復興特別所得税込み、5%〜45%の7段階)

**端数処理**:算出結果は**1円未満切り捨て**。

### Step 4: 住民税
市民税・県民税を**別々に計算し、それぞれ100円未満切り捨てしてから合算**する
(一括で「課税退職所得金額×10%」を計算してから切り捨てると、実務上の金額とズレが生じるため)。

```
市民税額 = 課税退職所得金額 × 市民税率(例:6%) → 100円未満切り捨て
県民税額 = 課税退職所得金額 × 県民税率(例:4%) → 100円未満切り捨て
住民税合計 = 市民税額 + 県民税額
```

※ 標準税率は市民税6%・県民税4%(合計10%)だが、自治体により配分が異なる場合がある。
本ツールでは標準税率(6%/4%)を採用し、自治体ごとの差異までは対応しないことを注記する。
また、均等割等は考慮しない簡易計算である旨を、結果画面のどこかに一言注記する
(小さめのテキストで可)。

### Step 5: 手取り額
`収入 - 所得税 - 住民税`

## 4. 結果表示(内訳を可視化)

「手取り額」の一発表示ではなく、計算過程を常時見える形で表示する:

```
退職金              3,000万円
────────────────
退職所得控除          800万円
────────────────
課税退職所得        1,100万円
────────────────
所得税                97万円
住民税               110万円
────────────────
手取り             2,793万円
```

「計算根拠を見る」を開かなくても内訳が一目で分かる構成とし、教育的価値を高める。
(数値は例示、実装時に正しい計算結果に置き換える)

## 5. 本体との数値差の明示方法

- 結果表示の下(または内訳の下)に、開閉式「計算根拠を見る」を設置
- 開くと、Step1〜4の詳細な内訳と算出根拠を表示
- 本体との差については、具体的な税率(20.315%等)を明記せず、
  将来本体側のモデルが変わってもUI文言の修正が不要な、抽象的な表現に留める:
  > 「本体の資産シミュレーターでは、長期シミュレーションを高速に実行するため、
  > 退職所得税について簡易モデルを採用しています。
  > このツールは国税庁の一次情報に基づく正確な計算のため、
  > 本体シミュレーターの結果とは金額が異なる場合があります。」
- methodologyページの既存の開示スタイル(「計算上の留意事項」)とトーンを揃える

## 6. 関数名・ファイル構成

税計算ロジックが今後増える見込み(年金税金計算・iDeCo出口税計算・退職所得控除など)を
踏まえ、`helpers.ts`に混在させず、専用モジュールとして独立させる。

- 新規ファイル:`src/lib/tax/retirement.ts`
- 関数構成:
  - `calcRetirementDeduction()` … Step1(控除額計算)
  - `calcRetirementTaxableIncome()` … Step2(課税退職所得金額の算出、種別自動判定込み)
  - `calcRetirementIncomeTax()` … Step3〜5を統括するメイン関数(ツールから呼び出す窓口)
- 既存`retirementTaxCalc()`(本体・`helpers.ts`)とは別実装。
  本体側の意図的簡易近似ロジックには手を加えない

## 7. 検証方針

- **控除額計算部分**:既存`retirementTaxCalc()`(80万円下限修正済み)と一致することを確認
  (共通ロジックとして`calcRetirementDeduction()`を本体側からも呼び出す形に
  リファクタリングするか、重複実装として個別に検証するかは実装時に決定)
- **税率・課税所得金額計算部分**:本体とは意図的に異なるため、一致検証ではなく
  国税庁の速算表・計算例との照合で正しさを担保
- テストケース:
  - 勤続20年以下・80万円下限が効くケース
  - 勤続20年超の通常ケース
  - 短期退職手当等(300万円以下/超の按分)
  - 特定役員退職手当等(1/2適用なし)
  - 障害者特例あり/なし
  - **控除額 > 退職金(例:退職金50万円・勤続3年)→ 課税退職所得0円・税額0円になる境界ケース**
  - 端数処理の確認(課税退職所得金額の1,000円未満切り捨て/所得税の1円未満切り捨て/
    住民税は市民税・県民税それぞれ100円未満切り捨て後に合算、を検証する具体例)
  - 田中誠シリーズ等、既存キャラクターの数値との突合(整合性チェック用途、一致は期待しない)

## 8. 決定事項・次回確認

- **`calcRetirementDeduction()`は独立実装とし、本体`retirementTaxCalc()`との共通化は行わない**
  (今回は判断確定)。理由:
  - 本体`retirementTaxCalc()`は将来的にも「意図的な簡易近似」という立ち位置を維持する前提であり、
    共通化すると本体側の変更がツール側の正確性を意図せず壊すリスク、逆にツール側の変更が
    本体のロック対象(simulate.ts/analyze.ts)に波及するリスクを両方避けたい
  - 控除額の計算式自体は国税庁ルールとして固定的(変更頻度が低い)なため、
    二重管理のコストは小さい
  - 一致検証(6節)はテストケースの突合で担保するため、共通化しなくても正確性は確認できる
  - 今後、本体側が簡易近似をやめて正確な累進課税に移行するような大きな設計変更があれば、
    その時点で`calcRetirementDeduction()`への一本化を再検討する
- methodologyページへの導線追記文言は既に提示済み(引き継ぎメモ参照)、
  ツールデプロイ後に反映
