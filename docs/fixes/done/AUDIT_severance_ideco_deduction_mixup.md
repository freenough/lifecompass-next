# 調査依頼：退職金の勤続年数控除に、無関係なiDeCo加入年数が混入している疑い

## 背景

以下の再現ケースで、本人・配偶者の退職金の手取り額に説明のつかない差が見つかった。

| | 退職金額面 | 勤続年数(退職金控除) | iDeCo | 退職金(手取り) | 退職所得税 |
|---|---|---|---|---|---|
| 本人 | 1,000万円 | 5年 | 加入年数13年・受取65歳(一時金) | 951万円 | 159万円 |
| 配偶者 | 1,000万円 | 5年 | なし | 919万円 | 81万円 |

額面・勤続年数がまったく同じ(1,000万円・5年)にもかかわらず、本人の方が税額が安く(手取りが多く)なっている。唯一の違いは、本人がiDeCoに加入している点(加入年数13年)だが、本人のiDeCo受取は65歳の一時金であり、今回の退職金(55歳時点)とは受取年が10年離れている。

以前確認した旧HTML版のコード(`retirementTaxCalc`関数、`AUDIT_spouse_severance_logic.md`参照)には、以下のコメントがあった。

```javascript
// 退職所得課税（iDeCo一時金＋退職金の合算対応）
// dcYears  : DC通算加入年数（iDeCo一時金の退職所得控除基準）
// sevYears : 勤務先勤続年数（退職金の退職所得控除基準）
// 同年受取の場合：max(dcYears, sevYears) で控除を一本化（重複期間調整の簡略化）
function retirementTaxCalc(idecoBalance, severanceAmount, dcYears, sevYears){...}
```

この「同年受取の場合」という前提条件が、実際のコードでは判定されずに**常に`max(dcYears, sevYears)`が適用されている**のではないか、という仮説がある。これが正しければ、退職金とiDeCoの受取年が異なる(合算課税されるべきでない)ケースでも、iDeCo加入年数が退職金の控除計算に紛れ込み、結果として本人だけ不当に有利な(または不当に不利な)計算になっている可能性がある。

## 調査してほしいこと

1. Next.js版の`retirementTaxCalc`(またはそれに相当する関数)は、`dcYears`(iDeCo加入年数)を使う条件として、「退職金とiDeCoが同一年に受け取られているか」を実際に判定しているか。判定箇所を関数名・ファイル名で示してください
2. 今回の再現ケース(本人:退職金55歳・iDeCo受取65歳、10年differenceあり)で、本人の退職金にかかる`retirementTaxCalc`呼び出しに渡されている`dcYears`の実際の値は何か(0/13など、実測してください)
3. 上記が13(iDeCo加入年数)である場合、それはなぜか。受取年が異なるのに`dcYears`が渡ってしまう条件分岐の欠落箇所を特定してください
4. 配偶者側(iDeCoなし)の場合は、`dcYears`にどのような値が渡っているか(0という想定で合っているか)
5. この控除計算のロジックが、以前の調査(`AUDIT_spouse_severance_logic.md`)で確認した「配偶者の退職金は本人と分離して課税される」という設計と矛盾しないか(配偶者側は正しく分離されているのに、本人側だけiDeCoとの区別が甘い、という非対称な実装になっていないか)

## 依頼の範囲

**調査のみ。実装・修正は行わないこと。** 原因が判明次第、対応要否をKENZOとClaudeで相談する。
