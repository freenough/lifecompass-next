# 調査指示書:配偶者iDeCo年金受取バグ・受取方式UI不整合

**種別:調査のみ(実装はしないこと)**
**背景:** 退職所得税計算バグ修正セッションの最終動作確認中に、KENZOが実機で以下の現象を発見。

---

## 現象1:iDeCo年金受取時、配偶者の受取額が0円になる

**再現条件(スクリーンショットより):**
- 配偶者のiDeCo残高:200万円
- 配偶者のiDeCo受取方式:「年金受取」相当の選択肢
- 結果:「iDeCo(手取り)」カードで 本人1,296万円 / 配偶者0万円 と表示される

**調査してほしいこと:**
1. iDeCo年金受取(`idecoReceiveType==='pension'`相当)の計算ロジックが、本人・配偶者それぞれの口座に対して独立に呼ばれているか、それとも本人側の変数だけを参照する実装になっていないか
2. 一時金受取(`lump-sum`相当)では配偶者分が正しく計算されているか(現状の退職金カードでは配偶者739万円と出ているため、口座自体の配偶者対応は機能している可能性が高い。iDeCo年金受取ロジック固有の欠落を疑う)
3. 該当関数名・コンポーネント名を報告(行番号ではなく)

---

## 現象2:受取方式の選択肢・ラベルが本人と配偶者で不一致

**再現条件:**
- 本人側の受取方式セレクトには「一時金」「年金」「併用」の3種類がある(と思われる)
- 配偶者側の受取方式セレクトには「年金」「年金受取」など、本人側と異なるラベル・選択肢しかなく、「併用」に相当する選択肢が見当たらない

**調査してほしいこと:**
1. 本人用・配偶者用でそれぞれの受取方式のenum定義・選択肢配列・ラベル文言がどこにあるか(同一ファイル内の別定義か、別ファイルか)
2. 定義が分岐している理由(意図的な仕様か、機能追加時の同期漏れか)
3. 「併用」ロジックが配偶者側にそもそも実装されているか、UIの選択肢が単に用意されていないだけか
