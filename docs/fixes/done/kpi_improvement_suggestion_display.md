# 実装：FIRE未達成カードへの改善案(動的境界探索)表示

## 背景

`improvement-search.ts`(`retirement_extension_contribution_logic.md`で実装済み)の`findImprovementThresholds()`(または`findExpenseReductionThreshold()`・`findRetirementExtensionThreshold()`)を使い、FIRE未達成カードに「支出何%削減/退職何年延長で届くか」を常時表示する。

これは残件③「未達成時の改善案自動提示」に対応する機能。

## 確定仕様

### 表示対象
FIRE達成カードが**未達成状態**のときのみ。達成済みカードには表示しない。

### ロジック
- 支出削減%の最小必要量(二分探索、0-50%上限)と、退職延長年数の最小必要量(1年刻み、`lifeEx-1`上限)を**両方**計算する
- **優先順位はつけない**。両方とも「達成に転じる」なら両方表示する。単位の違う量(%と年)を大小比較して片方を選ぶことはしない(この設計は一度採用しかけたが、「支出12%減 vs 退職2年延長」のようなケースで直感に反する結果になるため撤回済み)
- 組み合わせ(支出削減+退職延長を両方半分ずつ、等)は今回のスコープ外。実装しない

### 表示文言

| 状況 | 文言 |
|---|---|
| 両方届く | 「支出{X}%減または退職+{Y}年で達成」 |
| 支出のみ届く(退職は上限まで探索しても届かない) | 「支出{X}%減で達成」 |
| 退職のみ届く(支出は上限まで探索しても届かない) | 「退職+{Y}年で達成」 |
| どちらも届かない | 「大幅な見直しが必要」 |

`{X}`は整数%、`{Y}`は整数年で表示すること(小数点は出さない)。

### 配置

未達成カードの3行目として常時表示(タップ・ホバー不要)。既存の未達成カードの構成:

```
未達成                          ← メイン(既存)
退職後最低充足率{%}             ← サブ(既存)
支出{X}%減または退職+{Y}年で達成  ← 新規追加(3行目)
```

達成済みカード(「{fA}歳で達成」+「FIRE達成後最低充足率{%}」の2行構成)には触れない。3行目が増えるのは未達成カードのみ。

## 実行内容

1. `KpiGrid.tsx`のFIRE達成カードの未達成時レンダリング部分に、`findImprovementThresholds()`(または個別の2関数)の呼び出しを追加し、3行目のテキストを生成する
2. `StickyKpiBar.tsx`・`HeroDemo.tsx`は今回のスコープ外(これらは簡易表示のため、3行目の追加は行わない)。もし表示崩れ等の懸念があれば報告すること
3. 計算コストへの配慮:`findImprovementThresholds()`は複数回の`simulate()`呼び出しを伴う(二分探索+線形探索)。KPIカードの再描画のたびに毎回フル探索が走ると重くなる可能性があるため、`useMemo`等で入力(プロファイル・戦略)が変わらない限り再計算しないようにすること
