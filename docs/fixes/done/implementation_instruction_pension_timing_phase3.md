## 1. `PensionTimingCta.tsx`の実装

### 1.1 構成

第1〜3弾と同一構成:

1. 本格シミュレーターへの単一CTAボタン
2. その直下に`AffiliateLink`コンポーネント
   (`provider="matsui" landing="nisa"`、既存コンポーネントをそのまま再利用)

### 1.2 CTA文言(確定、spec 10章より転記)

```
この試算は増減率のみを見た簡易計算です。算出した受給開始年齢・年間受給額を、
資産シミュレーターの「年金受給開始」「年金受給額」欄にそのまま入力すれば、
他の資産状況・支出条件と合わせた詳細な試算ができます。
```

この文言は確定版であり、追加の言い換え・要約は行わない。フィールドラベル名
(「年金受給開始」「年金受給額」)は資産シミュレーター側の実際のラベルと
完全に一致させること(フェーズ1投資調査で確認済み:`penAge`=「年金受給開始」・
`penAmtVal`=「年金受給額」)。

### 1.3 CTAボタンのリンク先

本格シミュレーターへのリンクは、UTM付きURL(下記2章)を使用する。
**自動転記(URLパラメータでの`penAge`・`penAmt`への値の埋め込み)は行わない**
(v1スコープ外、方式B確定。spec 4・13章参照)。単純に本格シミュレーターの
トップへ遷移するリンクとする。

```

```

第1〜3弾と同一の命名規則(`{tool_name}_tool`)。`monthly_investment_tool`・
`fire_age_tool`・`compound_interest_tool`の実装パターンをそのまま踏襲すること。

## 3. GA4イベント(3種、第1〜3弾と完全同一のパラメータ構造)

### 3.1 `tool_calculate`

入力5項目すべてが埋まり計算が実行されたタイミングで発火。
**第1〜3弾と完全同一、パラメータなしで発火する**
(`gtag('event', 'tool_calculate')`)。

過去に複利計算機(第3弾)フェーズ3で、計算結果をパラメータとして統合する案が
検討されたが不採用となった経緯があり、その方針を維持する。本ツールにおいても
`target_age`・`compare_end_age`等のツール固有パラメータを追加しないこと
(実装前レビューで指摘・訂正)。

### 3.2 `tool_to_simulator_cta_click`

本格シミュレーターCTAボタンのクリックで発火。第1〜3弾と完全同一の
パラメータ構造。

### 3.3 `tool_to_nisa_cta_click`

**名称と挙動の対応関係に注意**(第1〜3弾からの既存の実装パターンをそのまま
踏襲する箇所):イベント名は`tool_to_nisa_cta_click`だが、実際に紐づくのは
NISA記事へのリンクではなく、`AffiliateLink`コンポーネント自体のクリックで
ある。この対応関係は第1〜3弾の実装と同一のため、本ツールでも同じ実装
パターンを踏襲すること(イベント名を変更したり、独自の新しいイベント名を
考案したりしない)。
