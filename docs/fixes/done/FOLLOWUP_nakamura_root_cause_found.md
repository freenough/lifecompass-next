# 中村夫婦シナリオA乖離:原因判明、調査は打ち切りでOKです

`INVESTIGATE_nakamura_scenario_mismatch.md`で依頼した調査は不要になりました。ファイルを探す必要もありません。原因が判明したためです。

## 原因

添付JSON(`(1).json`)とこちらの`lifecompass_中村夫婦①_split.json`を全項目diffした結果、差分は`spSevYrs`(美咲の勤続年数、退職所得控除の計算に使う)のみでした。

- こちらの`_split.json`: `spSevYrs: 0`(口座分割作業時に美咲へ退職金イベント1,000万円を追加したが、この勤続年数フィールドの更新を漏らしていた)
- 実機で使ったJSON: `spSevYrs: 13`

勤続0年だと退職所得控除がほぼ効かず、1,000万円の退職金の大部分が課税される。これが56歳以降、複利で拡大しながら乖離していったのが原因。**エンジン・スクリプトは正しく動作しており、バグではありません。**(この調査自体が、独自スクリプトが本番の`profileToSimParams()`/`simulate()`/`runMC()`を正しく呼び出していることの確認にもなったので、無駄ではなかったです)

## お願いしたいこと

1. `spSevYrs: 13`に修正した`lifecompass_中村夫婦①_split.json`(添付し直します)を正としてください
2. これに伴い、これまで報告済みの数値のうち**退職金が絡む部分(第9話・第10話・ブログのシナリオA/B/C)を`spSevYrs=13`で再計算**してください。それ以前の話数(第2〜8話)は美咲の退職金がまだ入っていない状態なので影響なし
3. 前回依頼した「独自スクリプトではなく本番関数を使う」という点は、今回の調査で**既に満たされていることが確認できた**ので、恒久スクリプト(`content-export.ts`)の新規作成は必須ではありません。ただし「完了報告に算出方法を明記する」運用は今後も続けてください(プロファイルの入力ミスのような今回のケースを早期発見しやすくなるため)
