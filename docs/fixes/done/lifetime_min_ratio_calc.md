# analyze.ts:退職後基準の「生涯最低充足率」と「最も厳しい年齢」の算出ロジック追加

## 背景

FIRE安全度カード(旧・FIRE達成カード)の再設計にあたり、新しい指標「生涯最低充足率」を導入する。これは既存の `fA`(FIRE達成年齢)判定と同じ前提(baseExp基準のFIREライン)を使いながら、「どれだけ余裕があるか/どれだけ足りないか」を連続値(%)で示すための指標。

これまでの調査で判明した既存ロジック(`src/lib/analyze.ts`)は以下の通り:

```
if (!fA && s.totalAssets > 0 && s.baseExp != null && s.totalAssets >= s.baseExp * 25) {
  const fromHere = snaps.slice(snaps.indexOf(s));
  if (fromHere.every(r => r.totalAssets > 0 && r.baseExp != null && r.totalAssets >= r.baseExp * 25)) {
    fA = s.age;
  }
}
```

## 実装したい内容

### 1. 対象期間の定義

**退職年齢(retAge)以降〜余命年齢(lifeEx)まで**を対象とする。積立期(退職前)は対象に含めない。

理由:退職前は資産形成の途上であり、baseExp×25のラインに届いていないのが当然のため、この期間を含めると「生涯最低充足率」が実質的に「現在の積立進捗率」になってしまい、本来検出したい「退職後のリスク」を示す指標として機能しなくなる。

### 2. 算出する値

対象期間内の各年について、

```
ratio = totalAssets / (baseExp * 25) * 100
```

を計算し、その**最小値**(`minRatio`)と、**その最小値を記録した年齢**(`minRatioAge`)の両方を返す。

実装上は、`fA`を探索するのと同じループ(退職年齢以降を走査する部分)の中で、同時に最小値とそのインデックス(年齢)を追跡すればよい。追加の走査は不要で、既存ループに変数を1つ追加する程度の変更で済むはず。

### 3. 関数の戻り値・インターフェース

既存の `analyze()` (または相当する関数)の戻り値に、以下を追加する形を想定。

- `minRatio: number | null`(対象期間が存在しない、またはbaseExpが取得できない場合はnull)
- `minRatioAge: number | null`

命名は既存のコードスタイル(`fA`, `dA`等の命名規則)に合わせて調整してよい。

### 4. `fA`との整合性の確認

`fA`が非nullの場合、理論上は`minRatio >= 100`になるはず(生涯を通じてラインを割らない年齢が見つかっているため)。`fA`がnullの場合は`minRatio < 100`になるはず。この対応関係が実際のデータで矛盾なく成立するか、実装後にフィクスチャで確認すること。

## 動作確認したいポイント

- 山本・中村・田中・佐々木の各フィクスチャで`minRatio`・`minRatioAge`を算出し、値が妥当な範囲(0〜200%程度)に収まっているか確認する
- 退職直後に大型の一時支出があるケース(前回の調査で再現した「達成率104%だが未達成」のケース)で、`minRatio`が100%を下回り、`minRatioAge`が退職直後の年齢(前回の例では56歳)になることを確認する
- `fA`と`minRatio`の整合性(`fA != null` ⇔ `minRatio >= 100`)が保たれているか確認する
