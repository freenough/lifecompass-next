# 指示ファイル:href属性へのbasePath自動付与に向けた事前調査(投資フェーズのみ)

## 種別
調査専用(コード変更なし)

## 背景
`src/lib/blog.ts`の`applyBasePathToHtml()`は現在、画像の`src`属性にのみ
`/asset-simulator`のbasePathを自動付与している。`href`属性(内部リンク)には
付与していないため、記事本文中の相対リンク(例:`/blog/xxx`)がbasePath無しの
まま出力され、404の原因になっていた(fire-checklist.mdで確認済み・該当記事は
既に手動修正済み)。

今後同様のミスが新規記事で再発しないよう、`applyBasePathToHtml()`を拡張して
`href`属性にも自動でbasePathを付与する「根本修正」を検討している。ただし、
過去に手動で`/asset-simulator`プレフィックスを付けてしまった記事が存在する
可能性があり、その状態で機械的に一括付与すると
`/asset-simulator/asset-simulator/...`のような二重プレフィックスが発生し、
かえってリンクを壊すリスクがある。

このタスクでは、実装はせず、**現状のリンク実態を洗い出す調査のみ**を行う。

## 調査対象
`lifecompass-next`リポジトリ内の全ブログ記事(現在14+本、コンテンツの格納場所
—— 例:`src/content/blog/`や`src/data/blog/`等、正確なパスは事前に確認する
こと。パスを推測・断定せず、実際のディレクトリ構成を確認してから着手する)

## 調査内容

### 1. 全記事内の内部リンク(href)を機械的に抽出
記事本文(Markdown/HTMLソース)内の`href="..."`属性を持つリンクをすべて抽出し、
以下のパターンに分類する:

- **パターンA**:`/asset-simulator/...`で始まる(既に手動でbasePathを付与済み)
- **パターンB**:`/blog/...`や`/tools/...`など、basePath無しの相対パス
  (自動付与されるとbasePathが正しく付く対象)
- **パターンC**:`https://freenough-lifecompass.vercel.app/...`のような絶対URL
  (これは`applyBasePathToHtml()`の対象外。href拡張では解決しない別問題として
  記録するのみでよい)
- **パターンD**:外部サイトへのリンク(`https://`で始まり、freenough-lifecompass
  ドメインではないもの)— basePath付与とは無関係なので除外してよいが、
  誤分類を避けるため一覧には残す

### 2. 記事ごとの集計表を作成
記事(スラッグ)ごとに、パターンA〜Dの該当リンクを一覧化する。特にパターンAが
1件でもある記事は、根本修正時に二重プレフィックス化するリスクがあるため
明確にフラグを立てること。

### 3. `applyBasePathToHtml()`の現在の実装を確認
`src/lib/blog.ts`内の該当関数の実装を確認し、`href`属性を拡張する場合に
どのような条件分岐(例:「既に`/asset-simulator`で始まっている場合はスキップ」)
が必要になりそうか、所感を報告に含める(実装はしない)。

## スコープ外(やらないこと)
- `applyBasePathToHtml()`の実装変更
- 記事内容・リンクの修正
- Git commit/push

## 完了報告に含めるべき事項
- ブログ記事の実際の格納パス(推測ではなく確認結果)
- パターンA〜Dの記事ごとの集計表(または全体サマリー+詳細は別ファイル添付でも可)
- パターンAが存在する記事の一覧(二重プレフィックスリスクがある箇所)
- パターンCの絶対URL該当記事の一覧(こちらは別問題として今後の検討対象)
- `applyBasePathToHtml()`の現在の実装内容と、href拡張時に必要そうな条件分岐の所感
