# 実装指示書: Hero見出しの改行位置を明示固定(360px幅3行崩れバグの修正)

対象ブランチ: mainから新規ブランチを切ること(例: `feature/lp-hero-heading-linebreak`)

## 0. 前提・背景

前々回セッションで発見済みの回帰バグ: Hero見出し「あなたのFIREは、何歳？」が、360px幅で「あなたの」/「FIREは、」の間で意図しない自動折り返しを起こし、本来2行のはずが3行になる

原因: フルードタイポグラフィ(`clamp()`)のフォントサイズ下限(2.5rem/40px)は375px幅で「あなたのFIREは、」が1行に収まる限界として決定されたものであり、360px幅では必要幅にわずかに足りず、ブラウザの自動折り返しアルゴリズムが単語境界を考慮せず途中で折り返してしまう

対応方針: `text-balance`の単語境界問題を明示的な`<br />`で解決した過去の前例(「毎月の資産を、記録する。」ブロック)にならい、フォントサイズをいじるのではなく、改行位置そのものを明示的に固定する

## 1. 実装内容

- Hero見出しの「あなたのFIREは、」と「何歳？」の間に明示的な`<br />`を挿入し、画面幅によらずこの位置で改行されるようにする
- この見出しに`text-balance`等、自動改行アルゴリズムに依存するクラスが付与されていないか確認し、付与されていれば除去する(`<br />`による明示固定と競合しないようにするため)
- 「あなたのFIREは、」というフレーズ自体に`inline-block`化等、折り返し防止の処理が必要か確認すること(過去の「突き合わせる」修正と同様のパターンが必要になる可能性がある)

## 2. 検証範囲

以下すべての幅で見出しが意図通り2行(「あなたのFIREは、」/「何歳？」)になっていることをスクリーンショットで確認すること。

- 320px(iPhone SE第1世代相当。この幅では「あなたのFIREは、」自体がさらに折り返され3行になる可能性がある。その場合は既知の物理的制約として完了報告に明記し、今回は対応不要とする)
- 360px(今回の主目的。修正前は3行崩れが発生していた幅)
- 375px、390px、428px(モバイル、現状問題なし。変化がないことを確認)
- 768px程度(タブレット、現状問題なし。変化がないことを確認)
- 1440px(デスクトップ、現状問題なし。変化がないことを確認)

## 3. 証跡要件

- 上記各幅でのスクリーンショット(特に360pxは修正前後の比較)
- 変更したファイルパス・該当箇所のdiff
- 320px幅での結果(2行に収まったか、3行のままか)を明記すること

## 4. 安全ルール(再確認)

- **完了報告にローカルファイルパスを一切含めないこと**。確認用画像は全てチャットにインライン表示するか、Artifact機能で共有すること
- コミット・pushは行わないこと。KENZOの明示的な指示を待つ
- devサーバーの停止は対象PIDを指定した個別停止のみ。全プロセス一括終了コマンドは使用禁止
- 完了報告にツールの内部ログ(シェルコマンド実行ログ等)をそのまま貼らないこと
