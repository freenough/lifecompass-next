# 指示書: GA4の本番限定化と、LP「FIREガイド」カードの二重表示解消に向けた事前調査

## 種別

**調査専用**。コード変更・git commit/push は一切行わないこと。

この指示書には、独立した2つのテーマ（A・B）が入っている。報告も、A・Bを分けて書くこと。

## 検証中の通信遮断（今回から標準ルール）

ローカルでPlaywright等を使って表示・計測するときは、**必ずGA4・AdSenseへの通信を遮断すること**（`googletagmanager.com`・`google-analytics.com`・`googlesyndication.com`・`doubleclick.net` 等へのリクエストを abort する）。これまでの検証で、localhostからの自動操作の記録が本番のGA4に送られていた可能性があるため。遮断の方法と、遮断できていることの確認方法も報告すること。

## A. GA4を本番環境でしか読み込まないようにする

### 背景

現状、ローカル（`next dev`）やVercelのPreview環境でも、GA4のタグが読み込まれて本番のGA4プロパティにデータが送られている可能性がある。サイトのアクセス規模がまだ小さい（3ヶ月で約26クリック）ため、検証のアクセスが混ざるとデータが大きく歪む。本番（Productionデプロイの本番ドメイン）でだけGA4を読み込む形にしたい。

### 調査項目

1. **GA4タグの読み込み方**
   - どのファイル・コンポーネントで読み込んでいるか（`next/script` の直書き、`@next/third-parties` の `GoogleAnalytics` 等）
   - 測定IDはどこから取っているか（環境変数名、直書きかどうか）
   - 読み込みに、現在なんらかの条件分岐（環境・ホスト名）があるかどうか
2. **イベント送信の仕組み**
   - `trackEvent` の実装
   - GA4のタグが読み込まれていないときの挙動（エラーにならず、何もしないで終わるか）
3. **実際の読み込み状況**（通信は遮断したうえで、リクエストが「発生しようとしたか」で判定すること）
   - `next dev`（localhost）で、GA4のスクリプトとデータ送信のリクエストが発生するか
   - `next build` → `next start`（localhost）で、同様に発生するか
4. **環境の判定に使える値**
   - このプロジェクトで使える環境変数（`VERCEL_ENV`・`NEXT_PUBLIC_VERCEL_ENV`・`NODE_ENV`・`NEXT_PUBLIC_SITE_URL` 等）と、それぞれがローカル・Preview・Productionで取る値
   - リポジトリ内から分かる範囲で報告すること。Vercelのダッシュボード側の設定（環境変数がどの環境に設定されているか）はKENZOが確認するので、確認が必要な項目を具体的に挙げること
5. **AdSense**
   - AdSenseのスクリプトの読み込み方と条件
   - ローカル・Previewでも読み込まれているか
   - GA4と同じ条件で本番限定にしてよいかの所感（AdSenseの審査・表示への影響がないかを含む）
6. **対象範囲**
   - 同じGA4のタグが、`lifecompass-next` の全ルート（一人法人のセクションを含む）で共通のレイアウトから出ているか
   - `freenough-main` リポジトリ（LP）でもGA4を読み込んでいるか。読み込んでいる場合は、同じ項目1〜5を確認すること
7. **Vercel Analytics 等、他の計測**が入っているかどうか
8. **実装方針の所感**（実装はしない）
   - 例：`NEXT_PUBLIC_VERCEL_ENV === 'production'` のときだけタグを出力する
   - Previewで表示確認するときに、GA4が「読み込まれていないこと」を確かめる方法

## B. LPの「FIREガイド」カードの二重表示解消

### 背景

LPの「FIREガイド」の横スクロールカード（`FireGuideCarousel`）は、アイキャッチ画像の中に記事タイトル・カテゴリが入っている。そのため、カード下のテキストのタイトル・バッジ・excerptと内容が二重になっている。

方針案は「カードを**画像＋日付だけ**にして、テキストのタイトル・excerpt・バッジを外す」。ただし、スマホでは画像が縮むため、画像内のタイトル文字が小さすぎて読めない懸念がある。判断の材料を集めたい。

### 判断の目安（KENZOとの合意事項）

- 画像内のメインタイトルが、375px幅で**14px相当以上**で表示されるなら、画像＋日付だけで確定
- それより小さい場合は、まずカード幅を広げる（例：画面幅の85%程度）ことで解決できるかを検討する
- それでも足りない場合は、スマホのときだけテキストのタイトルを残す

### 調査項目

1. **`FireGuideCarousel` の構造**
   - カードの中身（画像・バッジ・日付・タイトル・excerpt）と、それぞれのクラス
   - リンクの範囲（カード全体かどうか）
   - 画像の `alt` の現在の値
   - `next/image` の `sizes` の指定
2. **使われている場所**
   - LP以外（一人法人のLP等）でも使われているかどうか
   - excerpt が、このカルーセル以外で使われているかどうか（外した場合に excerpt が完全に未使用になるか）
3. **カードの寸法**
   - 375px・768px・1440pxでの、カードの幅と画像の表示サイズ（px）
4. **画像内のメインタイトルの表示サイズ（最重要）**
   - 375px幅で、LPに表示される4件それぞれについて、画像内のメインタイトル（例：「4%ルールは日本でも通用する?」）の**1文字の高さ**を、スクリーンショット上のピクセルで実測すること（deviceScaleFactor 1）
   - そこから推定される、テキストの文字サイズ換算（px相当）を報告すること
   - 実測に使った画像の該当部分を切り抜いて拡大し、DPR 1とDPR 3のそれぞれで見え方を提示すること（DPR 3は実際のスマホに近い見え方として）
5. **カード幅を広げた場合の試算**
   - 375px幅でカードを画面幅の85%程度（約320px）にした場合の、画像内のメインタイトルの文字サイズ換算
   - ブラウザ上の一時的なスタイル書き換えでスクリーンショットを撮れる範囲で撮ること（ソースは変更しない）
6. **画像＋日付だけにした場合の見え方**
   - 375px・1440pxで、ブラウザ上の一時的な書き換えによるスクリーンショット
   - カードの高さの変化（変更前→変更後）
7. **アクセシビリティ・SEO**
   - テキストのタイトルを外した場合に、リンクのアクセシブルな名前（`alt` または `aria-label`）として記事タイトルを渡す方法の所感

## 安全ルール（必ず守ること）

- `localStorage.clear()` などの破壊的操作は行わないこと。どうしても必要な場合は、対象オリジンが検証専用であることを確認し、実施前に報告すること。判別できない場合は操作せず、KENZOに確認を求めること
- devサーバーを停止するときは、ポートからPIDを特定し、そのPIDだけを個別に停止すること。`taskkill /F /IM node.exe` は**使用禁止**
- `tsconfig.tsbuildinfo` が書き換わった場合は元に戻し、報告すること
- この指示書を `done/` へ移動するのは構わないが、`docs/fixes/active/` フォルダ自体は削除しないこと

## 完了報告のフォーマット

- A・Bを分けて、各調査項目への回答を書くこと。ファイル名と関数名・コンポーネント名で示し、行番号には頼らないこと
- 実測値は、測定した幅・DPR・測定方法を併記すること
- Aについては、KENZOがVercelのダッシュボードで確認すべき項目の一覧を入れること
- Bについては、上記「判断の目安」に照らした所感を入れること（決定はKENZOが行う）
- **完了報告にローカルファイルパスは一切含めないこと。** スクリーンショットは、チャットにインライン表示するか、Artifact機能で共有すること
- 「確認した」「問題なし」とテキストで結論だけ述べるのは不可。スクリーンショットと実測値を実際に提示すること
- コード変更・commit・pushは行わないこと
