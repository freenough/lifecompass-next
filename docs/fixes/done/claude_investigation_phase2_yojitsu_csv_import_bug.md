# 調査指示：CSVインポート後、資産推移・予実比較に反映されない不具合／データ重複

作成日：2026-08-31
種別：**調査（原因が明確かつ局所的な場合のみ、その場で修正を許可）**
関連：`claude_investigation_phase2_yojitsu_snapshot.md`（CSV Export/Importの仕組みの調査、今回の不具合の前提知識）

---

## 背景

KENZOが過去分（2026-01〜2026-09、月次）の資産実績をCSVでインポートしたところ、以下の症状が発生した。

1. **左側「保有資産」の合計が0万円になった**（インポート前は現金が入力されていたはず）
2. **「資産推移」セクションが「記録を重ねると推移がグラフで確認できます」という空状態のまま**で、記録日一覧にも「2026-09：0万円」の1件しか出ない（本来はインポートした9ヶ月分が並ぶはず）
3. **「予実比較」の実績側にも何も反映されない**

**補足（重要）**：当初、再エクスポートした際に同じID・同じ年月の行が全月で2行ずつ重複して出力される点も不具合として疑っていたが、これはKENZOが**元のCSVに誤って現金の行を2行書いてしまった**ことが原因と判明済み。データ重複そのものは調査対象外でよい。

ただし、**この「同一年月に同じ現金の行が2行あるCSV」を取り込んだことが引き金となって、インポート処理自体が想定外の壊れ方をし、結果的にデータが空になった可能性がある**。単純に「重複行があると片方が正しく処理されない」程度であれば軽微だが、「同一年月内に重複行があると、その年月グループ全体の処理が失敗し、他の月・現在の保有資産にまで影響が及ぶ」ような壊れ方をしているなら、これは重大な設計上の弱さ（1箇所の入力ミスが全体を破壊する）なので、そこも含めて調査すること。

**このタスクは調査を主目的とし、原因が明確かつ修正が局所的（インポートロジックの単純なバグ等）である場合に限り、その場で修正してよい。原因が不明確、または影響範囲が広い場合は、修正せず原因報告のみ行うこと。**

---

## 調査1：保有資産（現在値）が0万円になった原因

**確認したいこと**
- CSVインポートが、`AssetSnapshot`（過去の記録）だけでなく、`AssetHolding`（現在の保有資産、常時ライブ編集される方）にも書き込む・上書きする実装になっているかを確認する
- なっている場合、なぜ0万円で上書きされたのか（インポートしたCSVの「今月」ラベルの行が空、または誤ったマッピングで0扱いになっている等）を特定する
- なっていない場合（本来`AssetHolding`には触れないはずの実装）、なぜ実機で0万円になったのかを、実データを見て特定する
- **同一年月内に重複行（今回のケース：同じ現金の行が2つ）があるCSVを安全なテストデータで再現し、それがインポート処理のどの段階で例外・想定外の挙動を起こすのかを特定する**（try-catchで握りつぶされて無言で失敗している、パース時に配列の扱いを誤っている、等の可能性を確認する）

**報告フォーマット**
- `AssetHolding`側のインポート時の挙動（触れる設計か触れない設計か）を明記
- 0万円になった具体的な原因をコード・実データで示す
- 重複行が引き金になっているかどうかを、再現テストの結果とともに明記

## 調査2：資産推移・予実比較に反映されない原因

**確認したいこと**
- 調査1の結果を踏まえた上で、`AssetSnapshotHistory.tsx`（資産推移のグラフ・一覧）や予実比較コンポーネントが、正しくstorageからデータを読み出せているかを確認する
- storage層にデータが存在するにもかかわらず表示されない場合、読み出し側のフィルタリング・ソート等のロジックに問題がないかを確認する

**報告フォーマット**
- 表示されない原因（storage側にデータが無いのか、読み出し側のバグなのか）を明記

---

## 全体の遵守事項

- 原因が明確かつ局所的な修正で対応できる場合のみ、その場で修正してよい。ただし、**現在KENZOの実データに重複が既に存在する可能性があるため、修正時はデータのクリーンアップ（重複除去）が必要かどうかも合わせて確認・報告すること**（安全なテストデータでの検証に留め、KENZOの実データを直接いじらない。重複除去が必要な場合は、その方法を提案するのみで、実データへの実行はKENZO確認後に行う）
- 原因が不明確、または影響範囲が広い（例：CSV Import機構自体の設計に起因し、他の機能にも波及する）場合は、修正せず調査結果のみ報告すること
- ロックファイルへの変更はゼロ
- 検証は安全なテストデータで行い、本番相当の実データ環境を使わないこと
- 完了報告には必ず実際のlocalStorageデータ・コード抜粋・再現手順を添付すること。推測のみの報告は不可
