# シナリオA数値の乖離:原因調査依頼

## 問題

添付JSON(`lifecompass_中村夫婦①(1).json`)を実機ブラウザで直接実行し、CSVエクスポートしたところ(`asset_simulation_2026-07-23.csv`)、報告された「シナリオA/第10話」の数値と一致しない。

| 年齢 | 実機CSV(添付) | 報告値 | 差 |
|---|---|---|---|
| 38 | 2,608万 | 2,608万 | 0 |
| 49 | 7,930万 | 7,930万 | 0 |
| 52 | 8,986万 | 8,986万 | 0 |
| 55 | 10,546万 | 10,546万 | 0 |
| 56 | 11,319万 | 11,319万 | 0 |
| **58** | **14,240万** | 14,124万 | -116万 |
| 65 | 12,111万 | 11,988万 | -123万 |
| 68 | 11,941万 | 11,812万 | -129万 |
| 80 | 14,630万 | 14,468万 | -162万 |
| 90 | 16,854万 | 16,645万 | -209万 |

**重要な手がかり**: 56歳まで(退職金発生前)は完全一致。58歳(退職金発生年)から乖離が始まり、以降拡大し続けている。乖離の開始タイミングが退職金発生年と一致することから、退職金の課税処理(退職所得税計算)か、その前後の処理に本番エンジンとの差異がある可能性が高い。

## 依頼したいこと

1. **報告済みの数値(シナリオA・シナリオB/C・NOTE第7〜10話)が、実際にどう算出されたか確認してください**。`scripts/nakamura-rebuild.js`(独自スクリプト)で計算したのか、実際に本番の`simulate()`/`analyze()`関数(または実機ブラウザ)を呼び出して算出したのか、切り分けて報告してください。

2. もし独自スクリプトで計算していた場合、**添付の実機CSV(38〜90歳の全年次データ)と1行ずつ突き合わせて、どの処理(退職金課税・iDeCo受給・特定口座の含み益課税など)でズレているかを特定してください**。SIMULATION_GUIDE.mdに記載の「よくある移植ミスのパターン」も参照すること。

3. 原因を特定したら、**今後の全ての数値報告(シナリオB/C・NOTE第7〜10話含む)を、独自スクリプトではなく実機ブラウザのCSVエクスポート、または本番コードの`simulate()`/`analyze()`/`runMC()`を直接呼び出す形で再取得し直してください**。プロジェクトの原則として「シミュレーター出力(CSV実出力)が唯一の正」であり、独自スクリプトでの再現計算はクロスチェック目的以外では使わない。

4. MC(モンテカルロ)の数値についても、同じスクリプトの計算結果を使っている場合は同様の乖離が疑われるため、本番の`runMC()`経由で再取得してください。

## 前回の指示についての補足(修正)

- MCの24.8% vs 23.0%の不一致:どちらか一方に統一すればよい(再実行して1回に揃える)
- シナリオBのNISA枠超過:調整不要。当初のNISA残高は旧NISA+含み益とみなせるため、追加拠出分が1,800万円を超えていなければ問題ない、という判断で進める

## 完了報告のフォーマット

- シナリオA数値の乖離原因(該当ファイル・関数・処理内容)
- 独自スクリプトを使っていた場合、なぜ実機と異なる結果になったかの説明
- シナリオA/B/C・NOTE第2〜10話、すべてを実機ベースで再取得した最終数値
- MCも含めて実機ベースで統一されていることの確認
