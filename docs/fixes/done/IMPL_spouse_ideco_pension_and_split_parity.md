# 実装指示書:配偶者iDeCo年金受取バグ修正 + 受取方式の本人パリティ実装

**種別:実装含む(調査は完了済み。本ファイルの内容で実装してよい)**
**背景:** 調査の結果、以下2点が判明。原因・修正方針は確定済み。関数名・コンポーネント名で報告すること(行番号は編集中にずれるため使用しない)。

## Stage A:配偶者iDeCo年金受取額が0円になるバグの修正

### 原因(確認済み)
- 配偶者の年金受取処理(`simulate()`内のSpouse iDeCo pension payoutブロック)は世帯収入(`income`)には正しく加算しているが、本人側にある`idecoAnnualGross`相当の年次記録フィールドが配偶者側に存在しない。
- KPIカードが参照する`a.spIdecoLumpNet`(`analyze.ts`)は一時金受取ルート専用の`spIdecoWithdrawalAmount`のみを集計しており、年金受取ルートではこの変数がセットされないため常に0になる。
- 結果としてシミュレーション自体(資産推移・世帯収入)は正しいが、KPI表示だけが0円になる「表示専用のバグ」。

### 修正内容
1. `YearSnap`型(`src/lib/types.ts`)に、本人の`idecoAnnualGross`に相当するフィールドを配偶者用として追加する(命名は本人側の命名規則に揃えること。例:`spIdecoAnnualGross`)。
2. `simulate()`の配偶者年金受取処理内で、上記フィールドに税引前受取額(本人側の`idecoAnnualGross = Math.round(idecoAnnualPension)`と同じ考え方)をセットする。
3. `analyze()`に、本人の`idecoTotalGross`/`idecoTotalTax`/`idecoTotalNetWithdrawal`に相当する配偶者版の集計を追加する。
4. KPI表示(`KpiGrid.tsx`)側で、配偶者の年金受取分もiDeCo(手取り)カードの配偶者内訳に反映されるよう接続する。
   - 現状`spIdecoLumpNet`は一時金専用の値である点に注意。年金受取分と一時金受取分を合算して表示するのか、内部的に分けて保持しつつ表示だけ合算するのか、実装しやすい方でよいが、**本人側のiDeCo(手取り)表示ロジックと同じ考え方**に揃えること。

### あわせて修正:配偶者のiDeCo受取年数がハードコードされている問題
- 現状、`simulate.ts`は`spIdecoRemainingYears = p.spouse?.idecoReceiveYears ?? 10`を参照するが、`profile.ts`の配偶者オブジェクト構築部で`idecoReceiveYears: 10`が固定値になっており、ユーザーが変更する手段がない。
- `SimulatorForm.tsx`に配偶者用の「iDeCo受取年数」入力欄を追加し(本人側の「年金受取年数」と同じUI)、`profile.ts`側もこの入力値を反映するよう修正すること。

## Stage B:配偶者のiDeCo受取方式を本人と完全パリティにする

### 現状(確認済み)
- 本人:`SimParams.idecoReceiveType: 'lump' | 'pension' | 'split'`の3択。ラベル「一時金」「年金」「併用」。`split`選択時は`idecoSplitRatio`(一時金割合)のスライダーが追加表示される。
- 配偶者:`SpouseParams.idecoReceiveType?: 'lump' | 'pension'`の2択のみ。ラベルも「一括受取」「年金受取」で本人側と不一致。`split`相当のロジック(按分計算)も`simulate.ts`側に一切存在しない。

### 修正内容(本人と完全パリティ)
1. **型定義:** `SpouseParams.idecoReceiveType`の型を`'lump' | 'pension' | 'split'`に拡張する。
2. **計算ロジック:** `simulate.ts`内の配偶者iDeCo受取処理に、本人側の`isSplit`/`idecoSplitRatio`による一時金・年金の按分ロジックと同等の処理を実装する。配偶者用の按分割合パラメータ(例:`spIdecoSplitRatio`)を`SpouseParams`に追加すること。
3. **UI:** `SimulatorForm.tsx`の配偶者用受取方式セレクト(`spIdecoReceiveType`)を本人側と同じ3択にし、ラベルも本人側と統一する(「一時金」「年金」「併用」)。`split`選択時は本人側と同様、按分スライダーを追加表示すること。
4. **profile.ts:** 配偶者オブジェクト構築部で、`split`選択時の按分割合(`spIdecoSplitRatio`)が正しく反映されるようにする。

### 検証してほしいパターン(実装後)
- 配偶者:一時金のみ
- 配偶者:年金のみ(受取年数を10年以外に変更したケースも)
- 配偶者:併用(一時金割合を変えた複数パターン)
- 本人と配偶者で異なる受取方式を組み合わせた場合(例:本人=一時金、配偶者=併用)
- 本人・配偶者とも受取方式を変えた際、iDeCo(手取り)カードの内訳・累計課税額(該当する場合)が期待通りに動くこと

## Stage C:配偶者セクションのUI見出し(セクション区切り)を本人と統一する

### 現状(スクリーンショットで確認)
- 本人側の「資産」パネルは、「保有資産」(NISA残高〜現金残高)と「受け取り設定」(勤続年数〜iDeCo受取開始)の2つの見出し(セクションラベル)で視覚的に区切られている。
- 配偶者側(「配偶者を入力する」を開いた状態)は同じ項目群が並んでいるにもかかわらず、この見出しが一切なく、NISA残高から勤続年数・iDeCo受取方式まで区切りなしに連続表示されている。

### 修正内容
- `SimulatorForm.tsx`の配偶者セクションに、本人側と同じ「保有資産」「受け取り設定」の見出し(セクションラベル)を追加する。
- 項目の並び・グルーピングの境界も本人側と一致させること(保有資産:NISA残高〜現金残高、受け取り設定:勤続年数(退職金控除)〜iDeCo受取開始以降)。
- 見出しのスタイル(フォント・色・余白)は本人側で使われているコンポーネント/クラスをそのまま流用すること(新規にスタイルを定義しない)。

## Stage D:本人/配偶者の全項目網羅性チェック(実装前に必須)

### 背景
Stage A〜Cで判明した不具合(iDeCo年金受取額0円、受取方式の選択肢不一致、iDeCo受取年数のハードコード、UI見出しの欠落)はいずれも「配偶者機能が本人の後追い実装で、1対1の機能パリティが確認されていない」という共通パターンに起因する。個別に見つかった箇所を直すだけでなく、**同じパターンの見落としが他にもないか**を実装前に洗い出すこと。

### やってほしいこと
1. `SimulatorForm.tsx`(またはフォーム定義箇所)にある**本人側の全入力項目**を一覧化する(ラベル文言・フィールド名・型・デフォルト値を含む)。
2. 同様に**配偶者側の全入力項目**を一覧化する。
3. 両者を突き合わせ、以下の観点で差分表を作成する:
   - 本人にあって配偶者にない項目(例:年金受取年数)
   - 項目は両方にあるがラベル文言が異なるもの(例:「一時金」vs「一括受取」)
   - 項目は両方にあるが型・選択肢の種類数が異なるもの(例:受取方式の3択 vs 2択)
   - 本人にあって配偶者には存在しない計算ロジック(`simulate.ts`側)
4. 3で洗い出した差分のうち、Stage A〜Cで既に対応済みのものは「対応済み」、対応不要と判断したもの(意図的に本人専用で良い項目があれば)は理由とともに報告し、それ以外の**未対応の差分はすべてStage A〜Cと同じ考え方で修正する**こと(本人側に合わせる。配偶者側を削って合わせるのではない)。

### 特に確認してほしい既知の指摘
- 「年金受取年数」が配偶者側の入力項目に存在しない(本人にはある)。Stage Aで依頼した「iDeCo受取年数」欄の追加と同一項目かどうかも確認し、ラベル文言を本人側と完全に一致させること(「年金受取年数」)。
