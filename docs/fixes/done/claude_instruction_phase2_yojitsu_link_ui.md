# 実装指示：プロファイル連携UIの新設（資産管理ツール側・手動リンクのみ）

作成日：2026-08-31
種別：**実装（未実装だった機能の新規追加）**
関連：`claude_investigation_phase2_yojitsu_link_ui_bug.md`（今回の調査、`instruction_phase2_profile_linking.md`の連携UIが未実装だったことが判明）／`claude_instruction_phase2_yojitsu_v1_plan_and_compare.md`（この連携を前提にしていたV1計画保存機能）

---

## 0. 背景・スコープ

調査の結果、`instruction_phase2_profile_linking.md`で指示されていた「シミュレータープロファイルと資産管理ツールプロファイルを紐づけるUI」が、自動連動（2節）・手動セレクター（3節）とも実装されていなかったことが判明した。このため、V1の「計画を保存」ボタンが誰にとっても有効化されない状態になっている。

今回は、旧指示書の内容をそのまま再現するのではなく、**必要最小限に絞って作り直す**。

- 対象：**手動での連携（リンク）操作のみ**
- 対象外：シミュレーター側「法人資産」セクションでの連携（今回は資産管理ツール側に一本化する）、読込時の自動切替（旧指示書2節相当。複雑さの割に必要性が薄いため今回は作らない。将来必要になれば別途指示する）
- ストアアクション自体（`linkSimulatorProfile`/`unlinkSimulatorProfile`）は既存のものをそのまま使う。新設するのはUIのみ

---

## 1. 設置場所

`src/components/assetManagement/AssetManagerProfilePanel.tsx`（既存の「リンク切れ」時の解除ボタンが既にある場所）に追加する。

- 各資産管理ツールプロファイルの表示行に、以下を追加する：
  - 現在の連携状態の表示（未連携／「〇〇（シミュレーター側プロファイル名）と連携中」）
  - **未連携時**：連携先のシミュレータープロファイルを選ぶ`<select>`＋「連携する」ボタン
  - **連携中時**：既存の解除ボタン（`unlinkSimulatorProfile`）をそのまま維持

---

## 2. シミュレータープロファイル一覧の取得

- シミュレーター側の保存済みプロファイル一覧は、`PlanManagerPanel.tsx`が計画生成時に使っているのと同じ**読み取り専用の`loadProfiles()`**（`src/lib/storage.ts`）を使う。新しい取得ロジックを作らない
- `ProfileDrawer.tsx`・`simulatorStore.ts`には一切触れない（読み取りのみのため、これらへの変更は不要なはず。もし読み取りだけでは実現できない場合は、実装を止めて先に報告すること）
- 一覧が0件の場合、`<select>`を無効化し「シミュレーター側に保存済みのプロファイルがありません」等の案内を表示する

---

## 3. 連携操作

- `<select>`でシミュレータープロファイルを選び、「連携する」ボタンを押すと、既存の`linkSimulatorProfile(assetProfileId, simulatorProfileId)`ストアアクションを呼び出す
- 成功したら、その場で表示を「連携中」表示に切り替える（再読み込み不要）
- 既に他の資産管理ツールプロファイルが同じシミュレータープロファイルにリンクされている場合の重複チェックは、今回は行わない（1つのシミュレータープロファイルに対し複数の資産管理ツールプロファイルがリンクされる状態を許容する。将来問題になれば別途対応する）

---

## 4. V1計画保存機能との整合確認

- 本UIで連携を成立させた後、`claude_instruction_phase2_yojitsu_v1_plan_and_compare.md`で実装済みの「計画を保存」ボタンが正しく有効化されることを実機で確認すること（今回の調査2で使った手動データ注入ではなく、**本UIから実際に連携操作を行って**確認すること）

---

## 5. 遵守事項

- ロックファイル（`types.ts`/`profile.ts`/`PortfolioPanel.tsx`/`simulate.ts`/`analyze.ts`/`montecarlo.ts`/`blog.ts`/`blogTopics.ts`/`concerns.ts`）への変更はゼロ
- `ProfileDrawer.tsx`・`simulatorStore.ts`は変更しない（2節の通り、読み取りのみで完結するはず）

- 自動連動ロジック（読込時の自動切替）は今回作らない
- 既存テスト（`full-verify.js`）が全てPASSすることを維持し、新規UIに対する検証を追加すること
- 検証は本番相当の実データ環境を使わないこと
