# 指示書:期間短縮型の「表示上の短縮」とシミュレーション反映のずれ 調査

**このセッションの役割:** 調査(および原因が明確な場合は修正)。設計判断が必要な場合は停止して報告すること。

## 症状(実機で確認された再現ケース)

元本4,100万・金利1%・返済年数30年(開始38歳、完済68歳)のローンに対し、53歳時点で期間短縮型の繰上返済を設定した場合:

- **100万円繰上げ**:モーダル内試算表示は「完済年齢: 68歳 → 67歳(1年短縮)」だが、90歳時点の総資産・支出などシミュレーション結果が繰上返済なしの場合と**全く変わらない**
- **150万円繰上げ**:同様に「68歳→67歳」表示だが、こちらは総資産に**差が出る**

100万円と150万円で表示上の短縮年数(1年)は同じなのに、実際のシミュレーション結果への反映有無が異なるのはおかしい。

## 疑われる原因(仮説)

`calcMortgageTermFromPayment`が返す新しい残存期間は連続値(小数、例:14.87年)である一方、モーダルの試算表示はこれを四捨五入または切り捨てて整数の完済年齢として表示している可能性がある。一方`simulate.ts`の年次ループは整数年齢で`age < endAge`のような判定をしており、この`endAge`に連続値がそのまま使われているのか、それとも別の丸め処理がかかっているのかで、表示上の「1年短縮」と実際の年次ループでの支払い対象年齢の変化が食い違っている可能性が高い。

具体的には、以下を確認してほしい。

1. **モーダル側(`LifeEventTimeline.tsx`)の表示ロジック**
   - 「完済年齢: 68歳 → 67歳」という表示を作る際、`calcMortgageTermFromPayment`の返り値(小数)をどう丸めて整数の年齢にしているか(`Math.floor`/`Math.round`/`Math.ceil`のどれか、あるいは単純に`prepayAge + 新残存期間`を丸めているだけか)を特定する
   - 100万円・150万円それぞれのケースで、`calcMortgageTermFromPayment`が実際に返す生の小数値(丸め前)を計算し、報告すること

2. **`simulate.ts`側の反映ロジック**
   - 期間短縮型の場合、新しい完済年齢(`endAge`)を年次ループの条件式にどう組み込んでいるか(該当行を提示)
   - この`endAge`が小数のまま使われているか、どこかで丸められているかを確認
   - 100万円・150万円それぞれのケースで、実際に何歳まで返済が計上されるか(年次ループのどの年齢まで`extraExp`に加算されるか)をログ出力やデバッグで直接確認すること

3. **表示とシミュレーションの整合性チェック**
   - 表示上「1年短縮」と出ているのに、実際の年次ループでは1年分の支払い除外が発生していない(=表示が事実と異なる)ケースがあるかどうかを、他の入力値パターンでも複数試して確認する
   - もし整合性が取れていないケースが存在する場合、それは「表示のバグ(実態を正しく反映していない)」であり、ユーザーに誤解を与える重大な問題として扱うこと

## 追加確認事項(最優先・別観点)

上記の「表示とシミュレーションのズレ」とは別に、**より根本的な確認漏れの疑いがある**。繰上返済額そのもの(例:100万円)は、ユーザーが手元資金から支出する一括のお金であるはずだが、現在の`simulate.ts`実装がこの一括支出自体を資産・支出の計算に反映しているかを最優先で確認すること。

具体的に確認してほしいこと:

- 繰上返済年齢(`prepayAge`)の年に、`prepayAmount`(例:100万円)が一時的な支出として`extraExp`(または資産計算)に計上されているか
- 計上されていない場合、現在の実装は「繰上返済によって将来の返済負担が減るメリットだけが反映され、繰上返済のために手元資金を使ったコストが一切反映されていない」状態になっている。これは数値の正確性に関わる重大な欠陥であり、最優先で修正が必要
- もし計上されていた場合は、その実装箇所(該当行)を報告し、上記「表示とシミュレーションのズレ」の調査と合わせて整合性を確認すること

この論点は、企画中の新ツール(繰上返済 vs 投資比較)の前提(手元資金の使い道のトレードオフを見せる)そのものに関わるため、最優先で確認・報告すること。

## 期待される挙動(あるべき姿)

- モーダルの試算表示とシミュレーション結果は、常に一致していなければならない。「表示は1年短縮と出るのに実際には0年しか短縮されていない」という状態はあってはならない
- 修正方針としては、以下のいずれかが考えられるが、原因特定後に判断すること(このチャットで確認してから実装すること)
  - (a) 表示側を「実際にシミュレーションに反映される年齢」に合わせて正確に丸める(=シミュレーション側の判定ロジックと同じ丸め方式を表示にも使う)
  - (b) シミュレーション側の年次判定を、小数の`endAge`をそのまま使える形に変更する(年の途中で返済が終わる場合の日割り的な扱いが必要になり、改修規模が大きくなる可能性がある)
  - (c) その他、原因次第で異なる対応が適切な場合はその旨提案する

## 報告フォーマット

- **(最優先)繰上返済額そのもの(一括支出)が資産・支出計算に計上されているか否か、該当箇所の有無**
- 100万円・150万円それぞれのケースで、`calcMortgageTermFromPayment`の生の返り値(丸め前の小数)
- モーダル表示の丸め処理の実装内容(該当コード)
- `simulate.ts`側の`endAge`判定ロジック(該当コード、行番号)
- 実際に年次ループで何歳まで返済が計上されているかの実測結果(100万円ケース・150万円ケース・繰上返済なしケースの3パターン比較)
- 原因の特定(表示側の問題か、シミュレーション側の問題か、両方か)
- 修正方針の提案(上記(a)(b)(c)またはその他、それぞれの改修規模感を含む)

**このバグは`simulate.ts`に関わる可能性が高いため、原因特定・修正方針の提案までで一度停止し、このチャットの確認を得てから実装に進むこと。原因がモーダル側の表示ロジックのみで完結する軽微な修正であっても、念のため実装前に報告すること。**
