# 実装指示:冒頭説明文の動的化+40歳到達タイミングの簡略化に関する注記追加

## 背景
今回の一連の修正で解消しきれていなかった2点をまとめて対応する。

1. `ResidentTaxTimingTool.tsx`冒頭の説明文が、退職月(1〜5月/6〜12月)によらず固定のまま
   になっており、1〜5月退職を選んだユーザーには実態と合わない説明(「翌年の新しい住民税」等)
   を見せ続けてしまっている
2. 「40歳以上65歳未満(介護保険料を含む)」チェックが、波1(1〜2年前の所得基準)・波2
   (退職年または退職前年の所得基準)の両方に一律の料率を適用しているという簡略化について、
   これまで一度も明示的な注記をしていなかった

## 修正内容

### 1. `ResidentTaxTimingTool.tsx` 冒頭説明文の動的化
現在の固定文言(「住民税は「前の年の所得」をもとに翌年課税される仕組みのため、退職すると、
①退職前から進行中だった住民税の残り と ②退職した年の所得をもとにした翌年の新しい住民税、
という2つのタイミングでお金が必要になります。」)を、`values.retirementMonth`に応じて
出し分けること:

- **6〜12月退職(現状の文言のまま)**:
  「住民税は「前の年の所得」をもとに翌年課税される仕組みのため、退職すると、①退職前から
  進行中だった住民税の残り と ②退職した年の所得をもとにした翌年の新しい住民税、という
  2つのタイミングでお金が必要になります。」
- **1〜5月退職(新規)**:
  「住民税は「前の年の所得」をもとに翌年課税される仕組みのため、退職すると、①退職前から
  進行中だった住民税の残り と ②退職前年の所得をもとにした今年の新しい住民税、という
  2つのタイミングでお金が必要になります。」

`ResidentTaxTimingResult.tsx`側の②見出しの出し分け(`impl_resident_tax_timing_wave2_fix.md`で
実装済み)と同じ`retirementMonth <= 5`の条件をそのまま使い、文言のロジックを重複させず
共通の判定関数・定数を参照する形にできないか検討すること(できれば1箇所にまとめる)。

### 2. 40歳到達タイミングの簡略化に関する注記追加
`residentTaxTiming.ts`側、`isAge40OrOver`がtrueの場合(または`socialInsuranceRateOverride`が
指定されていない場合)に、`assumptionNotes`へ以下を追加すること:

「社会保険料率(40歳以上65歳未満の設定)は、波1・波2のいずれにも同じ料率を一律に適用した
簡易試算です。実際は、それぞれの所得を得た時点(1〜2年前と退職時点)での年齢によって
異なる場合があります。」

- この注記は「40歳以上」がチェックされている場合のみ表示すること(40歳未満デフォルトの場合、
  この簡略化は実質的に問題にならないケースが多いため、注記の必要性は低い。ただし、
  40歳未満のまま計算しても、実際は波1時点で40歳以上だった可能性もゼロではないため、
  常時表示するかどうかは実装前に一度検討し、完了報告書に判断理由を記載すること)
- 「計算根拠を見る」アコーディオン内の社会保険料控除の説明箇所にも、同趣旨の一文を
  追記すること

## 検証要件
- ブラウザ実機で、退職月を1〜5月に切り替えた際に冒頭説明文が正しく変化することを確認すること
- 「40歳以上」チェック時に、新しい注記が`assumptionNotes`に表示されることを確認すること
- `tsc --noEmit`エラーなし、`full-verify.js`全PASSを確認すること(文言のみの変更のため、
  通常は影響なしのはずだが念のため確認)
