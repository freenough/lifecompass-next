# input-row-alignment: 単一値入力行のレイアウト統一（調査→実装の2段構え）

## 背景

モバイル幅（1024px未満・縦積みレイアウト）で、単一値入力行（例: 年齢、残高、
インフレ率）の入力欄の右側に大きな空白が残っている。一方、ポートフォリオ入力行
（アセットクラス選択＋比率%）はドロップダウンが `flex:1` で画面幅いっぱいまで
伸びる設計になっており、幅の決め方が統一されていない。

これを以下の2ルールに統一する:

- **単一値行**: ラベル左・「入力欄＋単位」のクラスタを右寄せ（`justify-between`）。
  入力欄は固定幅を維持し、余白は「入力欄の右」ではなく「ラベルと入力欄の間」に置く
- **複数要素行**（ポートフォリオ行など）: 現状の flex 分配を維持、変更なし

加えて、タイムライン（ライフイベント）の「開始年齢」「期間」の入力欄だけが
他の単一値行より狭い幅になっており、既に不揃いが発生している。これも標準幅に
統一する。

**重要: ステップ0は調査のみ。コードは一切変更しないこと。**
ステップ0の報告を確認して方針をGOしてから、ステップ1の実装に進む。

---

## ステップ0: 現状調査（コード変更禁止・報告のみ）

モバイル表示の単一値入力行（例: 年齢、残高、期待利回り）について、
以下を調査して報告すること。

1. 単一値入力行のJSX構造（親コンテナ・入力欄・単位表示）
2. 使用している共通コンポーネントがあるか
3. 親コンテナのレイアウト（flex / grid / justify / gap など）
4. 入力欄の現在のwidth指定（固定px・rem・Tailwindクラス・flexなど）
5. 単位（万円・歳・%）の配置方法
6. 「ライフプラン」「家計」「資産」「運用方針・リスク」で共通実装か、個別実装か
7. 「ラベル左・入力欄＋単位右」のレイアウトへ変更する場合、
   最小変更で済む実装案と影響範囲

### 調査対象の範囲（全4セクション＋内部ブロック）

以下すべてを対象に、各入力行を **A: 単一値行 / B: 複数要素行 / C: 全幅行** に
分類した一覧表を作ること。一覧には各行の
**実装ファイル・行番号・幅指定クラス（px換算値）** を含める。

- ライフプラン（年齢系など）
- 家計（インフレ率、年間支出合計、年間余剰CF、配偶者の年間収入・年金額 等）
- 家計内タイムライン（イベント追加フォーム: 開始年齢、期間、金額。
  イベント種別/サブ種別のドロップダウン行と名称入力行はC分類の想定）
- 資産（NISA/iDeCo/特定口座の残高等の単一値行、ポートフォリオ行はB分類の想定）
- 運用方針・リスク
  - 利回り設定（NISA rW/rR、iDeCo rW/rR、特定 rW/rR。
    構造は「入力欄＋%＋トグル」の3要素）
  - MC設定（積立期σ、取崩期σ。同じく「入力欄＋%＋トグル」）

### 特に確認すべき点

- **標準幅の特定**: 家計・資産などの単一値行で使われている入力欄幅のクラスを
  「標準幅」として特定する。逸脱している箇所（タイムラインの開始年齢・期間、
  他にあればすべて）を列挙する
- **幅指定の管理状態**: 標準幅が共通定数/共通コンポーネントで管理されているか、
  各所にハードコードされているか

### 報告フォーマット

```
## 調査報告: input-row-alignment ステップ0

### 1. 行分類一覧
| セクション | 行（ラベル） | 分類(A/B/C) | ファイル:行 | 幅指定クラス(px) |
|---|---|---|---|---|

### 2. 共通コンポーネントの有無
（あり/なし。ありの場合はコンポーネント名と使用箇所）

### 3. 標準幅と逸脱箇所
- 標準幅: （クラス名とpx換算値）
- 逸脱箇所: （一覧）

### 4. 単位表示の配置方法
### 5. 最小変更の実装案と影響範囲
### 6. 懸念点・確認したい事項
```

**ここで一旦停止し、報告を提出すること。GOの指示があるまでステップ1に進まない。**

## ステップ1: 実装（ステップ0のGO後にのみ着手）

### 変更内容

1. **単一値行（A分類）すべて**: 親コンテナを「ラベル左・入力クラスタ右」に変更
   （`justify-between` 相当）。入力欄＋単位はひとまとまりのクラスタとして右端へ。
   入力欄の幅指定・単位表示の内容は変更しない
2. **利回り設定・MC設定の行**: 「入力欄＋%＋トグル」の**3要素をクラスタごと**
   右寄せする。トグルだけが左に取り残される形にしないこと
3. **タイムラインの開始年齢・期間**: 入力欄の幅をステップ0で特定した標準幅に統一
   （金額は既に標準幅のはずなので、逸脱していた場合のみ修正）
4. **B分類（ポートフォリオ行）・C分類（全幅行）・ボタン行（追加/キャンセル）**:
   一切変更しない

### 幅指定の集約（提案のみ・実施はGO後）

幅指定が各所にハードコードされている場合、共通定数または共通行コンポーネントへの
集約案をステップ0の報告に含めること。集約を実施するかどうかは報告を見て判断する。

### 制約

- 2段レイアウト（要素を2行に分けて積む配置）を新規に作らないこと（既存原則）
- デスクトップ幅（lg以上）のレイアウトに影響を出さないこと。
  変更がモバイル/デスクトップ共通のクラスに及ぶ場合は、その旨を報告に明記する
- ブレークポイントを新規に導入・変更する場合は、該当ファイル・行・px値を
  実測したうえで報告すること（自己申告のみの「確認済み」は不可）

### 完了報告に含めるもの

- 変更ファイル一覧と変更内容の要約
- 6-A: KPIスナップショット比較（変更前後）— レイアウトのみの変更のため
  **KPI値は完全一致が期待値**。差分が出た場合は実装を止めて即報告
- 6-B: ts-nodeスクリプトによるスナップショット比較 — 同上
- モバイル幅（375px前後）での各セクションのスクリーンショットまたは
  実測確認結果（利回り設定・MC設定のトグル位置、タイムライン3行の幅統一を含む）
