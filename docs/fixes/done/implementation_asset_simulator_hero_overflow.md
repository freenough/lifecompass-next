## 0. 決定事項

調査報告の**案A**を採用する。

- 変更は`src/app/page.tsx:252`の1か所だけ。
- `lg:shrink-0`を削除し、`lg:min-w-0`を追加する。
- `lg:w-(--lp-hero-chart-width)`は残す（縮めるときの基準幅として使う）。

### 不採用とした案とその理由

- **下限幅の追加（`lg:min-w-[411px]`など）は入れない。**
  - 案Aでは、1,024px以上でカードは434.5pxより小さくならない（左列525.5px＋ギャップ16pxで決まるため）。
  - 411pxでも崩れないことは確認済みなので、下限は不要。
  - 下限を入れると、将来左列の最小幅が広がったときに、再びはみ出しの原因になる。
- **案B（gridへの変更）は採用しない。** 一人法人LPと書き方が揃う利点はあるが、今回の不具合は1行で解消できる。Hero全体の構造やギャップを変えると、1,200px以上の見た目まで変わってしまう。
- **案C（切り替え幅の変更）は採用しない。** ファーストビューが大きく変わり、一人法人LPとの前提（2列への切り替えはどちらも`lg`）も崩れるため。

## 2. 検証

- 対象幅：375・640・1,023・1,024・1,050・1,080・1,085・1,086・1,099・1,100・1,109・1,110・1,200・1,280・1,440px

  - カードの`left`・`right`・`width`
  - `clientWidth − 24`（右余白の内側の端）とカードの`right`の差（1,024px以上の全幅で、カードの右端がこの値以下であること）
  - 左列の`width`

### 2.2 変化しないはずの範囲の確認

- 1,110px以上（1,110・1,200・1,280・1,440px）：カードの`width`が520で、`left`が調査報告の値（566／632／672／752）と一致すること。
- 1,023px以下（375・640・1,023px）：縦積み表示の実測値が、調査報告の値と一致すること。

### 2.3 画面幅を変えたときの追従

ページを1,440pxで読み込んだあと、リロードせずに画面幅を1,024pxに変える。この状態で、次の2点を確認する。

- グラフ（`ResponsiveContainer`）がカードの幅に追従して縮むこと
- KPIカード3枚の高さ（`useEqualHeight`）が揃ったままであること

逆方向（1,024px→1,440px）も確認し、どちらもスクリーンショットを撮る。
