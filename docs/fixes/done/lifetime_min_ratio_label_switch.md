# 【前の指示の取り消し】計算ロジックはシンプルに戻し、ラベルを状態で切り替える方式に変更

## この指示について

直前に渡した `lifetime_min_ratio_start_age_fix.md`(開始年齢を`max(fA, retAge)`にする修正)は**取り消します**。まだ着手していなければ無視してください。着手済みであれば、以下の内容で上書きしてください。

## 新しい方針

「退職後最低充足率」という名前に計算範囲を合わせるのではなく、**状態(達成/未達成)によってラベル文言自体を変える**ことで解決する。

- **達成時(`fA != null`)**: ラベルを **「FIRE達成後最低充足率」** とする。計算範囲は `lifetime_min_ratio_calc.md`(最初の実装)と同じ、**`fA`以降〜lifeEx**(`retAge`との比較・clampは不要)
- **未達成時(`fA == null`)**: ラベルを **「退職後最低充足率」** とする。計算範囲は現状のまま **`retAge`以降〜lifeEx**

つまり、`minRatioStartAge = fA ?? p.retAge` という、`lifetime_min_ratio_naming_fix.md`時点のシンプルな計算ロジックに戻して問題ない。`Math.max(fA, retAge)`のようなclamp処理は不要。

## なぜこれで矛盾が解消するか

佐々木誠一のケース(`fA=57`、`retAge=60`)では、計算範囲が`[57, 90]`(退職前の57〜59歳を含む)になるが、ラベルが「FIRE達成後最低充足率」であれば、「FIRE達成した後の期間」という意味そのままなので、退職前の期間を含んでいても定義上正しい。「退職後」というラベルを使うのは未達成時のみであり、未達成時は必ず`retAge`以降で計算されるため、こちらも矛盾しない。

## 実装したい変更

1. `src/lib/analyze.ts`:`lifetime_min_ratio_start_age_fix.md`で加えようとしていた`Math.max(fA, retAge)`のロジックがあれば削除し、`fA ?? p.retAge`のシンプルな形に戻す(または最初から変更していなければ何もしなくてよい)
2. UIコンポーネント側(`kpi_grid_redesign.md`で実装予定のFIRE安全度カード):サブテキストのラベル文言を、達成時は「FIRE達成後最低充足率」、未達成時は「退職後最低充足率」と、状態に応じて出し分ける

## 動作確認したいポイント

- 佐々木のケースで、計算範囲が`[57, 90]`に戻り、値が`lifetime_min_ratio_calc.md`時点の`106.3%`(fA=57基準)になることを確認する
- 山本・中村のケースは`fA >= retAge`なので、`fA ?? retAge`でも`max(fA, retAge)`でも結果は変わらないはず。値に変化がないことを確認する
- UIのラベルが達成時「FIRE達成後最低充足率」・未達成時「退職後最低充足率」で正しく出し分けられること
