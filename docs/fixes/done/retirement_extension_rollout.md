# 実装：退職延長時の口座別積立ロジックを既存3箇所に横展開

## 背景

`retirement_extension_contribution_logic.md`(完了済み)で、退職延長時の正しい口座計算ロジック(特定口座`toAge`拡張+NISA/iDeCo/特定口座の合算額を特定口座へ)を`src/lib/improvement-search.ts`内に実装した(`buildRetirementExtension()`、非export)。

このロジックは新機能(動的境界探索)専用に作ったが、**同じ構造のバグ(`retAge`だけ書き換えてtoAge連動しない)が既存の以下3箇所にも残っている**ことが確認された。

1. `src/components/simulator/ImpactTable.tsx`(改善案インパクト比較表)の「退職2年延長」計算 → **実害確認済み**。KENZO自身のプロファイルで、手動フォーム変更(約1.2億円相当の効果)とインパクト表の表示差分(+1,496万円)が大きく乖離することを確認
2. `src/components/simulator/AiPanel.tsx`の`buildAIPayload()`内「退職2年延長」改善案 → 田中誠+2年では影響軽微(0.8%)だったが未修正のまま
3. `src/components/simulator/SensitivityPanel.tsx`の退職年齢スライダー(`altP`構築ロジック) → 実害確認済み(田中誠+5年で最終資産43%乖離)

**同じ計算を3箇所バラバラに再実装させず、共通関数として1箇所にまとめ、3箇所すべてがそれを呼ぶ形にすること。**

## 実行内容

### 1. 共通関数への切り出し

`improvement-search.ts`内の`buildRetirementExtension()`を、以下のいずれかの形でexportし、他コンポーネントから呼べるようにする(ファイル配置はClaude Codeの判断で良いが、`src/lib/`配下の適切な場所に置くこと。既存の`improvement-search.ts`にexportを追加するだけでも、`kpi-thresholds.ts`のように共通モジュール化してもどちらでも可):

- 入力:元の`SimParams`(またはprofile)、延長年数(delta)
- 出力:特定口座`toAge`拡張済み・NISA/iDeCo/特定口座の合算con反映済みの、新しい`SimParams`(またはそれに準ずるオブジェクト)

### 2. 3箇所への適用

#### `ImpactTable.tsx`
「退職2年延長」施策の計算(`pRet`相当の変数)を、共通関数の呼び出しに置き換える。delta=2固定で呼び出せばよい。

#### `AiPanel.tsx`
`buildAIPayload()`内の`pRet = {...p, retAge: p.retAge + 2}`相当の処理を、共通関数の呼び出しに置き換える。

#### `SensitivityPanel.tsx`
退職年齢スライダーの`altP`構築ロジックを、共通関数の呼び出しに置き換える。こちらはスライダーで任意のdelta(負の値=前倒しも含む可能性あり)を扱うため、deltaが負の場合(退職を早める場合)の挙動も確認し、負のdeltaでは元々の`toAge`のロジック(現状維持でよいか、それとも短縮方向にも同様の調整が必要か)を判断して報告すること。判断に迷う場合は実装を止めてKENZOに確認すること。

### 3. 検証

- 田中誠プロファイルで、3箇所それぞれの「退職2年延長」の結果が一致すること(最終資産・資産寿命等)を確認する
- 可能であれば、KENZOが確認した「手動フォーム変更 vs インパクト表」の乖離が、修正後は解消される(近い値になる)ことを確認する。ただし本人プロファイルのデータが手元にない場合はスキップしてよい

## 完了報告フォーマット

- 3箇所それぞれの修正箇所(関数名・コンポーネント名)
- 田中誠プロファイルでの3箇所の計算結果一致確認
- `SensitivityPanel.tsx`の負のdelta(退職前倒し)の扱いについての報告・判断
- 参照した関数・コンポーネント名(行番号ではなく)
- `full-verify.js`実行結果(全PASS必須)
- `npm run build`で型エラーがないことの確認

## 注意事項

- **`simulate.ts`・`analyze.ts`は変更禁止**
- 3箇所で計算ロジックを重複実装しないこと(今回のバグの根本原因は「同じロジックを複数箇所に個別実装し、修正が横展開されなかったこと」なので、同じ轍を踏まない)
- `SensitivityPanel.tsx`の負delta(前倒し)の扱いに確信が持てない場合は、実装を進めず先に確認を取ること
