## 背景

検証用モデル(初期資産4,000万円・全額全世界株式・年間取崩200万円(取崩率5.0%)・
μ=6.83%・σ=18.89%・60歳〜95歳)で、基準シナリオ(通常のモンテカルロ、暴落年を
固定しない)の破綻確率が59.5%と出た。一般に言われる「4%ルールなら破綻率は
数%〜10%台」という感覚より高めに出ており、プランニングチャット側では
「IID正規分布ベースのモンテカルロはヒストリカル・ブートストラップより破綻率が
高めに出る傾向がある」「100%株式・固定取崩という前提が厳しめ」という設計上の
性質として一旦説明しているが、念のため実装上のバグがないか確認したい。

## 調査項目

1. **残高がマイナスになった場合の扱い**
   `simulate.ts`で、取崩によって口座残高がマイナスになりうる年、残高が0で
   クリップされているか、それともマイナスのまま計算が続き、その後の年の
   運用リターン計算(マイナス残高×リターン率)に影響を与えていないか確認して
   ください。特に、マイナス残高に対してプラスのリターンが掛かると「マイナスが
   縮む(=見かけ上の資産回復)」、逆にマイナスのリターンが掛かると「マイナスが
   さらに拡大する」といった不自然な挙動が起きていないか確認してください。

2. **インフレ率の二重適用の有無**
   取崩額(baseExp)へのインフレ調整(inflR)が、コード内で1箇所だけで適用されて
   いるか、複数箇所で重複して適用されている経路がないか確認してください。
   `simulate.ts`内でbaseExp(または相当する変数)がインフレ調整される箇所を
   全て洗い出し、二重計上がないことを確認してください。

3. **年齢・年次ループの範囲(off-by-one)**
   退職年齢(curAge=retAge=60)から最終年齢(95歳)までのループが、想定通り
   35年分(60歳時点の期首残高から95歳まで)を計算しているか、1年多い・少ない
   といったズレがないか確認してください。特に「退職1年目」が60歳時点の
   期首残高に対する最初のショックとして正しく扱われているか、前回の検証
   スクリプトの実装(`scripts/sequence-risk-orcan-model-numbers.js`)と
   合わせて確認してください。

4. **破綻判定の条件**
   「破綻」の判定基準(残高が0を下回った時点で破綻とみなす、その後の年も
   ずっと破綻扱いが続く、等)が、記憶(userMemories)にある「strict FIRE達成
   定義」(生涯を通じて基準を下回らない)のロジックと矛盾していないか、
   `analyze.ts`のbankruptcyRate算出ロジックを確認してください。

5. **正規分布ショックの妥当性の参考情報(バグではないが記録として)**
   `simulate.ts`のクリッピング(±50パーセンテージポイント)が、σ=18.89%
   というより大きい前提値のもとでどのくらいの頻度で発動しているか
   (検証用モデルのN=1,000試行で、クリップに到達した試行が何件あったか)を
   カウントして報告してください。クリップの発動頻度が想定より高い場合、
   分布の裾が不自然に切り詰められている可能性があるため報告してください。
