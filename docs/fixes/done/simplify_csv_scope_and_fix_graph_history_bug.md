# 実装指示書：CSV Export/Importの全面簡素化＋グラフ過去月合算バグの調査・修正

作成日：2026-08-26
種別：**設計簡素化＋バグ修正（重要度：最高）**

---

## 0. 背景

これまで「表示：個人のみ／合算」トグルにCSVインポートの挙動を連動させる設計にしてきたが、
「個人のみを選んでいるのに法人ボタンを押すと法人データが更新される」といった説明自体が
ユーザーにとって直感に反し、混乱の元になっていた。今回、この設計を根本から見直す。

併せて、実機で「過去月（2026-06・2026-07）の合算グラフだけ、個人側の金額が反映されない」
という不具合が確認された（今月分は正しく合算されている）。この2点を同時に対応する。

---

## 1. 設計変更：CSV Export/Importを表示トグルから完全に切り離す

**Export**：常に個人・法人の全データ（保有資産＋記録履歴すべて）を出力する。「個人のみ／合算」の
スコープ切り替えは廃止する。

**Import**：CSVファイルの中身（各行の「区分」列）だけを見て判断する。表示トグルの状態は
一切参照しない。
- CSVに本人/配偶者の行があれば → 個人ストアへ書き込む
- CSVに法人の行があれば → 法人ストアへ書き込む
- 両方入っていれば → 両方書き込む
- どちらか一方しか入っていなければ → 入っている方だけ書き込まれる（もう片方は一切触れない）

この結果、`AssetDisplayScope`（`personalOnly`/`combined`）は、CSV関連の関数
（`parseHistoryCsv`・`parseHojinHistoryCsv`・`exportToCsv`・`exportToJson`等）から
**引数として一切受け取らない**ように変更すること。表示トグル自体（ページ上部の
「表示：個人のみ／合算」）は、グラフやKPIカードの表示用としてはそのまま残してよいが、
CSV/JSON入出力とは今後一切関係しないものとする。

確認ダイアログの文言も、常に「CSVの中身に何が入っていたか」に基づいて生成すること
（「個人・法人の両方に反映されます」「個人のみ反映されます」等、表示トグルの状態ではなく
実際にCSVから読み取った内容に応じて出し分ける）。

---

## 2. UIの統合：2つのExport/Importブロックを1つにする

`AssetExportImportControls.tsx`（個人セクション用）と`HojinAssetExportImportControls.tsx`
（法人セクション用）は、統合前の名残で2つに分かれているが、実質的に同じ処理になったため、
**1つのコンポーネント・1組のボタンに統合する**こと。

- ページには「Export / Import」ブロックが1つだけになる
- JSON・CSVそれぞれ、Export1ボタン・Import1ボタンのみ
- 内部的に個人ストア・法人ストアの両方を扱うが、UI上は利用者が「個人用」「法人用」を
  区別する必要がない

---

## 3. 確認ダイアログの要約表示（件数が多い場合）

CSVインポート時の確認ダイアログで、影響を受ける年月ラベルを列挙する現在の実装は、
数年分（数十〜百件超の年月）を一括インポートすると読めない量になる。以下のルールに変更する：

- 影響する年月の合計件数が5件以下：具体的な年月をすべて列挙する（現状通り）
- 6件以上：個別列挙をやめ、範囲と件数の要約にする
  - 例：「個人：2020-01〜2029-12（120件）／法人：2026-06〜2026-08（3件）を更新します」
  - 個人・法人でそれぞれ対象範囲が異なる場合は、分けて要約すること

---

## 4. グラフの過去月合算バグ：調査してから修正すること

**いきなり修正に着手せず、まず以下を確認し、報告すること**（これまでの経緯上、
推測に基づく修正がまた外れることを避けるため）：

1. 資産推移グラフ（`AssetManagementPage.tsx`、またはグラフ専用コンポーネントがあればそれ）が、
   「合算」表示時の**過去月**の合計値を、どこから計算しているかを特定すること
2. もし、`HojinAssetSnapshot.personalHoldings`または`totalPersonalAmount`
   （法人スナップショット自身が持つ表示用の複製、「記録する」を法人トグルON時に押した月だけ
   自動キャプチャされ、記録タイミングによって歯抜けになりうるフィールド）を参照している場合、
   これが原因である可能性が高い。以前まったく同じ原因でExport機能に不具合が発生し、
   個人ストア自身の真の記録履歴（`assetManagement/storage.ts`の`loadSnapshots()`）を参照する
   よう修正した前例（commit fcde8a3、`followup_evidence_request_f5ee8f8.md`2章）があるため、
   同じ修正パターンを適用できるはずである
3. 原因を特定し、報告した上で修正すること。もし上記の推測と異なる原因だった場合は、
   その原因を具体的に説明すること

- 1章：CSVインポート（個人行のみ・法人行のみ・両方混在の3パターン）それぞれで、
  正しいストアにのみ書き込まれることを示す、インポート前後のCSV（省略なし）
- 2章：Export/Importブロックが1つに統合された画面のスクリーンショット

  スクリーンショット

  の合算グラフが個人側の金額を正しく反映するようになったことを示すスクリーンショット
