# 調査専用指示書: デスクトップHero初期表示の見切れ＋ツールセクションのカード間余白

対象ブランチ: `feature/lp-container-width`(継続)

## 0. 前提・背景

前回の実装(Hero上部余白・チャートアスペクト比・ツールセクション左右余白)はスクリーンショットで検証済み、問題なし。その検証中にKENZOから新たに2点の指摘があった。

1. デスクトップでページを開いた際、ファーストビュー最下部に「お悩み」セクションの見出し・区切り線だけが中途半端に覗いており、違和感がある
2. モバイルのツールセクション(「かんたん計算ツール」)で、カード同士の間隔(左右外側の余白ではなくカード間そのもの)がまだ広く感じる

いずれも**調査専用**。方針決定・実装は次フェーズで行う(2フェーズ規律遵守)。

## 1. 調査目的

上記2点について現状を実測・棚卸しし、調整候補パターンを提示する。

## 2. 調査観点

### 2-1. デスクトップHeroファーストビューの見切れ

- 代表的なデスクトップ解像度(1440×900、1920×1080相当の論理ピクセル、ブラウザチェスト分を考慮した実効高さ)で、ページを開いた直後にどこまで見えているかスクリーンショットで記録すること
- 現状、Hero〜アイコン3つの下端から「お悩み」セクション見出しまでの余白(px)を実測
- **方針確定**: 案A(次セクションの見出しが画面内に一切入らないようにする)を採用する。KENZOの判断により、Hero見出し「あなたのFIREは、」の上部に空白を追加する方向で確定
- **実装はPC限定のブレークポイント指定で行うこと**。現状の`pt-4`(モバイル含む全幅適用)はモバイル分はそのまま維持し、`lg:`以上でのみ追加の上余白(`lg:pt-XX`)を加える形とする。モバイル表示(`lg:`未満)には一切影響させないこと
- 追加すべき`lg:pt-XX`の値を、より小さい解像度(1440×900相当)とより大きい解像度(1920×1080相当)の両方で次セクション見出しが画面内に入らなくなる最小値として算出すること(片方の解像度に最適化するともう片方で破綻しないか確認)
- 過剰に空白を足しすぎてHero自体が間延びして見えないかも合わせて確認すること

### 2-2. ツールセクションのカード間余白(モバイル)

- 対象: 「かんたん計算ツール」セクションのカードグリッド
- 現状の実装棚卸し
  - カラム間の`gap-x-*`の現在値(前回調査で`gap-x-6`と確認済みだが、モバイル/デスクトップでのブレークポイント指定があれば明記)
  - 行間の`gap-y-*`または区切り線(`border-y`等)まわりの余白の現在値
  - カード内部`p-6`(前回確認済み)が、カード同士の視覚的な間隔にどう寄与しているか(内側paddingと外側gapの合計値を算出)
- カード間(左右・上下双方)を1〜2段階圧縮した候補値でのスクリーンショット比較(モバイル375px基準)
  - 例: `gap-x-6`→`gap-x-4`、カード内部`p-6`→`p-4`等の組み合わせ
  - アイコン・タイトル・説明文が窮屈にならないか、行間が詰まりすぎて読みにくくならないか確認
  - 各カードがタップ可能な要素(リンク)である場合、タップ領域同士が近接しすぎて誤タップしやすくならないか確認
