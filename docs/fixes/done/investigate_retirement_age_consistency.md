# 指示書: 積立終了年齢・退職金イベントの退職年齢との整合性確認

作成日: 2026-07-22
対象: `lifecompass-next`
種別: 調査+修正(仕様確認が必要なため、まず調査から)

---

## 背景

佐々木誠一プロフィール(53歳、退職年齢55歳/60歳で比較検証中)を使ってシミュレーションする過程で、以下2点の疑問が生じた。

## 1. 積立終了年齢が退職年齢と連動していない

- NISA・iDeCo・特定口座の「積立終了」がいずれも60歳に設定されている一方、退職年齢を55歳に設定したケースがある
- 退職すれば収入源がなくなるため、実際には55歳で積立が止まるはずだが、**現在の計算ロジックが、入力された「積立終了年齢(60歳)」をそのまま額面通り使って、退職後も積立を継続する計算をしていないか確認してほしい**
- もし退職後も積立が続く計算になっている場合、これは実態と合わない、収入のない期間に支出が発生し続けるのと同じ矛盾になるため、修正が必要

### 対応方針
- 現在の計算ロジックがどうなっているか、まず調査して報告すること
- **退職年齢を変更した際に、各口座の「積立終了年齢」を自動的に退職年齢に合わせて更新する**(退職年齢の方が積立終了年齢より早い場合に限り、退職年齢を上限として積立を打ち切る)仕様に変更してほしい。ただし、これが計算ロジック・UIの両方に影響する変更であるため、実装方針(自動更新にするか、警告表示に留めるか等)は調査結果を踏まえて相談すること

## 2. 退職金イベントの年齢が退職年齢と連動していない

- 60歳退職のシナリオ(退職年齢を60歳に変更)にしても、ライフイベントの「退職金」が「55歳・1,500万円」のまま取り残されていた
- **退職金の金額自体は人によって異なるため、ツールが自動で正しい金額を計算・入力することはできない**(これはユーザーが手動で入力すべき値であり、対応不要)
- 問題にしたいのは金額ではなく、**イベントが発生する"年齢"の部分**。退職年齢を55→60に変更した際、退職金イベントの年齢が55のまま取り残され、気づかず古いままシミュレーションしてしまうミスが起きやすい、という点

### 対応方針
- 退職金イベントの金額を自動計算・自動入力する仕組みは不要
- ただし、**退職年齢を変更した際に、既存のライフイベント(特に退職金のような、退職と同時に発生することが多いイベント)の年齢が、新しい退職年齢と一致しているかを確認するよう促す警告(UI上の注意書き等)**は検討の価値がある。あくまで「気づけるようにする」程度の軽い対応でよく、自動で書き換える必要はない
- 実装コストが見合わない、あるいは既存の設計思想にそぐわない場合は、対応不要という判断でも構わない。調査結果を踏まえて相談すること
