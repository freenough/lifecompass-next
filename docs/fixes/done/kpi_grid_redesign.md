# KPIカード再設計:トップ4枚(FIRE安全度統合)+詳細アコーディオン4枚

## 前提

このファイルは `lifetime_min_ratio_calc.md` および、その後の追加修正である `lifetime_min_ratio_naming_fix.md`(達成時の計算範囲修正・名称を「退職後最低充足率」に確定)の実装が完了していることを前提とする。先にそちらを実装・確認してから、このファイルに着手すること。

また、`docs/fixes/active/` に古い版の `kpi_card_visual_hierarchy.md` が残っている場合、それは本ファイルの内容に置き換えられるため、古い方は無視(または削除)してよい。今回のレイアウト方針は当時のものと異なる(単純な上段2枚+下段4枚ではなく、トップ4枚均等+詳細アコーディオン4枚という構成)。

## 背景

現状6枚のKPIカードは、「退職できるか」「維持できるか」「いくら残るか」という異なる問いが混在しており、初見ユーザーにとって何を最初に見るべきか分かりにくい。今回、KPIを「生涯を通じて安全か」という一貫した問いに統一されたトップ4枚と、興味があれば深掘りする詳細4枚に再構成する。

## 実装したい変更

### A. トップKPI(4枚、PC横並び1行/スマホ2×2グリッド)

#### 1. FIRE安全度(旧・FIRE達成カードを置き換え)

`minRatio`・`minRatioAge`・既存`fA`を使い、以下の非対称表示にする。

- **達成時**(`fA != null`):
  - メイン(結論):`{fA}歳で達成`(例:「81歳で達成」)
  - サブ(根拠):`FIRE達成後最低充足率 {minRatio}%`(例:「101%」。`lifetime_min_ratio_label_switch.md`の方針に従い、計算範囲はfA以降〜lifeEx)
- **未達成時**(`fA == null`):
  - メイン(結論):`未達成`
  - サブ(根拠):`退職後最低充足率 {minRatio}%`(例:「92%」。計算範囲はretAge以降〜lifeEx全体)
  - `minRatioAge`(最も厳しい年齢)は、メイン/サブには出さず、**ツールチップ(「?」アイコン)の中、または後述の詳細アコーディオンで補足表示**する

- **色分け**(3段階、閾値は仮置き。実装後にフィクスチャで検証):
  - `minRatio >= 100` → 緑(達成)
  - `80 <= minRatio < 100` → 黄
  - `minRatio < 80` → 赤
- 状態切り替え時の分かりやすさのため、ラベル文言(達成時「達成年齢」/未達成時「生涯最低充足率」等、既存のカード内ラベル領域を使う)と、可能であれば状態アイコン(チェック/警告)を添える

#### 2. 資産寿命(拡張)

- 現状:緑(枯渇なし)/赤(枯渇する)の2段階
- 追加:**黄**を導入。目安として、終端年齢(余命)の5年以内に枯渇する場合は黄、それより早く枯渇する場合は赤とする。該当コード(前回調査:`KpiGrid.tsx:101-116`)を確認の上、閾値を追加する

#### 3. MC破綻確率(変更なし)

- 既存の3段階色分け(5%未満=緑/5〜15%=黄/15%以上=赤)はそのまま維持
- 固定モードでは値が算出できず「—」表示になる点も現状維持でよい(固定モード時のレイアウト調整は今回のスコープ外)

#### 4. 最終資産(変更なし)

- 既存の3段階色分けをそのまま維持

### B. 詳細アコーディオン(4枚、PC横並び1行/スマホ2×2グリッド)

既存の「退職イベント」アコーディオン内、またはそれに準ずる新しいセクションとして以下4枚を配置する。

1. **退職時充足率**(旧・達成率。計算ロジックは変更しない。ラベルまたは補足テキストで「退職した瞬間の充足率です」等、生涯最低充足率との違いを明示する)
2. **初年度取崩率**(既存の色分けロジックは変更しない。可能であれば「適正」等のテキストラベルを添える)
3. **年金開始時資産**(既存のまま)
4. **年金開始までの年数**(新規)
   - 計算式:`年金受給開始年齢 - 退職年齢`
   - 既に退職済み(現在年齢 >= 退職年齢)のケースにおける基準の切り替えは今回のスコープ外。まずは退職年齢基準のシンプルな実装でよい

「退職時総資産」「年金受給額」は今回のKPI/詳細情報から削除する(前者はチャートで代替可能、後者は入力値の再表示のため)。

## 動作確認したいポイント

- デスクトップでトップ4枚が1行に収まり、詳細4枚も1行に収まること(それぞれ4分割なので余りが出ない)
- スマホ幅でトップ4枚・詳細4枚がそれぞれ2×2グリッドで綺麗に収まること
- FIRE安達成/未達成の切り替え時、メイン数値・ラベル・色が一体となって切り替わることを確認する
- 山本・中村・田中・佐々木の各フィクスチャで、新しいFIRE安全度カードの表示内容(達成/未達成、メイン・サブの値)が妥当であることを確認する
- 固定モード・MCモード、戦略比較・シナリオ比較の各組み合わせで表示崩れがないこと

## 完了報告時にお願いしたいこと

- 変更したコンポーネント名(ファイルパスではなく関数/コンポーネント名)
- Before/Afterのスクリーンショット(デスクトップ・モバイル、達成時/未達成時それぞれ)
- KPIスナップショット比較・回帰確認(6-A/6-B)の結果。既存カードの値は変わらないはずだが、FIRE安全度カードは新指標のため、フィクスチャごとの新しい表示内容を報告に含めること
