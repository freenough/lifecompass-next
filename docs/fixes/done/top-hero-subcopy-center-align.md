# 指示: TOPページ ヒーローセクション サブコピーの中央揃え修正

## 背景
freenough-main(TOPページ、freenough.com)のヒーローセクションのサブコピー
「1,000通りの市場変動で、破綻確率まで計算します。」が、
iPhone SE相当の狭い画面幅(375px前後)で左揃えに見える。

調査の結果、原因は改行の扱いにあると推測される:
このテキストは `<br>` 等で「1,000通りの市場変動で、」「破綻確率まで計算します。」の
2行に強制改行されている可能性が高い。他のコピー要素(見出し等)は強制改行しておらず
自然な折り返しに任せている。強制改行された2行それぞれが中央揃えされていない
(または改行+中央揃えの組み合わせが環境によって崩れる)ことで、左揃えに見える
症状が出ていると考えられる。

## 修正方針(確定)
- **強制改行(`<br>`等)を削除し、他のコピー要素と同じく自然な折り返しに任せる**
- 中央揃えの実装も、他のコピー要素と同じ実装パターンに揃える
- 「改行位置を調整して見た目を整える」対応はしない。あくまで折り返しは
  ブラウザに任せる方針とする

## 調査してほしいこと
1. 該当のヒーローセクションのコンポーネントファイルを特定する
   (freenough-mainリポジトリ内、TOPページのheroまたはhero-copy相当のコンポーネント)
2. サブコピー「1,000通りの市場変動で、破綻確率まで計算します。」の実装を確認し、
   `<br>`・改行コード(`\n`)・`whitespace-pre`等、強制改行に関わる記述を特定する
3. 同じセクション内の他のコピー(「未来の選択肢を、自分の数字で描く。」等)の
   改行・中央揃えの実装パターンを確認し、それと同じ書き方に統一する

## 修正内容
- 強制改行の記述を削除し、単一のテキストとして自然な折り返しに任せる
- 中央揃えクラス(`text-center`等)を、他のコピー要素と同じ形で適用する

## 修正時の注意
- 上のコピー(「未来の選択肢を、自分の数字で描く。」)の見た目・レイアウトには
  一切影響を与えないこと
- デスクトップ幅・タブレット幅など他のブレークポイントでの見た目を崩さないこと
- 変更はこのサブコピー要素(またはその直接の親)に限定し、共通レイアウト
  コンポーネントを広範囲に変更しない

## 確認方法
- ブラウザ操作ツールでの実機確認を試みる:
  - iPhone SE相当(375px幅)での見た目(自然な折り返し・中央揃えになっていること)
  - 通常デスクトップ幅での見た目(崩れていないこと、不要な改行になっていないこと)
- ブラウザ操作ツールがタイムアウトする場合は、前回同様SSR出力・DOM構造・
  適用されているクラス名のgit diffで代替確認し、その旨を完了報告に明記する

## 完了報告に含めてほしいこと

- 修正内容(diff)

## 対応結果(完了)

### 対象リポジトリの訂正
指示では freenough-main(freenough.com)を想定していたが、該当コピーは実際には
**lifecompass-next リポジトリ**の `src/app/page.tsx` に実装されていた。freenough-main
の `app/page.tsx` は別デザインのTOPページであり、このコピー自体が存在しなかった。

### 実際の原因(仮説とは異なった)
`<br>`等の強制改行は使われていなかった。実際の原因は `src/app/page.tsx` 146行目の
`text-left` クラスの直書き。

親要素(134行目)は `items-center text-center sm:items-start sm:text-left`
(モバイル中央揃え・デスクトップ左揃え)という設計で、上のコピー
「未来の選択肢を、自分の数字で描く。」(143〜145行目)はこれを継承している。
一方、サブコピー「1,000通りの市場変動で〜」だけ `text-left` が個別指定されており、
モバイル幅でも常に左揃えに固定されていた。

### 修正内容(diff)
```diff
-            <p className="mt-2 text-left text-sm text-slate-500 leading-relaxed text-balance sm:text-base">
+            <p className="mt-2 text-sm text-slate-500 leading-relaxed text-balance sm:text-base">
               1,000通りの市場変動で、破綻確率まで計算します。
             </p>
```
上のコピーと同じクラス構成(`text-left`のみ削除)に揃え、親の中央揃え/左揃えの
継承に任せる形にした。

### 確認方法
- `npm run dev` を起動しブラウザ操作ツールでデスクトップ幅(実測1088px前後)の表示崩れがないことを確認。
- `resize_window` で375px幅を指定しても本環境では `window.innerWidth` が変化せず
  (DPIスケーリング絡みの環境問題と推測)、実機375px幅での目視確認は達成できなかった。
- 代替として、本リポジトリにTailwindのカスタム`sm`ブレークポイント上書きがない
  (デフォルト640px)ことを確認した上で、クラス差分(`text-left`削除のみ)から
  375px幅では親の`text-center`が効き上のコピーと同じ中央揃えになることを
  コードレベルで確認した。

### 影響範囲
- 変更はこの`<p>`要素のクラスのみ。上のコピー・見出し・共通レイアウトコンポーネントには影響なし。
- `sm:text-base`は維持しているため、デスクトップ幅でのフォントサイズ・左揃え
  (`sm:text-left`は親から継承)に変化なし。
