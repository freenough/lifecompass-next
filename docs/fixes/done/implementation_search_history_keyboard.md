# 実装指示書(追記):検索モーダルの「最近の検索」キーボード操作対応

作成日: 2026-08-04
種別: **実装**(前回の実装報告への差分対応。他5点の判断は承認済み、変更不要)
対象ファイル: `src/components/search/SearchModal.tsx`

---

## 背景

前回の実装報告で、0文字時に表示される「最近の検索」履歴リストが `↑`/`↓`/`Enter`
のキーボード操作の対象外になっていることが判明した。検索モーダルは「キーボードだけで
完結できる」設計を意図しているため、履歴表示時だけキーボードが使えなくなるのは
一貫性を欠く。これを解消する。

---

## 実装内容

### 1. フォーカス移動の対象に履歴項目を含める

- 0文字時(履歴表示中)も、`↑`/`↓`でリスト内のフォーカスが移動するようにする
- フォーカス時の見た目(背景ハイライト)は、検索結果一覧で使っているスタイルと同じもの
  (`bg-slate-50`相当、既存実装に準拠)を流用する

### 2. `Enter`時の挙動を「result系」と「history系」で分岐する

- **検索結果・注目リストにフォーカスがある場合**(既存の挙動、変更なし):
  フォーカス中のURLへ遷移する
- **履歴リストにフォーカスがある場合**(新規実装):
  遷移はしない。フォーカス中の履歴文字列を検索入力欄に代入し、その文字列で検索を
  実行する(=クリック時と同じ挙動をキーボードでも再現する)
- 実装上、フォーカス中の項目が「result系(URLを持つ)」か「history系(クエリ文字列)」
  かを判定できるよう、フォーカス管理のstate(またはref)に種別を持たせること

### 3. 影響範囲の確認

- 検索結果・注目リスト表示時(クエリが1文字以上、または0文字で履歴が空の場合の
  「注目」表示)は、今回の変更による挙動変化がないことを確認する
- `Esc`の挙動(モーダルを閉じる)は変更なし

---

## 検証

- 実機ブラウザで以下を確認し、報告すること:
  - モーダルを開いた直後(履歴がある状態)に`↓`を数回押し、履歴項目間でフォーカスが
    正しく移動するか
  - 履歴項目にフォーカスした状態で`Enter`を押し、遷移せず検索欄にその文字列が入り、
    検索が実行されるか
  - 履歴が空の場合(「注目」表示)は従来通り`Enter`で遷移することを再確認
  - `tsc --noEmit`・`full-verify.js`が引き続きクリーンであること
