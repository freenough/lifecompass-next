## 2. 40歳到達タイミングの簡略化に関する注記追加

### 表示条件の判断:「40歳以上」チェック時のみ表示する(指示書のデフォルト方針を採用)
指示書は「常時表示するかどうかは実装前に一度検討し、判断理由を記載すること」を求めていた。
検討の結果、**「40歳以上」チェック時のみ表示する(40歳未満のデフォルトでは表示しない)**
という指示書のデフォルト方針をそのまま採用した。理由は指示書の「実質的に問題にならない
ケースが多い」という確率的な理由づけよりも強い、**年齢が単調増加するという構造上の事実**
に基づく:

- 「40歳未満」(デフォルト、未チェック)の場合:今現在40歳未満であるならば、年齢は
  時間とともにしか増加しないため、1〜2年前(波1の所得を得た時点)の時点でも**論理的に必ず**
  40歳未満だったことになる。したがって、40歳未満の概算料率(14.6%)を波1・波2の両方に
  一律適用しても、簡略化による誤差は理論上一切生じ得ない(確率的に稀というレベルではなく、
  常に正確)。
- 「40歳以上」(チェック時)の場合:今現在40歳以上であっても、1〜2年前の時点で40歳未満
  だった可能性がある(例:今年40歳になったばかりのケースでは、波1の所得を得た1〜2年前は
  38〜39歳で40歳未満だった)。この場合、波1側にも15.4%(介護保険料込み)の料率を一律適用
  してしまうと、実際より社会保険料控除をやや過大に見積もり、波1の税額をわずかに過小評価する
  方向の誤差が生じ得る。

この非対称性(「40歳未満」は誤差ゼロが保証される一方、「40歳以上」は誤差が生じ得る)により、
「40歳以上」チェック時のみ注記を表示するという指示書の方針は、単なる「多くの場合は問題ない」
という緩い経験則ではなく、**構造的に正当化できる判断**であることを確認した。

### `socialInsuranceRateOverride`指定時は表示しない
`isAge40OrOver`がtrueでも、`socialInsuranceRateOverride`(社会保険料率の直接入力)が
指定されている場合はこの注記を表示しない。年齢由来の料率選択(14.6%/15.4%の二択)自体が
行われておらず、ユーザーが指定した単一の料率がそのまま両方の波に使われるだけのため、
「年齢による料率の違い」という注記の趣旨が当てはまらないと判断した。

### 実装箇所
- `calcResidentTaxTiming()`(`residentTaxTiming.ts`):`input.isAge40OrOver &&
  input.socialInsuranceRateOverride === undefined`の場合、`assumptionNotes`に
  「社会保険料率(40歳以上65歳未満の設定)は、波1・波2のいずれにも同じ料率を一律に適用した
  簡易試算です。実際は、それぞれの所得を得た時点(1〜2年前と退職時点)での年齢によって
  異なる場合があります。」を追加(指示書の文言をそのまま採用)。
- `ResidentTaxTimingResult.tsx`の「計算根拠を見る」アコーディオン内、社会保険料控除の
  説明段落にも同趣旨の一文を同じ条件(`input.isAge40OrOver && input.socialInsuranceRateOverride
  === undefined`)で追記。
