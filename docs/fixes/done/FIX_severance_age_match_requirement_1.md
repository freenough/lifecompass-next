# 実装依頼：退職金イベントの判定条件修正(退職年齢フィールドとの一致要件を撤廃)

## 背景

`AUDIT_spouse_severance_kpi_bug.md`の調査で、現在の実装は以下のようになっていることが判明した。

- 退職金(severance)イベントは、イベント自体の年齢(`age===ev.age`)に到達しても、その時点でプロファイルの退職年齢フィールド(本人`retAge`/配偶者`spRetAge`)に到達済み(`isRet`/`isSpRet`)でなければ、退職所得課税ルート(`retirementTaxCalc`)を通らず、無税の通常収入(`extraInc`)として扱われる
- この場合、資産には正しく反映されるが、「退職金(手取り)」KPIには一切カウントされず、退職所得税も発生しない
- これは旧HTML版(`legacy/STEP35_simulator.html`)から本人・配偶者とも対称的に移植された仕様であり、バグではなかった

KENZOと相談の結果、この仕様は現実の税制(退職金は受け取ったタイミングがプロファイル欄の退職年齢と一致するかどうかに関わらず、退職所得として課税される)とズレているため、**修正することでGO済み**。

## 実装内容

1. `src/lib/simulate.ts`のイベント処理ループで、`severance`サブタイプのイベントについて、`isRet`(本人)/`isSpRet`(配偶者)による分岐条件を削除する。イベント自体の発生年(`age===ev.age`、配偶者の場合は年齢軸変換後)を満たした時点で、常に`severanceGross`/`spSeveranceGross`(退職所得課税対象プール)に加算するよう変更すること
2. これにより、本人・配偶者向けの`retirementTaxCalc`呼び出しが、プロファイルの`retAge`/`spRetAge`フィールドと一致しない年に登録された退職金イベントについても実行されるようになることを確認すること
3. `analyze.ts`の`severanceNetKPI`/`spSeveranceNetKPI`集計ロジック、および`KpiGrid.tsx`の「退職金(手取り)」カード表示は、参照元の`snap.severanceNet`/`snap.spSeveranceNet`が正しく積まれるようになれば追従するはずだが、変更後に実際に反映されることを確認すること(表示側のロジック自体の変更は不要という想定だが、確認は必須)

## 確認事項

- 累計退職金(手取り)・退職所得税などのKPIが、年齢不一致ケースでも正しく反映されること
- **既存ケースの回帰確認**：退職年齢とイベント年齢が一致するケース(中村夫婦シリーズ:翔太58歳・美咲56歳)で、修正前と結果が変わらないこと
- **新規テストケース(配偶者)**：年齢不一致ケース(配偶者53歳・1,000万円、配偶者`spRetAge`=56歳という再現ケース)で、退職所得課税ルートを通ること・KPIに反映されることを確認すること
- **新規テストケース(本人)**：年齢不一致ケース(本人52歳・2,000万円、プロファイルの`retAge`が52歳と異なるケース)でも同様に、退職所得課税ルートを通ること・KPIに反映されることを確認すること。本人側も配偶者側と対称のロジックであることが前回調査で判明しているため、両方のケースで動作すること
