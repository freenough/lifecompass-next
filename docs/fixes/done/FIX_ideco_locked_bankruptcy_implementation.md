# FIX: iDeCo受給開始前に他資産が枯渇した場合の「破綻」判定追加

## 背景・問題

現在のシミュレーターでは、NISA・特定口座・現金をすべて使い切り、かつiDeCoが受給開始年齢(`idecoStartAge`)に達していない場合、以下の不自然な挙動が発生する。

- 生活費が毎年赤字(CFがマイナス)にもかかわらず、iDeCo残高が運用によって増え続け、資産が減らないように見える
- iDeCo受給開始年齢に達した年に、蓄積されていたはずの赤字が一気に精算されるかのように資産が0円になる

**実際のiDeCoは、原則60歳(加入期間に応じた受給開始年齢)まで中途解約・引き出しができない制度のため、この間に他の資産が尽きれば、それは実質的な資金ショート(破綻)である。** 現在のロジックはこれを検知・記録できていない。

### 再現条件(参考)

35歳開始・iDeCo単独312万円スタート・支出が徐々に増加するケースで、37歳時点でNISA・特定・現金が0になった後、59歳まで(iDeCo受給開始前)資産総額が減らずに増え続け、60歳で総資産が突然0円になる挙動を確認済み。

---

## 修正方針(確定・GO)

### 1. 破綻判定の追加

各年について、以下の条件を**すべて**満たす場合、その年を「資産枯渇(破綻)」と判定する。

```
NISA残高 = 0
かつ 特定口座残高 = 0
かつ 現金残高 = 0
かつ その年の生活費不足分(need)が上記3口座で賄いきれない
かつ iDeCoが受給開始年齢未到達(age < idecoStartAge)、またはiDeCoが受給開始年齢に達していても引き出し不可な状態(例:pension開始前の据え置き等、既存ロジックに準拠)
```

**重要:** iDeCo残高自体が0より大きくても、上記条件を満たせば「破綻」と判定すること。iDeCoの残高の有無は判定条件に含めない(引き出せないため)。

### 2. 破綻確定後の資産テーブル表示

破綻と判定された年以降は、既存の「資産完全枯渇後」のルールに統一する。つまり、iDeCoを含む全口座残高を0円として以降の年すべてに表示する。

既存の完全枯渇後のロジック(旧HTML版参考。Next.js版の該当箇所を確認のうえ同様に実装):

```javascript
while(snaps.length<targetLen){
  const l=snaps[snaps.length-1];
  snaps.push({...l, age:l.age+1, totalAssets:0, nisa:0, ideco:0, tax:0, cash:0, ...});
}
```

新しい判定(iDeCo受給開始前の資金ショート)についても、このロジックと同じ「破綻確定後は全口座0円」という結果になるようにすること。**新しい表示ルールを別途作らないこと。**

### 3. 影響を受けるKPI・機能(修正後に必ず動作確認)

- 資産寿命(assetLife)
- MC破綻確率(bankruptcyRate)
- 最短枯渇年齢・平均枯渇年齢
- 収支転換点
- 感度分析パネル
- 3戦略(cash_first / taxable_first / proportional)すべて
