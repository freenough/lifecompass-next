# StickyKpiBar.tsx:資産寿命の色分けを3段階(緑/黄/赤)に追従させる

## 背景

`kpi_grid_redesign.md`の実装で、通常のKPIグリッド(`KpiGrid.tsx`)の「資産寿命」カードは、緑(枯渇なし)/赤(枯渇する)の2段階から、**黄(終端年齢の5年以内に枯渇)/赤(それより早く枯渇)**を加えた3段階に拡張された。

しかし、モバイル用スティッキーKPIバー(`StickyKpiBar.tsx`)は独自に資産寿命の色分けロジックを持っており、こちらは緑/赤の2段階のままになっている。同じ「資産寿命」という指標が、画面内の場所(通常のKPIカード vs スクロール時のスティッキーバー)によって異なる色で表示される可能性があり、ユーザーに矛盾した印象を与える。

## 実装したい変更

`StickyKpiBar.tsx`内の資産寿命の色分けロジックを、`KpiGrid.tsx`で実装した3段階ロジック(緑:枯渇なし/黄:`dA >= lifeEx - 5`/赤:それより早く枯渇)と同じ条件・同じ閾値になるよう修正する。

**閾値・判定ロジックは共通の関数として切り出し、`KpiGrid.tsx`と`StickyKpiBar.tsx`の両方から参照する形にすること。** 単純にロジックを複製するのではなく、共通化を必須とする。理由は、この閾値(`lifeEx - 5`)は今後の運用で調整される可能性が高く(FIRE安全度の80%閾値なども実データを見ながら微調整する想定)、複製したままだと片方だけ修正して同期が崩れるリスクが継続的に残るため。

- 配置場所は既存のプロジェクト構成に合わせて判断してよい(例:`src/lib/kpi-thresholds.ts`のような共通モジュールを新設する、または既存の`analyze.ts`・`types.ts`に適した形で追加する等)
- 関数のインターフェースは、資産寿命の枯渇年齢(`dA`)と余命(`lifeEx`)を受け取り、`good`/`warn`/`danger`のvariantを返す形を想定。既存の`KpiCard`のvariant命名規則に合わせること
- 将来的に他の指標(FIRE安全度など)の閾値もこの共通モジュールに集約していく余地を残した設計にできると尚良いが、今回は資産寿命の共通化のみで良い(過度な先回りの汎用化は不要)

## 動作確認したいポイント

- モバイル幅で、通常のKPIカードとスティッキーバーの両方に資産寿命が表示される状況を作り、同じ入力条件下で両者の色が一致することを確認する
- 特に「黄色(終端間際に枯渇)」に該当するケース(前回確認済みの`dA=86歳、lifeEx=90`のフィクスチャなど)で、スティッキーバー側も黄色になることを確認する
- 緑(枯渇なし)・赤(早期枯渇)のケースでも、両者の表示が一致することを確認する
