# 実装指示書：TOPヘッダー・フッター幅／ロゴサイズの修正＋2本柱ブロック・フッター色の実装

作成日：2026-09-28
種別：**実装指示**（対象：`freenough-main`リポジトリ、ブランチは`feature/top-hero-refresh`の続き）
前提：本ブランチで実施済みのHero刷新・ヘッダー2リンク化・コンテナ幅72rem統一（Preview確認済み）

---

## 0. 経緯・今回の目的

前回の実装で、ヘッダー・フッター・Hero・理念ブロックのコンテナ幅を72rem（`--lp-container-width`）に統一したが、これは誤りだった。72remは**lifecompass-nextの本文コンテンツの幅**であり、**ヘッダー・フッターそのものの幅**として使われているかどうかは確認していなかった。

実際のPreviewを見ると、TOPのヘッダーは資産シミュレーター（`/asset-simulator`）・一人法人（`/hitori-hojin`）のヘッダーと比べて明らかに窮屈で、ロゴも小さく、左右に不自然な余白ができている。

今回は、**推測をやめて、lifecompass-next側の実際のヘッダー・フッターの実装を確認し、そこから正確な値をコピーする**。あわせて、まだ未実装の2本柱ブロック（縦積み・01/02表記・アイコン削除）とフッターの濃紺化も実装する。

**今回に限らず、以下を原則とする**：資産シミュレーター・一人法人と共通であるべき見た目・挙動（色、サイズ、余白、角丸、hover/focus/active等のインタラクション状態、transition、shadow等）は、仮値・類推値を作らず、必ずlifecompass-next側の実装を読んで同じ値をコピーする。確認できない・取得元が特定できない場合は、実装を止めてKENZOに確認する。

## 2. 準備：正確な値を実物から取得する（最優先・推測禁止）

以下は、`lifecompass-next`リポジトリの`src/components/layout/Header.tsx`・`Footer.tsx`（`/asset-simulator`・`/hitori-hojin`で実際に描画されているコンポーネント）を読んで確認する。**確認せずに前回同様の仮値・推測値を使うことを禁止する。**

1. **ヘッダーの外側コンテナの幅**：`max-w-*`クラスか、コンテナ制限なし（ほぼフルブリード）か。具体的な値（remまたはpx）。
2. **ヘッダーの左右padding**：`px-*`の値。
3. **ロゴのフォントサイズ・フォントウェイト**：`text-*`クラスや`font-*`クラスの値。
4. **フッターの外側コンテナの幅**：同様に確認する。
5. **フッターの左右padding**：同様に確認する。
6. **CTAボタンのhover（および可能ならfocus・active）時の見た目**：色の変化、影、transform（拡大・移動等）、transitionのduration/easing。資産シミュレーター・一人法人LPの主要CTAボタン（Hero・2本柱ブロック等の主ボタン）で使われている実際のクラス・CSSを確認する。プライマリボタンとセカンダリ（アウトライン）ボタンで挙動が違う場合は両方確認する。

確認した値を完了報告に明記し、freenough-mainの`app/components/Header.tsx`・`Footer.tsx`、および`app/page.tsx`内のCTAボタンに**そのまま同じ値**を適用する。lifecompass-next側とfreenough-main側で値が違う実装になっている場合（例：Tailwindの設定が違う、remの基準が違う等）は、実装を止めてKENZOに確認する。

## 3. ヘッダー・フッターへの適用

- `app/components/Header.tsx`：2.で確認した幅・padding・ロゴのフォントサイズを、そのままfreenough-mainのヘッダーに適用する。前回入れた`max-w-[72rem]`は、2.の確認結果に置き換える（結果的に72remと一致するならそのままでよいが、確認せずに残すことは禁止）。
- `app/components/Footer.tsx`：同様に、2.で確認した幅・paddingに置き換える。
- Hero・2本柱ブロック内のCTAボタン（プライマリ・セカンダリ双方）に、2.6で確認したhover（可能ならfocus・active）時の見た目・transitionをそのまま適用する。
- Hero・理念ブロック・2本柱ブロックのコンテナ幅（`app/page.tsx`側の72rem）は、**今回は変更しない**方針だが、これも「変数名が同じだから大丈夫」という前回と同種の思い込みにしないため、以下を実測で再確認してから完了報告に含めること（推測での結論は禁止）。
  - `/asset-simulator`・`/hitori-hojin`の実際のページで、本文コンテンツ（Hero相当のセクション）のコンテナが実際に何px（計算値）で描画されているか
  - freenough-mainのTOPページのHero等のコンテナが実際に何px（計算値）で描画されているか
  - 両者が一致していることを、CSS変数名の一致ではなく、**実際の計算幅（px）の一致**で確認する。もし一致しない場合（例：`--lp-container-width`は72remだが、実際のページ側で別のpadding等により有効幅が異なる等）は、変更せずKENZOに報告し指示を仰ぐ。
  - ヘッダー・フッターの幅（2.で確認した値）と、本文コンテンツの幅（72rem＝1152px）が異なる場合、それが資産シミュレーター・一人法人の実際のページでも同じ構造（ヘッダー・フッターの方が本文より広い）になっているかどうかも確認する。
  - 各幅でのヘッダー左端・本文（Hero）左端の座標を完了報告に含める。

## 5. 2本柱ブロックの刷新（縦積み・01/02・アイコン削除・右側に図）

`app/page.tsx`の2本柱ブロック（現状L47-92付近、直営事業/ライセンス協業事業のような横並び2カラムではなく、現状は「資産シミュレーター」「一人法人」の2カラム）を、次の構成に変更する。

### 5.1 全体構成

- 現状の横並び2カラム（grid、sm:grid-cols-2）をやめ、**縦に2ブロック積む**。
- 各ブロックは「左：テキスト、右：図」の2カラム（800px程度未満で1カラムに切り替え、図がテキストの上に来る）。
- 現状のアイコン（コンパスのPNG画像、ビルのSVG）は**削除**する。ただし、コンパスPNGはfavicon・OGP画像・JSON-LDのlogoとしても共用されている（調査済み）ため、**画像ファイル自体は削除しない**。このセクションでの`<Image>`呼び出し・SVGの表示だけを外す。

### 5.2 各ブロックの内容

**01：資産シミュレーター**
- 見出しの上（または横）に「01」の番号を、見出しより一回り小さいが十分目立つ大きさで表示する（clamp(30px, 4vw, 40px)程度、フォントはIBM Plex Monoやモノスペース系ではなく、freenough-main側で既に読み込まれている既存フォントでよい。番号の色はブランドグリーンを使う）。
- 見出し：「資産シミュレーター」
- 説明文：現状の「あなたの「足りる」を、数字で確かめる。」をベースに、もう少し具体的に1〜2文（例：「将来の資産推移を、FIRE達成率・資産寿命・モンテカルロ破綻率まで含めてシミュレーションできます。」）に拡張する。
- CTA：「資産シミュレーターを見る →」（`/asset-simulator`）
- 右側の図：資産シミュレーターLPの実際のHeroDemo（KPI3枚＋チャート）と同じ見た目のミニチャート。**可能であれば、HeroDemoコンポーネントをそのまま流用または簡易版として移植する**（React経由でコンポーネントを共有できるか、lifecompass-nextとfreenough-mainが別リポジトリのため静止画（PNG/SVG）として持ってくる必要があるかを確認し、実装方法を完了報告に記載する）。静止画にする場合も、実際のKPI表示（FIRE達成・資産寿命・MC破綻率）とチャートの配色（帯・中央値・FIREライン）に似せる。

**02：一人法人**
- 番号「02」、見出し「一人法人」、既存の説明文「完全リタイアだけがFIREじゃない。」をベースに1〜2文に拡張。
- CTA：「一人法人という選択肢を見る →」（`HITORI_HOJIN_URL`）
- 右側の図：一人法人LP側で検討中の「会社員と完全リタイアの間の分かれ道」の分岐図（一人法人LPのHero刷新で使っている、またはこれから使う予定のもの）と同じ考え方の簡易図。実装方法（既存アセットの流用／新規作成）を完了報告に記載する。

### 5.3 角丸・余白

- ボタン・カード状の要素の角丸は、資産シミュレーター・一人法人と同じ値にする（4pxを想定しているが、2.の調査で実際の値を確認し、そちらを優先する）。
- 01ブロックと02ブロックの間、ブロック内のテキストとCTAの間などの余白は、現状のTailwindスケールに沿った値で構わない（ピクセル単位の厳密指定はしない）。

## 8. 追加対応（実装報告を受けての承認事項）

以下2点を追加で実装する。commit・pushはこの2点を含めた第1段階の再確認後に行う。

### 8.1 モバイル幅でのロゴサイズ

TOPのロゴを、LP側のロゴクラス（`text-xs sm:text-lg`）そのまま流用ではなく、**TOP専用として全幅で`sm:text-lg`相当（21.6px、太さ800）に固定**する。LP側は横にセクション名（｜資産シミュレーター 等）が並ぶ前提で640px未満を小さくしているが、TOPにはセクション名がなくロゴ単体のため、640px未満だけ小さくする理由がない。他の値（フォントウェイト・トラッキング・色）はLPと同じ値を使う。

### 8.2 ヘッダーのsticky化

TOPのヘッダーも、LP（資産シミュレーター・一人法人）のヘッダーと同じ仕様にする。
- `sticky`（スクロールしても上部固定）
- 背景：`bg-white/90` + `backdrop-blur`（LP側の実際のクラスをそのまま確認して適用）
- 下端の境界線：`border-slate-200`（LP側の実際の値をそのまま確認して適用）

正確なクラス名・値は、2.と同様にlifecompass-nextのHeader.tsxを読んで確認し、推測せずそのままコピーする。sticky化によって、ページ内の他要素（Heroの上部余白等）に意図しないズレが出ないか、8.1と合わせて全10幅で再検証し、完了報告に追記する。

### 8.3 スマホ用メニューの開閉方式

TOPのスマホ用ハンバーガーメニューは、開くとヘッダーの高さが伸びてページ全体が下に押し下げられる方式になっている。LP（資産シミュレーター・一人法人）は、ヘッダーの下にドロップダウンとして重なって表示され、ページの他の要素は動かない方式。

lifecompass-nextのHeader.tsx（モバイルメニューの実装箇所）を読んで、開閉の実装方法（position、z-index、アニメーション、開閉トリガーの挙動）を確認し、TOPのHeader.tsxを同じ方式に直す。値は推測せず、実際のクラス・実装をそのままコピーする。

検証：375px・390px（メニューが表示される幅）で、メニューを開いた状態のスクリーンショットを撮り、ページの他要素が動かないこと、LPと同じ見た目・重なり方になっていることを確認する。開閉のtransition/animationがある場合はそれも合わせる。

### 8.4 PC幅ヘッダーナビのリンク色

1024px以上の横並びナビのリンク文字色・hover色・transitionが、TOP（`font-medium text-zinc-600`、hover時`text-black`）とLP（`text-slate-600`、hover時`text-slate-900`、transitionあり）で異なっている。lifecompass-nextのHeader.tsxのナビリンクの実際のクラスを確認し、TOPのHeader.tsxのナビリンクにそのまま適用する（色・transitionとも推測せずコピーする）。1024px以上で目視確認し、完了報告に追記する。
