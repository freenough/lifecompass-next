# 指示書: ブログ一覧カードのレイアウト変更(横並び+レスポンシブサムネイル)

作成日: 2026-07-16
対象: `src/app/blog/page.tsx`(および記事カードを別コンポーネント化している場合はそのコンポーネント)
種別: UI変更(実装)

---

## 1. 背景・目的

現在のブログ一覧(`/blog`)は縦積みカード(カテゴリタグ→日付→タイトル→説明文→CTA)で、サムネイル画像がない。LPの「FIREガイド」プレビューカードにはアイキャッチ画像があるが、両者は役割が異なる:

- LP: 初見ユーザー向けの説得材料。縦積み・大サムネで視覚的インパクト重視。
- ブログ一覧: 記事を比較検討しながらスキャンする場。テキスト量(特に説明文)を確保しつつ、記事を見分けやすくする視覚的手がかりとしてサムネイルを併用したい。

このため、ブログ一覧はLPと同じ縦積み大サムネ方式ではなく、**横並び(サムネ左・テキスト右)** の専用レイアウトに変更する。

アイキャッチ画像自体は今後もLPと同じ統一イメージ(シミュレーター画面ベースのテンプレート型)で作成していく方針のため、**同一素材をアスペクト比そのままに縮小表示する**前提で実装する。

---

## 2. 実装内容

### 2-1. カードレイアウトを横並びに変更

- 現在の縦積み1カラムカードを、サムネ(左)+テキスト(右)の横並びFlex/Gridレイアウトに変更
- サムネイルの実素材パスは未定(プレースホルダー枠で可)。`next/image`を使う場合は`fill`+`object-fit: cover`で対応
- サムネイル画像がまだ存在しない記事については、グレーのプレースホルダー(現状の枠のみ)を表示すること(画像なしでもレイアウトが崩れないようにする)

### 2-2. サムネイルサイズ(レスポンシブ・アスペクト比3:2固定)

| ブレイクポイント | サムネサイズ |
|---|---|
| PC(デスクトップ) | 130×87px |
| タブレット | 120×80px |
| モバイル | 100×67px |

- すべて3:2のアスペクト比で統一(同一元画像をリサイズするだけで対応できるようにする)
- **モバイルでもサムネイルは非表示にしない**こと。FIRE・資産運用系のタイトルは似た語彙が並びやすく、画像がある方が一覧性・記憶性が上がるため、非表示は避け、縮小表示で対応する
- ブレイクポイントの閾値は既存のTailwind設定(`sm`/`md`/`lg`等)に合わせて自然な値を選んでよい

### 2-3. カード内の情報量を行数固定で統一

- タイトル: 最大2行(`line-clamp-2`)。2行に収まらない場合は末尾を省略記号(…)で切る
- 説明文: 最大2行(`line-clamp-2`)。同様に省略記号で切る
- カテゴリタグ・公開日: 1行
- この行数固定により、記事によってカードの高さがバラつかないようにし、一覧スクロール時のリズムを保つ

### 2-4. 対象外(このタスクではやらないこと)

- カテゴリタグの色分け(シミュレーター活用/FIRE基礎知識/使い方ガイド)は別タスクとして扱う。今回のカード改修に色分けを含めても構わないが、必須ではない
- サムネイル画像素材そのものの新規作成・撮影はこのタスクの対象外(プレースホルダーで実装を進めてよい)

---

## 3. 受け入れ基準

- [ ] ブログ一覧のカードが横並び(サムネ左・テキスト右)レイアウトになっている
- [ ] サムネイルサイズがPC 130×87 / タブレット 120×80 / モバイル 100×67(すべて3:2比率)でレスポンシブに切り替わる
- [ ] モバイル幅でもサムネイルが非表示にならず、縮小表示されている
- [ ] タイトル・説明文がそれぞれ最大2行で省略記号処理されている(長いタイトルで実際に2行を超えるケースで確認すること。例:「FIRE計画で失敗しないための7つのチェックリスト|シミュレーション前に確認したいポイント」)
- [ ] サムネイル画像が存在しない場合でもレイアウトが崩れない(プレースホルダー表示)
- [ ] `npm run build`が型エラーなしで通る
- [ ] `scripts/full-verify.js`がPASSする(ブログページ自体は対象外だが、既存の回帰確認として実行)
