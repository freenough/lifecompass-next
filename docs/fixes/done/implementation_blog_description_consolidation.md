# 実装指示書:ブログ説明文言の定数化(3箇所の表記ゆれ解消)

作成日: 2026-08-03
背景: ブログフィルタ再設計時にリード文言(画面表示)のみ差し替えたが、
`metadata.description`とRSSの`<description>`が旧文言のまま取り残されていた
(前回の調査指示書で発見・報告済み)。今回はこの表記ゆれの解消に加え、
再発防止のため文言を共通定数化する。

## 背景・問題

同じ「ブログ一覧の説明文」を意図した文字列が、現在3箇所に別々にハードコードされている:

| 箇所 | ファイル | 現在の文言 | 状態 |
|---|---|---|---|
| 画面表示のリード文 | `src/app/blog/page.tsx`(該当`<p>`要素) | 「制度の解説だけでなく、独自シミュレーターでの試算結果もあわせて紹介しています。」 | 改修済み(最新) |
| `metadata.description` | `src/app/blog/page.tsx` 8行目付近 | 「FIREと資産形成に関する記事を発信しています。」 | 未改修(旧文言) |
| RSSフィードの`<description>` | `src/lib/blog.ts` 294行目付近 | 「FIREと資産形成の情報を発信しています。」 | 未改修(旧文言・表記も微妙に異なる) |

このまま放置すると、検索結果のスニペットやRSS購読者に見える文言が、実際にサイトへ
来た際の文言と一致しない。また、今後ブランドメッセージを変更するたびに同じ
更新漏れが再発するリスクがある。

## 決定した方針

1. 単なる文言の統一(3箇所に同じ文字列をコピー)ではなく、**共通定数として1箇所に
   定義し、3箇所がそこを参照する構造にする**
2. SEO用に短縮版・別文言を作る必要はない。現在の文言は40字程度で
   meta descriptionとしても十分な長さのため、画面表示・metadata・RSSすべてで
   完全に同一の文言を使う
3. 今回はこの1件(ブログ説明文)のみを対象とする。サイト全体のブランド文言
   (FREENOUGHの紹介文、ツール説明、キャッチコピー等)を今回まとめて集約する
   ことは**スコープ外**とする。ただし将来的に同種の文言を追加していく器と
   なるよう、ファイル名は汎用的な名前にする

## 実装タスク

### 1. `src/lib/siteCopy.ts`を新規作成

- 以下の定数を1つexportする(今回はこれ1件のみでよい):
  ```ts
  export const BLOG_DESCRIPTION =
    '制度の解説だけでなく、独自シミュレーターでの試算結果もあわせて紹介しています。';
  ```
- ファイル名・器としての位置づけは「将来サイト全体のブランド文言を追加していく
  想定」だが、今回中身を増やす必要はない。他の文言の洗い出し・追加は行わない

### 2. 3箇所からの参照に置き換え

- `src/app/blog/page.tsx`:
  - 画面表示のリード文(`<p>`要素)を`BLOG_DESCRIPTION`参照に置き換え
  - `metadata.description`を`BLOG_DESCRIPTION`参照に置き換え
- `src/lib/blog.ts`(294行目付近、RSSフィードの`<description>`)を
  `BLOG_DESCRIPTION`参照に置き換え
- いずれも`import { BLOG_DESCRIPTION } from '@/lib/siteCopy'`のような形になる想定
  (importパスの記法は既存コードの慣習に合わせる)

### 3. 確認事項

- 画面表示・`metadata.description`(ページソースのmetaタグ)・RSSフィード
  (`/feed.xml`等、実際のRSS出力ファイルを確認)の3箇所すべてが同一の文言に
  なっていることを実機確認する
- `full-verify.js`を実行し0 failuresを確認する

## 制約・注意事項

- `simulate.ts`・`analyze.ts`には一切触れない
- 今回対象とするのは「ブログ一覧の説明文」1件のみ。他の文言(ツールページの
  説明文、サイト全体のキャッチコピー等)には手を広げない
- 見出し(`<h1>ブログ</h1>`)は対象外(前回の改修時と同様、変更しない)
