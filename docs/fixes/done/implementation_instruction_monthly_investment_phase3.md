# 実装指示書:フェーズ3 CTA文言確定・UTM設定・GA4計測

## 背景・方針転換(重要)

当初のProduct Spec・フェーズ2指示書では「記事埋込対応」を予定していたが、検討の結果
**記事への埋込は行わず、リンク方式に変更する**ことになった。

理由:このブログはMDXではなく通常Markdown+remarkカスタムプラグイン方式で構築されて
おり(過去の設計判断)、状態を持つインタラクティブなReactコンポーネントを記事内に
埋め込むには本質的にMDX相当の仕組みが必要になる。これは既存の設計判断(あえてMDXを
避けた)と矛盾するため、埋込は見送り、記事からツールページへの**通常のMarkdownリンク
遷移**に変更する。

このため、**記事埋込用のコンポーネント抽出・ハイドレーション対応は不要**になった。
本フェーズは、フェーズ2で仮実装したCTAの文言確定・UTM設定・GA4計測のみに絞る。

## スコープ

### 実装するもの

1. `MonthlyInvestmentCta.tsx`のCTA文言を最終確定させる(フェーズ2では仮文言)
2. ツールページ→LifeCompass本体、ツールページ→NISA口座開設(アフィリエイト)の
   各リンクにUTMパラメータを付与する
3. GA4イベント3種(`tool_calculate`・`tool_to_simulator_cta_click`・
   `tool_to_nisa_cta_click`)を実装する

### 実装しないもの(スコープ外)

- 記事埋込機構(見送りにつき不要)
- 記事本文自体への手動リンク追加(記事執筆側で対応するため、Claude Codeの
  スコープ外。ツールページ側の受け口だけを本フェーズで整える)
- 記事側からの流入をツールページ側のコードで判定するロジック(GA4はUTM付き
  リンクのクリックを自動的にセッションのソース/メディアとして記録するため、
  ツールページ側で追加の判定コードを書く必要はない)

## 1. CTA文言の最終確定

`MonthlyInvestmentCta.tsx`内の仮文言を、以下に差し替える:

### 1-1. LifeCompass本体への導線

```
税金・NISA・iDeCo・退職金まで考慮した試算ができます
→ LifeCompassで続きをシミュレーション
```

- 「〜まで考慮した試算ができます」という表現に統一すること(「〜すべきです」
  のような断定的な言い切りにしないこと。既存のブログ記事の文体ルールと同じ
  トーンを踏襲する)

### 1-2. NISA口座開設(アフィリエイト)への導線

既存の`AffiliateLink`コンポーネント(フェーズ2で新規作成済み)を引き続き使用し、
`provider="matsui"` `landing="nisa"`を指定すること。文言・`[PR]`表記は
`affiliateLinks.ts`の既存の対応表(NISA口座開設先の一例として、松井証券の
情報はこちら)をそのまま使う(変更不要)。

### 1-3. 表示順序

既存の記事CTAルールと同じ方針:LifeCompassへの導線が主役(先に表示)、
アフィリエイトCTAは従(後に表示・視覚的に控えめ)。フェーズ2の実装時点で
この順序になっているはずだが、変更していないか念のため確認すること。

## 2. UTMパラメータの設定

### 2-1. ツールページ→LifeCompass本体

Product Spec通り、以下のUTMを付与する(フェーズ2では仮リンクだったため、
本フェーズで正式に設定する):

```
utm_source=tools
utm_medium=referral
utm_campaign=monthly_investment_tool
```

### 2-2. ツールページ→NISA口座開設(アフィリエイトリンク)

アフィリエイトリンクはASP(a8mat)側のURLパラメータ体系のため、GA4向けの
UTMは付与しない(既存のブログ記事内アフィリエイトリンクと同じ扱い)。

---

## 3. GA4イベントの実装

既存サイトのGA4実装パターン(gtag.js)に合わせて、以下3つのイベントを実装する:

| イベント名 | 発火タイミング | パラメータ |
|---|---|---|
| `tool_calculate` | 入力が変わり、計算結果が(再)表示されるたびに発火 | なし(頻度が高いため、パラメータは不要。発火回数のみ見る) |
| `tool_to_simulator_cta_click` | LifeCompass本体へのCTAリンクをクリックした時 | なし |
| `tool_to_nisa_cta_click` | NISA口座開設CTA(アフィリエイトリンク)をクリックした時 | なし |

### 3-1. `tool_calculate`の発火頻度への配慮

リアルタイム計算(入力の度に再計算)の仕様上、`tool_calculate`は同じユーザーの
1回の利用で何度も発火しうる。既存のGA4実装で使っているデバウンス・スロットリング
の慣習があれば踏襲し、なければ「入力欄からフォーカスが外れた時」または
「500ms程度の入力停止後」に発火する形にして、無意味に大量のイベントが飛ばない
ようにすること(必須ではないが、実装しやすければ対応すること)。

---

## 4. 記事側の受け口についての補足(参考、実装不要)

記事(`nisa-monthly-investment`)本文の執筆・CTA設置は別途(KENZO+Claude側で)
対応する。記事側のリンクには以下のようなUTMを想定している(参考情報として
記載するのみで、Claude Codeが実装する必要はない):

```
utm_source=blog
utm_medium=referral
utm_campaign=nisa_monthly_investment
utm_content=mid_cta または bottom_cta
```

このUTM体系は、既存記事(`ideco-nisa`等)のUTM命名規則(`utm_campaign`=記事
テーマ、`utm_content`=CTA位置)と一貫させる。ツールページ側のコードでこれを
判定する必要はない(GA4が自動的にセッションのソース/メディアとして記録する)。

## 5. 完了報告の形式

- 変更したファイル一覧
- CTA文言が最終版に差し替わっていることの確認(スクリーンショットまたは
  レンダリング結果のテキスト)
- 各リンクのURL(UTM込み)が実際に正しく生成されていることの確認
- GA4イベントが実際に発火することの確認(ブラウザの開発者ツールのネットワーク
  タブ、またはGA4のデバッグビューでの確認結果)
- 既存の`full-verify.js`・`verify-finance-core.js`が引き続きPASSすることの確認
- 変更範囲の確認(`git status`・`git diff`の結果)

**関数名・コンポーネント名で報告すること(行番号ではなく)。**
