# 調査依頼：退職金・iDeCo課税ロジックの全体総点検

## 背景

このセッションで、退職金・iDeCo関連の不具合が複数回見つかった(配偶者退職金の年齢不一致・dcYears混入・iDeCo年金受給後の追加取り崩し漏れ)。個別のバグを都度追うのではなく、一次情報(国税庁)から整理した「あるべきロジック」(`REFERENCE_retirement_ideco_tax_rules.md`、添付)と、現状の実装全体を体系的に突き合わせたい。

**このタスクは修正ではなく、現状の実装を漏れなく報告することが目的です。** 過去の調査(`AUDIT_severance_ideco_deduction_mixup.md`・`AUDIT_spouse_severance_logic.md`・`AUDIT_ideco_pension_tax_attribution.md`・`AUDIT_ideco_pension_sevyrs_dependency.md`)ですでに分かっている内容は再調査不要ですが、今回は「これまで質問していなかった項目」を含めて網羅的に確認してください。

## 調査してほしいこと(`REFERENCE_retirement_ideco_tax_rules.md`の章立てに対応)

### 1. 退職所得控除額の計算
- 勤続年数(`sevYrs`・`spSevYrs`・`idecoYrs`等)に**1年未満の端数がある場合、切り上げ処理が実装されているか**(UIが整数年しか入力させない設計なら、そもそも端数が発生しないため対応不要と判断できるが、その場合もその旨を報告すること)
- 障害者控除(+100万円)は未実装と思われるが、実装の有無を確認(おそらく未実装で問題ない機能だが、念のため)

### 2. 退職所得の1/2課税・例外
- `(収入金額-控除額)×1/2`の計算が正しく実装されているか(関数名・ファイル名)
- 特定役員退職手当等・短期退職手当等(役員等勤続年数5年以下)の例外(1/2課税を適用しないケース)は実装されているか。おそらく未実装と思われるが確認し、未実装であれば「一般の会社員を想定しているため対応不要」という理解でよいか、KENZOの判断材料として報告すること

### 3. 19年ルール・9年ルール
- これは調査済み・設計確定済み(`FIX_retirement_tax_calc_final.md`)。再調査不要。念のため、現在のコードが「同一年受取のみ合算、それ以外は独立計算」という確定した設計と相違ないか、1点だけ確認すること

### 4. 公的年金等控除
- これは調査済み(`AUDIT_ideco_pension_tax_attribution.md`)。再調査不要。ただし、**一時金と年金を併用(併給)するオプション**をLifeCompassが提供しているか確認すること(していない場合、その旨だけ報告。UIで一時金/年金の二択のみであれば対応不要と判断できる)

### 5. iDeCo受給ルールの制約
- 受給開始年齢の妥当性チェック(60〜75歳の範囲外を入力できてしまわないか、UIまたはロジック上の制約があるか)
- 通算加入者等期間が10年未満の場合の受給開始年齢の段階的な繰り下げ(60歳→61〜65歳)ルールは実装されているか、それとも「iDeCo受取開始年齢」を自由入力させる設計になっているか(自由入力なら、現実にありえない年齢設定(例:55歳受給開始)をユーザーが入力できてしまうため、バリデーションの要否を判断材料として報告)
- 年金受取の「繰上一時金」(受給開始5年後に残額を一括受取に切替可能)は実装されているか。おそらく未実装で問題ない機能だが確認

### 6. 特定口座の譲渡益課税
- `costBasis`(取得原価)の管理方法を関数名・ファイル名ベースで具体的に説明すること(前回セッションで簡略化方針だったことは把握しているが、実装の詳細を初めて確認する)
- 20.315%(所得税15%+復興特別所得税0.315%+住民税5%)の税率が正しく実装されているか

## 依頼の範囲

**調査・報告のみ。実装・修正は一切行わないこと。** 発見された論点は、対応要否をKENZOとClaudeで別途相談する。
