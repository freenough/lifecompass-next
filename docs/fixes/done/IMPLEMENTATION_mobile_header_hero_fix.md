# 実装指示書:モバイルヘッダー・HERO見出し・本文の改善(資産シミュレーターLP)

## 背景

iPhone SE等の狭い画面幅で、以下3つの表示崩れが確認された:

1. ヘッダーナビの文字が折り返す(「資産シミュレータ/ー」のように単語途中で改行)
2. HERO見出しのフォントサイズが大きすぎ、4行に折り返り、しかも改行位置が不格好(「あなたにとっ/ての」等)
3. 本文段落が中央揃えのため、行ごとの余白が不揃いでガタついて見える

**今回の実装スコープ:資産シミュレーターLP(`/asset-simulator`配下、`lifecompass-next`リポジトリ)のみ。**

Freenough TOP(`freenough.com`)は別リポジトリで管理されているため、このセッション・このリポジトリでは対応しない。TOP側は本指示書の内容を流用しつつ、TOPリポジトリを開いた別セッションで後日対応する想定(決定事項・ナビ項目・色・トランジション等の方針はTOP側にもそのまま適用する)。

---

## Phase 1:調査(実装前に必ず実施)

### 1-1. プロファイル管理ドロワーの背景オーバーレイ色を調査

資産シミュレーターのプロファイル管理ドロワー表示時、背景に暗転オーバーレイ(スクリム)がかかっている(スクリーンショットで確認済み、目視ではグレー系半透明、黒15〜20%程度の濃さに見える)。今回新設するハンバーガーメニューの背景オーバーレイをこれと同じ色味に揃えたいため、まず実際の値を特定すること。

```bash
grep -rn "backdrop\|bg-black\|rgba(0,0,0" src/components --include="*.tsx" -A2 | grep -i "drawer\|profile\|overlay"
```

上記で見つからない場合は、プロファイル管理ドロワーのコンポーネントファイルを直接開いて、背景オーバーレイ用の要素(`<div>`等)のクラス名・インラインスタイルを確認する。

**報告してほしい内容:**
- 実際に使われている値(Tailwindなら`bg-black/XX`のようなクラス名、生CSSなら`rgba(...)`の値)
- CSS直書きかTailwindユーティリティか
- z-index、transition(あれば)の値
- 実装ファイルのパス

**この値が確定するまで、Phase 2のオーバーレイ実装(2-2)は着手しないこと。** 値が見つかったら一度報告し、KENZOの確認を得てからPhase 2に進む。

### 1-2. 対象ファイルの特定

以下を確認し、報告すること:
- 資産シミュレーターLP側のヘッダーコンポーネントのファイルパス
- HEROセクション・本文段落のファイルパス
- HERO見出しの現在のフォントサイズ指定方法(固定`text-*`クラスか、既に`clamp()`を使っているか)
- Tailwindの`text-balance`/`text-pretty`が使えるバージョンかどうか(Tailwind CSS v3.4以降か確認)

## Phase 2:実装

### 2-1. ヘッダーのハンバーガーメニュー化(資産シミュレーターLP)

**対象:** 画面幅が一定以下(モバイル判定の既存ブレークポイントに合わせる、なければ768px未満を想定)のときのみハンバーガー表示に切り替え。PC幅は現状の横並びナビのまま変更しない。

**ナビ項目(この順序で統一・LP側は既にこのラベルのため変更不要):**
1. シミュレーター
2. ブログ
3. ツール
4. Note

**参考(このリポジトリのスコープ外):** Freenough TOP側も将来同じ4項目構成にする予定。TOP側の現行ラベルは「資産シミュレーター」だが、統一時に「シミュレーター」へ短縮変更する想定(TOP側リポジトリでの対応時にこの指示書を参照)。

- リンク先は既存のURLをそのまま使用
- ロゴ(`FREENOUGH`)はハンバーガーメニュー化後もヘッダー左に残し、右側にハンバーガーアイコン(Tabler Icons `ti-menu-2`)を配置
- メニュー展開時、アイコンを×(`ti-x`)に切り替える

**展開方式:**
- 上から下へスライドダウンで展開(ヘッダー直下に4項目を縦に並べる)
- 展開中はハンバーガーアイコンをタップすると閉じる。メニュー項目自体をタップすると遷移(閉じる処理は不要、ページ遷移するため)
- トランジション:`transition: [対象] 0.22s cubic-bezier(.4,0,.2,1)`(プロファイル管理ドロワーと同じイージング・速度で統一)

### 2-2. ハンバーガーメニューの背景オーバーレイ

**Phase 1-1で確定した値を使用すること。** ここでは暫定値として記載するが、調査結果と異なる場合は調査結果を優先する。

- 暫定値:黒の半透明、`rgba(0,0,0,0.15)`〜`rgba(0,0,0,0.2)`程度(プロファイル管理ドロワーと同一の値に揃える)
- メニュー展開中、ヘッダー下から画面下端まで(または該当領域)にオーバーレイを表示
- オーバーレイタップでメニューを閉じる処理も追加する(誤操作防止のため)
- z-indexはドロワーの値を参考に、既存の他要素と重ならないよう調整する

### 2-3. HERO見出しのフォントサイズ・改行調整(資産シミュレーターLP)

対象:LP側のHEROセクション見出し(TOP側の見出し「あなたにとっての『足りる』を、数字で描く。」は別リポジトリのため今回対象外。LP側に同様のHERO見出しがあれば同じ方針で調整)

- フォントサイズを`clamp()`に変更し、モバイル側の下限を現状より縮小する(現状recreateされている見た目のサイズ感から、モバイル最小値は22px前後を目安に調整。PC側の上限は現状維持でよい)
- `text-wrap: balance`(Tailwindなら`text-balance`クラス)を追加し、行の文字数バランスを自動調整する
- 上記だけで改行位置が不自然な場合、`<br>`を使った改行位置の手動指定を追加する(スマホ幅のみ効くよう`sm:hidden`等でPC側には影響しない形にする)

### 2-4. 本文段落の左揃え化(資産シミュレーターLP、スマホ幅のみ)

- HERO直後の説明文など、2行以上に及ぶ本文段落について、モバイル幅(既存ブレークポイントに合わせる)では`text-align: left`に変更する
- 1〜2行程度の短いキャッチコピー的な文言(ボタン直上のサブコピー等)は中央揃えのまま維持してよい。段落として複数行続く文章のみ対象とする
- PC幅の表示は現状維持(既に左揃えであれば変更不要、中央揃えのままなら今回はスマホ幅のみの対応としてPC側は変更しない)

## 実装後の確認事項

- iPhone SE幅(375px)相当のビューポートで、ヘッダー・HERO・本文それぞれ折り返しが解消されているか
- PC幅で従来の見た目から変化がないか(ヘッダー横並び・HEROサイズ・本文中央揃えなど)
- ハンバーガーメニューの開閉、オーバーレイタップでの閉じる動作
- 完了報告時は、変更したコンポーネント名・関数名を明記すること(行番号は編集中にズレるため使用しない)
