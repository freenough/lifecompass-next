# 実装：退職延長探索の達成判定基準の修正

## 背景

`improvement-search.ts`の`findRetirementExtensionThreshold()`は、現在「`fA !== null`(生涯のどこかで達成)」を成功条件にしている。これだと、延長した退職年齢よりずっと後(例:退職65歳に対しFIRE達成89歳)でようやく達成するケースも「成功」と判定してしまい、実際の画面で「+1年退職延長でFIRE達成」の直後に「89歳で達成」という表示が出て、ユーザーに強い違和感を与えることを確認した(スクリーンショットで実例確認済み)。

**`analyze.ts`の`fA`自体の定義は変更しない**(生涯どこかで達成、という指標は他の用途で正しく機能しているため)。変更するのは`improvement-search.ts`内の**探索の合格ライン**のみ。

## 修正内容

`findRetirementExtensionThreshold()`内の成功判定条件を、以下のように変更する。

- 変更前:`fA !== null`
- 変更後:`fA !== null && fA <= 新しいretAge`(延長後の退職年齢までにFIRE達成していること)

固定の年齢上限(65歳等)は設けない。探索上限は従来通り`lifeEx - 1`のまま。この基準変更自体が「延長するほど達成条件も厳しくなる」という自己抑制的な性質を持つため、上限は不要という判断(詳細はKENZOとの合意済み)。

`findExpenseReductionThreshold()`(支出削減側)は変更不要。支出削減は退職年齢を動かさないため、この問題は発生しない。

## 検証

1. 田中誠プロファイル(proportional戦略)で再検証し、新基準での最小必要延長年数を報告せよ。前回(旧基準)は16年(fA=67)だったが、新基準でも67≤71(新retAge)を満たすため、**結果が変わらないか変わるかを実際に確認**すること(変わらないと推測されるが、決め打ちせず実測すること)
2. 可能であれば、スクリーンショットで報告されたケースに近いプロファイル(退職年齢65歳、資産形成が緩やかなケース)で、新基準を適用した場合に必要な延長年数が何年になるか、旧基準(何年で「達成」と誤って表示されていたか)と比較して報告せよ。ただし正確な入力値が不明な場合、この項目は概算・参考値で構わない
