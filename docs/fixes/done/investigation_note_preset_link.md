# 調査指示書:note→シミュレーター プリセット連携の実現可能性

作成日:2026-08-02
種別:**investigation-only(調査のみ。実装は行わないこと)**

---

## 背景・目的

前セッション(内部リンク構造強化)で、note記事↔サイト間の連携強化は「4象限導線」としては
コスト対効果が低いと判断し見送った。一方で、より軽量な施策として「noteの記事を読んだ直後に、
その記事の主人公と同じ条件でシミュレーターを試せるボタン」(以下プリセットボタン)には
着手価値があると判断した。

現状の課題:
- LP(`freenough-main`)のキャラクターカードは田中さんのみnote連携が公開中、他3キャラ(中村夫婦・
  佐々木さん・山本さん)は「近日公開」のまま
- 田中さんも含め、note記事からシミュレーターへの遷移は現状「シミュレーターのトップに飛ぶだけ」で、
  記事で読んだキャラクターの数字がそのまま試せるわけではない
- オンボーディング機能(スターターモーダルの「サンプルデータで試す」)は実装済みだが、これが
  汎用サンプルなのか特定キャラクターのプロファイルなのか、本チャット側では実装詳細を把握していない

この調査の目的は、**note記事の読者が「自分と同じ条件」または「読んだキャラクターと同じ条件」で
即座にシミュレーターの結果を見られる導線を、どのくらいのコストで実現できるか**を明らかにすること。

---

## 調査対象

### 1. 現在のNext.js版(lifecompass-next / /asset-simulator)のURL経由プロファイル読み込み機構

- 旧HTML版(STEP29〜35)には `shareURL()` / `loadSharedURL()` という、プロファイルをbase64エンコード
  してURLクエリパラメータ(`?s=...`)に埋め込み、読み込み時に `applyProfile()` で復元する機構があった
- **Next.js版に同等の機構が移植されているか**を確認すること
  - 存在する場合:関数名・実装箇所(ファイルパス)・エンコード方式を報告
  - 存在しない場合:代替として何が使えそうか(Zustandのstate初期化ロジックなど)を報告

### 2. オンボーディング「サンプルデータで試す」の実装詳細

- ROADMAP.mdに記載のあった「サンプルデータで試す」ボタン(田中誠プロファイルまたは汎用サンプルを
  `applyProfile()`で読み込み)が、Next.js版でどう実装されているかを確認すること
  - 使われているプロファイルは田中誠固定か、汎用サンプルか
  - 実装コンポーネント名・ファイルパス
  - このロジックが「URLパラメータで指定したキャラクターのプロファイルを読み込む」形に
    拡張しやすい構造になっているか(所感でよい)

### 3. 各キャラクターのプロファイルデータの有無

- 田中誠・山本恒一・中村夫婦・佐々木誠一の4キャラクターについて、シミュレーター側に
  再利用可能な確定プロファイルデータ(パラメータ一式)が存在するか確認すること
  - `reference/simulation_fixtures.md` などに記載があるか(NEXT_CHAT_PROMPT_NextJS_03.mdに
    この参照ファイルの言及あり)
  - 存在する場合、コード内(TS/JSON)で参照可能な形になっているか、それとも
    ドキュメントに数値が書いてあるだけで実装には未反映か

### 4. LP側キャラクターカードのnote連携状況(現状再確認)

- `freenough-main` の `src/app/page.tsx` の `characters` 配列を確認し、現時点で
  田中さん以外のnoteリンクが追加されているか(前回セッション時点では「近日公開」のみだった)

### 5. note.com側での実装制約

- note.comの記事本文にはJavaScriptを埋め込めない(外部埋め込みブロックか、通常のMarkdownリンクの
  いずれか)という前提で、「プリセットボタン」は実質的に**通常のリンク(URLクエリパラメータ付き)**に
  なる想定である。この前提に誤りがないか、note.com側の仕様を踏まえて確認すること
  (Web検索が必要であれば行ってよい)
