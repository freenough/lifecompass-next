# 指示: スクロールアンカー位置の修正 ＋ 入力トグン表示条件の再調査（重要）

## 1. 「入力を閉じる」実行後のスクロール位置がずれている

### 現象
「入力を閉じる」を押した後、固定モード/MCモードタブの直上に着地するはずが、
実際には比較モード（比例取崩/現金優先/課税優先のチェックボックス行）を
通り過ぎた位置（KpiGridの手前）に着地している。1段階下すぎる。

### 修正
アンカーの位置を再確認すること。ページの構造上、
「固定モード / MCモード」タブ → 「比較モード（戦略比較/シナリオ比較、
比例取崩等のチェックボックス）」→ KpiGrid、という順序になっている。
アンカーは **「固定モード/MCモード」タブの直前** に置くこと
（比較モードのブロックやKpiGridにアンカーを置かない）。
修正後、実際に「入力を閉じる」を押した直後のスクロール位置が
固定モード/MCモードタブのすぐ上（タブが画面上部付近に見える状態）に
なることをスクリーンショットで確認すること。

## 2. 入力トグンが、KpiGridの列数切り替え（2列→3列）と同時に消えてしまう（再発疑い）

### 現象
画面幅を広げていくと、KpiGridのカードが2列から3列表示に切り替わる
ちょうどそのタイミングでトグンが消える。これは以前修正したはずの
「トグンの表示条件が、意図したブレークポイント（`lg:` 1024px、入力フォームと
結果が横並びになる境界）ではなく、別のブレークポイントに連動している」
という問題が形を変えて再発している疑いが強い。

### 調査・報告（実装前に必須）
以下を**具体的なpx値・該当ファイル・該当行**で報告してから修正すること。
「確認済み」で終わらせず、実測値を示すこと。

1. `KpiGrid.tsx` のカードが2列→3列に切り替わるブレークポイントの実際のpx値
   （Tailwindのクラス名と、それが何pxに対応するか）
2. `simulator/page.tsx` の入力フォームと結果セクションが縦積み→横並びに
   切り替わるブレークポイントの実際のpx値（`lg:flex-row` 等）
3. 現在、入力トグンの表示/非表示を制御しているクラス・条件式が、上記1と2の
   どちらの値と一致しているか

1と2が異なる値であることを確認したうえで、トグンの表示条件が**2ではなく1と
一致してしまっている**場合はそれが原因なので、2の値（`simulator/page.tsx`の
レイアウト切り替えブレークポイント）に修正すること。

### 確認方法
修正後、ブラウザの実際の画面幅を1と2の間の値（例: 2が1024px、1が640pxなら
800px程度）に設定し、その幅でトグンが表示され続けていること
（KpiGridの列数が何列であっても、レイアウトが縦積みである限りトグンは表示され続ける）
を実測して報告すること。

- 前回までの実装（StickyKpiBar・KpiCard共通化・入力トグンのfixed化）には触れない。
  今回はアンカー位置とbrekpoint条件の修正のみ。
- 完了後、`full-verify.js` がPASSすることを確認。
