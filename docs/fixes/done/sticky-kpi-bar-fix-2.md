# 指示: StickyKpiBar/入力トグンの追加修正3件

## 1. MC未実行時の右スロット判定がタブ選択状態を見てしまっている（バグ）

### 現象
MCモードのタブは選択したが、まだ実行ボタンを押していない状態で、
StickyKpiBarの右スロットが「MC破綻率: —」という空白表示になっている。
本来は資産寿命（固定モード時の値）が表示されるべき。

### 原因
右スロットの判定に `mode === 'mc'`（タブの選択状態）を使っているため、
「タブはMCを選んだが未実行」の状態でも `mode==='mc'` が true になり、
実際には存在しない `mcResult?.strategies[strategy]?.bankruptcyRate` を
表示しようとして空欄になっている。

### 修正
判定基準を `mode` ではなく、**実際にMC計算結果が存在するかどうか**に変更する。
具体的には `mcResult?.strategies[strategy]?.bankruptcyRate` が `undefined`/`null`
ではなく実際に値を持っている場合にのみ「MC破綻率: ◯%」を表示し、
それ以外（未実行）は常に資産寿命（`analysis[strategy].dA`）を表示する。

## 2. 「入力を閉じる」実行後、スクロール位置が中途半端になる

### 現象
入力欄が開いている状態で下の方（グラフやモンテカルロ分析など）まで
スクロールしてから「入力を閉じる」を押すと、閉じた後もその中途半端な
スクロール位置のまま取り残される。

### 修正
「入力を閉じる」がクリックされた際、入力欄を閉じると同時に、
入力パラメータセクションの最下部（固定モード/MCモードのタブの直上）まで
スムーズスクロールで移動させる。既存のDOM構造上、固定モード/MCモードタブの
直前に適切なアンカー（ref）を用意し、`scrollIntoView({ behavior: 'smooth', block: 'start' })`
等で実装すること。

## 3. StickyKpiBarの表示条件を「入力フォームの可視性」ベースに変更する（設計変更）

### 背景
現状の表示条件は「KpiGridが画面内に見えていない間は常にバーを表示」となっているが、
これだとKpiGridを通り過ぎてグラフ・モンテカルロ分析・年次資産テーブル・フッターなど、
入力操作とは無関係な情報を読んでいる間もバーが表示され続けてしまう
（結果としてページ最下部のフッターのリンクを覆ってしまう問題も発生していた）。

このバーの本来の目的は「入力を変える→結果を見る」という往復コストの削減であり、
その必要性があるのは**利用者が入力フォームを操作している間だけ**である。
入力フォームを通り過ぎて他のセクションを読んでいる段階では、バーは不要かつ邪魔になる。

### 修正
表示条件の監視対象を、`KpiGrid` の可視性から **入力フォーム（`SimulatorForm` 等、
入力パラメータ全体を囲むコンテナ）の可視性** に変更する。

- 表示条件: 「入力フォームが画面内に見えている **かつ** KpiGridが画面内に見えていない」
  場合にのみバーを表示する。
- 入力フォームが画面外に出た時点（グラフ以降のセクションに読み進めた場合）で、
  KpiGridの可視性に関わらずバーは非表示にする。
- これにより、フッター到達時も入力フォームはとっくに画面外のため、バーは自動的に
  非表示となる。**フッター専用の別のIntersectionObserverを追加する必要はない。**
- 「入力を閉じる」で入力フォームがDOM上非表示になっている間の扱いも確認すること
  （閉じている間は入力フォーム自体が見えないため、バーは表示されない状態が正しいか、
  それとも閉じている間もKpiGridが見えるまではバー表示を維持すべきか、
  実装前に一度報告してから進めること）。

## 制約・確認事項
- `simulate.ts` / `analyze.ts` は変更禁止。
- 前回までの表示内容・ブレークポイント・KpiCard共通化・fixed化した入力トグンの実装は維持。
- 完了後、`full-verify.js` がPASSすることを確認。

   報告された仕様通りに動作しているか
