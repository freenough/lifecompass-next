# 再差し戻し: MC設定ツールチップの縦クランプ(未実装が2回連続で確認された)

前回・前々回とも「解消した」との報告だったが、実機確認で依然として下に切れている。原因を明確にするため、今回は実装方法を具体的に指定する。

## 現状の問題

MC設定の?をクリックして出る吹き出しが、カード/パネル下端で見切れて全文が読めない。ホバーしながらスクロールすると見えるが、通常の操作(タップ/クリックのみ)では読めない。

## 確認事項(まず実施)

`InfoTooltip.tsx` を開き、**横方向(left-0/right-0のフリップ)と同様の縦方向(top/bottom)の分岐が実際にコード上に存在するか**を確認して報告すること。存在しない場合は以下を実装する。存在するのに発動していない場合は、判定条件(閾値計算・タイミング)のバグとして特定して修正する。

## 実装方針(縦方向)

1. 横方向のフリップと同じ考え方で、`useLayoutEffect`内でツールチップを開いた直後に以下を計測する:
   - アイコン(?)のビューポート内でのY座標(`getBoundingClientRect().bottom`)
   - ツールチップ本体の高さ(`getBoundingClientRect().height`、または開く前に一度非表示レンダリングして計測)
   - ビューポート高さ(`window.innerHeight`)
2. `アイコンのbottom + ツールチップの高さ > window.innerHeight` の場合、**上向きに開く**(`top: auto; bottom: 100%`相当のクラス切り替え。現在下向きに使っているクラスと対になるクラスを用意する)
3. 収まる場合は現状通り下向きのまま
4. MC設定は判定上「収まらない」に分類されるはずなので、**MC設定の?をクリックした際に吹き出しがアイコンの上に表示されることを実機(またはPlaywrightでwindow.innerHeightを縮小したシミュレーションではなく、実際のズームレベル・実ブラウザに近い条件)で確認**してからスクリーンショットを添付すること

## 検証時の注意

前回・前々回の報告で「解消」の判定が実態と合っていなかったため、今回は以下を徹底すること:

- Playwrightのheadless計測値だけで「解消」と判断しない
- 可能であれば実ブラウザ(Windows Chrome/Edge)でのスクリーンショットを完了報告に添付する
- スクリーンショットは「?をクリックした直後、スクロールや追加操作をしない状態」で撮ること(ユーザーの実際の操作パターンに合わせる)
