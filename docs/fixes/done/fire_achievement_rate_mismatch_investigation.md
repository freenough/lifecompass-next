# 【調査のみ】達成率104%なのに「FIRE達成:未達成」と表示される不整合の原因調査

## 目的

前回の調査で、FIRE達成カードの色分け(緑/黄)は `fA(FIRE達成年齢)が計算できたか` という二値判定(`fireAchieved = a.fA != null`)で決まっており、画面に表示される「達成率(%)」とは別の計算経路であることが分かった。

今回、実際の画面で「達成率104%」(100%を超えている)にも関わらず「未達成」(黄色)と表示されるケースが見つかった。100%を超えているのに未達成というのは直感に反しており、2つの指標(`fA`の判定と達成率%)が異なる定義・異なるタイミングのデータを参照している可能性が高い。**このファイルでは実装は行わず、原因の調査とレポートのみをお願いします。**

## 再現した状況(スクリーンショットより)

- 年間生活費を370万円に変更(他の入力は変更なし、退職55歳・年金受給開始65歳・余命90歳)
- 戦略比較モードで「比例取崩」基準
- KPIカード:「FIRE達成」→ **未達成**、「達成率 104%」
- 資産寿命:枯渇なし、初年度取崩率:2.0%、最終資産:1.2億円

達成率が100%を超えているにも関わらず未達成と表示されている。

## 調査してほしいこと

1. **達成率(%)の計算ロジック**
   - 画面の「達成率104%」がどこで・どのようなデータをもとに計算されているか、該当コード箇所を特定する
   - 何を分子・分母にしているか(例:退職時点の資産 ÷ 必要資産額、など)
   - どの年齢時点(現在/退職時/任意の時点)の値を使っているか

2. **`fA`(FIRE達成年齢)の計算ロジック**
   - `fA`がどのように計算され、どのタイミングで`null`になるか(前回調査時の該当コード:KpiGrid.tsx周辺)を再確認する
   - `fA`が示す「達成」の定義(例:生涯を通じて資産が一度も枯渇しないシナリオが存在する年齢、など)を明確にする

3. **2つのロジックの関係性**
   - 達成率(%)と`fA`が、同じ前提条件(退職年齢・生活費・インフレ率など)で計算されているか確認する
   - 達成率が計算に使っている時点(例:退職時点でのスナップショット)と、`fA`が判定に使っている前提(例:生涯を通じたシミュレーション結果)が異なっていないか確認する
   - 具体的に、今回のケース(生活費370万円、達成率104%)で`fA`がなぜ`null`になっているのか、シミュレーション上の理由を特定する(例:退職時点では資産が足りているように見えても、その後のどこかの年で資産が尽きるシナリオがあるため`fA`は未達成判定になっている、等の仮説を検証する)

4. **意図した仕様なのか、バグなのか**
   - 「達成率(%)」と「FIRE達成/未達成」が異なる意味を持つ指標として意図的に設計されている(例:達成率は退職時点のスナップ、FIRE達成は生涯を通じた安全性)のであれば、それ自体は問題ないが、その場合はUI上の表現(ラベルや説明文)が誤解を招く可能性がある
   - 逆に、本来一致すべき2つの値が計算ロジックの不整合(バグ)によってズレているのであれば、その根本原因を特定する
