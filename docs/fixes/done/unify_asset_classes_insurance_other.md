# 指示書：シミュレーターの銘柄一覧に「保険」「その他」を足す（案A）＋文言の修正（実装〜本番確認までまとめて）

## 1. 目的と背景

- シミュレーター（`src/lib/profile.ts`の`ASSET_CLASSES`、12種類）と資産管理ツール（`src/lib/assetManagement/categories.ts`の`ASSET_CLASSES`、14種類）の銘柄名の違いは、**「保険」「その他」の2つだけ**（共通の12種類は、μ・σ・groupの値も同じ）。
- 資産管理ツールからインポートすると、この2つが特定口座の行に入り、シミュレーターの`<select>`に選択肢がなかった。
- 方針（KENZO決定）：**シミュレーターの一覧に2つを足す。** 利回り（μ）・標準偏差（σ）は、**暗号資産と同じ扱い**（既定値を置かず、その口座を手動入力に切り替えるよう警告する）。

## 2. 仕様

### 2-1. 一覧に足す（`profile.ts`、ロックファイル。**この修正に限り変更を許可**）

`ASSET_CLASSES`の暗号資産の後ろに、順に追加する。

```ts
{ key: '保険',   mu: 0, sigma: 0, group: 'cash' },
{ key: 'その他', mu: 0, sigma: 0, group: 'cash' },
```

- μ・σは0のダミー（暗号資産と同じ）。コメントで、「既定の前提を置かない。含めた口座は手動入力を促す」と書く。
- `group: 'cash'`の理由：σが0なので、相関はどのグループでも結果が変わらない。資産管理ツール側が`?? 'cash'`で扱っているのと一致する。`ASSET_CORR`には行を足さない。

### 2-2. 手動入力の警告を、保険・その他にも広げる（`profile.ts`の`getCryptoManualWarnings`）

- 「既定の前提がない銘柄」の定数を作る（例：`NO_DEFAULT_ASSUMPTION_CLASSES = ['暗号資産', '保険', 'その他']`）。
- 判定の条件は、今のまま：**該当口座がアクティブ**、**積立期／取崩期のPF（割合の行）にその銘柄がある**、**その口座の利回りが自動（PF計算値を使う）**。
- 同じ口座に複数の銘柄があるときは、**警告を1つにまとめる**（銘柄名を「・」でつなぐ。例：「暗号資産・保険は既定の期待リターンを設定していません。…」）。
- **暗号資産だけの口座の警告文は、今と1文字も変えない。**（回帰の確認項目に入れる）
- 関数名は変えない（名前の整理は別作業。コメントだけ更新する）。呼び出し元（`src/app/app/page.tsx`）は変えない。
- **警告が出る条件の補足（KENZOへの説明用）：** 「現在のPF」（金額の行）に保険・その他があるだけでは出ない。積立期／取崩期のPFに入れて、その口座の利回りを自動にしたときに出る（暗号資産と同じ）。サンプルの既定は、利回りがすべて手動なので出ない。

### 2-3. 2つの一覧が、ずれないようにする

- `scripts/full-verify.js`（または、既存の仕組みに合わせた最小の方法。難しければ別の小さなスクリプトでもよい）に、**2つの`ASSET_CLASSES`の一致の確認**を足す。
  - 銘柄名の集合と順番が同じ。
  - μ・σは、未設定を0として比べて同じ。groupは、未設定を`'cash'`として比べて同じ。
- 失敗したとき、どの銘柄のどの値が違うかが分かる出力にする。

### 2-4. 文言の修正（前回の「一覧外」の件）

1. **一覧にない値**（保険・その他は一覧に入るので、CSV取り込みなどの任意の文字列だけが対象）の`<select>`表示は、「（一覧外）」を付けず、**値だけ**を、これまでと同じ薄い色（slate-400）で出す。（`PortfolioPanel.tsx`の`AssetClassSelect`）
2. 「①の比率をコピー」で、コピーしなかった口座のメッセージを、次の文言にする：
   「{口座名}は、銘柄が未選択、またはシミュレーターで選べない銘柄があるため、積立期の配分にはコピーしませんでした」
   - 既存の文言が書かれている場所（`PortfolioPanel.tsx`、または`simulatorStore.ts`）で直す。**メッセージの文言以外は変えない。**
   - 変更を許可するのは、`profile.ts`・`PortfolioPanel.tsx`、（文言がそこにある場合のみ）`simulatorStore.ts`。ほかのロックファイルは触らない。

### 2-5. 変えないもの

- 資産管理ツール側（`categories.ts`など）、法人側（`hojinCompanyState/`、`hojinAssetManagement/`）、`simulate.ts`・`analyze.ts`、ストアの残高同期の仕組み、`importFromAssetManagementPersonal.ts`。
- 積立期・取崩期PFの「+ 追加」の初期値（全世界株）。
- 法人側に、保険・その他の警告があるかは、**読んで報告するだけ**（変更しない）。

### 2-6. 動きの変化（正しい挙動）

- 保険・その他は、一覧に入るので、**コピーのガードの対象でなくなる**（`isUnmappedAssetClass`が偽になる）。現在のPFの保険の行は、積立期のPFにコピーされる。その口座の利回りが自動のままなら、手動入力を促す警告が出る。
- 保険・その他を含まないプロファイル・既存の確定値は、変わらない。
