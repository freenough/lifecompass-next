## 0. 今回の内容

1. Hero見出しの上の余白を広げる

## 2. Heroの余白拡大

- Heroセクション内、タグライン「FREE + ENOUGH.」より上の余白（Heroセクションの`padding-top`、またはヘッダー直下からタグラインまでの間隔）を広げる。目安として現状の1.5〜2倍程度を起点にしつつ、全幅でスクリーンショットを見ながら widow（ヘッダーとの間が詰まりすぎ／空きすぎ）にならない値に調整する。具体的な数値は実装者の裁量で決めてよいが、変更前後の値（Tailwindクラスとpx換算）を完了報告に明記する。

## 3. Hero見出しのフォントサイズ拡大

- 見出し（「あなたにとっての「足りる」を、数字で描く。」）のフォントサイズを、コンテナの左右にほぼ余白がなくなる程度まで大きくする。目安として、1440px幅で見出し1行の実際の幅がコンテナ幅（本文コンテナ、1152px前後）の90%以上になることを基準にする。
- **これまでの改行制御ルールは維持する**：
  - `text-wrap:balance`や固定ブレークポイントでの強制ではなく、`white-space:nowrap`のチャンク分割による流動的な折返し（「あなたにとっての」「「足りる」を、」の2チャンク＋`数字で描く。`）を維持する。
  - 「足り／る」「あなたにとって／の」の位置での分割は禁止（既存のルールのまま）。
  - フォントサイズを`clamp()`等で可変にしている場合、その上限値を引き上げる形で対応する。固定pxへの変更は避ける。
- 375〜1920pxの全幅で、見出しが何行になるか（2行／3行）と、意図しない位置での折返しがないかを確認し、完了報告の表に含める。

### 3.1 追加対応（B案採用）：1024px幅でも見出しを2行にする

前回実装の結果、1024px幅で見出しが3行になった（clampの上限を72pxに上げたため、1行目1,053pxが本文幅976pxに収まらない）。これを、**全幅で2行を優先する（B案）**に変更する。

- `clamp()`の中央値（現状8vw）を6.4vw程度に下げ、750px以上の幅で見出しが常に2行になるようにする。1280px以上では上限72pxのまま変わらない。
- 副作用として、1024px幅は約66px、768px幅は約49px（現状約61px）になる。768pxでも3行→2行になる想定。これは承知の上での変更。
- 1024px幅では、1行目の幅が約965px（66px換算）で本文幅976pxに対し約11pxの余裕しかない。**実際の描画で2行に収まっていることを、1024px幅で実測して報告する**（計算値ではなく、行数と1行目の実幅を計測する）。1023〜1100px付近の幅も追加で確認し、ぎりぎりで3行に落ちる幅がないかを見る。
- 改行制御ルール（nowrapチャンク方式、「足り／る」「あなたにとって／の」で割らない）は引き続き維持する。
- 375〜1920pxの全幅で、行数・フォントサイズ・1行目の幅を表にして完了報告に含める。768px幅の見た目（49px・2行）が問題ないかも報告する。

### 3.2 追加対応：見出しのフォントサイズをcqi方式に変更（スクロールバー対応）

3.1の実装後の実測で、スクロールバーが幅を取る環境（Windows等のデスクトップブラウザ）では、750〜983px幅で見出しが3行になり、1024px幅も余りが2.6pxしかないことが分かった。原因は、`vw`がスクロールバーを含む画面幅で決まる一方、本文コンテナ幅はスクロールバーを除いた幅になるため。あわせて、749〜768px付近の余りがほぼ0pxという不安定さも解消する。

- Heroの見出しを含む要素に`container-type: inline-size`を付け、見出しのフォントサイズを`vw`ではなく**`cqi`（コンテナ幅基準）**で指定する。
- 最小36px・最大72pxの`clamp()`の枠は維持する。中央値のcqi係数は、実測して決める（目安：コンテナ幅976px時に1行目が余裕をもって収まる値。3.1の6.4vwと同等の見た目を、コンテナ幅基準で再現する）。
- 1行目の幅に対し、**最低でも15px以上の余り**を確保できる係数にする。
- `container-type: inline-size`による副作用（要素の幅・高さ計算の変化、Hero内の他要素の配置崩れ）がないか確認する。特にHero内のCTA・リード文の配置、見出しの上下余白（112px等）が変わらないこと。
- 検証は、**スクロールバーなし・ありの両方の条件**で、700〜1300pxを1pxごとに実測し、行数と1行目の余りを表にして完了報告に含める。375・390・1366・1440・1920pxも含める。
- 「足り／る」「あなたにとって／の」で割れる改行が0件、横スクロールが0件であることを引き続き確認する。

## 4. MESSAGEブロックの左寄せ・文章統合

- MESSAGEラベル・本文とも、**中央揃え→左揃え**に変更する（SERVICESと同じ左揃えに統一）。
- 本文を、以下の2行のテキストに置き換える（文言はそのまま、改行位置もこの2箇所のみを意図した区切りとする）。

  1行目：
  > 人生に必要なお金も、理想の働き方も、人それぞれです。大切なのは、誰かの正解を追いかけることではなく、自分にとって「足りる(Enough)」を知ること。

  2行目：
  > Freenoughは、その「足りる」を、体験談ではなく、数字で描く場所です。

- モバイル幅での改行崩れ対策として、以前2本柱ブロックの説明文で採用した方式（文節ごとに`<wbr>`、`word-break: keep-all`、`overflow-wrap: anywhere`）を、この2行のテキストにも同様に適用し、375px・390px幅で単語・文節の途中で改行されないことを確認する。
- ブロックの最大幅（1行がどこまで伸びるか）は、左揃えにした際に読みやすい行長になるよう調整してよい（本文コンテナ幅いっぱいまで伸ばすか、読みやすい幅に制限するかは実装者判断でよいが、選んだ理由を完了報告に記載する）。

## 5. MESSAGE・SERVICESラベルの色変更（試験的）

- 現在「線＝緑、テキスト＝黒」になっているMESSAGE・SERVICESラベルを、**線・テキストとも緑**（ブランドグリーン、これまでと同じ値）に変更する。
- 「試験的な変更」のため、他の変更点と区別できるよう、完了報告で変更前後のスクリーンショットを並べて提示する。

## 6. 検証

- Hero上部の余白が広がっている（変更前後のpx比較）

- 「資産シミュレーター」「一人法人」の見出しが一回り大きくなり、01/02の数字に埋もれていない
- 横スクロールが発生していない
