# 指示: 入力トグンの表示不具合調査 ＋ StickyKpiBarのデザイン共通化

## 背景
前回実装（StickyKpiBar・入力トグンの常時sticky化）の実機確認で2点の問題が見つかった。

1. 「入力を閉じる」トグンが、スクロールした状態で画面上に一切表示されていない
   （sticky化した結果、消えてしまっている）
2. StickyKpiBarが紺色の帯に白文字という独自デザインになっており、
   `KpiGrid.tsx` の実際のKPIカード（緑/黄/赤の色分け・角丸ボックス）とは
   見た目が異なる。同じ情報は同じ見た目で出したいため、デザインを共通化する。

## やること

### 1. 入力トグンが表示されない不具合の調査・修正（最優先）
`sm:hidden`（640px未満でのみ存在）+ `sticky top-14` を追加した実装で、
実機（640px未満の縦積みレイアウト、スクロールした状態）でこのボタンが
画面のどこにも表示されないことを確認済み。以下を疑って調査すること。

- `top-14`（3.5rem = 56px）の値が実際のヘッダー高さと一致しているか
  （ヘッダーは `保存/読み込み` ボタンを含む2行構成に見えるため、実際の高さが
  想定より大きく、ボタンがヘッダーの下に隠れている可能性がある）
- ボタンの親要素に `overflow:hidden` や `transform` が設定されており、
  sticky の効果が親要素内でしか効いていない可能性
  （`position: sticky` は祖先要素に `overflow` が指定されていると機能しないため）
- z-indexの設定漏れにより、ヘッダーの背後に描画されている可能性

修正後、640px未満の画面幅で実際にページをスクロールし、ボタンが常に
画面内の同じ位置に見え続けることをスクリーンショット等で確認すること。

### 2. KpiCard共通コンポーネントの切り出し
現在 `KpiGrid.tsx` に埋め込まれている「KPIカード1枚分」の見た目
（色分けクラス・ラベル/値のレイアウト・角丸等、既存の `.kpi.g`/`.kpi.y`/
`.kpi.r`/`.kpi.n` 相当のスタイル）を、独立したコンポーネント
`src/components/simulator/KpiCard.tsx` として切り出す。

- props例: `label`（ラベル文字列）, `value`（表示値）, `tone`（`'good'|'warn'|'danger'|'neutral'` 等、
  既存の色分け基準にそのまま対応させる）
- `KpiGrid.tsx` はこの `KpiCard` を今まで通りの枚数・今まで通りのグリッド
  （画面幅に応じた2列/3列のレスポンシブ制御はそのまま `KpiGrid.tsx` 側に残す）で並べる。
  **`KpiGrid.tsx` の見た目・列数の挙動を変えないこと。**

### 3. StickyKpiBarをKpiCard共通コンポーネントで再構築
`StickyKpiBar.tsx` を、独自デザイン（紺色の帯）から `KpiCard` を使う形に書き換える。

- 表示するカードは常に2枚固定（左:FIRE達成、右:資産寿命/MC破綻率。内容は前回指示書の通り変更なし）
- **画面幅によらず常に2枚を横並び均等幅（50/50）で表示する。**
  `KpiGrid.tsx` 側の2列/3列のレスポンシブ切り替えとは独立させ、
  StickyKpiBarは列数のレスポンシブ制御を一切持たない。
- 表示条件（`lg:`未満でのみ表示、KpiGridの可視状態に応じた出没）は前回指示書のまま変更なし。
- 位置（`fixed bottom-0`、safe-area対応）も変更なし。

## 制約・確認事項
- `simulate.ts` / `analyze.ts` は変更禁止。
- `KpiGrid.tsx` の既存の列数・見た目（2列/3列の切り替わり方）に一切影響を与えないこと。
  `KpiCard` への切り出しはあくまでリファクタリングであり、見た目の回帰がないことを確認する。
- 完了後、`full-verify.js` がPASSすることを確認。
- 完了報告は自己申告ではなく、実装ファイルの該当箇所をgrep等で提示すること。

## 動作確認観点
1. 640px未満の画面幅で、スクロール中も入力トグンが常に同じ位置に見え続けるか
   （ヘッダーの下に隠れていないか、スクリーンショットで確認）
2. KpiGrid.tsx が既存通り、iPad幅で3列・iPhone幅で2列のまま変わっていないか（回帰確認）
3. StickyKpiBarが、iPhone幅・iPad幅どちらでも常に2枚均等幅で表示されているか
4. StickyKpiBarのカードの色分け（緑/黄/赤）がKpiGrid本体のカードと同じ配色になっているか
5. 前回指示書の動作確認観点（複数戦略選択時の値の一致・セーフエリア・z-index重なり）が
   引き続き問題ないか
