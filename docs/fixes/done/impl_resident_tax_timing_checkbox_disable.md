# 実装指示:社会保険料率上書き時の「40歳以上65歳未満」チェックボックスのグレーアウト

## 背景
「社会保険料率が分かっている」にチェックを入れて数値を入力すると、`socialInsuranceRateOverride`が
`isAge40OrOver`より優先される(`socialInsuranceRateOverride ?? (isAge40OrOver ? 15.4 : 14.6)`)。
しかし現状のUIでは両方のチェックボックスが独立して操作できてしまい、「40歳以上」にチェックを
入れたのに反映されているか分からない、という誤解を招く。

## 修正内容(`ResidentTaxTimingForm.tsx`)
- `values.useSocialInsuranceRateOverride`(「社会保険料率が分かっている」のチェック状態を
  保持する既存のstate。名称は実装時の既存コードに合わせること)が`true`の間、
  「40歳以上65歳未満(介護保険料を含む)」チェックボックスを`disabled`にし、
  視覚的にグレーアウトすること(既存の他のdisabled表現があればそのスタイルに合わせる)
- グレーアウト時、チェックボックスの近くに小さく「社会保険料率を直接入力しているため、
  この項目は使用されません」等の一言を添えること
- 「40歳以上」のチェック状態(true/false)自体は、非活性化してもリセットしない
  (「社会保険料率が分かっている」のチェックを外せば、元の40歳以上の設定がそのまま復活する
  ようにする。前回の`retirementYearIncomeOverride`非表示化の際の設計判断と同様、
  状態を保持したままにする)
- 計算ロジック側(`residentTaxTiming.ts`)は変更不要(既存の優先順位ロジックが
  既に正しく動作しているため、UI側の見た目のみの修正)

## 検証要件
- ブラウザ実機で、「社会保険料率が分かっている」にチェックを入れた状態で「40歳以上」の
  チェックボックスがグレーアウトし、操作不能になることを確認すること
- 「社会保険料率が分かっている」のチェックを外すと、「40歳以上」が再び操作可能になり、
  かつ以前のチェック状態が保持されていることを確認すること
- 計算結果(税額)に変化がないこと(見た目のみの修正であるため)を確認すること
- `tsc --noEmit`エラーなし、`full-verify.js`全PASSを確認すること

## 禁止事項
- 計算ロジックの変更
- `docs/fixes/active/` フォルダの削除
