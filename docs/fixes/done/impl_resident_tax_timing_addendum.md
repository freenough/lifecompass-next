# 実装指示:resident-tax-timing 追加対応(.gitignore整備・給与所得控除注記の定量化・非課税基準警告)

## 背景
第1段階(計算ロジック・表UI)の実装は完了済み(104 PASS、full-verify.js全PASS、tsc clean)。
その後の調査(`docs/fixes/active/betsuhyo5-extraction/investigation_report.md`)で、
給与所得控除の速算表近似について、所得税法別表第五との誤差が「区分ごとに最大400円〜1,200円」
であることが定量的に判明した。本指示はこの調査結果と、別途保留していた住民税非課税基準の
警告表示を実装に反映するための追加対応である。

## 対応1: .gitignore の整備(最優先・最小変更)

調査作業で生成された16MB規模の生XML等の一時データが `docs/fixes/active/betsuhyo5-extraction/`
配下に残置されている。これをcommit対象から除外する。

- リポジトリルートの `.gitignore` に以下を追加すること:
```
# 調査・実装作業で生成される大容量の一時データ(スクリプトで再取得可能なもの)
docs/fixes/**/raw-data/
```
- 今回の `betsuhyo5-extraction/` 配下の生XML・中間データについては、上記パターンに沿うよう
  `raw-data/` サブディレクトリに移動してから `.gitignore` を適用すること
  (指示書・報告書(.md)自体は対象外とし、そのまま残すこと)
- `docs/fixes/` フォルダ全体・`docs/fixes/active/` フォルダ自体の削除は禁止(既存の恒久ルール)

## 対応2: 給与所得控除の注記文言を定量化

`src/lib/tax/residentTaxTiming.ts` 内、給与所得控除計算に関する既存の注記
(assumptionNotesまたはコードコメント)を、以下の内容に差し替えること:

- 変更前の想定:「近似値である」という定性的な注記のみ
- 変更後:収入帯によって誤差の上限が一意に決まる(ランダムに変動するわけではない)ことが
  伝わる表現にする。「400円〜1,200円」のような幅のある書き方だけを単独で使うと、
  同じ年収でも誤差が不確定であるかのように誤読されるため避けること。以下の趣旨で記載すること:

  「本ツールの給与所得控除額は、所得税法別表第五(4,000円刻みの区分表)に対して、
  お客様の収入が属する区分に応じて一定の差が生じる場合があります
  (190万円超〜360万円以下の区分:最大1,200円、360万円超〜660万円以下の区分:最大800円、
  660万円超〜850万円以下の区分:最大400円、それ以外の区分:差なし)」

  可能であれば、実際に算出した`taxableIncomeAssumption`が該当する区分を判定し、
  その区分に対応する上限値のみをUIに表示する(全区分を並べず、該当区分の数値だけを
  動的に出す)実装にすることが望ましい。実装コストが見合わない場合は、上記の全区分併記
  でもよいが、その場合も「収入帯によって決まる」ことが伝わる文言にすること
- 上記の数値根拠(調査報告書のURL・ファイルパス)をコード内コメントに明記すること
- UI(ResidentTaxTimingResult.tsx)側のassumptionNotes表示にも、この定量化された文言を反映すること

## 対応3: 住民税非課税基準の警告表示(新規)

### 方針
全国一律の厳密な非課税判定(級地区分・扶養人数別)は本ツールのスコープ外とする。
その代わり、単身・扶養なし・1級地を前提とした簡易基準を下回った場合に、
**税額は非表示にせず併記した上で**警告文を表示する。

### 実装前の確認事項(必須)
- 個人住民税の非課税限度額(均等割・所得割それぞれ、単身・扶養なしの場合の基準額)について、
  総務省の一次情報ページで最新の基準額を確認してから実装すること。記憶や推測で数値を
  ハードコーディングしないこと。確認したURLをコード内コメントに明記すること
- 均等割と所得割で基準額が異なる場合、**低い方(より保守的に警告が出やすい方)**を
  警告発火の閾値として採用すること

### ロジック仕様
```ts
type NonTaxableWarning = {
  mayBeNonTaxable: boolean;
  message: string; // 警告文。閾値・前提条件を明記すること
};
```
- 波2(nextYearTax)の課税所得算出過程で、給与所得(給与所得控除後、基礎控除前)が
  上記で確認した基準額を下回った場合に `mayBeNonTaxable: true` とする
- 警告文には必ず「単身・扶養なしを前提とした全国共通の簡易基準であり、実際の判定は
  お住まいの自治体(級地区分)・扶養状況により異なります」という限定条件を含めること
- `ResidentTaxTimingResult.tsx` で、`mayBeNonTaxable: true` の場合に税額の表示に加えて
  警告文をアラート形式で表示すること(税額そのものは隠さない、指示書の方針通り)
- 波1(currentYearTax)側にも同様の警告要否がないか検討し、必要であれば同一ロジックを
  共通関数化して両方から呼び出すこと(二重実装しないこと)

## 検証要件
- `scripts/verify-resident-tax-timing-tool.js` に以下のケースを追加すること:
  - 非課税基準を明確に下回る低年収パターン(例:年収100万円程度)で `mayBeNonTaxable: true` が
    返ることを確認
  - 明確に基準を上回るパターン(既存の400/600/800万円パターン)で `mayBeNonTaxable: false` を確認
- `full-verify.js` 全PASS・`tsc --noEmit` エラーなしを再確認すること
- 完了報告書に、非課税基準の一次情報URLと確認した具体的な金額を明記すること

## 禁止事項
- 級地区分別・扶養人数別の精緻な非課税判定ロジックの実装(スコープ外)
- 非課税可能性がある場合に税額そのものを非表示にすること(併記が方針)
- 一次情報での確認なしに非課税基準額をハードコーディングすること
- `docs/fixes/active/` フォルダ自体の削除
- `calcResidentTax()` 本体の改修
