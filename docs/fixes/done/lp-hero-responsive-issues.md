# 修正指示: lp-hero-responsive-issues

対象はLP(トップページ)のヒーローセクション。これまで作業していたシミュレーター側(page.tsx等)とは別コンポーネントのため、まず該当コンポーネントの場所を特定してから着手すること。

## 症状1: 中間幅でグラフが右側で切れる・グラフ枠下部に余分な空白ができる

- デスクトップ全幅(添付2枚目)では正常
- それより狭い、PCとモバイルの中間くらいの幅(添付1枚目)で、グラフの右端が見切れ、かつグラフカードの下部に余分な空白が生まれる

**調査手順:**
1. ブラウザの幅を1280pxから375pxまで100px刻みで狭めながら、どの幅で症状が発生し始めるかを特定する(単一の壊れた幅ではなく、範囲を特定すること)
2. その幅で、グラフを囲むカード・グラフのラッパー(ResponsiveContainer等)それぞれの実際のwidth/heightをDevToolsで実測する
3. カードの高さが固定値(例:`h-[500px]`等)になっていないか、グラフの最小幅(min-width)がカードの実際の幅より大きくなっていないかを確認する
4. 原因を報告してから修正する(決め打ちで直さない)

**修正の方向性(参考、確認後に決定):**
- カードの高さを固定値ではなく内容に応じた可変(auto)にする、またはこの中間幅用のブレークポイントを追加する
- グラフのwidth/height指定がこの幅で正しく再計算されるようにする

## 症状2: 狭いモバイル幅でKPIミニカード(FIRE達成年齢・資産寿命・MC破綻確率)が崩れる

- 文字(ラベル・数値)が途中で切れる
- 「枯渇なし」が折り返して2行になり、そのカードだけ縦に伸びて他の2枚とツラが揃わなくなる

**調査手順:**
1. 該当3枚のカードのコンテナが何列指定になっているか(例: 常時3列固定か、レスポンシブに列数が変わるか)を確認する
2. カード同士の高さを揃える指定(グリッドのitems-stretch等)が効いているか確認する
3. 文字が切れる原因(font-sizeが固定か、white-space指定、パディング等)を確認する

**修正の方向性(参考、確認後に決定):**
- 狭い幅ではカードを3列のまま維持するかどうかを含め、文字サイズを段階的に縮小する、または3列→レイアウト崩れが起きない列数に変更する等、視認性が保てる形にする
- カード内テキストの折り返しを許容する場合でも、3枚のカードの高さは揃える(items-stretch、または各カードのheightをmin-heightで統一)
- 数値・ラベルが省略されず読めることを優先する

## 確認事項

- 症状1: 特定した幅の範囲すべてで、グラフが切れず・余分な空白がないことをスクリーンショットで確認
- 症状2: 320px〜400px程度の実機/相当幅で、3枚のカードの文字が切れず、高さが揃っていることをスクリーンショットで確認
- 通常のPC幅・タブレット幅で回帰がないことを確認
- 6-A/6-B相当の確認(LP側に同等の検証スクリプトがあれば実施、なければその旨報告)
