## 0. 背景・位置づけ

フェーズ1（画面統合・型統一・資産クラス一本化）は完了済み。本指示書は同じ資産管理ツールに対する追加実装で、以下3点を扱う：

1. CSVで過去の記録履歴（スナップショット）もスプレッドシートでまとめて編集できるようにする
2. 記録の保存上限を引き上げ、値を1箇所で管理できるようにする
3. 法人→個人の資産移転（役員報酬・取崩）を記録する際、税金の扱いが予測側（シミュレーター）と実績側でズレないようにする専用フォームを追加する

いずれもロックファイル・フェーズ1で確定した設計（`personalOnly`/`combined`軸、ライブ参照方式等）を変更しない。

## 1. CSV機能の刷新（記録履歴対応）

### 1-1. フォーマット変更

既存の6列（ID／口座カテゴリ／資産クラス／区分／金額(万円)／更新日）に、**「年月」列を追加した7列**にする。

- **年月列は必須**（空欄行は作らない）。現在の保有資産（`AssetHolding[]`）も、Export時は**現在の年月**（例：`2026-08`）をラベルとして持たせる
- つまり「現在値」という特別扱いは廃止し、**「今月の記録」として統一的に扱う**。1行＝「ある年月時点の、ある保有資産項目の残高」

### 1-2. Export仕様

- Export範囲は既存の`personalOnly`/`combined`トグルに連動する（`combined`なら法人行も含める）
- 出力対象：現在の保有資産（今月ラベルとしてExport）＋保存済みの全記録履歴（`AssetSnapshot[]`）

### 1-3. Import仕様（重要・以下のルールを厳密に実装すること）

- **年月ラベルごとにグループ化**し、**そのグループを「CSVに残っている行の内容だけ」に完全に置き換える**（削除→挿入方式）
  - CSVにその年月ラベルの行が1つでも存在する → そのグループは、CSVに書かれている行だけの構成に総入れ替えされる（CSVから消した行は削除、内容を書き換えた行は更新、IDが空の新規行は新規追加として扱う）
  - CSVにその年月ラベルの行が1つも存在しない → そのグループには一切触れない（既存のまま保持）
- **今月（現在の年月）ラベルのグループが更新対象に含まれる場合**：`AssetHolding[]`（現在の保有資産）と、`AssetSnapshot[]`内の今月分の記録の**両方**を、CSVの内容で同期させる（常に一致させる。今月の記録が存在しない場合は新規作成する）
- **過去の年月ラベル**：`AssetSnapshot[]`内の該当月の記録のみを更新する（現在の保有資産には影響しない）
- インポート時、**月数・件数の上限によるバリデーション（弾き）は行わない**（過去数年分の一括投入を想定した用途のため）。件数上限は2章の共通ロジックに委ねる
- 確認ダイアログ（`window.confirm`等）は、影響を受ける年月ラベルの一覧を表示した上で表示すること（例：「2026-06、2026-08 の記録を上書きします」）

## 2. 保存上限の設定変更

- `MAX_SNAPSHOTS`を、資産管理ツール専用の設定ファイル（例：`src/lib/assetManagement/config.ts`）に一元化し、個人・法人（統合後は共通コンポーネント）両方がここを参照するようにする
- 値を**24→300**に引き上げる
- 合計件数（CSVインポート後も含む）が上限を超えた場合、既存の「古い方から自動削除」ロジックをそのまま適用する
- **自動削除が発生した場合、削除された年月範囲を明示した通知（トースト/バナー等）を画面に表示する**こと（例：「保存上限のため、2001-03〜2001-06の記録を自動削除しました」）

## 3. 資産移転ヘルパー（法人→個人）

### 3-1. 目的

法人から個人への資金移動を記録する際、引き出し額と個人側の税引後増加額を手計算せずに、両方の保有資産を整合の取れた形で同時更新するための専用入力フォームを追加する。

### 3-2. UI仕様

法人資産セクション内に新規フォームを追加する：

- **入力**：引き出し額（万円）
- **モード切替（手動トグル、2択）**：
  - 「取崩（税率を適用）」：法人の内部留保からの引き出しとして扱う
  - 「役員報酬・給与としての入金（税率を適用しない）」：通常の給与収入として扱う
  - デフォルトの選択はどちらでもよいが、ユーザーが毎回明示的に選ぶ形にすること（無指定のまま実行できないようにする）
- **税率入力欄**：「取崩」モード選択時のみ表示。初期値は現在の個人化想定比率の値を自動で埋める（個別の移転ごとに上書き可能）

### 3-3. 実行時の計算・更新仕様

- 「取崩（税率を適用）」モード：
  - 法人保有資産の合計から、引き出し額の**全額**を減算する（内訳をどの口座・資産クラスから減らすかはユーザーが個別に手動調整する前提。自動配分ロジックは実装しない）
  - 個人保有資産に、`引き出し額 × 税率 ÷ 100` の金額を加算する
- 「役員報酬・給与」モード：
  - 法人保有資産の合計から、引き出し額の全額を減算する
  - 個人保有資産に、引き出し額をそのまま（税率を適用せず）加算する
- 実行後は、通常の保有資産編集と同様に`AssetHolding[]`が更新される。スナップショットへの記録（`AssetSnapshot`への反映）は、既存の「記録する」ボタン操作を別途行う必要がある（本ヘルパーは保有資産の更新のみを行い、自動記録はしない）

### 3-4. 移転履歴ログ

- 実行した移転操作（日時・引き出し額・モード・適用税率・結果としての法人減算額／個人加算額）を、簡易なログとして別途保存する（例：`hojinTransferLog`、新規の非ロック・独立ストレージ）
- 本指示書のスコープでは、ログの**保存のみ**を実装する（一覧表示・編集・削除UIは対象外。将来の予実比較機能で参照する可能性があるための下地）

## 4. 個人化想定比率の説明文言更新

- 現在の説明文「法人の利益状況を踏まえて、将来どのくらいの割合を個人の手取りとして受け取れそうか、目安をご自身で設定してください」を、**「まだ引き出していない法人保有資産のうち」**という前提が伝わる文言に更新する（移転ヘルパー導入後は、既に移転済みの分は実績として確定するため、比率が対象とするのは残りの未確定分であることを明確にする）
- 文言の具体的な調整幅は実装者の裁量でよいが、上記の意味が伝わることを確認すること
- 計算ロジック自体（合計表示・進捗計算）は変更しない

## 6. 完了報告時に確認すべき項目（スクリーンショット必須）

- CSVを一度Exportし、年月列付きで出力されることを確認
- Exportしたcsvの一部の年月グループだけを編集して再Importし、**編集した年月のみ**が更新され、他の年月の記録に影響が出ないことを確認（削除→挿入がグループ単位で正しく動くこと）
- 今月ラベルの行を編集してImportし、現在の保有資産・今月のスナップショット記録の**両方**が同期して更新されることを確認
- 保存上限（300件）を一時的に下げるなどして、超過時に自動削除＋通知が出ることを確認（本番の上限値は300のままに戻すこと）
- 資産移転ヘルパー：「取崩」モードで実行し、法人資産が引き出し額全額減り、個人資産に税引後の金額のみが加算されることを確認
- 資産移転ヘルパー：「役員報酬」モードで実行し、個人資産に引き出し額がそのまま加算されることを確認
- 移転履歴ログがlocalStorageに正しく保存されていることを確認（実機で直接確認）
- ロックファイルへの依存がゼロであることのgrep確認結果を報告に含める
- `scripts/full-verify.js`・`tsc --noEmit`のPASS結果を報告に含める
