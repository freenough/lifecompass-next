# 追加調査指示:生HTML `<a>` タグの挙動切り分け

前回報告の以下のテスト結果について、原因が特定できていません。

```
<a href="https://evil.example.com" onclick="alert(3)">怪しいリンク</a>
→ <a>タグ自体は消え、中のテキスト「怪しいリンク」だけが残る
```

`href` は defaultSchema で元々許可されているため、本来は `onclick` だけが
剥がされて `<a href="https://evil.example.com">怪しいリンク</a>` という形で
残るのが期待される挙動です。タグ自体が消えたのは想定と異なります。

## 確認してほしいこと(切り分けテスト)

以下の2パターンを追加でテストし、結果を比較してください。

### テストA: onclickなしの通常のリンク
```
<a href="https://example.com">test</a>
```
これが残るかどうかを確認する。

- **残る場合** → onclick属性との組み合わせで何かが起きている可能性が高い
  (sanitize処理がonclickを検知した際、属性除去ではなくノード自体を
  破棄するような設定・実装になっていないか確認する)
- **残らない場合** → `<a>` タグ自体がこのパイプラインでサニタイズ対象外
  (＝生HTMLの`<a>`は経路に乗った時点で全て除去される)になっている
  可能性が高い。この場合、以下の点を追加確認する:
  1. `allowDangerousHtml` の設定値と、生HTML(html型mdastノード)が
     `toHast()` 時点でどう扱われているか(前回報告にあった「生htmlノードは
     toHast()の時点で丸ごと破棄される」という説明と矛盾しないか再確認)
  2. 今回追加した独自ノード型(`affiliateLink`)用の`handlers`が、
     通常の生HTML `<a>` ノードの変換処理に何らかの影響を与えていないか
     (handlersの登録が意図せず既存のHTML処理経路を上書き・迂回して
     いないか)
  3. カスタムスキーマ(`affiliateLinkSchema`)の `tagNames` に `a` が
     正しく含まれているか、`defaultSchema` のマージ方法(スプレッド構文
     による浅いコピー等)で `a` の定義が意図せず欠落していないか

### テストB: URLプロトコルの確認
```
<a href="javascript:alert(1)">test</a>
```
これも合わせてテストし、`href` がどう扱われるか確認する
(サニタイズで`javascript:`スキームが正しく無害化されるかの確認。
今回の本題とは別だが、ついでに確認しておくと安心材料になる)。

## 完了報告に含めてほしい内容
- テストA・Bそれぞれの出力結果
- 「残る/残らない」の切り分け結果から特定できた原因
- 原因が③(スキーマのマージ方法)だった場合は、`affiliateLinkSchema`の
  実際の中身(該当箇所のコード)を報告に含めること
- 今回のAffiliateLink自体(`<AffiliateLink provider="matsui" .../>`)の
  出力には影響がないと考えられる理由も一言添えること(独自ノード経路と
  生HTML `<a>` の経路が本当に別物であることの確認)
