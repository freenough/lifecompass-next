# 退職後最低充足率:名称確定と計算範囲の修正(fA達成時の矛盾解消)

## 前提

このファイルは `lifetime_min_ratio_calc.md` の実装完了報告(山本・中村で `fA != null` かつ `minRatio < 100` となる矛盾が発見された件)を受けた追加指示。報告いただいた「選択肢1」の方針を採用する。

## 決定事項

### 1. 名称を「退職後最低充足率」に確定

「生涯最低充足率」という名称は、実際の計算範囲(退職年齢〜余命)よりも広い印象(誕生〜死亡のようなニュアンス)を与えるため、**「退職後最低充足率」に変更する**。

- 詳細アコーディオンの「退職時充足率」(一時点)と、「退職後最低充足率」(退職後の期間全体での最低値)が、「時」と「後」の対比で一貫した命名になる
- 変数名(`minRatio`等)はそのままで良いが、UI上のラベル・ツールチップ・コメント等、ユーザーに見える箇所の文言はすべて「退職後最低充足率」に統一すること

### 2. 計算範囲を達成/未達成で分岐させる(矛盾の解消)

現状の実装(`retAge〜lifeEx全体の最小値`)を、以下のように条件分岐する。

- **`fA != null`(達成)の場合**: 集計範囲を **`fA以降〜lifeEx`** に限定して最小値を再計算する。この範囲内は定義上ラインを割らないため、`minRatio`は必ず100%以上になり、「◯◯歳で達成」というメイン表示と矛盾しなくなる
- **`fA == null`(未達成)の場合**: 現状のまま **`retAge〜lifeEx全体`** で最小値を計算する(比較対象の`fA`が存在しないため、この範囲のままで矛盾は生じない)

つまり、達成時は「fA以降で最も厳しかった年の充足率」、未達成時は「退職後で最も厳しかった年の充足率」を返す、という2つの異なる集計ロジックになる。

### 3. 「途中の谷」の情報は捨てずに残す(任意・優先度低)

達成時、`retAge〜fA`の間に一時的にラインを割った谷(例:山本さんのケースで64歳・89.8%)が存在する場合、この情報はメイン/サブ表示からは外れるが、完全に捨てるのはもったいない。可能であれば、達成時のカードのツールチップ内に「途中、◯◯歳で一時的にラインを下回る期間がありましたが、◯◯歳以降は安定します」のような一言を追加できないか検討してほしい。ただし実装コストが高い場合はこの3番目の対応は見送ってよく、1・2の対応を優先すること。

## 動作確認したいポイント

- 山本・中村のフィクスチャで、`fA != null`の場合に`minRatio`が100%以上になることを確認する(再修正後の値を報告)
- 田中・佐々木のフィクスチャで、`fA == null`または`fA`が早期に成立するケースの挙動に変化がないか確認する(佐々木は元々`minRatio=142.4% >= 100`なので、fA以降に範囲を絞っても同じか、より高い値になるはず)
- UI上のラベル文言がすべて「退職後最低充足率」に統一されていること(「生涯最低充足率」という文言が残っていないか grep 等で確認)
