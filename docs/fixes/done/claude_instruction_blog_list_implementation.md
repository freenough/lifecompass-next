## 1. ページの外枠・見出し

- `BlogPage` の外側 `<main className="max-w-3xl mx-auto px-4 py-12">` を、`Container`（default）＋ `py-12` に置き換える
  - `<main>` の入れ子を解消するため、`main` ではなく `div` 相当にすること
- 見出しを `PageHeader` に置き換える
  - タイトル：「ブログ」
  - 説明文：`BLOG_DESCRIPTION`
  - パンくず：資産シミュレーター（`/`）› ブログ（`/blog`）
- 期待値：コンテンツ左端x座標が、1440px幅で168px、768px・375px幅で24px（お悩み一覧・ツール一覧と一致）

## 2. 2カラム構成（lg以上）

- lg以上は `grid lg:grid-cols-[minmax(0,1fr)_300px] lg:gap-10 lg:items-start` とする
  - 左列（メイン）：フィルター＋記事一覧
  - 右列：サイドバー
- サイドバーは `sticky` で、`top` は83px（ヘッダー59px＋24px）とする
- lg未満は1カラムとし、サイドバーの中身（注目記事・導線カード）を**記事一覧の後（ページ最下部）**に表示する
- 注目記事と導線カードは、フィルターの選択に関係なく常に同じ内容を表示する

## 3. 注目記事

- 新しいファイル（例：`src/lib/featuredPosts.ts`）に、注目記事のslugを表示順に並べた配列を置く

  ```ts
  // 注目記事（ブログ一覧サイドバー用）。表示順に並べる。
  // LPの「FIREガイド」（blog.ts の featured / priority）とは独立して管理する。
  export const FEATURED_POST_SLUGS = [ /* 4件 */ ] as const;
  ```

- **初期値は暫定で、公開日が新しい順に4件**とする。完了報告に全21件の一覧（タイトル・slug・公開日）を載せること。KENZOがそこから4件を選び直す
- 存在しないslugが入っていた場合は、その項目を表示せずに読み飛ばすこと。dev環境ではコンソールに警告を出すこと
- 表示用コンポーネントを新設する（例：`FeaturedPostsList`）
  - props に GA4用の `location`（`'sidebar'` ／ `'mobile_bottom'`）を持たせる
- 見た目：
  - 見出し「注目記事」は、`SectionRule`＋小さめの見出しにする
  - 各項目は「番号（1〜4）＋記事タイトル（`line-clamp-2`）」だけとする。**画像・カテゴリ・説明文は出さない**
  - 項目全体をリンクにし、項目の間は区切り線とする
  - タイトルには `[line-break:strict]` を付ける
- 見出しのレベルは、記事カードのタイトル（`h2`）との関係を見て、見出しの階層が不自然にならないように決めること。判断した内容を報告すること

## 4. シミュレーターへの導線カード

- 注目記事の下に、小さな導線カードを新設する（例：`SimulatorCtaCard`）
  - props に GA4用の `location` を持たせる
- 中身：
  - 短い見出し（例：「あなたのFIREは何歳？」）
  - ボタン「シミュレーターで試算」（リンク先は `/app`）
- ボタンの文言は `CONCERN_CTA_LABELS.fullSimulator` を参照するなど、お悩みカードと表記を一致させること
- 見た目：角丸4px。ボタンは既存の濃紺CTAボタンと同じトーン（ホバーで浮き上がる）にする
- **高さの条件**：サイドバー全体（注目記事4件＋導線カード）の高さを、**560px以下**に収めること
  - 1366×657のビューポート（1366×768のノートPCからブラウザのツールバーを除いた近似）で、stickyの状態のまま導線カードの下端まで見えることをスクリーンショットで確認すること
  - 収まらない場合は、実装で吸収せず、実測値を添えて報告すること

## 5. 記事カード（現在の横長の形を維持）

- 角丸：
  - カードは `rounded-xl` から `rounded`（4px）に変更する
  - サムネイルの枠は `rounded-lg` から `rounded` に変更する
- タイトルの `min-h-[44px] sm:min-h-[49.5px]` と、説明文の `min-h-[45.5px]` を削除する。`line-clamp-2` は維持する
- タイトルの色を `text-[#0F2A4A]` から `text-slate-900` に変更する（`PageHeader` とそろえる）
- タイトル・説明文に `[line-break:strict]` を付ける
- ホバー：ツールカードと同じ定義にする
  - `hover:-translate-y-1 hover:shadow-lg hover:border-slate-300`
  - transitionは200ms程度
  - `motion-reduce:hover:translate-none`
- バッジ（カテゴリ）はそのまま維持する。フィルターのチップに件数は付けない
- サムネイルの `sizes` は変更不要（表示サイズが変わらないため）

## 6. フィルターのURL連動

- テーマ（複数）とステージ（単一）の選択状態を、URLのクエリに反映する（例：`?topics=nisa,ideco&stage=saving`。キー名と値の形式は既存のデータに合わせて決めてよい）
- フィルター変更時は `router.replace`（履歴を積まない）を使い、スクロール位置は動かさないこと
- ページを開いたとき・戻るボタンで戻ったときに、クエリから選択状態を復元すること
- 不正な値（存在しないテーマ・ステージ）は無視すること
- 「フィルタをリセットする」を押したら、クエリも消すこと
- **SEOの条件**：
  - `useSearchParams` を使う場合は `Suspense` 境界を置くこと
  - サーバーで生成されるHTML（フォールバックを含む）には、**絞り込みなしの全記事のリンクが含まれている**こと。`curl` などで取得したHTMLで確認し、記事リンクの件数を報告すること
- canonical URLがクエリなしの `/asset-simulator/blog` のままであることを確認すること

## 7. GA4イベント

- 既存の `trackEvent` と、既存イベント（例：`concern_cta_click`）の命名・パラメータの形式にそろえて、以下を追加する。イベント名・パラメータ名は既存の規則に合わせて調整してよい。最終的な定義を報告すること

  | イベント（例） | 送るタイミング | 主なパラメータ（例） |
  |---|---|---|
  | `blog_filter_click` | テーマ・ステージのチップを押したとき | 種別（topic／stage）、値、選択後の状態（on／off） |
  | `blog_post_click` | 記事へのリンクを押したとき | slug、場所（list／sidebar／mobile_bottom）、表示位置（何番目か） |
  | `blog_cta_click` | 導線カードのボタンを押したとき | 場所（sidebar／mobile_bottom） |

- dev環境でイベントが発火することを、実際に送られる値（`dataLayer` への push の内容など）で確認し、報告すること。本番のGA4プロパティにテスト送信しないよう注意すること

## 8. 記事詳細ページのパンくず

- `BlogPostPage` のインラインのパンくず（表示用 `<nav>` と BreadcrumbList の JSON-LD）を、共通の `Breadcrumb` に置き換える
  - 項目：資産シミュレーター（`/`）› ブログ（`/blog`）› 記事タイトル
- 表示では、**最後の項目（記事タイトル）を1行で省略表示**にする（現状と同じ）
  - `Breadcrumb` に最後の項目を省略するためのオプションを追加してよい
  - お悩み一覧・ツール一覧の見た目は変えないこと
- JSON-LDの記事タイトルは省略せず、全文を出すこと
- `BlogPostPage` の `<main>` の入れ子も解消すること
- 変更前後のJSON-LDの差分（nameの2か所だけが変わる見込み）を実データで提示すること

## 安全ルール（必ず守ること）

- `localStorage.clear()` などの破壊的操作は行わないこと。どうしても必要な場合は、対象オリジンが検証専用であることを確認し、実施前に報告すること。判別できない場合は操作せず、KENZOに確認を求めること
- devサーバーを停止するときは、ポートからPIDを特定し、そのPIDだけを個別に停止すること。`taskkill /F /IM node.exe` のような全プロセス一括終了コマンドは**使用禁止**
- `tsc` などで `tsconfig.tsbuildinfo` が書き換わった場合は元に戻し、報告すること
- **commit・pushはKENZOの明示的な指示があるまで行わないこと**
