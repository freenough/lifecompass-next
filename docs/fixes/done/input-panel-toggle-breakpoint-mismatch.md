# 差し戻し: input-panel-closed-spacing(scrollガードでは未解決、設計の食い違いが根本原因)

前回の修正(scrollIntoViewに640pxガードを追加)は、症状を止めただけで根本原因を解決していません。結果として「タブレット幅(640〜1024px)でトグルボタンを押しても何も起きない」という新たな不具合が発生しています。

## 根本原因

- フォーム本体の表示制御: `hidden sm:flex` → **640px以上ではformOpenの状態に関わらず常に表示**
- 開閉トグルボタンの表示制御: `lg:hidden` → **1024px未満まで表示**

この2つのブレークポイントが一致していないため、640〜1024pxの範囲では「ボタンは見えるが、押しても対応するCSSの変化が存在しない」状態になっています。以前はscrollIntoViewの副作用で何か動いているように見えていた(これが元の「空白」バグ)だけで、機能自体は最初から存在していませんでした。

## 修正方針(いずれかを選び実装、判断理由も報告に含める)

**方針A(推奨): トグルボタンの表示範囲をフォーム開閉が実際に機能する範囲に合わせる**
- ボタンの表示条件を `lg:hidden` → `sm:hidden`(またはフォームが常時表示される640px以上ではボタン自体を非表示にする)に変更する
- 640px以上ではボタンを表示せず、フォームは常に開いた状態として扱う
- この場合、640〜1024pxのレイアウトが「常にフォーム全文表示」で問題ないかを確認すること(縦に長くなりすぎないか等)。問題があれば方針Bを検討する

**方針B: フォーム開閉機能を1024pxまで拡張する**
- `hidden sm:flex` を `formOpen` state で制御するクラスに変更し、1024px未満では常にJSのopen/closed状態に従って表示/非表示を切り替える(sm:flexで強制上書きしない)
- 1024px以上でのみ常時表示にする
- この場合、実際にタブレット幅でトグルを押すとフォームの表示/非表示が切り替わることを実機確認する

どちらの方針でも、**ボタンが表示されている幅では、押すと必ず見た目上の変化が起きる**状態にすること。

## 確認事項

- 640px, 768px, 1024px, 1024px以上の各幅で、ボタンの有無とクリック時の挙動をスクリーンショットで確認
- モバイル375pxで従来通り開閉が機能することの回帰確認
- 元々の症状(「入力ボタンの下の空白」)がこの範囲でも解消されていることの確認
