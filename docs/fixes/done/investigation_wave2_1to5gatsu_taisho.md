# 調査指示:1〜5月退職時の「波2」所得基準年の誤りの検証と設計修正案(調査のみ・実装しない)

## 背景・疑われる不具合
ユーザーの手動テストにより、**1〜5月退職のケースで「②(退職翌年6月からの新規課税)」が、
本来計算すべき対象と異なる金額を返している疑いが強い**ことが判明した。

### 制度上の整理(前提。既存の調査報告書群で確認済みの住民税年度ルールに基づく)
住民税は「ある暦年C年の所得」を基準に、**C+1年6月〜C+2年5月**に徴収される。
退職年をY、退職月をMとすると:

**M(退職月)が6〜12月の場合(既存実装が正しく対応できているケース)**
- 波1(進行中):今年(Y)6月〜翌年(Y+1)5月、所得基準=前年(Y-1)
- 波2(次に来る):翌年(Y+1)6月〜翌々年(Y+2)5月、所得基準=**今年(Y)の部分所得**
  (退職月までの月割り推計。既存の`priorYearIncome/12×retirementMonth`はこのケースには正しい)

**M(退職月)が1〜5月の場合(実装に誤りがある疑いが強いケース)**
- 波1(進行中):前年(Y-1)6月〜今年(Y)5月、所得基準=前々年(Y-2)。**これは既存実装で正しく対応済み。**
- **波2(次に来る、本来最優先で計算すべきもの)**:今年(Y)6月〜翌年(Y+1)5月、
  所得基準=**前年(Y-1)のまるまる1年分の所得**(`priorYearIncome`をそのまま使うべきで、
  月割りしてはならない)
- 波3(さらにその次、現行ツールのスコープ外の可能性):翌年(Y+1)6月〜翌々年(Y+2)5月、
  所得基準=今年(Y)の部分所得(月割り推計。現状の`calcNextYearTax()`の計算式に近い)

**疑い**:現状の`calcNextYearTax()`は、退職月(M)によらず常に
`priorYearIncome/12×retirementMonth + postRetirementIncome`という同一の式を使っている。
この式は6〜12月退職には正しいが、1〜5月退職に対しては「波2」ではなく「波3」に相当する
計算をしてしまっており、**1〜5月退職のユーザーに対しては、本来最優先で表示すべき
「波2(前年まるまる1年分を基準にした、最も近く・最も金額が大きい新規課税)」を
一切計算・表示できていない可能性が高い**。

**本指示は調査・設計検討のみを目的とする。コードの変更は一切行わないこと。**

## 調査・検証内容

### 1. 現状のコードの動作確認
- `residentTaxTiming.ts`の`calcNextYearTax()`が、退職月によって分岐しているか、
  常に同一の月割り推計式を使っているかをコードを読んで確認すること
- 上記の「疑い」の通りであることを、実際にコードを追って確認・報告すること

### 2. 制度上の整理が正しいかの再確認
- 上記「制度上の整理」の表(波1・波2・波3の所得基準年・徴収期間の対応)が、既存の調査報告書
  (`investigation_juminzei_taimurag.md`・`investigation_juminzei_futsuchoshu_wariate_result.md`)
  で確認済みの住民税年度ルールと矛盾しないかを再確認すること
- 特に、1〜5月退職時の「波2」が本当に「前年(Y-1)のまるまる1年分」を基準にするという理解が
  正しいか、既存の一次情報の範囲内で裏付けが取れるかを確認すること(新たな一次情報調査が
  必要な場合はその旨を報告し、本指示の範囲では実装しないこと)

### 3. 具体的な影響額の試算(現状のバグの深刻さを定量化)
- KENZOさんの手動テスト例(退職前年年収600万円・5月退職)について:
  - 現状の実装が返す「②」の金額(月割り推計ベース、小さい値)
  - 本来「波2」として表示すべき金額(前年600万円まるまる1年分を基準にした年間住民税額)
  の両方を試算し、差分がどの程度になるか(概算でよい)を報告すること

### 4. 設計修正案の提示(実装はしない、方針の提案のみ)
以下の観点から、修正の設計案を複数提示すること:

**案A:波2の所得基準を退職月で分岐させる**
- 6〜12月退職:現状通り(退職年の部分所得、月割り推計)
- 1〜5月退職:`priorYearIncome`をそのまま(月割りせず)使う
- この場合、`CurrentYearTax`の`incomeBasisYearLabel`(前々年/退職前年)との整合性、
  UIの見出し文言(「退職した年の所得をもとにした」という現状の説明文が、1〜5月退職では
  実態と合わなくなる)への影響も含めて検討すること

**案B:波3(退職年の部分所得を基準にした、さらに先の新規課税)を別途追加する**
- 1〜5月退職の場合、案Aの「本来の波2」に加えて、現状の計算式が担っていた「波3」も
  別途表示するかどうか(ツールのスコープをどこまで広げるか)を検討すること
- 追加する場合のUI設計(③として追加するか、比較表・注記に留めるか)の所見を述べること

**両案共通で検討すべき点**
- `totalCashNeeded`(確保しておきたい現金の目安)の算出範囲が、この修正でどう変わるか
  (1〜5月退職のケースで、現状より大幅に増額される可能性が高いことを明記すること)
- 6〜12月退職のケースには一切影響がないことの確認方法
