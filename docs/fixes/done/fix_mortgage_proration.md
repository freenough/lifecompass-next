# 指示書:住宅ローン完済境界年の按分処理 実装

**このセッションの役割:** 実装。`simulate.ts`(ロックファイル)への変更を含むため、実装完了後はコミットせず報告のみ行い、このチャットの確認を得てからコミット・pushすること。

**前提:** 一括支出の計上(`age === expEv.prepayAge`時の`extraExp += expEv.prepayAmount!`)は実装済み(未コミット)。調査(`investigation_mortgage_proration_feasibility.md`)により、按分処理は`mortgage`ブロック内で局所的に完結することを確認済み。

## 背景

期間短縮型の繰上返済で、新しい完済年齢(`endAge`)が小数(例:67.25歳)になる場合、従来は整数年齢との比較(`age < endAge`)により「境界年の返済額が丸ごと発生する/しない」の二択になっていた。これを、境界年のみ端数比率で按分する形に変更し、経済的に正確な効果を反映させる。

## 実装要件

### 1. 按分ロジックの実装

`simulate.ts`の`mortgage`ブロック内、既存の`if (age >= evAge && age < endAge) { extraExp += payment; }`(該当行、前回セッションで212行目付近と報告あり)を、以下の方針で置き換える。

```javascript
const boundaryAge = Math.floor(endAge);
const fraction = endAge - boundaryAge;      // 通常(繰上返済なし/軽減型)は常に0
if (age < boundaryAge) {
  extraExp += payment;
} else if (age === boundaryAge && fraction > 0) {
  extraExp += payment * fraction;           // 端数年のみ按分
}
```

- `endAge`が整数のとき(繰上返済なし・返済額軽減型)は`fraction = 0`となり、従来通りの挙動(境界年に追加支出なし)と完全に一致すること。この後方互換性を必ず確認すること
- `prepayType`による明示的な分岐は不要(`fraction`の値が自然に0になるため)。ただし念のため、返済額軽減型で`fraction`が意図せず非ゼロにならないことをコードレビューで確認すること

### 2. 一括支出計上との重複ケースの確認(必須)

繰上返済年(`prepayAge`)と、按分の対象となる完済境界年(`boundaryAge = Math.floor(endAge)`)が同じ年になるケースがあり得るかを確認すること。

- あり得る場合:その年の`extraExp`に「一括支出(`prepayAmount`)」+「按分後の返済額(`payment * fraction`または通常の`payment`)」が両方正しく加算されることを実測で検証すること
- あり得ない場合(数学的に同年になり得ない理由があれば):その理由を報告に明記すること

該当するテストケース(繰上返済年と完済境界年が近接する、または一致するパラメータ)を意図的に作成し、実測で確認すること。

### 3. 既存フィクスチャの更新

- `reference/simulation_fixtures.md`・`scripts/full-verify.js`の期間短縮型フィクスチャ(前回セッションで按分導入前提として一時追加した24ケース中の該当分)を、按分処理導入後の正しい値に更新すること
- 繰上返済なし・返済額軽減型のフィクスチャは影響を受けないはずだが、念のため回帰確認すること

### 4. 新規フィクスチャの追加

- 端数比率が明確にわかるケース(例:`fraction = 0.25`となるパラメータ)で、境界年の`extraExp`が`payment * 0.25`と正確に一致することを検証するフィクスチャ
- 上記2番の重複ケース(該当する場合)の検証フィクスチャ

### 5. 表示側(`LifeEventTimeline.tsx`)への言及

按分処理導入により、表示とシミュレーションの整合性は自然に取れるようになるため、`Math.ceil`修正は実装しないこと(調査報告での推奨通り)。ただし、モーダル内の試算表示文言(「完済年齢: 68歳→67歳」等)が、実際には端数年で一部返済が残ることを踏まえてもなお正確な表現になっているか、念のため確認すること(誤解を招く場合は文言修正を検討し、その場合は設計判断としてこのチャットに報告すること)。

## 検証(必須・省略不可)

1. 繰上返済なし・返済額軽減型のフィクスチャが完全に一致すること(1円単位)
2. 期間短縮型の按分ケースが正しく計算されること(境界年の`extraExp`が期待通りの按分値になること)
3. 重複ケース(2番)の検証結果
4. `full-verify.js`・`tsc`実行結果
5. 計算方法の明記(本番関数経由であることの確認)
