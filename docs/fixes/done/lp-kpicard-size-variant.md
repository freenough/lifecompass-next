# 修正指示: lp-kpicard-size-variant

## 症状

iPhone SE幅(375px)で、LPヒーローセクションのKPIミニカードのうち「資産寿命」の値(例:「枯渇なし」)が折り返して2行になり、そのカードだけ縦に伸びて他の2枚と高さが揃わない。

## 前提・制約

`KpiCard.tsx` はシミュレーター本体(KpiGrid)とLP(HeroDemo)の両方で使われている共有コンポーネント。**シミュレーター側の見た目には一切影響を与えないこと**が絶対条件。

## 方針: KpiCardにサイズのバリアント(props)を追加する

- `KpiCard`に `size` のようなpropsを追加する(例: `size?: 'default' | 'sm'`、未指定時は従来通り`'default'`)
- `size="sm"`のときのみ、値(数値)部分のフォントサイズを一回り小さくする
- シミュレーター側の呼び出し箇所は`size`を渡さない(=デフォルトのまま、変更なし)ことを徹底する
- LP側(`HeroDemo.tsx`)の3枚のカードにのみ `size="sm"` を渡す

## 実装前に必ず行うこと: 実測

決め打ちでフォントサイズを決めず、以下を実測してから変更量を決定すること。

1. 375px幅で、現在の「枯渇なし」の値テキストの実際の幅(scrollWidth)と、カード内でテキストに使える幅(clientWidth、padding控除後)を計測する
2. 値のフォントサイズを何段階か(例: 現状→1段階小→2段階小)試し、「枯渇なし」が1行に収まる最小の変更量を特定する
3. その段階で、他の値(「52歳」「1.2%」等、短い値)も文字が小さすぎて視認性が悪くならないか確認する
4. 決定したサイズと根拠(実測値)を完了報告に含める

## 確認事項

- 375px幅で、3枚のKPIミニカードが全て同じ高さになり、「枯渇なし」等の値が1行に収まることをスクリーンショットで確認
- シミュレーター側のKpiGrid(通常表示・モバイル)で、フォントサイズ等の見た目が一切変わっていないことをスクリーンショットで確認(必須)
- 320px程度のさらに狭い幅でも崩れないか確認
- PC幅のLPヒーローで回帰がないことを確認
