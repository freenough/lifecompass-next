# 実装指示書: ツールセクション(「かんたん計算ツール」)外側余白の整列回復＋内側余白のさらなる圧縮

対象ブランチ: `feature/lp-container-width`は削除待ちのためmainから新規ブランチを切ること(例: `feature/lp-tool-section-spacing`)

## 0. 前提・背景

前回リリースで「かんたん計算ツール」セクションの`Container`の`paddingX`を`tight`(px-2)に変更したが、KENZOの実機確認で「FIREガイド」等の他セクションと左右の外側余白が揃わなくなっていることが判明した。外側は他セクションと揃えて戻し、その代わり内側(カード間・カード内部)をさらに詰める方針とする。内側の`gap-x-3`/`p-3`は未検証の値のため、今回の実装内で確認まで行う。

## 1. 外側余白を他セクションに合わせて戻す

- 「かんたん計算ツール」セクションの`Container`の`paddingX`を`tight`から`default`(px-6)に戻す
- 「FIREガイド」等、他セクションと左右の外側余白が完全に揃うことを確認すること

## 2. 内側余白をさらに圧縮(モバイル限定)

- 列間: `gap-x-4 lg:gap-x-8`を`gap-x-3 lg:gap-x-8`に変更(モバイルのみ、`lg:`は変更しない)
- カード内部: `p-4 lg:p-6`を`p-3 lg:p-6`に変更(モバイルのみ、`lg:`は変更しない)

### フォールバック条件

- `gap-x-3`/`p-3`適用後、モバイル375px幅で以下のいずれかに該当する場合は、該当する値のみ前回確認済みの安全な値(`gap-x-4`または`p-4`)に戻すこと
  - アイコン・タイトル・説明文のいずれかが窮屈に見える、または行間が詰まりすぎて読みにくい
  - カードがタップ可能なリンクである場合、隣接カードとのタップ領域の間隔が近すぎて誤タップしやすい
- `gap-x-3`と`p-3`は個別に判断してよい(片方だけ`gap-x-4`に戻し、もう片方は`p-3`のまま、という組み合わせも可)
- 最終的にどの値を採用したかを完了報告に明記すること

## 3. 検証範囲

- モバイル375px幅: ツールセクション単体のスクリーンショット、およびKENZOが確認した画面(「FIREガイド」→「かんたん計算ツール」の連続した並び)を含むスクリーンショットで、外側余白が揃っていることを確認
- デスクトップ: 前回実装(`lg:gap-x-8`、`lg:p-6`)に変化がないことを確認
- 変更後のツールセクションが、他セクション(FIREガイド等)と左右の外側ラインが視覚的に一致していることをスクリーンショットで明示すること

## 4. 証跡要件

- 変更前後のスクリーンショット(モバイル375px、「FIREガイド」〜「かんたん計算ツール」の連続表示を含む)
- 変更したファイルパス・該当箇所のdiff
- フォールバックを適用した場合は、その判断理由と最終的に採用した値

## 5. 安全ルール(再確認・強調)

- **完了報告にローカルファイルパスを一切含めないこと**。確認用画像は全てチャットにインライン表示すること。パスの共有はKENZOが明示的に指示した場合のみに限定する(過去2回、指示なしにパスを貼る事案が発生している)
- コミット・pushは行わないこと。KENZOの明示的な指示を待つ
- devサーバーの停止は対象PIDを指定した個別停止のみ。全プロセス一括終了コマンドは使用禁止
- 完了報告にツールの内部ログ(シェルコマンド実行ログ等)をそのまま貼らないこと
