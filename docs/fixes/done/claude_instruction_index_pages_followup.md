# 指示書: 一覧ページ改修の追加修正（feature/index-pages-polish）

## 種別

実装指示（前回の完了報告に対する追加修正）。引き続き `feature/index-pages-polish` ブランチで作業すること。

## 1. ツールカード：lg未満は1列にする（B-4 案a）

- `ToolsPage` のカードグリッドを、**lg（1024px）未満は1列、lg以上は2列**に変更する
- カード内のレイアウトの切替幅（lg）は、前回の実装のまま変更しないこと
- お悩み一覧のグリッド（`sm:grid-cols-2`）は変更しないこと

## 2. ツールカード：和文の禁則処理（`line-break: strict`）

- ツールカードの**タイトルと説明文の両方**に `line-break: strict` を適用する
- Tailwindに専用ユーティリティがなければ、任意値クラス `[line-break:strict]` を使うこと
- 目的は、「ー」（長音符）や小さい「ゃ・ゅ・ょ・っ」などが行頭に来るのを防ぐこと
- 前回報告にあった「目標資産到達年齢シミュレータ／ー」のような分かれ方が、どの幅でも起きないことを確認すること
- `text-balance` は使わないこと（和文見出しで改行が崩れた経緯があるため）
- サイト全体（globals.css等）への適用は今回は行わず、ツールカードに限定すること

## 3. お悩み一覧：ジャンプ用チップを375pxで1行にする

- **sm（640px）未満のときだけ**チップの左右余白（必要ならチップ間の `gap` も）を詰め、375px幅でお悩み一覧の4つのチップ（貯める／リタイアする／受け取る／取り崩す）が1行に収まるようにする
- sm以上の見た目は変更しないこと
- **文字サイズは下げないこと。** 余白の調整だけで375px幅に収まらない場合は、実装を止めて実測値を添えて報告すること
- 調整は `JumpChips` コンポーネント側で行い、ツール一覧のチップにも同じ値が適用されてよい
- 確認する幅：
  - お悩み一覧：375px・360px
  - ツール一覧：375px（1行に収まるかどうか）

  360pxで折り返す場合は、報告のみで対応不要

## 4. コミット計画の提示（まだコミットしないこと）

作業ツリーには、今回の改修とは別に、KENZO自身が行った次の未コミット変更が残っている。

- 指示書13件の `active/` → `done/` 移動
- `active/` 内の画像2件の削除

これらは今回の改修とは**別のコミット**にする方針。今回はコミットを実行せず、完了報告で次の**コミット計画だけ**を提示すること。

- コミット1（`feature/index-pages-polish`）：前回と今回の一覧ページ改修で変更・新設したファイル。**ファイルを個別に指定する**形でリストアップすること。`git add -A` や `git add .` は使わない前提で計画すること
- コミット2：KENZOの `docs/` 移動・削除分と、処理済みの調査指示書・実装指示書の `done/` 移動分。どのブランチにコミットするのが適切か、所感を添えること

コミットとpushは、KENZOがこの計画を確認し、明示的に指示してから行うこと。

## 安全ルール（必ず守ること）

- `localStorage.clear()` などの破壊的操作は行わないこと。どうしても必要な場合は、対象オリジンが検証専用であることを確認し、実施前に報告すること。判別できない場合は操作せず、KENZOに確認を求めること
- devサーバーを停止するときは、ポートからPIDを特定し、そのPIDだけを個別に停止すること。`taskkill /F /IM node.exe` のような全プロセス一括終了コマンドは**使用禁止**
- commit・pushはKENZOの明示的な指示があるまで行わないこと
- `docs/fixes/active/` フォルダ自体は削除しないこと
