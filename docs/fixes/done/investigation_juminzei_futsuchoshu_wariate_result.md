## 1. 特別徴収→普通徴収 切替時の残額割当ルール:サマリー

### 法定ルール(全国共通・地方税法第321条の5第2項が根拠)は「退職月による分岐」のみ
一次情報(大阪市・江東区等、複数自治体の公式ページが揃って地方税法第321条の5を根拠として明示)で確認できたのは以下の**3区分**:

| 退職月 | 扱い | 法的性質 |
|---|---|---|
| **1月1日〜4月30日** | 退職月〜5月分までの残額を**最後の給与・退職金から一括徴収(義務)**。本人の意思にかかわらず強制。 | 全国共通(地方税法第321条の5第2項) |
| **5月1日〜5月31日** | 特別徴収期間(6月〜翌5月)の最終月にあたるため、そもそも残額が5月分の1ヶ月のみ。最後の給与から通常通り特別徴収されて終わるだけで、実質的に「一括徴収」という操作は発生しない。 | 制度設計上自動的にそうなる(1〜4月ルールとは別枠) |
| **6月1日〜12月31日** | 本人からの申出があった場合のみ、残額を最後の給与・退職金から一括徴収可能(任意)。申出がなければ**普通徴収に切り替わり**、後日自治体から納付書が届く。 | 全国共通(地方税法第321条の5第2項) |

※ 自治体ページによって「1月〜4月」「1月〜5月」と説明の切り方に揺れがあるが(江東区は「1月〜5月」とまとめて表記)、これは5月退職が「1〜4月ルールの延長」ではなく「単に残り1ヶ月分を通常通り天引きするだけ」という別の理由で同じ結果になるための表現の違いであり、制度としての矛盾ではない。

### 「普通徴収に切り替わった残額が年4期(6月・8月・10月・翌1月)のどれに・どう配分されるか」は、**一次情報レベルでは確認できなかった**
- 大阪市・江東区・横浜市いずれの公式ページも、普通徴収への切替自体(6〜12月退職で申出がない場合に普通徴収になること)までは明記しているが、**「残額が既存の4期のうちどの期に乗るか」という具体的な按分・割当方法は記載しておらず、いずれも「詳細は窓口へ問い合わせ」という案内で終わっている**。
- 総務省の一次情報(地方税制度ページ)にも、この配分方法を直接規定した記述は見当たらなかった。
- 普通徴収の年4回という納期の枠組み自体は地方税法・同施行令が定める標準的な仕組みだが、**「特別徴収から切り替わった残額を、既存のどの納期にどう乗せるか」は法律で一律の計算式として明文化されているわけではなく、各自治体の賦課実務(システム上の運用)に委ねられている**、というのが一次情報から言える最も正確な結論。
- 民間解説サイト(Boxil等、二次情報)には「残っている納期回数に応じて振り分けられる」という趣旨の記述があったが、これは自治体公式ページや法令で裏付けが取れておらず、**二次情報のみに基づく未確認情報として扱う**。

### 一括徴収の「選択」制度の要件・手続き(6〜12月退職)
- 一括徴収を選択できるのは**退職者本人の申出があった場合のみ**。会社側が一方的に一括徴収を選ぶことはできない。
- 手続きは会社(特別徴収義務者)が市区町村へ「給与所得者異動届出書」を提出する形で行う。この届出書に、本人の意向(一括徴収を希望するか、普通徴収でよいか)を反映させる。
- 最後の給与・退職金の合計額が残税額に満たない場合は、一括徴収を選んでも徴収しきれなかった不足分は普通徴収に回る(この点は1〜4月の強制一括徴収でも同様)。

## 2. 退職月ごとの残額配分の具体例

一次情報(自治体公式ページ)から確認できた範囲のみを示す(**「普通徴収の第何期にいくら乗るか」の精密な数値例は一次情報で裏付けが取れなかったため含めていない**)。

| 退職月 | 特別徴収 | 一括徴収/普通徴収 |
|---|---|---|
| 2月退職(例) | 1月〜2月は通常通り特別徴収 | 2月〜5月分(4ヶ月分)を最後の給与・退職金から**義務として一括徴収**。徴収しきれない場合のみ不足分が普通徴収へ。 |
| 5月退職 | 5月分のみ残っている状態 | 最後の給与から**通常通り1ヶ月分だけ特別徴収**して終了(一括徴収の対象にならない)。 |
| 6月退職・9月退職・12月退職(いずれも6〜12月グループ) | 退職月まで特別徴収 | 本人が申し出れば一括徴収可、申し出なければ**残り月数分(6月退職なら11ヶ月分、12月退職なら5ヶ月分)がまとめて普通徴収に切り替わる**。ただし、この普通徴収税額が年4期(6月・8月・10月・翌1月)のうち未到来の期にどう配分されるかは一次情報で確認できず、自治体ごとの賦課実務による。 |

**結論**: 月ごとに「一括徴収される/されない」「普通徴収に回る残り月数」までは一次情報で正確に再現できるが、「普通徴収の第◯期にいくら」という粒度の期別内訳は、現時点の公開一次情報だけでは全国一律のロジックとして再現できない。

## 3. 退職年所得(波2の課税所得)の正しい合成方法

### ① 退職前給与+退職後給与の合算:**制度上正しい(国税庁一次情報で確認)**
- 国税庁 No.2674「中途就職者の年末調整」により、**年の途中で転職した場合、前職分の給与と再就職後の給与は合算して年末調整(=年間の給与所得)を行う**ことが明記されている。前職の源泉徴収票の提出が前提で、提出できない場合は年末調整ができず本人が確定申告で精算する。
- したがって「退職年の所得 = ①退職前(1月〜退職月)の給与所得 + ②退職後、同一年内に得た給与収入」という合算の理解は制度上正しい。翌年度の住民税(波2)の課税所得は、この合算後の年間所得を基準に計算される。

### ② 賞与(ボーナス)の扱い:「年収÷12×月数」は過大・過小評価のリスクがあり、記事・ツールでの注記が必要
- 給与所得控除・住民税の課税対象は「その年に支払われた給与等の収入金額」の**年間合計**であり、月給と賞与を区別せず合算する。月割りという概念は制度上存在しない(月次の特別徴収額は前年の年税額を単純に12分割しているだけで、賞与から住民税が天引きされることはない)。
- 「退職前年の年収 ÷ 12 × 退職月までの月数」という自動算出は、賞与が特定の月(多くは6月・12月)に偏って支給されるという実態を無視した近似であり、**退職月がボーナス月の前か後かによって実際の所得から大きくズレる**(例:6月に賞与+7月退職なら過小評価、逆に賞与前に退職すれば過大評価)。
- 一次情報でこの近似の妥当性を直接裏付ける記述はない(そもそも国税庁・総務省は「月割り計算」という概念自体を規定していない)。したがって、この点は**制度上の照合ではなく、モデルの単純化の限界として記事・ツール双方に明記する必要がある**、という報告に留まる。

### ③ 給与所得控除の適用単位:**年間ベースが原則(国税庁一次情報で確認)**
- 国税庁 No.1410「給与所得控除」により、給与所得控除額は「給与等の収入金額」(=1年間の合計収入)を基準に、金額に応じた表・計算式で1回だけ算出される。月割り後の金額に個別に給与所得控除を適用するという制度上の仕組みは存在しない。
- `src/lib/tax/`配下の既存実装(`retirement.ts`の`calcResidentTax()`、`ideco.ts`の`calcComprehensiveIncomeTax()`)はいずれも「年間の課税所得金額」を受け取って計算する設計になっており、月割りの概念は一切含まれていない。この点は**既存実装と制度の前提が一致しており、矛盾はない**。
- したがって、新規ツールで「退職前給与+退職後給与」を合算する際も、**合算後の年間収入金額に対して給与所得控除を1回だけ適用する**のが制度上・既存実装との整合性の両面で正しい設計。月ごとに給与所得控除を分割適用するような実装は行うべきではない。

## 5. `currentYearTax.payments[]` / `nextYearTax.taxableIncome` への実装指示反映ポイント

- **`currentYearTax.payments[]`(波1・切替時の残額)**:
  - 退職月から「1〜4月」「5月」「6〜12月」の3区分に応じて、一括徴収・通常特別徴収終了・普通徴収切替のいずれかに分岐させる設計は一次情報で裏付けが取れる。
  - ただし「普通徴収に切り替わった場合の期別内訳(6月/8月/10月/1月のうちどれにいくら)」は一次情報で確認できなかったため、**期別の精密な金額配分をシミュレーションで断定的に表示するのは避けるべき**。実装案としては、「普通徴収切替後の残額合計」までを表示し、期別の内訳は「自治体により異なるため目安」といった注記付きの概算(例:残っている期に均等分割)に留めるか、そもそも期別分割を表示せず合計額のみ表示する設計を推奨。
  - 一括徴収と普通徴収の判定に**本人の意思(申出の有無)という不確定要素が入る**(6〜12月退職の場合)。ツールでは「一括徴収を選んだ場合」「普通徴収のままの場合」の2パターンを切り替えられるUIにするなど、単一の断定的な計算結果にしない設計が必要。

- **`nextYearTax.taxableIncome`(波2・翌年度課税の基準所得)**:
  - 「退職前給与(自動算出) + 退職後の給与収入(入力)」を**合算してから給与所得控除を1回だけ適用する**という計算順序が制度上正しい。現状の設計案(「退職前年の年収÷12×退職月までの月数」で波2の課税所得を自動算出)は、この合算後の金額に対する近似の一部としてなら妥当だが、**賞与の扱いによる誤差が大きくなりうる点を、ツールのUI・記事の両方で明記する必要がある**(例:「賞与を含む年収を単純に月割りしているため、退職時期とボーナス月の関係で実際の税額と差が生じます」等の注記)。
  - 給与所得控除を月割り後の金額に個別適用するロジックは制度上の根拠がなく、既存の`calcResidentTax()`等の年間ベース設計とも矛盾するため、**実装しないこと**を明確な指示として反映すべき。
