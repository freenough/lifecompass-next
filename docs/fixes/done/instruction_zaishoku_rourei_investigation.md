# 指示書:在職老齢年金ロジックの実装状況調査(調査のみ・実装しない)

## 目的

ブログ記事「在職老齢年金(60代で働くと年金はいくら減るか)」執筆のため、
資産シミュレーター側が在職老齢年金(厚生年金の支給停止調整)をモデル化して
いるか、している場合はどの基準額・計算式を使っているかを調査する。

**このセッションはコード変更を一切行わない。調査と報告のみ。**

---

## 前提となる一次情報(必ずこれを基準に照合すること)

以下は日本年金機構・厚生労働省の一次情報で確認済みの事実。コード内の値と
この一次情報を必ず照合し、一致しているか・古いままかを判定すること。
**照合の際、コード内コメントや他サイトの二次情報だけを根拠にせず、
下記の一次情報の数値そのものと突き合わせること。**

- **令和8年度(2026年4月〜)の支給停止調整額は「65万円」**
  出典:日本年金機構「在職老齢年金制度が改正されました」
  https://www.nenkin.go.jp/tokusetsu/zairoukaisei.html
  および日本年金機構「在職老齢年金の計算方法」
  https://www.nenkin.go.jp/service/jukyu/seido/roureinenkin/zaishoku/20150401-01.html
- 参考:令和7年度(2025年度)は51万円、令和6年度以前の法定額は48万円だった
  (令和7年の年金制度改正法により法定額が48万円→62万円に引き上げられ、
  これに賃金スライドが適用されて令和8年度は65万円になった)
- 計算式(日本年金機構の公式定義):
  ```
  支給停止額(月額) = (基本月額 + 総報酬月額相当額 − 支給停止調整額) ÷ 2
  ```
  - 基本月額:加給年金額を除いた老齢厚生年金(報酬比例部分)の月額
  - 総報酬月額相当額:その月の標準報酬月額 +(直近1年間の標準賞与額 ÷ 12)
  - 老齢基礎年金は対象外(在職中でも全額支給される)
  - 基本月額+総報酬月額相当額が65万円以下なら支給停止なし(全額支給)

## 調査項目

1. `financeCore.ts`・`simulate.ts`・年金関連の計算ファイル(ファイル名に
   `pension`が含まれるもの等、心当たりのある箇所を横断的に検索)に、以下の
   いずれかに該当するロジックがあるか
   - 支給停止調整額に相当する定数(48万円/51万円/62万円/65万円など、
     単位に注意して検索。円換算・万円換算どちらの可能性もある)
   - 「基本月額」「総報酬月額相当額」に相当する変数名・計算処理
   - 在職老齢年金・支給停止・pension reduction・zaishoku 等を示唆する
     コメントや関数名
2. 該当ロジックが存在する場合:
   - 使われている基準額は現在いくらか、どのファイルのどの関数/定数か
     (行番号ではなく関数名・定数名で報告)
   - 上記の一次情報(令和8年度=65万円)と一致しているか、古い値
     (51万円・48万円など)のままか、そのギャップを明記
   - 計算式が上記の公式定義と一致しているか(端数処理・老齢基礎年金の
     除外の扱いを含めて)
3. 該当ロジックが存在しない場合:
   - `pension-timing`ツール等の年金額計算は、在職老齢年金による減額を
     考慮せず「満額受給」を前提にしているという理解でよいか、該当コードを
     示した上で確認する
   - 他に年金の「満額」前提を明示的にコメントしている箇所があれば併記

## 報告形式

- 発見有無(あり/なし)
- 該当ファイル名・関数名/定数名(行番号は使わない)
- 発見した場合:現在の基準額の値と、一次情報(65万円)との差分・更新要否
- 発見しなかった場合:その旨と、判断根拠となったコード箇所
- 不明な点・判断に迷った点があれば、断定せずその旨を報告に含める

## 注意事項

- これは調査のみ。コードの変更・修正は一切行わないこと
- ファイルパス・関数名は実在を確認した上で報告し、存在を前提に書かないこと
- 一次情報と食い違う値を発見しても、この調査セッションでは修正しない
  (修正は次の実装フェーズで判断する)
