# 指示書:ライフイベントモーダル 前0バグ 調査

このセッションの役割: 調査のみ。実装はしないこと。原因箇所と、通常入力欄で使われた修正パターンを特定し、報告してください。

## 背景

シミュレーターの通常のパラメータ入力欄(年間手取り収入・年間生活費など)では、数値入力欄に前0が付く問題はすでに解消済み。一方、ライフイベント追加モーダル(「収入」「再雇用」等のイベントタイプを選んで追加する画面)の入力欄では、数値を入力すると前0が付いたまま表示される(例:51歳と入力すると「0051」と表示される)。

添付スクリーンショットの対象画面:

開始年齢:「0051」歳
期間:「023」年
金額:「040」万円/年

## 調査してほしいこと

### バグの再現箇所の特定
- ライフイベント追加モーダルの実装ファイルを特定(LifeEventTimeline.tsxが有力候補と思われるが、モーダル部分が別コンポーネントに分離されている可能性もあるため確認すること)
- 対象の入力欄(開始年齢・期間・金額、他のイベントタイプの入力欄も含む)のstate管理方法・onChangeハンドラの実装を確認

### 通常入力欄での既存修正パターンの特定
- 年間手取り収入・年間生活費等、前0問題がすでに解消済みの入力欄(SimulatorForm.tsxが有力候補)の実装を確認
- どのような修正で解消されたか(例:stateの型、value属性の与え方、onChangeでのパース処理、type="number"かtype="text"か、String(Number(...))のような正規化処理の有無など)を具体的に特定

### 両者の差分の報告
- モーダル側がなぜ同じ修正の恩恵を受けていないのか(実装がそもそも別ロジックになっている/修正時にモーダル側が漏れた、等)を明らかにする
- モーダル内の他の数値入力欄(名称以外の全項目)についても同様の問題が起きていないか確認し、対象範囲をリストアップする

### 修正方針の提案(実装はしないこと)
- 通常入力欄と同じパターンを踏襲できるか、モーダル特有の事情(イベントタイプ切り替え時のフィールド動的表示など)で単純適用できない箇所がないかを含めて、方針案を提示する

## 報告フォーマット
- 該当ファイル・行番号
- 通常入力欄の修正パターン(コード引用可、簡潔に)
- モーダル側の現状の実装(コード引用可、簡潔に)
- 対象入力欄の一覧(モーダル内の全数値欄)
- 修正方針案(1〜2パターン、それぞれの影響範囲)

実装・コミットはしないこと。調査結果をこのチャットに報告し、方針確認を経てから実装指示書を別途作成する。
