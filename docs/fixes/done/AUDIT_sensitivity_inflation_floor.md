# 調査依頼：感度分析パネルのインフレ率Δ下限クランプ

## 背景

感度分析パネルで「インフレ率Δ」スライダーを大きくマイナス方向に動かしても、結果がマイナスインフレ（デフレ）にならない現象をKENZOが確認した。

旧HTML版（STEP29〜STEP35、確認できる範囲すべて）の`drawSens()`関数には、以下の下限クランプが存在することを確認済み：

```javascript
const pS={...p,
  curAge:newCurAge,
  acct:{ ... },
  inflR:Math.max(0,p.inflR+dI),   // ← ここでベースライン+Δを合成し、0%未満にならないようクランプ
  retAge:...,
  penAge:penAge
};
```

また、旧HTML版のスライダー定義（インラインHTML）は以下の通り：

```html
<input type="range" class="sens-slider" id="ssInfl" min="-2" max="3" step="0.5" value="0" oninput="onSensInput()">
```

Δの可動域は固定（-2〜+3）だが、ベースラインのインフレ率（`p.inflR`）はプロファイルごとに変わる可変値のため、ベースラインが低い場合（例：1%）はΔを大きくマイナスにするとクランプが効いてしまい、「スライダーは動くのに結果が変わらない」という状態になる。

**確認したいのは、この仕様がNext.js版にも同じ形で移植されているか**、という点。
