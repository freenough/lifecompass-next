# 実装指示:resident-tax-timing フェーズ2(社会保険料控除・調整控除)+ 前提条件の追加開示

## 背景
`investigation_shakai_hoken_kojo_report.md`(フェーズ1調査)で確定した設計方針に基づき、
社会保険料控除・調整控除を計算パイプラインに追加する。また、給与所得控除の年度対応実装
(前回完了)で新たに意味を持つようになった「退職は今年である」という暗黙の前提を、
フェーズ0と同様にUIで開示する。

## パート1:社会保険料控除の追加

### 設計方針(調査報告書で確定済み)
- 標準ケース:概算料率をデフォルトとする
  - 40歳未満:**14.6%**(厚生年金9.15%+健康保険(全国平均)4.95%+雇用保険0.5%)
  - 40歳以上65歳未満:**15.4%**(上記+介護保険0.81%)
- より正確に試算したいユーザーは、社会保険料**率**を上書きできるようにする
  (固定の年間金額ではなく、**率(%)**で上書きする設計とする。理由:波1・波2で基準となる
  収入額が異なる年になるため、金額の上書きだと一方の波にしか正しく適用できない。
  率であれば両方の波に一貫して適用できる)
- 雇用保険料率(0.5%)は`mhlw.go.jp`ドメインでの一次情報再確認が未実施のまま(調査報告書の
  申し送り事項)。**実装前に、厚生労働省の一次情報で雇用保険料率(令和8年度、一般の事業、
  被保険者負担分)を再確認すること。数値に変更があれば、14.6%/15.4%の合計値を修正すること**

### `residentTaxTiming.ts` への変更
- `ResidentTaxTimingInput`に以下を追加:
  - `isAge40OrOver?: boolean`(デフォルトfalse。trueで15.4%、falseで14.6%をデフォルト料率とする)
  - `socialInsuranceRateOverride?: number`(任意。指定時はこちらを優先。単位は%、例:14.6)
- 収入→課税所得の変換チェーンに社会保険料控除を追加すること:
  `年収 → 給与所得控除 → 給与所得 → 社会保険料控除(年収×料率) → 住民税基礎控除(43万円) → 課税所得`
  (各ステップで個別に0円未満をクランプせず、**最終的な課税所得の算出時に1回だけ
  `Math.max(0, ...)`でクランプする**こと。指示書のこれまでの実装パターンと合わせる)
- 波1・波2の両方に同じ料率(`isAge40OrOver`/`socialInsuranceRateOverride`)を適用すること
- `CurrentYearTax`・`NextYearTax`の型に、実際に使用した社会保険料控除額
  (`socialInsuranceDeductionApplied: number`)を追加し、UIの「計算根拠を見る」で
  内訳として表示できるようにすること

### `ResidentTaxTimingForm.tsx` への変更
- 「より正確に試算する」セクション内に追加:
  - 「40歳以上65歳未満(介護保険料を含む)」チェックボックス
  - 「社会保険料率が分かっている」チェックボックス+料率入力欄(%単位、
    既存の`useRetirementYearOverride`と同じUIパターンで実装すること)

## パート2:調整控除の追加

### 設計方針(調査報告書で確定済み、独身・扶養なし前提での単純化式)
- 課税所得金額が5万円以上200万円以下:**常に2,500円**
- 課税所得金額が200万円超205万円以下:`(50,000 − (課税所得金額 − 2,000,000)) × 0.05`で線形逓減
- 課税所得金額が205万円超:**0円**
- 課税所得金額が5万円未満の場合の扱いは、実装前に総務省または自治体の一次情報で
  再確認すること(調査報告書ではこの下限ケースの明記がなかったため)

### `residentTaxTiming.ts` への変更
- **`calcResidentTax()`本体は改修しないこと(既存の禁止事項を継続)。**
- 代わりに、`calcResidentTax()`の呼び出し結果(所得割)から調整控除を差し引く共通ヘルパー関数
  (例:`calcIncomeTaxPartWithAdjustment(taxableIncome: number): number`)を新設し、
  波1(`calcAnnualResidentTax()`内)・波2(`calcNextYearTax()`内)の両方から呼び出すこと
  (二重実装しないこと)
- 調整控除の適用後、所得割が0円を下回らないよう`Math.max(0, ...)`でクランプすること
- `CurrentYearTax`・`NextYearTax`の型に、適用した調整控除額
  (`adjustmentDeductionApplied: number`)を追加すること

## パート3:「退職は今年」という前提の開示

`ResidentTaxTimingResult.tsx`のフェーズ0で追加済みの前提条件ボックス(独身・扶養家族なし等の
注記)に、以下を追記すること(動的に現在の年を埋め込むこと。ハードコードしないこと):

「本ツールは、退職が今年({現在の年}年)であることを前提に、その時点の税制で試算しています。
実際の退職が翌年以降になる場合、適用される税制(控除額等)が変わり、結果が異なることがあります。」

`{現在の年}`は`calcResidentTaxTiming()`内で既に算出している`retirementYear`相当の値を
そのままUIに渡す形でよい(新たに`Date`を呼び直さず、計算結果から取得すること)。

## 検証要件
- 社会保険料控除・調整控除それぞれについて、Python Decimal等で複数パターン
  (課税所得が200万円前後の境界を含む)を検算し、完了報告書に記載すること
- 40歳未満/以上、料率上書きあり/なしの組み合わせで`verify-resident-tax-timing-tool.js`に
  検証項目を追加すること
- 既存の(社会保険料控除・調整控除を含まない)テストケースへの回帰がないことを確認し、
  むしろ「これらの控除を追加したことで税額がどう変化したか」を完了報告書に明記すること
  (前回の給与所得控除年度対応の時と同様、変化は意図通りであることを示すこと)
- `full-verify.js`全PASS・`tsc --noEmit`エラーなしを確認すること
- ブラウザ実機で、40歳以上チェックボックス・料率上書き・前提条件の注記(現在年が
  正しく埋め込まれているか)を確認すること

  (再確認の結果、数値が同じであれば「確認済み」として実装してよい)
- 調整控除・社会保険料控除の計算ロジックの重複実装(波1・波2で別々の実装を作らないこと)
- `docs/fixes/active/` フォルダの削除
