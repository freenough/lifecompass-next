## 2. `PensionTimingForm.tsx`(入力フォーム、5項目)

spec 5章の通り、以下5項目を実装する:

1. **老齢基礎年金**(65歳時点・年額、万円):数値入力
2. **老齢厚生年金**(65歳時点・年額、万円):数値入力
3. **生年月日区分**:「1962年4月2日以降生まれ」Yes/Noのトグル or ラジオ
   (生年月日ピッカーは実装しない。UIラベルは「1962年4月2日以降生まれですか?」
   のような分かりやすい問いかけ形式にする)
4. **検討中の受給開始年齢**:60〜75歳のセレクト(1歳刻み)。デフォルト値は
   65歳ではなく、**比較の起点となる65歳以外の値**(例:70歳)を初期選択とする
   ことを推奨。理由:65歳をデフォルトにすると、初回表示時に差額・損益分岐が
   両方とも「該当なし」表示になり、ツールの価値が伝わりにくいため
5. **比較終了年齢**:80/85/90/95/100歳のセレクト(デフォルト90歳を推奨。
   簡易生命表における平均的な余命の目安として妥当な水準)

各項目、他ツール(`MonthlyInvestmentForm.tsx`等)と同じ入力コンポーネント・
バリデーションパターンを踏襲すること。

## 3. `PensionTimingResult.tsx`(メイン結果、spec 7章)

### 3.1 見出し結果

`calcPensionAmountAtAge()`を選択年齢(targetAge)・65歳(REFERENCE_AGE)それぞれで
呼び出し、以下を表示:

- 「◯歳から受給すると、年額は◯◯万円になります(65歳受給比◯◯%)」
  (◯◯% = `selectedTotal / referenceTotal * 100`、小数第1位まで)
- **65歳受給との差額**:`selectedTotal - referenceTotal`を「+◯◯万円/年」
  「−◯◯万円/年」の形で表示し、同時に比率差(◯◯%)も併記する
  (例:「+75万円/年(+42%)」)
- 内訳表示:老齢基礎年金・老齢厚生年金それぞれの増減後金額

### 3.2 損益分岐年齢の表示(重要、フェーズ1のJSDoc・spec 6.2節を厳密に反映)

`calcBreakEvenAge()`の戻り値`{ age, foundWithinHorizon }`に応じて、
以下の3パターンを明確に出し分ける:

| ケース | 条件 | 表示 |
|---|---|---|
| 選択年齢が65歳と同一 | `targetAge === 65` | 損益分岐セクション自体を非表示(65歳同士の比較は無意味なため) |
| 比較終了年齢内に交点あり | `foundWithinHorizon === true` | 「◯◯歳まで生きると65歳受給より得になります」 |
| 比較終了年齢内に交点なし | `age === null && foundWithinHorizon === false`(かつtargetAge≠65) | 「比較終了年齢(◯◯歳)内では、65歳受給との逆転は起こりません」 |

**「損益分岐なし」という表現は使わないこと**(spec 6.2節で明示的に禁止。
ユーザーが「比較終了年齢の設定次第で結果が変わる」ことを理解できる文言にする)

## 4. `PensionTimingComparisonTable.tsx`(補助テーブル、spec 7章)

以下の行を表示する比較テーブル:

- 60歳(繰上げ参考値)
- 65歳(原則)
- 選択中の受給開始年齢(ハイライト表示。60・65・75と重複する場合は
  重複行を作らず、該当行に「選択中」ラベルを付与する形にする)
- 75歳(繰下げ参考値)

各行に以下3列を表示:

| 受給開始 | 年額 | (比較終了年齢)までの累計 |
|---|---|---|

累計受給額列は`calcBreakEvenAge()`内部の累計計算ロジックをそのまま利用できる
よう、フェーズ1の関数をUI側から呼び出す際に**各年齢ごとの累計値を取得できる
補助関数が必要になる場合は、`pensionCore.ts`に累計計算用の関数
(例:`calcCumulativeAmount(basicAmount, employeesAmount, targetAge, isNewRate, upToAge)`)
を追加してよい**(フェーズ1のスコープ外だが、UI要件から自然に必要になる
共通ロジックのため、独自再実装ではなく`pensionCore.ts`側への追加として扱う。
UI側での累計計算の再実装は禁止)。

比較終了年齢を変更すると、テーブル全体(累計列)が自動再計算されること
(リアルタイム反映、ページリロード不要)。

## 5. 法務注記(固定文言、4点。spec 7章)

1. 額面ベースの簡易計算であり、在職老齢年金・加給年金・振替加算・税金・
   社会保険料・年金生活者支援給付金・障害年金/遺族年金との調整・企業年金等は
   考慮しない旨
2. 繰上げは老齢基礎・厚生の同時請求が原則である旨(v1スコープの明示)
3. 繰上げは取消不可であり、障害年金請求に制限が生じる等の重要な制約が
   ある旨(実際の判断は年金事務所へ確認するよう案内)
4. インフレ非考慮の注記(第1〜3弾と完全同一の固定文言をそのまま使用)

第1〜3弾と同じ法務注記ブロックのUIコンポーネント・スタイルを踏襲する。
