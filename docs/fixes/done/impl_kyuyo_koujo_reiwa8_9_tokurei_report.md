# 完了報告:給与所得控除テーブルへの令和8・9年分特例(74万円)の年度対応実装

`impl_kyuyo_koujo_reiwa8_9_tokurei.md` の実装完了報告。

## 実装内容

### 1. `calcSalaryIncomeDeduction()` の年度対応化
シグネチャを `calcSalaryIncomeDeduction(incomeYen: number, incomeYear: number): number` に変更し、
3つの年度区分でテーブルを切り替えるようにした。

- **incomeYear <= 2025(令和7年分以前)**: 既存の65万円ベースのロジックをそのまま使用(無変更)。
- **incomeYear === 2026 または 2027(令和8年・9年分)**: 国税庁一次資料(Q3-1①の表)で確認した
  74万円特例テーブルを実装:
  - 74万1,000円未満: `deduction = incomeYen`(所得0円ちょうど。**当初「740,000円固定」で実装したところ、
    収入74万〜74万999円の間だけ所得が1〜999円漏れ出るバグを自己レビューで発見・修正した**。
    詳細は「発見した実装上の注意点」参照)
  - 74万1,000円以上219万1,000円未満: `deduction = 740,000`(固定。所得=収入-74万円と等価)
  - 219万1,000円以上219万3,000円未満: `deduction = incomeYen - 1,451,000`
  - 219万3,000円以上219万6,000円未満: `deduction = incomeYen - 1,453,000`
  - 219万6,000円以上220万円未満: `deduction = incomeYen - 1,456,000`
  - 220万円以上: 既存の速算表(×30%+8万円等)と共通の`calcSalaryIncomeDeductionUpperBrackets()`
    を呼び出す(360万・660万・850万円の区分は令和7年度版と完全に同一であることを、
    前回セッションの調査で確認済み)
- **incomeYear >= 2028(令和10年分以降・未確定)**: 指示書の指示通り、190万円までの区分を
  69万円に据え置く保守的な近似とし、コード内コメントに「一次情報が確認でき次第、正確な
  境界値に修正すること」と明記した。**「204万円」等の未確認の数値はコードに一切使用していない。**

### 2. 波1・波2それぞれで参照する所得年の決定
- `calcResidentTaxTiming()`のトップレベルで`const retirementYear = new Date().getFullYear();`
  を1回だけ算出し、波1・波2の両方に渡す設計にした(指示書で確認済みの「常に今使われる」前提)。
- 波2(`calcNextYearTax`):`retirementYear`をそのまま所得年として使用。
- 波1(`calcCurrentYearTax`):`incomeBasisYearLabel`に応じて
  `incomeYear = usesTwoYearsAgo ? retirementYear - 2 : retirementYear - 1` を算出。

### 3. `calcSalaryDeductionApproxMaxError()` への対応
シグネチャに`incomeYear`を追加し、`incomeYear > 2025`の場合は**区分によらず`null`を返す**
(令和8年分以降のテーブルは所得税法別表第五との照合を行っていないため)。呼び出し元の
`salaryDeductionApproxNote()`は、`null`の場合「所得税法別表第五との誤差は令和7年分のテーブルの
み検証済みで、この年分については未検証です」という注記に切り替える(具体的な金額を示す
既存の注記を、未検証の年度については出さないようにした)。

## 発見した実装上の注意点(自己レビューで発見・修正済み)

74万1,000円未満の区分を当初「`deduction = 740,000`固定」で実装したところ、収入74万〜74万999円
(999円幅)の間だけ所得が1〜999円の端数で漏れ出る(所得が厳密に0円にならない)バグがあることに、
`verify-resident-tax-timing-tool.js`実行時の自己チェックで気づいた。国税庁の表は「74万1,000円未満は
所得0円」と明記しているため、`deduction = incomeYen`(収入金額そのもの)に修正し、所得が厳密に
0円になるようにした。影響額は最大999円(住民税ベースで最大約100円)ときわめて小さいが、
一次情報の表を正確に再現するため修正した。

## 令和7年分の既存計算結果への影響(回帰確認)

**波1は完全に無影響。** 本セッションの実行時点(2026年8月)では`retirementYear=2026`となり、
波1の所得基準年は「前々年=2024年」または「退職前年=2025年」のいずれかで、両方とも
`incomeYear <= 2025`の既存ロジック(無変更)に該当する。MATRIXの12パターンで
`currentYearTax.remainingAmount`が一つも変化していないことを確認済み。

**波2は「今年(2026年)」が令和8年分特例テーブルの対象になったため、意図通り変化した。**
既存のMATRIX検証データのうち、400万円・5月退職の1パターンのみ数値が変わった
(月割り推計所得が74万〜220万円の範囲に該当したため):

| ケース | 修正前(常に65万円テーブル) | 修正後(2026年分は74万円テーブル) |
|---|---|---|
| 400万円・5月退職(波2合計) | 63,600円 | **54,600円** |

他の11パターンはいずれも「月割り推計所得が既に0円にfloorされる低所得帯」または
「220万円を上回り上位区分の速算表が令和7年度版と共通のため無影響」のいずれかに該当し、
数値は変化していない。この変化は**バグではなく、今回の実装が正しく機能している証拠**である。

## 令和10年分(2028年)以降が未実装であることの明記

**指示書の指示通り、令和10年分(2028年)以降の正確な給与所得控除テーブルは実装していない。**
理由:69万円が恒久的な最低保障額になることは確認済みだが、フラット部分の正確な上限額
(200万円台のどこか)について、本セッションでは一次情報の裏付けが取れなかったため
(前回の`investigation_kyuyo_koujo_reiwa8_taiou_report.md`のグラフから概算した「204万円」は、
今回のセッションでは一次情報で再確認できておらず、指示書の禁止事項によりコードに書き込んで
いない)。暫定措置として、上限額を令和7年度版と同じ190万円のまま据え置く保守的な近似を実装し、
コード内コメントに「一次情報が確認でき次第、正確な境界値に修正すること」と明記した。
2028年以降に本ツールを実際に使うユーザーが出てくる前に、正確な境界値の一次情報確認と
修正を行う必要がある。
