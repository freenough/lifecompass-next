# StickyKpiBar.tsx:「FIRE達成」を「FIRE安全度」の新デザインに追従させる

## 背景

`kpi_grid_redesign.md`の実装で、通常のKPIグリッド(`KpiGrid.tsx`)の「FIRE達成」カードは「FIRE安全度」に置き換えられ、以下の内容になった。

- 達成時:メイン「{年齢}歳で達成」、サブ「FIRE達成後最低充足率 {%}」
- 未達成時:メイン「未達成」、サブ「退職後最低充足率 {%}」
- 3段階色分け(`minRatio >= 100`緑 / `80〜100`黄 / `80未満`赤)

しかしモバイル用スティッキーKPIバー(`StickyKpiBar.tsx`)は、旧来の「FIRE達成」表示(達成=緑/未達成=黄の2段階、`fA`の二値判定ベース)のまま追従していない。資産寿命のときと同様、同じ画面内で通常のKPIカードとスティッキーバーの表示・色が食い違う状態になっている。

## 実装したい変更

`StickyKpiBar.tsx`内の「FIRE達成」表示を「FIRE安全度」に置き換え、`KpiGrid.tsx`と同じロジック・同じ表示形式にする。

- タイトルを「FIRE達成」から「FIRE安全度」に変更する
- 表示内容を、達成時「{fA}歳で達成」、未達成時「未達成」に変更する(スティッキーバーはスペースが限られるため、サブテキスト「FIRE達成後最低充足率/退職後最低充足率 {%}」は省略し、メイン表示のみにする、あるいは既存のスティッキーバーの情報密度に合わせて適宜調整してよい。この判断はStickyKpiBarの既存デザイン(他の指標がどの程度の情報量で表示されているか)に合わせること)
- 色分けを`minRatio`ベースの3段階(緑/黄/赤)に変更する

## 共通化の方針

前回の資産寿命対応(`sticky_kpi_bar_asset_longevity_sync.md`)で、`src/lib/kpi-thresholds.ts`に閾値判定の共通関数(`assetLongevityVariant`)を作成した実績がある。今回も同様に、**FIRE安全度の色分けロジック(`minRatio`から`good`/`warn`/`danger`を返す関数)を`kpi-thresholds.ts`に追加し、`KpiGrid.tsx`と`StickyKpiBar.tsx`の両方から参照する形にすること**。閾値ロジックの複製は行わないこと。

- 関数名は`fireSafetyVariant(minRatio: number | null): 'good' | 'warn' | 'danger'`のような形を想定(既存の命名規則に合わせて調整してよい)
- 現在`KpiGrid.tsx`側にこの色分けロジックが直接書かれている場合は、そちらもこの共通関数を呼び出す形にリファクタリングすること(`KpiGrid.tsx`側のロジックだけ残った状態を避けるため)

## 動作確認したいポイント

- モバイル幅で、通常のKPIカードとスティッキーバーの両方に「FIRE安全度」が表示される状況を作り、達成/未達成それぞれで表示内容・色が一致することを確認する
- 3段階(緑/黄/赤)それぞれのケースで両者が一致することを確認する(黄色のケース:`minRatio`が80〜99%程度になるフィクスチャまたは入力調整で再現する)
