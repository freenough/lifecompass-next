# 指示書: CLAUDE.md への設計原則追記

作成日: 2026-08-03
このチャットの役割: 企画・意思決定 / 実行: Claude Code

## 背景

前回セッション(topics/primaryTopicフィールド調査 → ブログフィルタ再設計 → 関連負債解消)で
確定した設計原則が、このチャットのメモリにのみ記録されており、`CLAUDE.md`に反映されていない。
`CLAUDE.md`は過去セッションで一貫して「プロジェクト全体の原則・よくある間違い」を集約する
場所として参照されてきたため、今回確定した原則もここに追記する。

またあわせて、retirement-taxツールが本体シミュレーターと別の税額計算ロジックを使っている
という設計判断も、まだ明文化されていなければ追記する(実装者が誤って統合しようとするのを防ぐため)。

さらに、CLAUDE.mdの「アーキテクチャ」セクションにあるFIRE達成年齢の定義が旧仕様のまま
残っている(下記「作業内容3」参照)ため、あわせて修正する。

## 作業内容

1. リポジトリ(`lifecompass-next`)の`CLAUDE.md`を開き、既存の構成・見出しレベルを確認する
2. 「設計原則(2026-08-03追加)」セクションを、既存の「UI刷新フェーズの設計原則(Phase 3)」の後・
   「セッション管理」の前に、独立した`##`見出しとして新規挿入する
   (シミュレーター本体のアーキテクチャ/検証ルールと、ブログ・ツールのコンテンツ層の話が
   混在しないようにするため)。以下の内容を追記する:

```markdown
## 設計原則(2026-08-03追加)

### category軸とtopics軸は別役割・安易に統合しない
- `category`:記事の制作形式を表すブランド軸(表示用バッジ)
- `topics`:記事の主題を表すスコアリング・フィルタ用の軸
- 見た目が似ていても、統合・置換すると意味の異なる2つの分類が壊れるため注意

### 表示用途への転用はfrontmatter非変更が基本
- スコアリング専用データ(frontmatterのtopics等)に表示用の意味を持たせたい場合、
  frontmatter自体は変更せず、コード側のマッピングテーブル(例:`blogTopics.ts`の
  `TOPIC_GROUPS`)で対応する

### エンティティ属性は単体で切り出さない
- 「このエンティティのこの属性だけ共通化する」は避ける(同じエンティティのメタデータが
  複数箇所に分散する構造を新たに生むため)
- 共有ファイルに切り出す単位は「エンティティ全体」(例:ツールなら`TOOLS`配列そのもの
  を`toolMetadata.ts`に集約、属性だけの抜き出しはしない)

### 表記統一は定数化までワンセットで行う
- 同じ文言が複数箇所にハードコードされている問題を見つけたら、値を揃えるだけでなく
  定数化(例:`siteCopy.ts`)まで行い再発防止する
- ただし対象範囲は実害が確認された箇所に限定し、「ついでに全体を集約する」提案には
  慎重に線を引く(スコープの肥大化を避ける)

### retirement-taxツールは意図的な別実装
- `retirement-tax`ツールは本体シミュレーター(`simulate.ts`/`analyze.ts`)とは別の
  税額計算ロジック(`src/lib/tax/retirement.ts`)を使用している
- これはバグや統合漏れではなく意図的な設計判断。本体ロジックへの統合を提案・実施しない
- 記事内でこの実装差について言及しない方針(コンテンツ制作上の注意点)
```

3. 既に同趣旨の記述(特にretirement-taxの別実装について)がCLAUDE.md内に存在しないか
   事前に`grep`で確認し、重複があれば追記をスキップしてこのチャットに報告する

4. **FIRE達成年齢の定義を修正する(旧仕様の記述が残っているため)**
   - 「アーキテクチャ」セクション内、現在以下のようになっている箇所を修正対象とする:

     > FIRE達成年齢には3つの定義がある:①最低限(積立期最終値 >= 支出×25)②最速
     > (取崩期に90歳まで資産>0)③安心(取崩期に生涯資産 >= 支出×25)。

   - これを以下の単一定義に置き換える:

     > FIRE達成年齢 = 総資産が「生活費×25」を上回り、以後生涯その水準を一度も
     > 下回らない最初の年齢(生涯維持条件。瞬間的な到達ではない)。

   - `findFireAge()`(または現行実装の該当関数)の実装が実際にこの単一定義通りに
     なっているか、修正前に必ずコードで確認する。もし実装が①②③のいずれか(特に
     旧定義)のままだった場合は、ドキュメントだけ書き換えず、実装とドキュメントが
     一致しない旨をこのチャットに報告し、コード修正の要否を確認してから進める
     (ドキュメント修正のみ先行させない)
   - この項目は他の3項目とは性質が異なる(新設ではなく既存記述の修正)ため、
     完了報告でも分けて明記する

5. `full-verify.js`など既存の検証スクリプトへの影響はないはずだが、
   ドキュメントのみの変更であることを完了報告に明記する

## 完了報告に含めるべき内容

- 追記した見出し・行番号ではなく**セクション名**で報告(行番号は使わない)
- 重複チェックの結果(重複ありでスキップした場合はその旨)
- FIRE達成年齢について:実装(`findFireAge()`等)が単一定義通りだったか、
  それとも実装とドキュメントに乖離があったか(乖離があった場合は詳細)
- コミット・pushは行わず、差分のみ提示してこのチャットの確認を待つ
