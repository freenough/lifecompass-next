## 前提

本機能は`simulate.ts`(ロックファイル)への変更を伴う、承認済みの例外対応
である。Product Spec確定版の内容を正確に実装すること。疑義がある場合は
実装を進めず、報告すること。

## 実装タスク

### 1. 型定義追加

`SimParams`型(`src/lib/types.ts`等、実際の定義箇所)に以下を追加:

```typescript
retirementSurplusReinvest?: boolean;
```

- 既存の`mcStdDynamic?`等と同じoptionalパターンに揃える
- デフォルト値は`false`(フィールド欠落時のfalsy評価に依存する設計のため、
  明示的なデフォルト代入処理が別途必要な箇所があれば、そこも`false`にする)

### 2. `simulate.ts`:黒字処理ロジックの変更

既存の黒字処理分岐(`if (surplus >= 0) { cash += surplus; }`相当。実際の
変数名・行番号は現行コードに合わせること)を、Product Spec 4.1章の仕様に
従って変更する:

- 条件を`surplus > 0`に変更(`=== 0`のケースは何もしない)
- `retirementSurplusReinvest`が`false`または未設定の場合は、従来通り
  `cash += surplus`のみ(分岐追加によって既存動作が変化しないこと)
- `retirementSurplusReinvest === true`かつ`surplus > 0`の場合:
  - `p.spouse`が存在しない場合:按分計算を行わず、`surplus`全額を
    `tax`・`taxCostBasis`に加算
  - `p.spouse`が存在する場合:Product Spec 4.2章の定義に従い、その年の
    本人収入・配偶者収入を再計算し、按分比率を算出、`tax`/`taxCostBasis`・
    `spTax`/`spTaxCostBasis`にそれぞれ加算

### 3. 按分比率計算ロジックの実装

- `income`変数の構築ロジック(給与・年金・収入イベント・iDeCo年金受取の
  税引後手取り額)を参考に、本人分・配偶者分を分離して算出する関数または
  インラインロジックを実装する
- 退職金(`severanceGross`/`spSeveranceGross`)・iDeCo一時金は対象外とする
- 収入イベントは`owner`フィールドで判別し、`owner`が未設定の場合は本人扱いとする
  - 実装前に、現行のイベントデータ構造で`owner`が実際に100%付与されているか
    (未設定ケースが存在しうるか)を確認し、完了報告に記載すること
- 按分比率の計算は**その年ごとに独立して行う**こと。前年の比率をキャッシュ・
  保持して使い回してはならない
- 本人・配偶者の収入合計が0の場合は50:50にフォールバックする

### 4. costBasis更新の実装

黒字加算と同時に、加算した額と同額を`taxCostBasis`(本人)・`spTaxCostBasis`
(配偶者、対象時)にも加算する。既存の積立期拠出処理(`tax += taxConEff*ratio;
taxCostBasis += taxConEff*ratio;`)と同じパターンを踏襲する。

### 5. 処理順序の確認

既存の黒字処理分岐が置かれている位置(Growth適用・各種税計算後、surplus算出後)
に変更をそのまま挿入し、処理順序自体は変更しないこと。

## 検証スクリプト(`scripts/verify-retirement-surplus-reinvestment.js`新規作成)

以下のテストケースを実装し、`full-verify.js`へ組み込むこと:

1. **境界値**
   - 黒字ちょうど0円:`retirementSurplusReinvest=true`でも按分処理が
     走らず、従来動作(この場合cashにも加算されない、収支トントン)と一致すること
   - 本人収入のみ(配偶者収入0、配偶者は存在する):按分が100:0になること
   - 配偶者収入のみ(本人収入0):按分が0:100になること
   - 両者収入0(配偶者は存在する):50:50フォールバックになること
   - 配偶者が存在しない場合:按分計算がスキップされ、全額本人へ加算されること

2. **代表ケース**
   - 本人年金300万・配偶者年金100万・支出300万 → 黒字100万が75万:25万に
     按分されること

3. **iDeCo年金受取ケース**
   - iDeCo年金形式受取中の年で、按分比率にiDeCo年金税引後額が正しく
     合流していること(本人・配偶者それぞれ)

4. **costBasisラウンドトリップ検証**
   - 黒字加算後、数年後に取崩が発生した際の課税額が、黒字加算前(仮に
     機能OFFだった場合)と比べて過大になっていないこと(黒字分が誤って
     含み益として課税されていないことの確認)

5. **按分比率の年次再計算テスト(最重要)**
   - 1年目:本人年金300万・配偶者年金100万(黒字→75:25)
   - 2年目:本人年金100万・配偶者年金300万に変化(例:配偶者のみ繰下げ
     受給等の設定)
   - 2年目の按分が25:75になっていることを確認する(初年度の比率を
     固定・使い回すバグが混入していないことの検証)

6. **回帰テスト(最重要)**
   - `retirementSurplusReinvest`が未設定(またはfalse)の場合、既存の
     全テストケース・田中/山本/中村3キャラクターの数値が、本機能実装前と
     完全に一致すること

境界値・代表ケース・ランダムケースを含め、既存の検証スクリプト(例:
`verify-pension-timing.js`)と同水準の網羅性(100件超のランダムケース含む)
を目安とする。
