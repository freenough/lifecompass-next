## タスク1:ヘッダー/モバイルメニューへの「使い方ガイド」追加(実装可・GO確認済み)

### 背景
現在のグローバルナビ(デスクトップヘッダー)は「シミュレーター/ブログ/ツール/Note」の4項目。
`/guide`(使い方ガイド)への導線がヘッダーになく、フッターのみに存在する。
初見でシミュレーターに圧倒された人が最初に必要とするコンテンツである可能性が高いため、
ヘッダーに5項目目として追加する方針が確定した。

### やること

1. **調査**:該当コンポーネントを特定する
   - デスクトップヘッダーのナビ項目を定義しているファイル(`Header.tsx`等)
   - モバイル用ハンバーガーメニューの実装コンポーネント(デスクトップヘッダーと項目が
     同期しているか、別管理か)
   - 現在ハンバーガーメニュー内に「使い方ガイド」が含まれていないことを確認
     (含まれていた場合はこのタスクの前提が崩れるため、その場合は実装せず報告のみ)

2. **実装**:
   - デスクトップヘッダーに5項目目として「使い方ガイド」を追加(`/guide`へのリンク)
   - 配置順は「シミュレーター/ツール/ブログ/使い方ガイド/Note」を基本案とするが、
     既存コンポーネントの実装しやすさを優先してよい(大きく変える必要はない)
   - モバイルハンバーガーメニューにも同じ項目を同期して追加
   - LifeCompassという開発コードネームが混入していないかgrep確認(既存ルール通り)

3. **確認**:
   - デスクトップ・モバイル両方の実機(またはPlaywright、ただしスクロールバー幅の
     既知の環境差に注意)で表示確認
   - `full-verify.js`実行、0件失敗を確認

### 完了報告に含めること
- 変更したファイルパス・コンポーネント名
- ナビ項目の最終順序
- 実機確認方法(実ブラウザ/Playwrightどちらで確認したか)

## タスク2:ブログ・Toolsのタグ実態調査(調査のみ・コード変更禁止)

### 背景
前回調査で、ブログには`category`(2値、記事同士の関連表示に使用中)と`tags`
(11/13記事に存在するが未使用)フィールドがあることが判明した。Tools側には
タグ相当のメタデータが存在しない。今後「ブログ⇄Tools横断の関連コンテンツ表示」を
実装するための共通タクソノミー設計を、この調査結果をもとに別途行う。
**タグ設計そのものは今回のスコープ外。実データの洗い出しのみ行う。**

### やること

1. **ブログ13記事の`category`・`tags`の実値を全件一覧化する**
   - frontmatterから`category`・`tags`(存在する場合)の値をそのまま抽出
   - `tags`が存在しない2記事のスラッグ・タイトルを明記
   - `category`に使われている2値が具体的に何かを明記

2. **関連記事コンポーネントの現在のマッチングロジックを詳細に確認する**
   - `category`一致で絞り込んでいるのか、`tags`は本当に一切参照していないのか
   - コンポーネントの型定義(interface/type)を確認し、`tags`フィールドが
     型として既に存在するか、frontmatter上にだけ値があってコード側の型には
     ないのか(この場合は改修範囲が変わるため重要)
   - 表示件数の上限・ソート順(新しい順、関連度順等)も確認

3. **Toolsページの型定義・メタデータ構造を確認する**
   - 7ツールの実装(`page.tsx`または設定ファイル)に、テーマ分類に転用できそうな
     既存フィールド(ツール名・扱う制度名の定数など)がないか
   - 新規に`tags`または`topics`フィールドを追加する場合、7ツール分の型定義・
     データ定義がどのファイルに集約されているか(1箇所か、ツールごとに分散しているか)

4. **改修規模の再評価**
   - 前回レポートで「中」と評価した改修規模について、型定義まで確認した上で
     見積もりをアップデートする(小/中/大の再判定+理由)

### 成果物
- `docs/investigation/tag_taxonomy_investigation.md`として格納
- 13記事分の`category`/`tags`実値の一覧表を含めること
- コードは一切変更しない

## タスク4:孤立2ツール(`retirement-tax`・`ideco-withdrawal`)のブログリンク調査(調査のみ)

### 背景
前回調査で、`retirement-tax`(退職金課税シミュレーター)と`ideco-withdrawal`
(iDeCo受取シミュレーター)の2ツールが、13本のブログ記事のどこからも
リンクされていないことが判明した。

**方針**:自然に文脈が合う既存記事があればリンク追加(コンテンツ編集のみ)、
無理に繋がる記事がない場合はリンクを追加せず、将来記事の企画候補として
保留する(既存の「アフィリエイトは自然な文脈がある場合のみ挿入」という
運営方針を内部リンクにも適用する)。

### やること

1. **13記事全ての本文テーマを簡潔に確認する**(既存タイトル・リード文レベルで可)

2. **`retirement-tax`(退職金課税)と関連しそうな記事を判定する**
   - 退職金・退職所得控除・iDeCo一時金受取との合算課税等に触れている記事があるか
   - あれば記事名・該当箇所(見出しレベルで可)を報告

3. **`ideco-withdrawal`(iDeCo受取シミュレーション)と関連しそうな記事を判定する**
   - `ideco-nisa`記事は積立時のiDeCo/NISA比較が主眼のため、受取時の話に
     自然に繋げられそうか確認する(繋げられない場合は無理にリンクしない)
   - 他に受取・取り崩しをテーマにした記事(`withdrawal-strategy-comparison`等)との
     文脈適合性も確認する

4. **判定結果を報告する**(この段階では実装しない)
   - 各ツールについて「自然に繋がる記事あり(記事名・箇所)」または
     「自然に繋がる記事なし(将来記事の候補として保留)」のいずれかを明記
   - 「あり」と判定した組み合わせについては、次回の実装指示書でリンク追加を行う

### 成果物
- タスク2と同じ`docs/investigation/`配下、または同ファイルに追記
- コードは一切変更しない(判定結果の報告のみ)
