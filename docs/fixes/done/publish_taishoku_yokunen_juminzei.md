# 実装指示:「退職後の住民税はいくら?」ブログ記事の公開

## 目的
記事`taishoku-yokunen-juminzei.md`(このファイルと同じ場所にアップロード済み)を、
既存のブログ記事と同じ構成・検証フローで公開する。画像3点(アイキャッチ1枚+本文中図版2枚、
いずれも添付済み)も合わせて配置すること。

## 添付ファイル
- `taishoku-yokunen-juminzei.md`(記事本文、Markdown)

## 作業内容

### 1. frontmatterの確定
記事冒頭のコメント欄に仮のfrontmatterを記載しているが、実際のブログ記事のスキーマ
(既存記事、特に直近の在職老齢年金記事を参考にすること)に合わせて正式なfrontmatter
形式に変換すること。以下の項目について、既存の設計原則に従って判断すること:

- `category`:「シミュレーター活用」(本記事の数値は全て`resident-tax-timing`ツールの
  本番出力であり、独自再現の要素はゼロのため。既存の判定基準
  ─「記事の核となる数値が本番シミュレーター/ツール実出力由来か」─ にそのまま合致する)
- `topics`/`primaryTopic`:`src/lib/blogTopics.ts`の`TOPIC_GROUPS`を確認し、
  在職老齢年金記事(直近の類似テーマ記事)がどのグループに分類されているかを参考にしつつ、
  最も適切なグループを選定すること。判断に迷う場合は、選定理由と共に完了報告書に
  記載し、KENZOさんの確認を仰ぐこと
- `stages`:退職前後のステージに該当する既存のタグ付けパターンに合わせること
- `slug`:`taishoku-yokunen-juminzei`を仮で使用しているが、既存記事のslug命名規則
  (英語スラッグの付け方)に沿っているか確認し、問題があれば調整すること

### 2. 画像の配置
- `src/lib/blog.ts`または既存記事の画像配置パターン(直近の在職老齢年金記事を参照)に
  従い、3枚の画像を適切なディレクトリに配置すること
- ファイル名は、既存の命名規則(`{slug}-eyecatch.png`等)に合わせて調整すること
  (現在の`eyecatch-juminzei-taimurag.png`等は仮の名前)

### 3. 内部リンクの確認
- 本文中の2箇所のツールリンク(`/asset-simulator/tools/resident-tax-timing?utm_source=blog&utm_medium=referral&utm_campaign=resident_tax_timing_blog`)について、
  `applyBasePathToHtml()`が正しく`/asset-simulator`のbasePathを適用するか確認すること
  (既知のバグ:`href`に対してbasePathが適用されないケースがあることが過去に判明している。
  本記事の公開時に同じ問題が再発していないか、実機で必ずクリックして確認すること)
- UTMパラメータの命名規則(`utm_source=blog&utm_medium=referral&utm_campaign={topic}_blog`)
  が正しく適用されているか確認すること

### 4. 関連記事セクションについて
- テンプレートの方針通り、本文末尾に手動の「関連記事」セクションを追加していないことを
  確認すること(サイト側で自動生成されるため、手動追加すると重複表示になる)

### 5. concerns.ts への追記チェック
- 公開チェックリストの一環として、`src/data/concerns.ts`内に本記事のテーマ(退職後の
  住民税)に対応する既存のconcernカードがあれば、`articleUrl`の追加が必要か確認すること
  (該当する項目が現状なければ、対応不要)

## 検証要件(公開前チェックリスト、`blog_article_template.md`のチェックリストに準拠)
- [ ] TL;DR(この記事の結論)がリード文の直後にあるか
- [ ] 本文中盤・終盤にツールへのCTAがあるか(現状2箇所)
- [ ] FAQが3〜5個、簡潔な回答で配置されているか(現状4問)
- [ ] 使用した数値がすべて本番ツールの実出力からの引用であること(記事内に手計算・
  独自再現の数値が混入していないか、`resident_tax_timing_article_data.md`と
  照合して再確認すること)
- [ ] 「です・ます調」で統一されているか
- [ ] 経験者的な言い切り表現になっていないか、断定表現には試算条件が明示されているか
- [ ] アイキャッチ画像が1536×1024px(3:2)であるか(作成済み、配置時に再確認)
- [ ] 図版の主要数値が実データと一致しているか(作成済み・確認済みだが、配置後に
  表示崩れがないか再確認すること)
- [ ] `full-verify.js`が全PASSであること(記事追加が既存の検証に影響しないことの確認)

## 完了報告書に含めるべき内容
- frontmatterで判断に迷った項目(特に`topics`/`primaryTopic`)とその理由
- 内部リンクのbasePath適用の実機確認結果

- チェックリストの充足状況

## 禁止事項

  書き換えないこと)
- 本文末尾への手動の関連記事セクション追加
- `docs/fixes/active/` フォルダの削除
