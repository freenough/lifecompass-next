# 実装指示書:配偶者「退職所得税(合計)」へのiDeCo年金税混入(二重計上)の修正

**種別:実装含む(調査は完了済み。本ファイルの内容で実装してよい)**
**背景:** 調査の結果、`simulate.ts`内の「Spouse iDeCo pension payout」ブロックに、`spRetirementTaxPaid += spPensionTax`という行が残っており、これがStage Aで新規追加された`spIdecoTaxPaid += spPensionTax`と並存していることが原因と判明。同じ配偶者の年金税(`spPensionTax`)が「退職所得税(合計)」用の集計(`spRetirementTaxPaid`)と「iDeCo(手取り)」用の集計(`spIdecoTaxPaid`)の両方に二重計上されていた。本人側は`idecoTaxPaid`(年金税)と`retirementTaxPaid`(一時金税のみ)が元々分離されており、対称性が崩れていたのは配偶者側のみ。

---

## 修正内容

1. `simulate.ts`の「Spouse iDeCo pension payout」ブロックから、`spRetirementTaxPaid += spPensionTax`の1行を削除する。
2. `spIdecoTaxPaid += spPensionTax`はそのまま残す(iDeCo(手取り)カードの累計課税額用として正しい集計)。
3. 修正後、`spRetirementTaxKPI`(退職所得税カード用)は「配偶者の一時金税(severance税+iDeCo一時金税)」のみを合算した値になり、本人側の`idecoLumpTax`と対称になることを確認する。

---

## 確認してほしい副次的な論点

`showSpouseRetirement`(配偶者の退職所得税内訳行を表示するかどうかの判定)が、修正前は`spRetirementTaxKPI`の非ゼロ判定を経由して、実質的に「配偶者が年金受取でも(誤って混入した年金税のおかげで)内訳行が表示される」という副作用に依存していた可能性がある。修正後、**配偶者が年金受取のみ(一時金なし)の場合に、退職所得税カードの配偶者内訳行が意図せず非表示にならないか**を確認すること。

- 期待される正しい挙動:配偶者が年金受取のみの場合、退職所得税カード自体(または配偶者の内訳行)は表示されない(退職所得税は一時金系にのみ発生する概念のため、これは正しい)。
- 万一、退職金イベントがあるのに配偶者の内訳行が表示されなくなるような副作用が出た場合は、`showSpouseRetirement`の判定条件自体を見直すこと(`spIdecoSelfNet`や退職金イベントの有無等、他の条件で正しく判定されるようにする)。
