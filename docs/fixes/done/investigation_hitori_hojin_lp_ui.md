# 調査指示：一人法人LP（`/hitori-hojin`）のUI見直しに向けた現状調査

作成日：2026-09-24
種別：**調査のみ（コード・ファイル・ブランチへの変更は一切禁止）**
対象リポジトリ：`lifecompass-next`
対象ページ：一人法人LP（本番URL `https://www.freenough.com/hitori-hojin`）

---

## 背景

本体（資産シミュレーター側）では、お悩み一覧・ツール一覧・ブログ一覧の改修で、見出し・カード・文言・禁則の基準をそろえた。一人法人LPは、この基準から外れている箇所が多い。

- 記事カード：アイコンとテキストの間の空白が大きい、角丸が4pxでない、シェブロンがない、同じセクション内のアイコンが全件同じ
- 2列グリッドで、件数が奇数のため右下が空く
- タイトル・説明文で禁則が効いていない改行がある（「何が変わっ／た？」など）
- 導入文の1行が長い（60字超）
- ボタン文言（「資産シミュレーターで試算する →」）や「無料・登録不要・データは端末内に保存」が、本体の統一後の表記と異なる、または直書き
- セクション見出しの作りが、本体LPの「───」線の見出しと異なる

今回は、本体の基準を一人法人LPへ当てはめる実装指示書を書くために、**現状の構造と、本体側で作った共通コンポーネントをそのまま使えるか**を調べる。Heroのデザインの方向性（合算図・タイポグラフィ）は今回の対象外で、別途検討する。

---

## 0. 開始時・終了時の状態確認（必須）

調査の開始時と終了時に次を実行し、出力をそのまま報告に貼ること。

```
git status
git branch --show-current
```

- 開始時に未commitの変更があった場合は、中身に触れず、ファイル名だけを報告すること
- 終了時の出力が開始時と完全に一致していることを確認すること
- 本指示書自体が未追跡ファイルとして出るのは想定どおり

---

## 1. 所在・配信の仕組み・構成

1. 一人法人LPのルートファイル（`page.tsx` 等）のパスと、`/hitori-hojin` 配下のルート構成（LP・ブログ一覧・記事詳細など）
2. `basePath: '/asset-simulator'` の下で、`/hitori-hojin` がどういう仕組みで配信されているか（rewrites・別のルートグループ・`freenough-main` 側からの転送など）。`next.config` 等の該当部分の抜粋
3. ページを上から順に、セクションごとに対応するコンポーネントとファイルパスを一覧にする
   - ヘッダー／Hero／導入文／「一人法人を知る」／「一人法人を考える」／「すべての記事を見る →」／「法人の資産も、FIREの進捗に。」ブロック／下部CTA（「一人法人を考える前に…」）／フッター
4. 一人法人側のレイアウト（ヘッダー「FREENOUGH｜一人法人」・フッター）が、資産シミュレーター側のレイアウトとどう分かれているか
5. 各コンポーネントが、LP以外のページ（一人法人ブログ一覧・記事詳細、資産シミュレーター側のページ）でも使われているか
6. 上記コンポーネントのうち、ロックファイルに当たるもの

## 2. 記事カードのデータと描画

1. 「知る」「考える」に並ぶ記事が、どこで定義されているか（手動の配列か、ブログのデータから自動抽出か）。定義ファイルのパスと、該当部分の抜粋
2. 各セクションの件数（現状3件・5件）が固定か、記事の追加で変わるか
3. カードの各要素がどのデータ項目から来ているか（タイトル・説明文・アイコン・リンク先）
4. アイコンの決まり方（セクションごとに固定か、記事ごとに持っているか）
5. リンクの作り方（`next/link` か `<a>` か、相対パスか `HITORI_HOJIN_SITE_URL` 等の絶対URLか）

## 3. 現状のスタイルの実測値

開発サーバーで表示し、DevToolsの計算済みスタイル（computed style）で次を実測する。**1440px・768px・375px** の3幅で測ること。

| 対象 | 測る項目 |
|---|---|
| ページ全体 | 本文コンテナの最大幅と左右の余白（本体 `Container` の値：1440pxで左168px、768px・375pxで24px と比較） |
| Hero | h1のfont-size・font-weight・color、説明文のmax-width・font-size・1行の文字数 |
| 導入文 | max-width、font-size、line-height、1行のおよその文字数 |
| セクション見出し | 要素（h2か等）、font-size、color、配置（中央寄せ等）、サブタイトルの要素とcolor |
| 記事カード | grid-template-columns、gap、padding、border-radius、border、shadow、ホバー時の変化、アイコン列の幅とアイコン〜テキスト間の距離、タイトル・説明文のfont-size・color、`line-break` の指定の有無 |
| 「すべての記事を見る →」 | 要素、font-size、color、ホバー時の変化 |
| 法人資産ブロック | カード全体とボタンのborder-radius、ボタン文言、注記文言 |
| 下部CTA | 説明文のmax-width、ボタンのborder-radius、ボタン文言 |

あわせて、ページ内の見出しの階層（h1〜h3の並び）を一覧にすること。

## 5. 本体側の共通コンポーネントを使えるか

次のコンポーネント・定数について、一人法人LPでそのまま使えるかを判断する材料を集める。

- `Container`・`SectionRule`・`SectionHeading`・`ListSectionHeading`・`PageHeader`・`Breadcrumb`・`JumpChips`
- ツール一覧のカード（lg以上：アイコン左・テキスト中央・シェブロン右の横並び／lg未満：説明文を全幅）
- `concernCtaLabels.ts`（`CONCERN_CTA_LABELS`）
- `featuredPosts.ts` と、ブログ一覧サイドバーの番号付きリスト

調べること：

1. 一人法人側に、上記と**同等の役割を持つ別のコンポーネント**がすでにあるか（あればファイルパスと、本体側との違い）
2. 上記コンポーネントの中に、資産シミュレーター側に固有の前提が入っていないか
   - 例：`Breadcrumb` の起点が「資産シミュレーター」に固定されている、リンクが `next/link` でbasePathの影響を受ける、`@theme` トークンが一人法人側のページで効かない等
3. 一人法人側のページで、本体側と同じフォント・`globals.css`・`@theme` トークンが読み込まれているか

**判断（そのまま使うか、引数を増やすか、別に作るか）は報告しなくてよい。** 材料だけを事実として並べること。
