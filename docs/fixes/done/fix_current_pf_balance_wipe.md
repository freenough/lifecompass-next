## 1. 症状（KENZOの報告・スクリーンショット2枚）

- 入力欄に、NISA 1,700／iDeCo 1,200／特定口座 6,000／現金 2,000（総資産 10,900万円）を入れる。
- 「運用方針・リスク」の「① 現在のPF」で、どれかの口座の「+ 追加」を押す（NISAでもiDeCoでも同じ）。
- **NISA・iDeCo・特定口座の残高が全部0になり、総資産が2,000万円（現金だけ）になる。**

## 2. 原因（コードを読んで特定済み）

### 2-1. 本体：`src/store/simulatorStore.ts` の `updatePortfolio`（195〜201行目）

```ts
if (phase === 'current') {
  paramPatch.bNisa  = cur.nisa.reduce((s, r) => s + (r.amount ?? 0), 0);
  paramPatch.bIdeco = cur.ideco.reduce(...);
  paramPatch.bTax   = cur.tax.reduce(...);
}
```

編集した口座だけでなく、**3口座すべての残高を、PFの保有銘柄の合計で上書きする。** PFが空の口座は合計0になり、入力欄の残高が消える。現金はPFの対象外なので残る。

### 2-2. 同じ作りのバグ：`updateSpousePortfolio`（215〜229行目）

`spNisaBal / spIdecoBal / spTaxBal` を、3口座ぶん毎回PFの合計で上書きしている。配偶者の資産を入れて配偶者のPFを触ると、同じ現象が起きるはず。

### 2-3. 直すと現れる副作用：`src/lib/profile.ts` の `getAggregateWeights`（270〜281行目）

```ts
const bNisa = totalCur > 0 ? bNisaCur : p.bNisa;   // 3口座まとめて判定
```

3口座の「PF合計の総和」が0より大きいと、**3口座とも**PFの合計を使い、0より大きくなければ**3口座とも**`p.b*`を使う。PFが1口座だけ入っている状態（今回の修正で到達できるようになる）だと、PFが空の口座の重みが0になり、σの全口座集計（`calcAggregateSigma`）から外れる。**口座ごとの判定に直す**（commit 1に含める）。

### 2-4. 計算経路の確認結果（commit 2の仕様の根拠）

- **μ（期待リターン）は、「① 現在のPF」の行から計算していない。** `getEffectiveRW`／`getEffectiveRR` が `calcMu` に渡すのは、`portfolio.working`／`portfolio.retirement`（**割合%の行**）だけ。`current`（金額の行）は`calcMu`・`calcPortfolioMetrics`に渡らない。
- **`current`の`assetClass`を読むのは、`copyCurrentToWorking`（265〜306行目）だけ。** 金額の比率を`working`の割合にコピーしている。
- `calcMu`は未知の`assetClass`を `?? 0` でμ0%として計算する（`profile.ts:70`）。**空文字`''`が`working`に紛れ込むと、μ0%の資産として入ってしまう。** だから、未選択行を`working`へコピーさせない（commit 2の仕様）。
- `getUnconfiguredAccounts`・`getCryptoManualWarnings` が見るのは`working`／`retirement`の行だけ。未選択行の影響を受けない。
- 入力欄の残高（`SimulatorForm.tsx:445/453/461`）は `up({ bNisa: v })` で`params`だけを変え、PFの行は触らない。

## 3. commit 1：残高が消えるバグの修正（未選択値には依存させない）

### 仕様

| 項目 | 方針 |
|---|---|
| 本人 | 編集した口座の残高**だけ**を更新する。ほかの2口座は触らない |
| PFが空の口座 | **既存の残高を維持する**。行が0本のとき、その口座の`b*`は更新しない |
| PFに行がある口座 | 従来どおり、その口座の`amount`合計を`b*`に入れる（行が1本以上あれば、合計0でも反映） |
| 配偶者 | 本人と同じ。`spNisa→spNisaBal`、`spIdeco→spIdecoBal`、`spTax→spTaxBal`を、編集した口座だけ |
| `getAggregateWeights` | **口座ごとに**、PFの行が1本以上あればPFの合計、なければ`p.b*` |
| `copyCurrentToWorking` | 変更なし（すでに`>0`のときだけ`params`を更新している） |
| `importPersonalAssets` | 変更なし（一括上書きは仕様） |

### 注意

- commit 1だけだと、空の口座で最初の「+ 追加」を押した時点で**その口座（1つだけ）**の残高が0になる（0万円の行ができるため）。ほかの口座は消えない。これはcommit 2の初期金額で解消する。**だから、デプロイは2つのcommitをそろえてから。**
- 口座を表す対応（`nisa→bNisa`など）は、定数のマップにして、本人と配偶者の2か所で重複して書かない。

## 4. commit 2：未選択行と、最初の追加時の初期金額

### 仕様

1. **`assetClass: ''` を「未選択」と定義する**（`profile.ts`に定数を1つ。例：`UNSELECTED_ASSET_CLASS = ''`）。型は`string`のまま。
2. **対象は「① 現在のPF」（金額の行）だけ。** 本人・配偶者の両方。`working`／`retirement`（割合の行）の「+ 追加」は、これまでどおり（`全世界株`、割合0）。変えない。
3. **「+ 追加」を押したときの新しい行**：`{ assetClass: '', pct: 0, amount: X }`
   - その口座の行が0本のとき、`X`＝その口座の現在の残高（`params.bNisa`など。配偶者は`spNisaBal`など）。
   - すでに行があるとき、`X`＝0。
   - 銘柄を自動で決めない（「全世界株 1,700万円」にしない）。
4. **`<select>` に「銘柄を選択」（value=""）を足す**（`PortfolioPanel.tsx`の81〜89行目と、配偶者側の同じ部分）。未選択のときは文字色を薄くするなど、選択済みと見分けられるようにする（色は3色以内の原則を守る）。
5. **未選択行は、金額の合計には入れる**（実際のお金だから）。入っていない扱いになるのは、銘柄（μ）だけ。
6. **`copyCurrentToWorking` のガード**：ある口座の行のうち、`amount > 0`で`assetClass === ''`の行が1本でもあれば、**その口座は`working`へコピーしない**（`working`の既存の行は、そのまま残す）。
   - 理由：未選択行を除いて比率を再計算すると、選択済みの銘柄の割合が過大になる。`''`のままコピーすると、`calcMu`がμ0%として計算する。どちらも、利用者の意図と違う結果になる。
   - コピーしなかった口座があることを、**画面で利用者に伝える**（既存のメッセージの出し方に合わせる。ボタンの呼び出し側を確認して、最小限で）。文言の例：「NISAは未選択の銘柄があるため、積立期の配分にはコピーしませんでした」。
   - 残高の同期（`b*`）は、これまでどおり。
7. **μを0%として扱う経路を作らない。** `calcMu`・`calcPortfolioMetrics`は変更しない。`working`／`retirement`の行に`''`が入らないことを、確認項目で確かめる。

### 実装前に、読んで確かめること（第1段階の報告に含める）

- `assetClass`の型と、`<select>`の選択肢（`ASSET_CLASSES`）の網羅性。`''`以外に、未知の値が入りうる経路はあるか。
- `copyCurrentToWorking`の呼び出し元（ボタン）と、既存のメッセージ表示の仕組み。
- `src/lib/importFromAssetManagementPersonal.ts`：資産管理ツール側の銘柄を`assetClass`に変換するとき、対応がない銘柄が`''`などになる経路があるか。
- `src/lib/storage.ts`：`''`を含む行を保存・読み込みしたときの挙動（読み込み時の補完・検証が`''`を弾かないか）。
- 古い保存データ（行が全世界株で入っている）が、そのまま読み込めること。

## 5. 確認項目

再現の数値：NISA 1,700／iDeCo 1,200／特定口座 6,000／現金 2,000（総資産 10,900万円）。

### commit 1

1. 本人のNISAの「+ 追加」を押しても、iDeCo・特定口座・現金の残高が変わらない。iDeCo・特定口座でも同様。
2. 配偶者側でも、同じ操作で、ほかの口座が変わらない。
3. PFが空の口座の残高が維持される（PFのどの口座も触らなければ、10,900のまま）。
4. すでにPFが登録済みの口座は、従来どおり編集でき、残高が合計に追従する。
5. PFが1口座だけの状態で、σの全口座集計（`getAggregateWeights`）が、PFが空の口座の`p.b*`も重みに含める。
6. 総資産合計・シミュレーション結果が、不要に変わらない（PFを触らなければ、変更前と一致）。

### commit 2

7. 空の口座で最初の「+ 追加」を押すと、銘柄は「未選択」、金額はその口座の残高（NISAなら1,700）。合計・総資産が変わらない。
8. 2本目の「+ 追加」は、銘柄は未選択、金額は0。
9. 未選択の行が混ざる口座は、`copyCurrentToWorking`でコピーされず、`working`の既存の行が変わらない。画面にその旨が出る。選択済みの口座だけの場合は、従来どおりコピーされる。
10. `working`／`retirement`の行に、`''`が入っていない（コピー後に確認）。`getEffectiveRW`・`getEffectiveRR`・σが、未選択行の有無で変わらない。
11. 保存→読み込みで、未選択の行が`''`のまま復元される。古い保存データも読み込める。
12. 資産管理ツールからのインポートが、これまでどおり動く（インポート後は未選択行が残らない、または残る場合の挙動が仕様どおり）。
