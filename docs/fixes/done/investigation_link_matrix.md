# 調査指示書:サイト内部リンク構造マトリクス調査(investigation-only)

作成日:2026-08-01
種別:**調査のみ。コード変更は一切行わない。**

---

## 背景・目的

FREENOUGHは以下のコンテンツ群で構成されている:
- LP(トップページ、`freenough-main`リポジトリ)
- 資産シミュレーター本体(`lifecompass-next`、`/asset-simulator`配下)
- Tools(7種、`/asset-simulator/tools/`配下)
- ブログ記事(13本、`/asset-simulator/blog/`配下)
- note.com連載小説(4シリーズ、外部サイト。サイト側からnoteへのリンクのみ調査対象)
- 静的ページ(guide, methodology, about, disclosure, privacy-policy, disclaimer)

これらの間の内部リンク(相互導線)がどこまで実装済みで、どこが欠けているかを
**マトリクス形式で可視化**したい。企画チャット側(この指示書の発注元)で、
今後どこに何のリンクを足すかを判断する材料にする。

**今回はコードを一切変更しない。調査結果をレポートとしてまとめるのみ。**

---

## 対象リポジトリ

1. `freenough-main`(LP本体、独自のブログ/ツール実装なし)
2. `lifecompass-next`(シミュレーター・Tools 7種・ブログ13本、すべて`/asset-simulator`配下)

両方のリポジトリを横断して調査すること。

---

## 調査項目

### A. ノードごとの発リンク(outbound link)の洗い出し

以下の各ノードについて、**他ノードへの内部リンクが実装されているか**を
ファイル・コンポーネント単位でgrep/読み込みして確認する。

#### A-1. LP(freenough-main)
- トップページ本体(`src/app/page.tsx`等)からのリンク一覧
- `Header.tsx`のナビゲーションリンク一覧
- `Footer.tsx`のリンク一覧
- キャラクターカード(田中誠・山本恒一・中村夫婦・佐々木誠一)の`href`設定状況
  (どれが実リンク済みで、どれが「近日公開」のプレースホルダーか)

#### A-2. シミュレーター本体(lifecompass-next)
- `src/app/simulator/page.tsx`および配下コンポーネントからの外部/内部リンク
  (Tools一覧・ブログ・guide・methodology等への言及があるか)
- 特に「Toolsへの逆導線」(高機能に迷った人向けの簡易ツールへの案内)が
  存在するか

#### A-3. Tools(7種:monthly-investment / fire-age / compound /
   pension-timing / retirement-tax / ideco-withdrawal / education-cost)
- `/asset-simulator/tools/`一覧ページの実装有無・内容
  (現状カード羅列か、カテゴリ分けされているか)
- 各ツールページの共通CTAコンポーネント(シミュレーターへのリンク・
  アフィリエイトリンク)の実装箇所
- 各ツールから**ブログ記事への**リンクが存在するか(現状ゼロと想定されるため
  重点確認)
- ツール同士の相互リンク(関連ツール表示)が存在するか

#### A-4. ブログ(13記事)
- ブログ一覧ページ・各記事ページの構造
- 「関連記事」自動生成コンポーネントの実装箇所と**マッチングロジック**
  (カテゴリ一致?タグ一致?手動指定?ブログ記事同士のみが対象か、
  他のコンテンツ種別〈Tools等〉も対象にできる設計になっているか)
- 各記事のfrontmatterで使われているフィールド一覧
  (`category`・`tags`・`topics`相当のものがあるか、あれば実際の値も一覧化)
- 各記事から**Toolsへの**リンクが何本あるか(記事9本目以外にあるか)
- 各記事からnote該当シリーズへのリンク有無

#### A-5. 静的ページ
- `guide`・`methodology`・`about`・`disclosure`ページから
  シミュレーター/Tools/ブログへのリンク有無

#### A-6. note(外部サイトのため、サイト側→note方向のみ)
- サイト内(LP・ブログ・シミュレーター)からnote.comへのリンク箇所を
  全リポジトリ横断でgrep(`freenough.com`ではなく`note.com`文字列で検索)

### B. マトリクスの作成

Aの調査結果を、以下の形式でMarkdown表にまとめる。

```
| From ＼ To | シミュレーター | Tools一覧/個別 | ブログ一覧/個別 | note | 静的ページ |
|---|---|---|---|---|---|
| LP | ○/△/✗ + 実装箇所 | ... | ... | ... | ... |
| シミュレーター | - | ... | ... | ... | ... |
| Tools | ... | ... | ... | ... | ... |
| ブログ | ... | ... | ... | ... | ... |
```

各セルには:
- `○`(実装済み)/`△`(部分的・条件付き)/`✗`(未実装)
- 実装箇所(コンポーネント名・ファイルパス。行番号は変動するため不要)
- `△`の場合は「何が部分的か」を一言で

---

### C. タグ/トピック設計への転用可否の調査

将来的に「共通トピックタグ(例:nisa, ideco, pension, withdrawal等)による
コンテンツ横断の関連リンク」を導入したいと考えている。そのための前提調査:

1. ブログのfrontmatterに`category`や`tags`に相当するフィールドが
   既に存在するか。存在する場合、13記事それぞれの値を一覧化する
2. Toolsの各ページ(または設定ファイル)に、テーマ分類に使えそうな
   メタデータ(例:ツール名・扱う制度)が既にあるか
3. 現在の「関連記事」コンポーネントは、新しいフィールド(`topics`配列など)を
   追加した場合、どの程度の改修で「ブログ記事だけでなくTools/他コンテンツも
   対象にした関連コンテンツ表示」に拡張できそうか。改修規模の所感を
   (小/中/大)で評価してコメントする
