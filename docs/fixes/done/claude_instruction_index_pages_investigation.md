# 指示書: お悩み一覧・ツール一覧・ブログ一覧の幅統一と細部改修に向けた事前調査

## 種別

**調査専用**。コード変更・ファイル作成（報告以外）・git commit/push は一切行わないこと。

## 背景

`/asset-simulator` 配下の3つの一覧ページについて、以下の改修を予定している。

- お悩み一覧ページ（「お悩み一覧」）
- ツール一覧ページ（「かんたん計算ツール」）
- ブログ一覧ページ（「ブログ」）

改修は2段階でリリースする予定。

- **段階A**: 左右の外側余白をLPと完全一致させる。あわせて、ページ見出し部分の共通コンポーネント化と、画面上に見えるパンくずリストを追加する
- **段階B**: 各ページの細部改修（下記「予定している改修内容」参照）

本調査では、段階A・Bの実装指示書を書くために必要な事実を一度に洗い出す。

ブログ一覧ページは、段階Aの項目（幅・ページ見出し・パンくず）のみ調査対象とする。ブログ一覧は別途、メイン一覧＋注目記事サイドバー構成への再設計（段階C）を予定している。そのため、段階Aの実装をブログにも同時適用するか、段階Cとあわせて行うかは、本調査の結果を見て決める。段階Bの細部改修はブログ一覧には適用しない。

## 予定している改修内容（調査の前提。まだ実装しない）

### 段階A（3ページ共通）

- 外側コンテナを、LPで使っている `Container`（`paddingX="default"`）と同一にする。px値の直書きで合わせるのではなく、同じコンポーネントを使う
- ページタイトル＋説明文の部分を共通の `PageHeader` 的なコンポーネントにまとめる（既存の類似コンポーネントがあれば流用）
- 画面上に見えるパンくずリストを追加する

### 段階B: お悩み一覧

- カード内ボタンの文言を、行き先が分かる形に統一する。現在は「60秒で試算する」と「詳しく試算する」が混在している。かんたん計算ツール行きは「かんたんツールで試算」、シミュレーター本体行きは「シミュレーターで試算」とする
- ステージ見出し（貯める／リタイアする 等）をLPのセクション見出し様式（「─── ラベル」形式）に揃える
- ページ上部に、各ステージセクションへのジャンプ用チップを置く
- カードの角丸を4px（サイト共通値）にする
- 列数は2列のまま

### 段階B: ツール一覧

- カードのレイアウトを変える。現在の縦積み（アイコン→タイトル→説明文）から、**横並び（アイコン左・テキスト右）**にする。アイコンは現在の線アイコンをそのまま使い、背景の正方形などは付けない
- カード右端にシェブロン（›）を置く（スマホでも押せると分かる手がかりとして）
- 説明文を `line-clamp-2` で2行に揃える
- ホバー時の浮き上がりエフェクトを現状より強くする
- ページ上部に、各カテゴリセクションへのジャンプ用チップを置く
- カードの角丸を4px（サイト共通値）にする
- 列数は2列のまま

## 調査項目

### 1. ロックファイル・LP共有コンポーネントへの影響（最優先）

`concerns.ts`・`ConcernCard.tsx` はロックファイルで、原則変更禁止。以下を確認すること。

- お悩み一覧ページのカード描画に使われているコンポーネントとデータソースのファイル名。`ConcernCard.tsx`／`concerns.ts` を使っているかどうか
- ボタン文言（「60秒で試算する」「詳しく試算する」）と「詳しく読む→」が、どのファイルのどこで定義されているか（データ側か、コンポーネント側か）
- カードの角丸・枠・余白のクラスが、どのファイルで定義されているか
- **LPの「お悩み」セクションと、お悩み一覧ページが同じコンポーネントを共有しているか**。共有している場合は、段階Bの変更がLPに波及する範囲を具体的に列挙すること
- 上記の改修を、ロックファイルに触れずに実現できる方法があるか（ラッパー・props追加・一覧ページ専用コンポーネント等）の所感。**実装はしない**
- ツール一覧についても同様に確認すること。カード描画のコンポーネント名、LPの「かんたん計算ツール」セクションとの共有有無、ツール定義データの所在

### 2. 幅・コンテナ（段階A）

- LPで使っている `Container` コンポーネントのファイル名と、`paddingX` の選択肢と実際の値
- 3ページの現在の外側コンテナの実装（`Container` を使っているか、独自の `max-w-*`／`px-*` か）
- 1440px幅で、LP・お悩み一覧・ツール一覧・ブログ一覧それぞれのコンテンツ左端x座標の実測値（px）
- ブログ一覧のコンテナをLP幅に広げた場合に、現在の横長記事カード（左サムネイル＋右テキスト）の見た目がどう変わるかの所感（1440pxでの1行あたりの文字数の目安など）。**実装はしない**
- ブログ一覧ページが `blog.ts`（ロックファイル）以外のどのファイルで描画されているか。段階Aの変更が `blog.ts` に触れずに済むかどうか

### 3. ページ見出し・パンくず（段階A）

- 3ページのタイトル＋説明文部分の現在の実装。共通化されているか、ページごとの直書きか
- 既存の `PageHeader` 的コンポーネントがサイト内にあるか（ブログ・使い方ガイド等で使われていないか）
- 画面表示用のパンくずコンポーネントが既に存在するか
- BreadcrumbList構造化データ（JSON-LD）が、この3ページで出力されているかどうか。出力されている場合は、表示用パンくずとデータを共有できる構造かどうか

### 4. セクション見出し様式（段階B）

- LPの「─── ラベル／見出し」形式のセクション見出しが、共通コンポーネント化されているか。されていればファイル名とpropsを報告すること
- 一覧ページのステージ見出し・カテゴリ見出しの現在の実装

### 5. ジャンプ用チップ（段階B）

- 2ページのセクション一覧（お悩み：ステージ名とカード件数、ツール：カテゴリ名とカード件数）
- 各セクション見出しに、現在 `id` 属性が付いているか
- 固定ヘッダーの高さ（px）。アンカー移動時に見出しがヘッダーの下に隠れないための `scroll-margin-top` 値を決めるため
- サイト内に、チップ型UIの既存コンポーネントがあるか（ブログ一覧のフィルターチップ等）。あれば流用可否の所感を報告すること

### 6. ツールカードのレイアウト・ホバー（段階B）

- ツールカードの現在のクラス構成（padding、アイコンサイズ、タイトル／説明文のフォントサイズ、カード全体がリンクかどうか）
- 現在のホバーエフェクトの実値（translateY量、box-shadow値、transition時間）。LPのCTAボタンやツールカードのホバーと同じ定義を共有しているかどうか
- 全ツールのタイトル一覧と、1440px幅での最長タイトルの描画幅（px）

### 7. 現状スクリーンショット

3ページそれぞれについて、以下の幅でファーストビューを撮影すること。

- 375px
- 768px
- 1440px

LPトップも1440pxで1枚撮影すること（左端整列の比較用）。

## 検証環境の安全ルール（必ず守ること）

- `localStorage.clear()` などの破壊的操作は行わないこと。どうしても必要な場合は、対象オリジンが検証専用であることを確認し、実施前に報告すること。判別できない場合は操作せず、KENZOに確認を求めること
- devサーバーを停止するときは、ポートからPIDを特定し、そのPIDだけを個別に停止すること（`taskkill /F /PID <番号>` 等）。`taskkill /F /IM node.exe` のような全プロセス一括終了コマンドは**使用禁止**
- この指示書を `done/` へ移動するのは構わないが、`docs/fixes/active/` フォルダ自体は削除しないこと

- 項目1のLP波及範囲と、ロックファイル回避策の所感は必ず含めること
- 実測値（px）は、測定した幅と測定方法を併記すること
- **完了報告にローカルファイルパスは一切含めないこと。** 確認用のスクリーンショットは、すべてチャットにインライン表示するか、Artifact機能で共有すること
- 「確認した」「問題なし」とテキストで結論だけ述べるのは不可。スクリーンショットと実測値を実際に提示すること
- コード変更・commit・pushは行わないこと
