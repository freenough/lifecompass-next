---

## 全体像

ヘッダーに検索アイコンを追加し、クリックでモーダルが開き、ブログ記事・ツール・固定ページを
横断検索できるようにする。検索は完全クライアントサイド(Fuse.js)で、ビルド時にRoute
Handlerで生成したJSONインデックスをfetchして使う。

---

## 1. 検索インデックスの生成

### 1-1. 固定ページ一覧の拡張

`src/app/sitemap.ts` の `STATIC_PATHS` を `{path, title}` 形式に拡張する。

対象は以下7件のみ(調査報告に基づき確定済み。それ以外の固定ページは含めない):

| path | title |
|---|---|
| `/guide` | 使い方ガイド |
| `/methodology` | 計算ロジック・前提 |
| `/disclosure` | 広告・アフィリエイトに関する開示 |
| `/privacy-policy` | プライバシーポリシー |
| `/disclaimer` | 免責事項 |
| `/about` | 運営者情報 |
| `/concerns` | お悩み一覧 |

※ `/blog` `/tools` は一覧ページのため対象外(個別記事・個別ツールが別途インデックスされるため重複回避)。
※ `/` `/app` は固有のtitle/descriptionを持たないため対象外。
※ `/disclosure/old` は既存のsitemap除外方針を踏襲し対象外。

`sitemap.ts` の既存の呼び出し元(sitemap.xml生成ロジック)が壊れないよう、型変更の影響範囲を
確認してから変更すること。`STATIC_PATHS` の構造を変える場合、既存の`.map()`等の参照箇所も
合わせて修正が必要になる可能性がある。

### 1-2. Route Handlerの新規作成

`src/app/search-index.json/route.ts` を新規作成。既存の `rss.xml/route.ts` と同じ規約
(`request`引数や`cookies()`等の動的APIを使わず、ビルド時に静的レンダリングされる形)で、
`NextResponse.json(...)` を返す `GET()` ハンドラとする。

統合するデータソースと正規化後の型:

```typescript
type SearchIndexItem = {
  type: 'blog' | 'tool' | 'page';
  title: string;
  description: string;
  url: string; // basePathを含めない相対パス(既存コンポーネントの慣習と統一)
  category?: string;
  keywords: string[];
};
```

各データソースからの変換ルール:

- **ブログ記事**(`getAllPosts()`由来):`title`/`description`(またはexcerpt)/`slug`から
  `url`を組み立て/`category`/`keywords: topics`をそのままマッピング
- **ツール**(`TOOLS`配列由来):`title`/`description`/`href`を`url`に/`category`は未設定
  (ツールに既存の`category`フィールドがなければ省略)/`keywords: topics`。
  **`Icon`フィールドは含めない**(JSON化不可のため。クライアント側で`slug`をキーに`TOOLS`配列
  から再解決する設計は1-4節で扱う)
- **固定ページ**(1-1で拡張した`STATIC_PATHS`由来):`title`をそのまま/`description`は
  存在しないため空文字/`category`なし/`keywords: []`

## 3. 検索モーダルコンポーネントの新規作成

`src/components/search/SearchModal.tsx` を新規作成。

### 3-1. データ取得とFuse.js設定

- モーダルが開いたタイミングで `withBasePath('/search-index.json')` を`fetch()`し、
  取得したJSON配列をFuse.jsに渡す(`withBasePath()`は`src/lib/siteConfig.ts`の既存ヘルパーを
  使用。fetchはLink/ImageのbasePath自動付与の対象外のため必須)
- Fuse.js設定:

```typescript
const fuse = new Fuse(items, {
  keys: [
    { name: 'title', weight: 0.7 },
    { name: 'keywords', weight: 0.2 },
    { name: 'description', weight: 0.1 },
  ],
  threshold: 0.4, // 初期値。閾値の厳密なチューニングはこの指示書のスコープ外
  includeScore: true,
});
```

### 3-2. 結果の表示ロジック

- 検索クエリが空文字の場合:
  - LocalStorageから最近の検索履歴(検索実行時に保存したクエリ文字列、最大5件程度)を
    「最近の検索」として表示
  - 履歴が空の場合、`getAllPosts()`結果のうち`featured: true`の記事と、`TOOLS`配列の主要
    ツール数件(全件でも可、7件程度なら全件表示で問題ない)を「注目」として表示
- 検索クエリが入力されている場合:
  - Fuse.jsの検索結果を`type`別にグルーピングする(**フラットな関連度順一本化ではなく、
    グルーピング表示**。この決定はこのチャットで確定済み、変更しないこと)
  - グループの表示順序は **ツール → ブログ → ページ** の固定順(該当件数が0件のグループは
    見出しごと非表示)
  - 各グループ内はFuse.jsのスコア順(関連度順)でソート
  - グループ見出しのスタイルは、`src/app/tools/page.tsx`・`src/app/concerns/page.tsx`で
    使われている既存パターン(`text-lg font-semibold text-slate-700 mb-4`)と統一する。
    **バッジ/pill形状は使わない**(調査の結果、記事1件単位のタグ用途とリストのグルーピング
    見出し用途は別物と判断したため)
  - `type: 'tool'`の結果には、`TOOLS`配列から`slug`(またはurlの一致)で該当ツールを
    引き当て、`tool.Icon`をタイトル横に表示する(`size={20}`程度、`@tabler/icons-react`の
    既存使用パターンに準拠)
  - `type: 'blog'`/`type: 'page'`の結果にはアイコンを付けない

### 3-3. キーボード操作

- `Esc`:モーダルを閉じる
- `↑`/`↓`:結果リスト内でフォーカス移動(グループを跨いでの移動も含む)
- `Enter`:フォーカス中の結果へ遷移(`next/link`でbasePath自動付与、既存コンポーネントと
  同じ書き方でhrefにbasePathを含めない)

### 3-3-1. 結果行のホバー/フォーカス状態

- マウスホバー時、および`↑`/`↓`キーでのフォーカス移動時の両方で、結果行の背景に
  `var(--surface-1)`相当の薄いグレーを付ける(claude.aiのCDSトークン相当。プロジェクト内で
  既存のCSS変数命名がある場合はそちらに合わせる。なければ`bg-slate-50`等、サイトの既存
  グレースケールに準じたTailwindクラスで代替してよい)
- キーボードフォーカス中の行には、右端に軽いヒントテキスト(例:「Enterで開く」)を
  `text-xs text-slate-400`程度の目立たない見た目で表示する(必須ではないが、あれば
  キーボード操作の発見性が上がる)
- マウスホバーとキーボードフォーカスは同じスタイルを共有してよい(状態管理を分けて
  二重にスタイル定義する必要はない)

### 3-4. 背景オーバーレイ

- モーダルが開いている間、背景を暗くするオーバーレイ(scrim)を表示する
- 参考にしたプロファイル管理ドロワー(STEP系プロトタイプ)にはこの時点でオーバーレイの
  実装が確認できなかったため、**実装前に本番の`lifecompass-next`側で該当パターン
  (プロファイル管理ドロワー、または他のモーダル・ドロワー系UI)に実際にオーバーレイが
  存在するか確認すること**。存在する場合は同じ色・不透明度・実装方法(CSS変数があれば
  それ)に揃える。存在しない場合は`rgba(0,0,0,0.4)`程度を新規に採用してよい
- オーバーレイクリックでもモーダルを閉じられるようにする(`Esc`と合わせて2通りの
  閉じ方を用意)

### 3-5. 検索実行時のLocalStorage保存

- ユーザーが結果をクリック(または`Enter`で遷移)したタイミングで、そのときの検索クエリ文字列を
  LocalStorageの履歴に追加(重複は末尾に移動、最大5件を超えたら古いものから削除)

## 4. ヘッダーへのボタン追加

`src/components/layout/Header.tsx` を編集。

- `IconSearch`(`@tabler/icons-react`)を使った検索ボタンを追加。設置位置はPC/モバイル
  共通でハンバーガーボタンと横並び(モバイルでは`IconMenu2`/`IconX`の隣)
- 開閉状態は既存のハンバーガーメニューの`useState<boolean>(open)`とは**独立した**別の
  `useState`で管理すること(3-2までで触れた通り、干渉しない設計とする)
- クリックで`SearchModal`を開く
- ボタン自体の状態変化は、STEP系プロトタイプの`.prof-btn`(プロファイル管理呼び出しボタン)と
  同じ2段階パターンを踏襲する:
  - ホバー時:`var(--bg2)`相当の薄いグレー背景(プロジェクト内の対応するCSS変数、なければ
    `bg-slate-100`等で代替)
  - モーダルが開いている間(active状態):薄い青系の背景(`#E6F1FB`)+ 青系のボーダー
    (`#92BCF0`)+ 青系のアイコン色(`#0C447C`)。モーダルを閉じたら通常状態に戻す
  - 「ホバー」と「開いている間」は別状態として扱う(開いている間にマウスが離れても
    青系の表示を維持すること)
