# 調査指示：資産管理ツール「実績記録（スナップショット履歴）」機能の現状確認

作成日：2026-08-31
種別：**調査のみ（実装・修正は一切行わない）**
関連：`NEXT_CHAT_PROMPT_phase2_yojitsu.md`（引き継ぎ、2.1節）／`phase2_design_proposal_draft.md`（フェーズ2設計仕様v2）

---

## 背景

フェーズ2の次の課題は「シミュレーションの予測カーブを『計画』として保存し、資産管理ツール側の実績と重ねて予実差を追える」機能の設計。しかしこの前提として、資産管理ツール側に「保有資産の“今の値”だけでなく、“過去のある時点の値”を記録・参照できる機能」が実際に存在するかどうかが、一度も実物で確認されていない。

設計資料上は、`AssetSnapshot`/`HojinAssetSnapshot`という型が既に存在し、`profileId`フィールドを持つことが記録されている。また別セッションの作業ログでは、CSV履歴機能（`YYYYMM`形式）やスナップショット上限300件への引き上げが実装されたとの記述もある。ただし、これらが実際に「ユーザーが月次で実績を記録し、後から時系列で参照できる」という体験として機能しているかどうかは未検証。**このタスクは、それを事実確認することのみを目的とする。**

推測・設計判断・実装は一切行わないこと。

---

## 調査1：スナップショット記録機能の実在確認

**確認したいこと**
- 個人・法人それぞれの資産管理ツール画面に、「現在の保有資産」とは別に「ある時点の値を記録として保存する」操作（ボタン・フォーム等）が実際に存在するか
- 存在する場合、その操作をトリガーするコンポーネント・関数はどれか（ファイル名・関数名を特定）
- 記録の単位は月次固定か、任意タイミングで複数回記録できるのか

**対象ファイル**
- 資産管理ツール関連のページ・コンポーネント一式（`AssetManagementPage.tsx`、法人側の対応コンポーネント、および両者が参照する`src/lib/assetManagement/`配下）
- `AssetSnapshot`/`HojinAssetSnapshot`型の定義ファイルと、それを読み書きしているstore/lib

**報告フォーマット**
- 「記録する」に相当する操作が存在するか否かを明記し、該当コード箇所を抜粋
- 存在する場合、実際にブラウザで安全なテストデータを使って1件記録し、保存された実データの形状（キー名・フィールド）をそのまま貼り付けること（推測でのフィールド列挙は不可）

## 調査2：記録した実績の参照・表示機能の実在確認

**確認したいこと**
- 記録済みのスナップショットを、後から一覧・グラフ等で参照できる画面が存在するか
- 存在する場合、表示は「総資産の推移のみ」か「資産クラス別・口座別の内訳」まで見られるか
- 個人・法人は別々に表示されるのか、合算されるのか

**対象ファイル**
- 調査1で特定したファイル群に加え、履歴表示・グラフ描画に関わるコンポーネント

**報告フォーマット**
- 実機でのスクリーンショット（履歴一覧・グラフ等、実際に表示されている画面）を必ず添付
- 表示単位（総資産のみ／内訳あり、個人法人別／合算）を明記

---

## 調査3：CSV履歴機能との関係整理

**背景**
過去の作業ログに「CSV履歴機能をYYYYMM形式（区切り文字なし）で実装した」との記録がある。これが調査1・2のスナップショット機能そのものなのか、別の仕組みなのか未整理。

**確認したいこと**
- CSV履歴機能は、`AssetSnapshot`のエクスポート/インポートなのか、それとも別のデータ構造を扱っているのか
- CSVで書き出せる履歴の範囲（何ヶ月分・何件まで）と、実際の記録画面（調査1）との対応関係

**報告フォーマット**
- CSV履歴機能とスナップショット記録機能の関係を、簡単な図または箇条書きで整理して説明
