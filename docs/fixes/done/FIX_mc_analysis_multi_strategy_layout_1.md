# FIX: MC破綻確率カードの簡素化とモンテカルロ分析欄の戦略別リスト表示

## 経緯

先日実装した「戦略比較モードの複数選択対応(`displayStrategy`導入)」について、実機確認の結果、以下の2点を追加で見直す。

1. MC破綻確率のKPIカードに、複数戦略選択時は戦略ごとの詳細(色ドット・戦略名・破綻確率・枯渇年齢・p10/中央値/p90)を`footer`経由で詰め込んだが、これによりKPIカードだけ縦に大きく伸び、他のカードと高さが揃わない。特に画面幅が狭い場合(2カラムグリッドなど)でレイアウトが崩れる
2. グラフのp10〜p90帯を選ぶ手段が`displayStrategy`(単一値KPIカードと共通)に統合されているが、複数の中央値を同時表示している以上、帯だけ独立して選べたほうが自然(旧版の「バンド:」ドロップダウンに近い形)

## 修正方針(確定・GO)

### 1. MC破綻確率のKPIカードを単一値表示に戻す

複数戦略選択時も、他の単一値KPIカード(資産寿命・最終資産など)と同じ形式に統一する。

- 値:`displayStrategy`の破綻確率(%)を表示
- 補足(sub):「{表示戦略名}基準・詳細は下記」のように、モンテカルロ分析欄への導線を示す一言を添える
- 単一戦略選択時は、補足文言も含めて現状のまま(変更不要)

前回追加した`footer`経由の戦略別リスト表示(`KpiGrid.tsx`)は、このカードからは削除する。

### 2. モンテカルロ分析欄に、戦略別の詳細を移す

複数戦略選択時、モンテカルロ分析欄(既存の詳細表示エリア)に、`activeStrategies`ごとの行を表示する。

**レイアウト方針:テーブル(横の列揃え)ではなく、1戦略=1ブロックの積み上げ型にする。** 列を厳密に揃えようとする表形式は、画面幅が狭くなると折り返しでガタつくため採用しない。

各戦略のブロック構成:

- 1行目:色ドット(戦略識別色)+戦略名(13px, `text-secondary`)+破綻確率(16px・太字・色分け、`margin-left:auto`で右寄せ)。`flex-wrap:wrap`で、収まらない場合は自然に折り返す
- 2行目(補足・11px・`text-muted`):「枯渇した{n}試行:平均{}歳・最短{}歳」(破綻確率0%の場合は「全試行で資産維持」)に続けて、「p10 {}・中央値 {}・p90 {}」を**通常の文章として同じ行に流し込む**(固定の`<br>`による改行は入れない。ブラウザの自動折り返しに任せることで、デスクトップ・スマホ双方に同じマークアップで対応できるようにする)

単一戦略選択時は、この欄は現状のまま(変更不要)。

### 3. バンド選択を独立させる(displayStrategyから分離)

モンテカルロ分析欄の見出し行に、「グラフのバンド」という独立したドロップダウンを追加する。選択肢は`activeStrategies`に含まれる戦略のみ。

- `displayStrategy`(単一値KPIカードの基準)とは別の状態として`bandStrategy`を新設する
- `AssetChart`のp10〜p90帯は、`displayStrategy`ではなく、この`bandStrategy`を参照するように変更する
- `bandStrategy`が`activeStrategies`に含まれなくなった場合(該当戦略のチェックを外した場合)、選択中の戦略の先頭に自動的にフォールバックする(`displayStrategy`のフォールバックロジックと同様の実装でよい)
- グラフ下の注記(「確率的モード・中央値{n}本+{戦略名}のバンド」)も、`bandStrategy`を参照するように更新する

**注意:** 前回の実装で`displayStrategy`に統合したのは、単一値KPIカード群(資産寿命・最終資産・収支転換点・初年度取崩率など)については引き続き有効な設計です。今回切り離すのは「グラフの帯」だけです。単一値KPIカードは`displayStrategy`のまま変更しないこと。

### 4. グラフ凡例の見切れ修正

複数戦略選択時、資産推移グラフ下の凡例(FIREライン・p10・p90・戦略ごとの中央値)が、狭い画面幅で1行に収まらず、横スクロール(◀▶)が発生してしまい、一部の凡例(戦略の中央値ラベルなど)が見えなくなる問題を確認した。

- 凡例を、横スクロールではなく`flex-wrap`で**複数行に折り返す**形に変更する
- あわせて、戦略ごとの凡例ラベルを「中央値(現金優先)」から**「現金優先」のみに短縮する**(グラフ上部の注記で「中央値の線であること」は既に説明されているため、凡例側での重複表現を削り、折り返しの発生自体も減らす)
