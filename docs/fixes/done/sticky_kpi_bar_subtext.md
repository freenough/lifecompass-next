# 実装：StickyKpiBar・HeroDemoのFIRE達成カードにサブテキストを追加

## 背景

`KpiGrid.tsx`本体のFIRE達成カードは、KPI再設計により未達成時に

```
未達成
退職後最低充足率{%}
支出{X}%減または退職+{Y}年で達成
```

という3行構成になった。一方`StickyKpiBar.tsx`・`HeroDemo.tsx`(前回`kpi_improvement_suggestion_display.md`でスコープ外とした簡易表示箇所)は「未達成」の見出しのみで、サブテキストが一切ない状態のまま(実機のモバイル表示で確認済み)。本体との情報量の落差が大きすぎるとの指摘があった。

## 確定方針(方式A)

- **追加するもの**:充足率のサブテキストのみ(`退職後最低充足率{%}`/達成済みなら`FIRE達成後最低充足率{%}`)
- **追加しないもの**:改善案文言(「支出{X}%減または退職+{Y}年で達成」)。これは本体(`KpiGrid.tsx`)のみで表示し、`StickyKpiBar`・`HeroDemo`には含めない

理由:スティッキーバー・簡易表示は「一目で状況を把握する」役割であり、詳細なアクション提案は本体に譲る、という役割分担。可変長の改善案文言をタイトな省スペースUIに入れると、モバイル表示のレイアウト崩れリスクが高い。

## 実行内容

### `StickyKpiBar.tsx`
FIRE達成カードの表示部分に、`KpiGrid.tsx`と同じ`minRatio`(既存の`analyze.ts`算出値、追加計算不要)を使い、サブテキストを1行追加する。

- 達成時:「{fA}歳で達成」の下に「FIRE達成後最低充足率{%}」
- 未達成時:「未達成」の下に「退職後最低充足率{%}」

### `HeroDemo.tsx`
同様にサブテキストを追加する。こちらは固定デモデータのため、表示される数値も固定値になる想定。

### レイアウト確認
サブテキスト追加によって、モバイル幅(実機確認済みのスクリーンショット相当、320px程度を想定)でバーの高さ・折り返しが崩れないことを確認すること。崩れる場合はフォントサイズ・余白の調整で対応し、テキスト自体を省略しないこと。

## 完了報告フォーマット

- `StickyKpiBar.tsx`・`HeroDemo.tsx`それぞれの修正箇所(関数名・コンポーネント名)
- 田中誠プロファイル(未達成)・山本恒一プロファイル(達成済み)それぞれでの表示確認(サブテキストの実際の値)
- モバイル幅でのレイアウト確認結果(崩れの有無、調整した場合はその内容)
- 参照した関数・コンポーネント名(行番号ではなく)
- `full-verify.js`実行結果(全PASS必須)
- `npm run build`で型エラーがないことの確認

## 注意事項

- **改善案文言(`findImprovementThresholds()`等)はこの2箇所には追加しないこと**(方式Aで確定済み)
- `simulate.ts`・`analyze.ts`は変更禁止。既存の`minRatio`をそのまま利用する
- 色分けロジック(`kpi-thresholds.ts`の共通関数)は既に統一済みのため、変更不要
