# 調査指示：一人法人LP Hero右側カードを「実際の機能」で動かす方式の実現可能性調査

## 背景

一人法人LP（`/hitori-hojin`）のHero右側に「個人＋法人 合算」カード（個人資産と法人保有資産の積み上げバー、凡例、「目標までの進捗 68%」）がある。KENZOのレビューで、このカードは見た目だけのモックに見え、「張りぼて感」があると判断した。

資産シミュレーターLP（`/asset-simulator`）では、同じ課題を次の方式で解決済みである。

- Hero：`HeroDemo.tsx`が固定の`DEMO_PROFILE`／`DEMO_EVENTS`を本番の`simulate()`／`analyze()`／`runMC()`に渡して実際に計算し、結果を描画している
- 「毎月の資産を、記録する。」ブロック：`HeroDemo.tsx`と同じ計算結果（FIRE達成年齢時点の資産額）を目標額とする動的な進捗カードに作り替えた。カウントアップは`HeroDemo.tsx`から共通フックとして抽出し、IntersectionObserverで画面内に入った時に発火させている

一人法人LPのHero右側カードも、同じ考え方（見せかけではなく、本物の計算ロジック・コンポーネントを固定のデモデータで動かす）で作り直したい。方針を確定する前に事実確認が必要なため、**このタスクは調査のみを目的とする**。調査中に気づいた不具合があっても、その場での修正は行わないこと。

- モバイル幅（375px）でのカードの表示状態（表示されているか、Hero本文の下に回り込んでいるか、非表示か）
- アニメーションの有無

**報告フォーマット**
- 該当ファイルと、値を決めている箇所のコード抜粋
- デスクトップ幅・375px幅それぞれのスクリーンショット

## 調査2：法人資産管理ツール本体の構造と、LPからの再利用可能性

**確認したいこと**
- 法人資産管理ツール（Hero CTA「法人資産管理ツールを開く」の遷移先）で、次の3つの機能がそれぞれどのファイル・関数・コンポーネントで実装されているか
  - 法人預金・証券口座などの法人資産の記録
  - 個人資産との合算とFIRE進捗の表示
  - 将来の手取り目安の試算
- 特に「個人＋法人の合算」と「目標までの進捗」の計算について
  - 計算ロジックが、ストアやlocalStorageから切り離された純粋関数として存在するか（固定のデモデータを渡せば結果が返るか）
  - 進捗の分母（目標額）は何から決まっているか。資産シミュレーターの`simulate()`／`analyze()`の結果を使っているか、ユーザー入力の固定値か
  - `hojinCompanyState/mc.ts`など、関連する既存モジュールとの関係
- ツール本体に、合算の内訳や進捗を描画する表示用コンポーネントがあるか。ある場合、propsだけで描画できるプレゼンテーション用コンポーネントか、ストアやcontextに強く依存しているか
- ロックファイル（`simulate.ts`・`analyze.ts`・`PortfolioPanel.tsx`・`simulatorStore.ts`・`profile.ts`・`blog.ts`・`blogTopics.ts`・`concerns.ts`・`ConcernCard.tsx`ほか、既存の指示書で定められたもの）への依存の有無

**報告フォーマット**
- 3機能それぞれの実装箇所と、依存関係が分かるコード抜粋
- 「デモデータを渡すだけでLPから呼び出せるか／大きな改修が必要か」を、合算計算・進捗計算・表示コンポーネントのそれぞれについて明記
- ロックファイルへの依存の有無（依存している場合はimport箇所の抜粋）

## この調査結果の使い道

調査結果を持ち帰り、KENZOとの設計チャットで次を確定させる。

- 右側カードを「本物の計算＋固定デモデータ」で動かせるか、その場合の改修規模
- デモデータの与え方（資産シミュレーターLPの`DEMO_PROFILE`と整合させるか、一人法人向けに別のデモ人物を用意するか）
- 目標額と進捗の計算方法、カウントアップ・バーのアニメーションの発火方式
- 実装は見た目の主観判断を伴うため、専用ブランチ（例：`feature/hitori-hojin-hero-live-demo`）で作業し、Vercel Preview URLで確認してからマージする
