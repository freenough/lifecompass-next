# 実装指示書:getAggregateWeightsの重み計算を積立期・取崩期で統一

## 背景

`docs/fixes/done/investigation_aggregate_sigma_weight_bug.md`(調査済み)の通り、
`getAggregateWeights()`で積立期の重みだけ「現在残高+年間積立額1年分」を使っており、
取崩期(現在残高のみ)と計算式が食い違っている。この差はモンテカルロの実際の
シミュレーション結果には一切影響しない(表示専用)ことを確認済み。PF画面の
「全口座集計σ」が「取崩期は積立期と同じPFを使う」ON時でも積立期・取崩期で
微妙に異なる値になる、表示上の整合性の問題を解消する。

## 対象ファイル

`src/lib/profile.ts`の`getAggregateWeights()`のみ。
**ロックファイル(`simulate.ts`・`analyze.ts`・`montecarlo.ts`)は変更しないこと。**
他のファイルには一切触れないこと。

## 変更内容

`getAggregateWeights()`で、積立期(working)・取崩期(retirement)ともに
「現在残高のみ」を重みとして使うよう統一する。「年間積立額1年分を加算する」
という現状の積立期側の処理を削除する。

変更前:
```ts
if (phase === 'working') {
  return [bNisa + (p.cNisa ?? 0), bIdeco + (p.cIdeco ?? 0), bTax + (p.cTax ?? 0)];
}
return [bNisa, bIdeco, bTax];
```

変更後のイメージ(実装はコードの慣習に合わせて調整して構わない):
```ts
// 積立期・取崩期とも「現在残高」のみを重みとして使う(退職までの積立額や
// 運用成長を先読みしない、表示用の簡易目安であることを明示する)。
return [bNisa, bIdeco, bTax];
```

`phase`引数自体は型シグネチャ上残しても構わないが、`working`/`retirement`で
異なる計算をする理由がなくなる点をコメントに明記すること。

## コメントの更新

`getAggregateWeights`のJSDocコメント(249〜253行目付近)を、「積立期・取崩期
ともに現在残高のみを重みとして使う、表示専用の簡易値である」旨に更新すること。
「口座間の重みは実際の残高・積立額」という現状の記述のうち、「積立額」の部分は
削除・修正すること。

## 影響範囲の確認

1. この変更は`getAggregateWeights`を経由する以下の表示にのみ影響する:
   - `PortfolioPanel.tsx`の全口座集計μ/σ表示(積立期・取崩期)
   - PF計算値を使う(自動)モード時の`mcStd`/`mcStdR`の初期値
   前回の調査で確認済みの通り、自動モード時はこの初期値が`simulate.ts`の
   年次ループで動的に上書きされるため、モンテカルロの計算結果(破綻確率・
   p10/p50/p90等)には影響しないはずである。この認識に相違がないか、
   `full-verify.js`実行後に確認すること。
2. `full-verify.js`を実行し、全PASSを確認すること。決定論的フィクスチャ・
   MCフィクスチャともに変更前と差分が出ないことを確認し、報告に含めること
   (万一差分が出た場合は、前回調査の判定(実害なし)に誤りがあった可能性が
   あるため、差分の内容を詳しく報告し、修正は保留すること)。
3. `tsc --noEmit`がクリーンであることを確認すること。
