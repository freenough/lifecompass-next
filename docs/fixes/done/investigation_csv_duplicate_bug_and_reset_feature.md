# 実装指示書：CSVインポート重複バグの根本原因調査＋全データリセット機能

作成日：2026-08-24
種別：**調査優先・その後修正（重要度：高）**
背景：CSV関連の完了報告が3回連続で実態と食い違っている。今回は実装前に、原因を実コードに基づいて説明することを必須とする。

---

## 0. 重大な事実（証拠）

ユーザーの実際の使用環境からエクスポートされたCSVを直接確認したところ、以下が確認された：

```
1787495855852_tlxzfb, 2026-08, 法人預金, 現金, 法人, 300, ...   ← 1回目
1787496349695_jooky9, 2026-08, 法人証券口座, 全世界株, 法人, 0, ... ← 1回目
1787495855852_tlxzfb, 2026-08, 法人預金, 現金, 法人, 300, ...   ← 2回目（重複）
1787496349695_jooky9, 2026-08, 法人証券口座, 全世界株, 法人, 0, ... ← 2回目（重複）
1787495855852_tlxzfb, 2026-08, 法人預金, 現金, 法人, 300, ...   ← 3回目（重複）
...
1787495855852_tlxzfb, Aug-26, 法人預金, 現金, 法人, 300, ...    ← 「Aug-26」グループも残存
```

同一ID・同一年月（`2026-08`）の行が最大5回重複している。加えて、以前修正したはずの「Aug-26」という誤った年月ラベルのグループも、この環境には残っている。

これは「年月グループ単位で削除→挿入」という指示書の仕様（`implementation_asset_management_addon_csv_transfer.md`§1-3）が、少なくともこの環境では機能していないことを意味する。過去2回の完了報告では「実機確認済み」とされていたが、この重複は再現している。

---

## 1. 最優先タスク：原因の特定と説明（実装より先に行うこと）

**いきなり修正に着手しないこと。** 以下の手順で進めること：

1. CSVインポート処理のコード（グループ判定・削除・挿入を行っている箇所）を再度、一行ずつ読み直す
2. 「なぜ既存行が削除されずに新規行が追記され続けるのか」を、コードを引用しながら具体的に説明する。考えられる原因の例（先入観を持たず、実コードで確認すること）：
   - 削除条件のフィルタ（年月・IDの比較）が意図通りに一致していない（型の違い、文字列の前後空白、大文字小文字等）
   - 削除処理自体が呼ばれていない、または呼ばれる前に挿入処理が先に走っている
   - 複数回のインポート操作（例：確認ダイアログの二重発火、Reactの再レンダリングによる二重実行）
   - 保存処理が「既存配列に追加」になっており、「置換」になっていない
3. 過去2回の完了報告で「実機確認済み」としていたにもかかわらず、この不具合が見逃された理由も併せて説明すること（テストした環境・データパターンが、今回の不具合が再現する条件と異なっていた可能性が高い。具体的にどう違ったのかを特定すること）
4. 上記1〜3の説明を、**実装に着手する前に**報告すること

---

## 2. 修正：グループ置換ロジック

原因特定後、以下を満たす形で修正すること：

- 同一年月ラベルのインポートを**複数回実行しても**、結果として重複行が発生しないこと（べき等性を持たせる）
- 修正後、**同じCSVを3回連続でインポートしても行数が変わらないこと**を確認する自動テストを`full-verify.js`に追加すること（今後この種の不具合が再発しても自動検出できるようにする、回帰テスト化）

---

## 3. 修正：年月正規化の再確認

前回「Aug-26」形式の正規化を実装したはずだが、この環境には未正規化の「Aug-26」グループが残っている。以下を確認すること：

- 正規化ロジックが実際にデプロイ・反映されているか（ビルドキャッシュ等の問題がないか）
- 既存の壊れたデータ（既に「Aug-26」等の誤ラベルで保存されてしまったスナップショット）を、アプリ起動時または明示的な操作で正規化・統合するマイグレーション処理を追加すること（新規インポート時のバリデーションだけでは、既に壊れたデータは直らないため）

---

## 4. 新機能：全データリセット

- 資産管理ツール（個人／法人）に、「全データを削除する」機能を追加する
- 削除対象を選択できるようにする：「個人のみ」「法人のみ」「両方」
- 実行前に、対象範囲を明示した確認ダイアログを表示し、**取り消せない操作である旨を明記**すること
- 削除対象：保有資産（`AssetHolding[]`）、記録履歴（`AssetSnapshot[]`）、移転履歴ログ（該当する場合）。設定値（目標資産額・個人化想定比率等）を削除するかどうかは、対象範囲選択とは別に、含める/含めないを選べるようにすること

---

## 5. 調査：combined表示でのCSVインポートについて

ユーザー報告：「合算（`combined`）表示にしてCSVインポートしようとしても、法人側の行しか反映されないように見える」

- この挙動を実機で再現できるか確認すること
- 再現した場合、原因を特定し修正すること
- 再現しない場合、その旨と確認手順を報告すること（お茶を濁さず、実際に試した操作を明記すること）
