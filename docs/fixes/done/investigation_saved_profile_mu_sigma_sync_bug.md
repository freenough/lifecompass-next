# 調査専用指示書:保存プロファイル読み込み時のμ/σ再計算の整合性確認(バグ疑い)

**ロックファイル(`simulate.ts`・`analyze.ts`・`montecarlo.ts`)は変更禁止・読むだけ。**
**`profile.ts`・store関連ファイルも今回は変更禁止・読むだけ(調査のみ)。**
コードの変更は一切行わず、調査結果の報告のみでお願いします。

## 背景

添付JSON(`暴落シナリオ.json`)は、`pfManualFlags`が全項目`false`(PF自動計算=ON)
であるにもかかわらず、`params`内に古い前提値(`rRNisa: 4`・`rRIdeco: 4`・
`rRTax: 4`・`mcStd: 16`・`mcStdR: 8`)が保存されている。これはASSET_CLASSES
見直し(全世界株μ7.0%→6.83%・σ16.0%→18.89%等)より前に保存されたスナップ
ショットと思われる。

このJSONをツールに読み込んだ結果、PF画面の表示は新しい値(μ:6.8%・σ:18.9%)に
なっていた(スクリーンショットで確認済み)。プランニングチャット側では「自動
モードなので、保存値は無視されて現在のASSET_CLASSESから再計算される」と
仮説を立てたが、**実際にコードを確認したわけではなく、この仮説が正しいか
確認したい**。

特に、σ(mcStd/mcStdR)については、別件の過去調査(`docs/fixes/done/`配下、
「積立期/取崩期σの重み計算不整合」調査)で「自動モード時は`simulate.ts`の
年次ループ内で動的に上書きされる(`getAccountSigmaW`/`getAccountSigmaR`
経由、ASSET_CLASSESを都度参照)」ことが確認済みだが、**μ(各口座のrW/rRリターン)
についても同様に動的な再計算・上書きが行われるのか、まだ確認できていない**。
もしμがこの経路を持たず、保存されたJSON内の古い値(例:rRNisa=4)がそのまま
`simulate()`に渡っている場合、PF画面の表示(6.8%)と実際の計算に使われる値
(4%)が食い違う、実害のあるバグということになる。

## 調査項目

1. **JSON読み込み(プロファイルのロード処理)の流れを追ってください。**
   保存された`params`オブジェクト(`rRNisa`・`mcStdR`等の古い値を含む)が、
   ストア(store)にロードされた時点でどう扱われるか:
   - ロード時に即座に再計算・上書きされるのか
   - それとも古い値がそのままストアに保持され、何らかの表示コンポーネント
     (PF画面等)だけが別途ライブ計算した値を「見せて」いるだけで、ストア内の
     実データ(`params.rRNisa`等)自体は古い値のままなのか

2. **`profileToSimParams`(またはSimParamsへの変換処理)を確認してください。**
   `simulate()`に実際に渡される`SimParams`の`rRNisa`・`rWNisa`・`rRIdeco`・
   `rWTax`等の値は、以下のどちらの経路で決まるか特定してください:
   - (a)ストアの`params.rRNisa`等をそのまま使う(pfManualFlagsがfalseでも
     関係なく、保存された生の数値を使う)
   - (b)`getEffectiveMcStd`/`getEffectiveMcStdR`と同様の「Effective」関数
     (例:`getEffectiveRateRNisa`のようなもの)が存在し、pfManualFlagsが
     falseのときはportfolio(資産配分)とASSET_CLASSESから都度`calcMu`等で
     再計算した値に差し替えている

3. **もし2で(a)だった場合(=μが保存値をそのまま使う設計だった場合)、
   これはPF画面の表示(ライブ計算)とシミュレーション結果(保存値ベース)が
   食い違う実害のあるバグと考えられます。** その場合、以下も確認してください:
   - この食い違いはσ(mcStd/mcStdR)にも同様に存在するか、それともσだけは
     前回確認済みの動的上書き(年次ループ内)によって実害がないままなのか
   - `pfManualFlags`が本来意図している設計(自動モードなら常に最新の
     ASSET_CLASSESを反映するはず、という前提)と実装が一致しているか

4. **添付JSON(`暴落シナリオ.json`)をそのまま読み込んでMC実行した場合、
   実際に`simulate()`に渡る`rRNisa`・`mcStdR`等の値をログ出力等で
   実測してください。**(コードを変更せず、一時的なデバッグ出力や、
   既存のテストスクリプトへの一時的な追加で確認し、確認後は元に戻すこと)

5. **保存(save)処理自体の確認。** JSONへの書き出し処理(プロファイルの
   保存機能)が、`params.rRNisa`・`params.mcStdR`等をどう書き出しているか
   確認してください:
   - 保存時点で、PF画面に表示されているライブ計算後の実効値(例:μ6.8%・
     σ18.9%)を反映した状態で書き出しているか
   - それとも、ストア内に保持されている(場合によっては古いままの)
     `params`オブジェクトを、ライブ値との整合性チェックをせずそのまま
     `JSON.stringify`しているか
   - もし後者だった場合、「PF自動計算=ON(pfManualFlags=false)のプロファイルを
     保存すると、保存時点の最新の実効値ではなく、過去のいずれかの時点の
     スナップショット値がそのままファイルに書き出される」という、保存側の
     バグとして報告してください。これは前述の読み込み側の論点(項目1〜4)とは
     独立した問題であり、両方が別々に存在しうる(例:保存は正しいが読み込みが
     おかしい、あるいはその逆、あるいは両方とも正しくない)ため、それぞれ
     個別に判定してください

## 出さなくてよいもの

- 修正案・修正コードは不要(このセッションでは調査のみ)
- ファイルの変更は一切行わないこと(一時的なデバッグ出力も、確認後は必ず元に戻すこと)
