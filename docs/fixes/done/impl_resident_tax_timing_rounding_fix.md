# 実装指示:resident-tax-timing 表示上の丸め誤差の修正(手動テストで発見)

## 背景・発見された不具合
ブラウザでの手動確認により、以下の表示不整合が見つかった:

- 退職前年年収600万円・12月退職・一括徴収選択時:
  - 「① 退職前から進行中の住民税の残り」の残額表示:17万円
  - 「② 退職した年の所得をもとにした…新しい住民税」の小計表示:40万円
  - これらを単純に足すと57万円になるが、ヘッドライン「確保しておきたい現金の目安」は56万円と表示される

原因は計算ロジックの誤りではなく、**表示上の丸め方式の不整合**である:
- `currentYearTax.remainingAmount`(生の円単位)を個別に万円へ四捨五入すると17万円
- `nextYearTax.total`(生の円単位)を個別に万円へ四捨五入すると40万円
- しかし`totalCashNeeded`(生の円単位の合計値)を四捨五入すると56万円になる
  (個別に丸めた値の合計と、合計してから丸めた値が、丸めの境界値付近でズレるため)

`calcResidentTaxTiming()`の計算そのもの(円単位)は正しい。**円単位の値は一切変更しないこと。**
本指示は表示(万円への丸め方法)のみを対象とする。

## 修正方針
「個別に丸めてから合計する」方式に統一し、画面上のどの足し算も必ず一致するようにする。

- 円単位の生の値から万円への丸めは、**表示直前の最小単位(内訳・①・②の各項目)でのみ行う**
- ヘッドライン(合計値の表示)は、円単位の`totalCashNeeded`を独自に丸めるのではなく、
  **既に万円へ丸めた①(`remainingAmount`)と②(`nextYearTax.total`)を足した値**を表示すること
- 「退職時に給与・退職金から差し引かれる想定」「自分で納付する想定」の内訳も、
  同様に万円へ丸めた①の値をベースに算出し、ヘッドライン(=①+②の丸め後合計)との整合を保つこと:
  - 天引き想定(万円) = `isWithheldAtSource` が true なら 丸めた①、false なら 0
  - 自己納付想定(万円) = ヘッドライン(丸めた①+丸めた②) − 天引き想定(万円)
  (このように「ヘッドラインから逆算」する形にすることで、内訳の合計が必ずヘッドラインと一致する)

## 対象ファイル
- `ResidentTaxTimingResult.tsx`:ヘッドライン・内訳表示・①②のセクション表示すべてに適用
- `ResidentTaxTimingComparisonTable.tsx`:「今の住民税の残り」列・「翌年6月〜」列を個別に万円へ丸めた上で、
  「合計」列は独自に丸めるのではなく、その2つの丸めた値を足した値を表示すること

## 実装上の注意
- `residentTaxTiming.ts`側の型・関数・円単位の計算結果は一切変更しないこと
  (`totalCashNeeded`という円単位のフィールド自体は今まで通り存在してよいが、
  UIでの万円表示にはこのフィールドを直接丸めて使わないこと)
- 万円への丸め処理を行うヘルパー関数(`toManYen`等)は既存のものを流用し、
  「個別に丸めてから合計する」呼び出し順序に変更するだけでよい
- 端数(0.5万円未満)の扱いは、既存の`Math.round`の丸めルールをそのまま踏襲すること

## 検証要件
- 今回発見された具体的なケース(退職前年年収600万円・12月退職・一括徴収)で、
  ①(17万円)+②(40万円)=ヘッドライン(57万円)に一致することを確認すること
  (丸め方式の変更によりヘッドラインの表示値が56万円→57万円に変わる想定。これは想定通りの挙動であり、
  円単位の計算結果が変わったわけではないことを完了報告書に明記すること)
- 同様のケースが他の入力パターン(400/600/800万円×1/5/9/12月、一括/分割それぞれ)でも
  発生していないか、全パターンで①+②=ヘッドライン、天引き想定+自己納付想定=ヘッドライン、
  の一致を`verify-resident-tax-timing-tool.js`に検証項目として追加すること
- 比較表の「合計」列についても、同様に全4パターン(3/6/9/12月)で列の整合を確認すること
- `full-verify.js`全PASS・`tsc --noEmit`エラーなしを再確認すること

## 禁止事項
- `residentTaxTiming.ts`内の円単位の計算ロジックの変更
- `totalCashNeeded`等、既存の型定義フィールドの削除・意味変更
- `docs/fixes/active/` フォルダの削除
