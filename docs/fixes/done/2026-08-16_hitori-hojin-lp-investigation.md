## 確定済みのLP骨格(参考情報)
```
Header → Hero → Intro
→ 「一人法人を知る」(キュレーションカード、初期3記事)
→ 「一人法人を考える」(キュレーションカード、初期5記事 + シリーズ通読リンク1本)
→ [将来、Phase 1では非表示]「一人法人のお金を計算する」
→ [将来、Phase 1では非表示]「個人＋法人の資産を管理する」
→ 「ブログ一覧」(全記事、新着順、series/seriesOrderでのフィルタ・並び替え可能)
→ FIRE資産シミュレーターへのCTA
→ [将来、Phase 1では非表示]NOTE
→ Footer
```
技術要件:
- 「知る」「考える」(将来は「計算する」「管理する」も)は同一の汎用ブロックコンポーネントで実装できるようにする
- 「知る」「考える」のカテゴリ分類は、既存`blogTopics.ts`の`TOPIC_GROUPS`パターンを踏襲し、将来記事追加時に手動で並べ直さず自動分類されるようにする
- 記事間の内部参照は相対回数(前々回等)を使わず説明的ハイパーリンクにする方針のため、記事URLのslugが実装時に確定している必要がある

## 調査してほしいこと

### 1. 既存カードUIコンポーネントの再利用可能性
- `/asset-simulator`の「お悩みカード」(`concerns.ts`が参照される表示コンポーネント)の実装箇所を特定し、コンポーネント名・propsの構造を報告してください
- このコンポーネントが「一人法人を知る/考える」向けに、タイトル・説明・アイテム一覧を受け取る汎用的な形(`<ContentSection title items />`のようなイメージ)で流用できそうか、あるいは別途新規実装が必要そうか、実際のコード構造から判断して報告してください
- 流用する場合、既存コンポーネントを直接importして使うか、同じパターンで新規コンポーネントを複製すべきか(既存locked資産への影響を避ける観点)、両案の実装コストを比較してください

### 2. ブログ一覧・frontmatterスキーマの設計調査
- 既存の`src/lib/blog.ts`の`getAllPosts()`関数のシグネチャ・返り値の型・frontmatterのパース方法を報告してください
- 新規`hojinBlog.ts`を作る場合、`getAllPosts()`相当の関数をゼロから複製することになりますが、以下のフィールドを持たせたい場合の実装イメージを示してください:
  - `series`(シリーズ識別子、例: `'hitori-hojin'`)
  - `seriesOrder`(シリーズ内の並び順、数値)
  - `category`相当(「知る」「考える」のようなキュレーション分類)
- 既存`blogTopics.ts`の`TOPIC_GROUPS`パターン(topics軸とcategory軸の分離)を、`hojinBlog.ts`側でも同様に持たせる場合、どの程度既存パターンを流用できるか報告してください

### 3. ブログ一覧のフィルタ・並び替え機能の実装可能性
- 現在の`/asset-simulator/blog`一覧ページの実装(新着順でのソート等)を確認し、`series`フィルタと`seriesOrder`ソートを追加する場合の実装イメージ(クエリパラメータ方式か、専用ページ方式か等の選択肢)を報告してください

### 4. LPページのルーティング調査
- `/hitori-hojin`のLPページ自体を`src/app/hojin/page.tsx`のような形で新規作成する場合、既存の`/asset-simulator`LP(`src/app/page.tsx`等、実際のパスを確認してください)の構造をどの程度参考にできるか、ページコンポーネントの構成を報告してください

### 5. 最小構成の見積もり
上記を踏まえ、「LP1ページ＋知る/考えるカード表示＋ブログ一覧(シリーズフィルタ付き)」を実装するために**必要な新規ファイル一覧**を提示してください。既存ファイルへの変更が必要な場合は、変更内容を最小限に絞って報告してください(特にrewrite設定以外で`freenough-main`側に変更が必要かどうか)。
