# 調査依頼：予実比較「合算（法人含む）」線 追加のための設計前提調査

作成日：2026-09-03
種別：**調査のみ（実装は行わない）**
関連：`claude_investigation_extraEvents_persisted_recompute.md`（`corporateSnaps`の計算コスト等は調査済み）

---

## 0. 目的

予実比較グラフに「合算（法人含む）」線を追加するにあたり、以下4点を実コードで確認してほしい。設計判断はこのチャットで行う。

---

## 1. 調査してほしいこと

### 1.1 個人化想定比率の適用方式

- シミュレーター画面の「合算(法人含む)」線が、法人残高をそのまま個人カーブに加算しているのか、それとも`個人化想定比率`（`personalizationRatio`）を乗じた額を加算しているのかを、実コード（該当する計算関数）を引用して確認する
- 上記を計算している関数のファイルパス・関数名を明記する

### 1.2 個人化想定比率の値の取得元とライブ性

- `個人化想定比率`がどこに保持されているか（`useAssetManagerProfileStore`か、`useCompanyStateStore`か、別のstoreか）を確認する
- ライブstateのみ（ページ跨ぎで消える）か、永続化されている値か（`companyStateByProfile`等）を確認する
- 現在この値を変更できるUI（スライダー）が、変更するたびに即座に永続化しているか、それとも他の設定と同様「シミュレーター画面での保存」時点で一括永続化されるのかを確認する

### 1.3 MCモードでの「合算」線の実装

- 添付画像で確認された「合算(法人含む)中央値」が、実際にどう計算されているか（個人側のP50に法人残高の中央値相当を単純加算しているだけか、他の方式か）を、該当コードを引用して確認する
- 合算側にP10〜P90に相当する帯（Area）が存在するか、存在しないかを明確に確認する

### 1.4 `displayScope`（個人のみ／合算）の管理構造

- 資産管理ページ上部の「表示：個人のみ／合算」セレクタが、どのstate/propで管理されているか（`AssetManagementPage.tsx`のローカルstateか、storeか）を確認する（前回のバグ調査で`displayScopePref`という名前が出てきているので、その後継として確認）
- この値を`PlanComparisonSection.tsx`（現在propsは`plans`, `personalSnapshots`, `onPlansChanged`, `currentProfileId`, `linkedSimulatorProfileId`）に新たにpropとして渡す場合、既存の値をそのまま渡せる構造になっているか（`AssetManagementPage.tsx`内で`PlanComparisonSection`をレンダリングしている箇所を確認する）

### 1.5 法人取崩トグルOFFで保存された計画（`corporateSnaps`が存在しない計画）

- 現在の`PlanSnapshot`型・`generatePlan()`の実装で、法人取崩を含まない計画を選択した状態は、既存のコードのどこでどう判別できるか（例：何らかのフラグの有無、`extraEvents`が空だったことを示す情報が保存されているか等）を確認する。無ければ「無い」と報告するだけでよい

### 1.6 取り崩し戦略名の日本語表示

- `strategy`の値（`proportional`等の内部識別子）を「比例取崩」「現金優先」「課税優先」という日本語表示に変換する、既存のマッピング関数・定数が既にどこかに存在するか確認する（シミュレーター側の選択UIなどで使われているはず）。存在すればファイルパス・関数名を報告する

---

## 2. 報告フォーマット

- ファイルパス・関数名・関連コードを引用
- 1.1〜1.6それぞれについて確認できた事実を明記
- 不明瞭な場合は推測で埋めず、その旨を報告する

## 3. やらないこと

- コードの変更
- 新しい計算ロジックの実装
- UIの変更

以上は、本調査結果をもとにこのチャットで設計を確定させたうえで、別途の実装指示書で依頼する。
