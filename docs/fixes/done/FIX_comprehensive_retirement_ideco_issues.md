# 実装依頼：総点検で発見された4項目の修正

## 背景

`AUDIT_comprehensive_retirement_ideco_review.md`の総点検で、以下4点が見つかった。KENZOの判断で全て対応する。

---

## 1. 配偶者のiDeCo受給開始年齢にバリデーションがない(優先度:高)

**問題**:本人側は`calcIdecoEligibleAge`で通算加入期間に応じた繰り下げ・75歳上限が`profile.ts:408-409`で強制クランプされるのに対し、配偶者側(`profile.ts:488`)は`p.spIdecoStartAge || p.spRetAge || 60`とクランプが一切ない。UIの`<Field min={60} max={75}>`はHTML属性のみで、キーボード直接入力には効かない。

**修正内容**:配偶者側にも本人側と同じロジックを適用する。`calcIdecoEligibleAge(spIdecoYrs, spCurAge, spCIdecoTo)`相当の呼び出しを追加し、`Math.max(spIdecoEligible, Math.min(75, p.spIdecoStartAge))`で配偶者の実際の受給開始年齢をクランプする。

## 2. 配偶者の特定口座に譲渡益課税が適用されない(優先度:高)

**問題**:本人側は`costBasis`(取得原価)を追跡し、取り崩し時に含み益率(`gainR`)を計算して20.315%課税しているが、`SpouseAcct`型に`costBasis`フィールドが存在せず、配偶者の特定口座は常に「残高全額=取得原価(含み益ゼロ)」として扱われ、譲渡益課税が一切かからない。

**修正内容**:
1. `SpouseAcct`型(`types.ts:33`付近)に`costBasis`フィールドを追加
2. 初期化を本人側と同様に(`p.spouse?.acct?.tax?.costBasis ?? p.spouse?.acct?.tax?.bal`)に変更
3. 積立期の拠出時、本人側と同様に残高とコストベース双方を同額増加させる処理を配偶者側にも追加
4. 取り崩し時、`withdraw()`内の本人側ロジックと同様に、配偶者の特定口座からの取り崩しにも含み益率ベースの20.315%課税を適用する

## 3. 「短期退職手当等」(勤続5年以下)の1/2非適用ルールが未実装(優先度:中)

**参考(一次情報)**:`REFERENCE_retirement_ideco_tax_rules.md`2章に記載の通り、勤続年数(役員等以外)が5年以下の場合、退職所得控除後の金額のうち300万円を超える部分には1/2課税が適用されない。

```
通常: 退職所得 = (収入 - 控除) × 1/2
短期(年数≤5年)の場合:
  remaining = 収入 - 控除
  退職所得 = min(remaining, 300万円) × 1/2 + max(0, remaining - 300万円)
```

**修正内容**:`retirementTaxCalc`(`helpers.ts`)内で、実際に使用される年数(`yrs`)が5以下の場合に、上記の短期計算式を適用する分岐を追加する。`yrs`は既存の「同一年受取か別年受取か」の判定を経た後の値を使うこと(3分岐のどのケースでも、確定した`yrs`が5以下なら短期ルールを適用)。

## 4. 勤続年数の端数処理が切り捨てになっている(優先度:低)

**問題**:`retirementTaxCalc`の`Math.floor(...)`は、税制上求められる「1年未満切り上げ」とは逆方向。現状はUI側が整数入力に丸めるため実害はないが、将来のAPI等の入力経路に備えて修正しておく。

**修正内容**:`Math.floor`を`Math.ceil`に変更する。
