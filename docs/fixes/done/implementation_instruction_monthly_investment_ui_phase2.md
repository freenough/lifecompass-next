## 1. 入力仕様

Product Spec 3章の入力項目をそのまま実装する。**入力は5項目**(FREENOUGH Tools
共通原則の「6項目以内」を満たす):

| 項目 | 型 | 初期値 | UI要素 |
|---|---|---|---|
| 現在の年齢 | 数値(歳) | 35 | number input |
| 目標達成年齢 | 数値(歳) | 55 | number input |
| 現在の資産額 | 数値(万円) | 100 | number input |
| 目標資産額 | 数値(万円) | 3000 | number input |
| 想定利回り(年率) | 数値(%) | 5 | number input + 3%/5%/7%のプリセットボタン |

### 1-1. `years`の算出

`financeCore.ts`は年齢を扱わないため、呼び出し側(このページのコンポーネント)で
`years = 目標達成年齢 - 現在の年齢`を算出してから`calcRequiredMonthlyContribution`
に渡すこと。

### 1-2. リアルタイム計算(FREENOUGH Tools共通原則に従う)

送信ボタンを設けず、いずれかの入力値が変わるたびに再計算し、結果を即座に更新する
こと(`onChange`ベース。デバウンスは不要、`calcRequiredMonthlyContribution`は
1ms未満で完了する軽量な計算のため)。

### 1-3. 入力バリデーション

- 目標達成年齢が現在の年齢以下の場合(`years <= 0`)、`calcRequiredMonthlyContribution`
  は`null`を返す。この場合、結果エリアには計算結果ではなく「目標達成年齢は現在の
  年齢より後に設定してください」という趣旨のメッセージを表示すること
- 現在の資産額が目標資産額以上の場合(戻り値`0`)は、これをエラーではなく
  「既に目標資産に到達しています。積立は必要ありません。」という正常な結果メッセージ
  として表示すること(`null`と`0`を画面表示の面でも明確に区別すること)

## 2. 出力仕様

Product Spec 4章に対応する。

### 2-1. メイン結果

```
{現在年齢}歳から{目標達成年齢}歳({years}年間)で {目標資産額}万円 に到達するには

毎月の積立額(概算): {結果}万円

※年率{入力利回り}%で複利運用した場合の試算です。実際の運用成果を保証するものではありません。
```

メイン数値(毎月の積立額)は視覚的に最も強調される大きさ・太さで表示すること。

### 2-2. 利回り別の感度テーブル(必須)

ユーザーが入力した利回りに加え、3%・5%・7%の3パターンで
`calcRequiredMonthlyContribution`を計算し、以下のようなテーブルで並べて表示する:

| 想定利回り | 必要な毎月積立額 |
|---|---|
| 年率3% | XX万円 |
| 年率5% | XX万円 |
| 年率7% | XX万円 |

- ユーザーの入力値がこの3パターンのいずれかと一致する場合は、その行を
  ハイライト表示すること(「入力値」であることが分かるように)
- ユーザーの入力値が3パターンのいずれとも一致しない場合(例:年率4.5%と入力)は、
  ユーザー入力値の行を4行目として追加し、テーブル内に含めること(4パターン表示になる)

### 2-3. 注記(必須・法務面、文言は固定)

結果表示の直下に、常に以下の文言をそのまま表示すること(意訳・言い換え不可):

> この計算は、入力された利回りで毎年一定に運用できたと仮定した概算です。
> 実際の相場は変動するため、この通りに資産が増えるとは限りません。
> 税金・NISA非課税枠の上限は考慮していません。
> より詳しい条件で試算したい場合は、資産シミュレーターをご利用ください。

## 4. デザイン方針(FREENOUGH Tools共通原則に従う)

Product Spec 12章の原則をそのまま適用する:

- **1画面完結**:結果を見るためにスクロールが必須にならないよう、入力エリアと
  結果エリアを縦に並べつつ、コンパクトなレイアウトにすること
- **モバイル対応を優先すること**:このツールはスマホからの直接流入(検索経由)を
  主要動線として想定しているため、既存のROADMAP.mdにある「モバイル対応」より
  優先度を上げて本ツールだけ先行対応すること。`lg:`ブレークポイント(1024px)を
  基準に、モバイルでは入力欄を縦一列にすること(既存プロジェクトの「2行レイアウト
  禁止」「単一カラムのレスポンシブレイアウトを優先」という原則に従う)
- **ブランドトーン**:LifeCompass本体と同一のカラー・フォントを使用すること
  (CTAのカラーは`#334155`、既存の口座別カラー等は本ツールでは使用しない
  想定だが、全体の配色トーンは合わせること)
- **1画面完結**の原則上、感度テーブル(2-2)が縦に長くなりすぎないよう、
  3〜4行程度に収まる設計にすること(既に2-2の仕様がこれを満たしている)

## 5. コンポーネント設計の指針

- 入力フォーム・結果表示・感度テーブル・CTAは、それぞれ独立したコンポーネントに
  分割すること(将来、同じ結果表示コンポーネントを記事埋込版(フェーズ3)でも
  再利用するため)
- 状態管理は当該ページ内のローカルstate(`useState`)で完結させ、Zustandストア
  (`simulatorStore.ts`)には接続しないこと(本ツールはLifeCompass本体と状態を
  共有しない、完全に独立したツールであるため)
