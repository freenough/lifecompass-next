## 1. タイトル・説明文のmin-height対応

### 背景
前回の完了報告で、タイトル・説明文は`line-clamp-2`のみ実装済み(最大2行での省略)だが、`min-height`による強制的な行数固定は行われていないとの報告があった。短いタイトル・説明文の記事では、カードの高さがわずかに小さくなる。

### 対応内容
- タイトルブロック・説明文ブロックそれぞれに、2行分の高さを確保する`min-height`を追加する
  - 例:タイトルが`text-base sm:text-lg`であれば、その行高(line-height)×2行分に相当する値を`min-h-[...]`で指定
  - 説明文についても同様に、実際に使用しているフォントサイズ・line-heightから2行分の高さを算出して指定すること(前回報告にあった `line-clamp-2` のクラスと矛盾しない値にする)
- 実装後、短いタイトル・短い説明文の記事(例:サンプルデータで意図的に1行のみのテキストを用意するか、既存記事から短めのものを選ぶ)と、長いタイトル・長い説明文の記事とで、カード全体の高さが一致することをスクリーンショットで確認すること

## 2. サムネイル画像の上下余白調査・修正

### 背景
サムネイル画像(実寸1536×1024、3:2比率でコンテナの`aspect-[3/2]`と数値上は一致)を表示すると、上下に余白が出ている(KENZOによる目視確認)。画像素材自体を確認したところ、画像内部に余白は焼き込まれていない(ロゴ・チャートがキャンバス端までフルブリードで配置されている)ため、**原因はCSS実装側にある可能性が高い**。

### 調査観点(優先順に確認)

1. **`object-fit`の指定を確認する**
   - サムネイル`<img>`(または`next/image`)に`object-cover`が明示的に指定されているか
   - `object-fit`が未指定、または`object-contain`になっている場合はこれが原因の可能性が高い
2. **コンテナのpadding/marginを確認する**
   - サムネイル用div(`shrink-0 self-center`のコンテナ)に、意図しない`padding`や、子要素である`<img>`との間に隙間を生む`gap`指定が入っていないか
3. **`next/image`を使用している場合、`width`/`height`属性(intrinsic size)とコンテナの`aspect-[3/2]`指定に矛盾がないか確認する**
   - `fill`プロパティを使わずに`width`/`height`を直接指定していると、指定値と実際の1536×1024の比率がズレていた場合にレターボックス的な余白が出ることがある。`fill`+親要素`position: relative`の構成に統一されているか確認

### 対応方針
- 上記調査で原因を特定し、該当箇所を修正する(`object-cover`の明示指定、余分なpadding除去、または`next/image`の`fill`構成への統一、のいずれか実際に該当した内容)
- 修正後、実際にブラウザdevtoolsで画像要素の描画サイズとコンテナサイズを比較し、上下・左右に余白がピクセル単位で残っていないことを確認すること
- 原因が上記3点のいずれにも当てはまらなかった場合は、自己判断で別の対応を進めず、調査結果(何を確認し、何が原因ではなかったか)を報告して確認を仰ぐこと
