# 実装指示書:退職直後の暴落シナリオ検証スクリプト(検証用モデル・オルカン単体)

## 背景

前回`scripts/sequence-risk-tanaka-numbers.js`を田中さんプロファイルで実装したが、
田中さんは`pfManualFlags`で全資産クラス手動固定のため、先日確定したASSET_CLASSES
の新しい前提値(全世界株σ:16.0%→18.89%等)を反映できないことが判明した。

これを受けてプランニングチャット側で方針を変更し、田中さんではなく、この記事
専用の単純化した「検証用モデル」を新規に使うことにした。実在の家計を模した
ものではなく、退職直後の暴落タイミングという1変数だけを見るための実験的な
設定であることを、記事側で明示する前提。

## 対象・制約

**ロックファイル(`simulate.ts`・`analyze.ts`・`montecarlo.ts`)は変更禁止。**
import元として読むだけ。前回同様、新規スクリプトを1本作成する形。
既存の`scripts/sequence-risk-tanaka-numbers.js`は削除せず残してよい(前回の
検証結果として一旦保持。使わないことをコメントで明記すること)。

## 検証用モデルの条件(プランニングチャットで確定済み)

- 退職年齢:60歳、シミュレーション期間:60歳〜95歳(35年)
- 初期資産:4,000万円、全額を全世界株式(オルカン相当)で運用、単一口座
  (NISA/iDeCo/特定の区別をせず、1つの口座にまとめて計算できる形にすること。
  既存のパラメータ構造上どうしても複数口座への分割が必要な場合は、全額を
  1口座に寄せ、他口座残高は0円にすること)
- 年間取崩額:200万円(年金等の収入は考慮しない、公的年金・住宅費・医療費・
  税社会保険料は考慮しない検証用の単純設定)
- 期待利回り・σ(取崩期):μ=6.83%・σ=18.89%(先日確定した全世界株LTCMA新前提値、
  `pfManualFlags`で手動固定し、ASSET_CLASSES自動計算は経由しない設定でよい)
- インフレ率:既存記事(繰上返済記事等)で使っている標準値を踏襲すること
  (具体的な数値は既存記事のスクリプトを参照して合わせること)

## シナリオ設計(前回と同じ、3シナリオ×N=1,000試行)

| シナリオ | 退職1年目のZスコア | 2年目以降 |
|---|---|---|
| A. 基準(通常のモンテカルロ) | ランダム(固定しない) | ランダム |
| B. 中程度の下落 | -2σに固定 | ランダム(montecarlo.tsと同じ乱数生成ロジック) |
| C. 深刻な下落 | -3σに固定 | ランダム(同上) |

「退職1年目」は取崩期の1年目(シミュレーション開始と同時に取崩が始まる設定の
ため、シミュレーション1年目=退職1年目)。乱数生成は前回同様、`montecarlo.ts`
内の`randNorm()`をそのまま再利用すること(独自再実装禁止)。

## 出力してほしい数値

各シナリオ(A/B/C)について:
- 破綻確率(bankruptcyRate)
- 資産寿命の分布(depletionMean・depletionMin)
- p10/p50/p90(95歳時点)
- **退職1年目時点での実際の資産減少額・減少率**(円ベース。B・Cそれぞれ、
  試行間で値が変わるか一定か明記すること。前回の田中さんスクリプトでは
  静的σモードのため試行間で下落率が一定だったが、今回のモデルでも同様か
  確認すること)
- B・Cについて、Aとの差分(破綻確率が何ポイント上がったか等)

前回同様、非シード乱数のため2回実行して数値の安定性(方向性・おおよその
規模が再現するか)を確認し、報告に含めること。

## 数値ルールの遵守

- `simulate()`・`montecarlo.ts`の乱数生成は本番のものをそのまま呼ぶこと。
  独自の再実装・簡略化は行わないこと
- 手計算・推測値は禁止。全て実行結果から取得すること

## 完了報告に含めるべき内容

- 実行結果(A/B/C各シナリオの上記数値一覧、2回分)
- 退職1年目の実際の資産減少率(B/Cそれぞれ)
- スクリプトの配置場所
- この検証用モデルの設定(取崩率5.0%相当)が、基準シナリオ(A)である程度の
  破綻率を示しつつ極端になりすぎていないか、所感を併記してもらって構わない

チャット側で行います。
