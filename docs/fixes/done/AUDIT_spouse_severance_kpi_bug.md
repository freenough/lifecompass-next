# 調査依頼：配偶者の退職金KPIが反映されない件(再現あり)

## 背景

`AUDIT_spouse_severance_logic.md`の調査で、Next.js版は配偶者の退職金を本人と分離して課税処理する実装(`spSevYrs`・配偶者専用`retirementTaxCalc`呼び出し・年齢軸変換)が確認された。

しかし、実際にKENZOが以下の操作を行ったところ、KPI表示に矛盾が生じることを確認した。

## 再現手順

1. 中村夫婦シリーズ相当のプロファイルを読み込む
2. ライフイベントで「収入」→「退職金」を追加
   - 対象者：配偶者
   - 開始年齢：53歳
   - 期間：1年
   - 金額：1,000万円/年
3. 更新後のKPIグリッドを確認

## 観測された結果(矛盾あり)

| KPI | 本人 | 配偶者 |
|---|---|---|
| iDeCo(手取り) | 2,808万円 | 391万円 |
| 退職金(手取り) | 0万円 | **0万円** |
| 退職所得税(合計:299万円) | 259万円 | **40万円** |

**矛盾点**：配偶者の退職所得税が40万円計上されているにもかかわらず、配偶者の退職金(手取り)は0万円になっている。課税されているなら相応の手取りが発生するはずで、両方が同時に成り立つのは不自然。

## 調査してほしいこと

1. このプロファイルの配偶者退職年齢(`spRetAge`相当のフィールド)は何歳に設定されているか。今回入力したイベント年齢(53歳)と一致しているか
2. 配偶者の退職金イベント(53歳・1,000万円)は、実際にどう処理されているか
   - 通常収入(`extraInc`相当)として扱われていないか
   - 退職所得課税ルート(`retirementTaxCalc`の配偶者向け呼び出し)に正しく渡っているか
3. 「退職所得税(配偶者)40万円」の内訳は何か。配偶者のiDeCo一時金のみに由来するものか、それとも今回追加した退職金イベントも含まれているか(含まれる場合、なぜ手取りKPIには反映されないか)
4. 配偶者の退職金イベントの年齢(53歳)が、プロファイルの配偶者退職年齢と一致しない場合、意図的に「一致しないと退職金として認識されない」仕様なのか、それとも認識されるべきだがされていない不具合か
5. `KpiGrid.tsx`の「退職金(手取り)」カードで、配偶者分の値がどの変数から参照されているか(関数名・変数名ベースで)。その変数が実際に0になっている原因
