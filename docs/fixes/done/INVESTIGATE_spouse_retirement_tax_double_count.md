# 調査指示書:配偶者の「退職所得税(合計)」にiDeCo年金課税分が混入している疑い

**種別:調査のみ(実装はしないこと)**
**背景:** KPIグリッド再編の完了報告で、Claude Codeから「『退職所得税(合計)』カードの値(`a.idecoLumpTax + a.spRetirementTaxKPI`)は、本人分(`idecoLumpTax`)は一時金税のみ、配偶者分(`spRetirementTaxKPI`)は一時金税＋年金税が混在という非対称な既存の計算がある」との指摘があった。実機確認の結果、この非対称が実際に数値の二重表示として顕在化していることを確認した。

---

## 再現条件(実機確認より)

- 本人・配偶者とも:iDeCo受取方式=年金、退職金イベントあり(勤続年数5年、退職金手取り739万円で本人・配偶者同額・対称条件)
- 結果:
  - 本人の退職所得税:61万円
  - 配偶者の退職所得税:**136万円**
  - 配偶者のiDeCo累計課税額(iDeCoカード側に別途表示):75万円
  - 61(本人) + 75(配偶者のiDeCo年金税) = 136 と数値が一致しており、**配偶者の退職所得税に、本来退職所得税に含まれるべきでないiDeCo年金税(75万円)が加算されている**ことが強く示唆される

---

## 本来あるべき仕様(確認事項)

退職所得税というKPIは、税制上「退職所得」に分類される課税(退職所得控除→1/2課税→分離課税)の合計を表すべきである。これに該当するのは:
- 退職金の一時金
- iDeCoの一時金受取(併用選択時は一時金部分のみ)

iDeCoの**年金**受取(公的年金等控除適用・雑所得課税)は、この概念に含まれるべきではない。この年金分の税額は、既にiDeCo(手取り)カードの「累計課税額」として別枠表示されているため、退職所得税カードに含めると二重計上になる。

本人側の`idecoLumpTax`は一時金税のみを正しく参照していると思われるため、**配偶者側の`spRetirementTaxKPI`が一時金税だけでなく年金税まで合算してしまっている実装になっていないか**を調査する。

---

## 調査してほしいこと

1. `spRetirementTaxKPI`(またはこれに相当する変数)の算出箇所(`analyze.ts`または`simulate.ts`)を特定し、具体的に何を合算しているかを確認する。
2. 本人側の`idecoLumpTax`の算出箇所と比較し、対称になっていない点(配偶者側だけ年金税が混入している具体的な計算式・変数)を特定する。
3. なぜ非対称な実装になったのか、経緯を確認する(配偶者機能の後追い実装時の同期漏れである可能性が高いが、実際にそうか確認すること)。
4. この二重計上が影響する範囲を確認する。「退職所得税(合計)」カードの表示だけの問題か、それとも他のKPI(世帯の手取り合計等、この値を参照している別の集計)にも影響が波及しているか。
5. 修正の方向性(案・実装はしないこと):配偶者側も本人側と同様、退職所得税には一時金税のみを計上し、年金税は含めない形に揃えるのが妥当と考えられるが、この認識で問題ないか確認すること。
