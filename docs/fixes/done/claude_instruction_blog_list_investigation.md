# 指示書: ブログ一覧の再設計（段階C）に向けた事前調査

## 種別

**調査専用**。コード変更・git commit/push は一切行わないこと。ブラウザ上でスタイルを一時的に書き換えて見え方を確かめるのは可。ただしソースは変更しないこと。

## 背景

お悩み一覧・ツール一覧は、次の対応を完了してmainにマージ済み。

- LP幅への統一
- 共通 `PageHeader`
- 共通 `Breadcrumb`（表示とJSON-LDを同じ配列から出力するもの）

今回はブログ一覧ページを再設計する。予定している構成は次のとおり（まだ実装しない）。

### 確定している方針

- 外側コンテナを `Container`（default）にして、LPと左端をそろえる
- ページ見出しを `PageHeader` に置き換え、パンくず「資産シミュレーター › ブログ」を付ける
- **2カラム構成**：左に記事一覧（メイン）、右に幅の狭い「注目記事」サイドバー（5記事程度）を置く
  - サイドバーは **lg以上でのみ表示**し、`position: sticky` で、記事一覧をスクロールしても固定表示されるようにする
- 注目記事は手動で選ぶ。ロックファイルの `blog.ts` にはフィールドを追加しない。別ファイル（例：`featuredPosts.ts`）にslugを表示順に並べる方式にする
- 記事詳細ページのパンくずを、共通 `Breadcrumb` に置き換える
  - 表記は現在の「Home › Blog › 記事名」から「資産シミュレーター › ブログ › 記事名」に変える
  - 表示とJSON-LDを同じデータから出す形にそろえる

### 調査結果を見て決める方針

- 記事カードの形：2列グリッドでサムネイルを上に置く形にするか、現在の横長（左サムネイル＋右テキスト）のままにするか
- カード上のバッジ：現在のカテゴリ（シミュレーター活用／FIRE基礎知識）から、フィルターと同じテーマ（topics）表示に変えるか
- フィルターのチップに記事件数を表示するか
- サイドバーの注目記事の下に、シミュレーターへの導線カードを置くか
- lg未満（スマホ・タブレット）での注目記事の出し方（例：フィルターの下に横スクロールのカード列）

## 調査項目

### 1. 現在の構造

- `BlogPage`・`BlogListClient` の構成（どこまでがサーバー側で、どこからがクライアント側か）
- 記事データ（`getAllPosts()` ／ `BlogPostMeta`）の全フィールドと、一覧で実際に使っているフィールド
- 現在の記事数（通常ブログ）
- サムネイル（アイキャッチ）がある記事とない記事の件数。画像の縦横比と、表示方法（`next/image` かどうか・サイズ指定）
- フィルターの仕組み
  - テーマ（複数選択）とステージ（単一選択）の状態をどこで持っているか
  - URLのクエリと連動しているか
  - 両方を選んだときの絞り込み条件（AND／OR）
- 絞り込んだ結果が0件のときの表示
- ブログ一覧に関係するGA4イベント（フィルタークリック・カードクリック等）があれば、イベント名と送信している値

### 2. 記事カード

- カードの現在のクラス構成
  - タイトルの `min-h-[49.5px]`（2行分の予約）
  - サムネイルの130px固定
  - 説明文の行数制御
  - カード全体がリンクかどうか
- カード上のバッジ（カテゴリ）の出し方と、`category` の値の種類ごとの件数
- テーマ（`topics`／`primaryTopic`）について：
  - 記事ごとの設定状況（未設定の記事があるか、複数のテーマを持つ記事の件数）
  - 表示名の対応表の所在（`blogTopics.ts` はロックファイル。読み取り専用で使えるかどうか）
- テーマごと・ステージごとの記事件数（チップに件数を出す場合の参考値）

### 3. 2カラム＋sticky サイドバーの実現性

- `position: sticky` を効かなくする要因が、ブログ一覧の祖先要素にないか（`overflow: hidden`／`overflow: auto` 等）。`layout.tsx` からページまでの祖先要素を確認すること
- ヘッダーの高さ（前回調査では59px）と、sticky の `top` 値の想定
- 仮に「メイン列 `1fr`＋サイドバー280〜320px＋間隔40px」とした場合の、1440px・1280px・1024px幅でのメイン列の幅（実測またはブラウザ上の一時的なスタイル書き換えで確認）
- 上記のメイン列の幅で、次の2案それぞれの見え方
  - 案1：現在の横長カード
  - 案2：2列グリッドでサムネイルを上に置くカード

  各案について、タイトル・説明文の1行あたりの文字数と、サムネイルの表示サイズを報告すること。ブラウザ上の一時的な書き換えでスクリーンショットを撮れる範囲で撮ること
- サイドバーに注目記事5件（カテゴリ小ラベル＋タイトル2行程度）を並べた場合の概算の高さ。1366×768・1440×900の画面高さに収まるかの見込み。シミュレーター導線カードを追加した場合も同様に報告すること

### 4. 既存の部品で流用できるもの

- シミュレーターへの導線カード・CTAボタンの既存コンポーネント（LPの最終CTA等）で、サイドバーに小さく置けるもの
- 横スクロールのカード列（カルーセル）の既存実装があるか
- 前回新設した `PageHeader`・`Breadcrumb`・`JumpChips` をブログにそのまま使えるか

### 5. 記事詳細ページのパンくず

- `blog/[slug]/page.tsx` の現在のパンくず（表示用 `<nav>` と BreadcrumbList の JSON-LD）の実装
- 共通 `Breadcrumb` に置き換える場合の項目（資産シミュレーター › ブログ › 記事名）と、JSON-LDの `item` URLの組み立て
- 置き換えでJSON-LDの出力内容がどう変わるか（変更前後の差分の見込み）
- 一人法人ブログの記事詳細（`hitori-hojin/blog/[slug]/page.tsx`）も同じ構造だが、**今回は対象外**の予定。影響がないことだけ確認すること

### 6. 入れ子の `<main>`

- 前回報告された、`BlogPage`・記事詳細ページ・使い方ガイドの `<main>` が入れ子になっている問題について、ブログ一覧と記事詳細で `div` に置き換える場合の影響（スタイル・スキップリンク等）

### 7. 現状スクリーンショット

- ブログ一覧：375px・768px・1024px・1440px のファーストビュー
- ブログ一覧：1440pxで記事カードが2〜3件見えるところ
- 記事詳細：1440px・375pxでパンくずが見える部分（任意の1記事）

## 検証環境の安全ルール（必ず守ること）

- `localStorage.clear()` などの破壊的操作は行わないこと。どうしても必要な場合は、対象オリジンが検証専用であることを確認し、実施前に報告すること。判別できない場合は操作せず、KENZOに確認を求めること
- devサーバーを停止するときは、ポートからPIDを特定し、そのPIDだけを個別に停止すること。`taskkill /F /IM node.exe` のような全プロセス一括終了コマンドは**使用禁止**
- この指示書を `done/` へ移動するのは構わないが、`docs/fixes/active/` フォルダ自体は削除しないこと
