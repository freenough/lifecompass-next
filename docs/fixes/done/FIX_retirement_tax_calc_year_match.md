# 実装依頼：retirementTaxCalcの「同年受取」判定漏れ修正

## 背景

`AUDIT_severance_ideco_deduction_mixup.md`の調査で、`src/lib/helpers.ts`の`retirementTaxCalc`関数に以下の不具合が確認された。

```javascript
const yrs = Math.max(1, Math.floor(hasSev ? Math.max(dcYears, sevYears) : dcYears));
```

`hasSev`(`severanceAmount > 0`)だけで分岐しており、`idecoBalance`(その年に実際にiDeCoを受け取っているか)を見ていない。そのため、退職金とiDeCo一時金が異なる年に発生する場合でも、退職金の控除計算に無関係なiDeCo加入年数(`dcYears`)が混入する。本人・配偶者どちらの呼び出しにも共通する欠陥。

KENZOと相談の結果、以下の3分岐に修正することでGO済み。

- 退職金のみ(iDeCo受取なしの年) → `sevYears`のみを使う(今回の修正対象)
- iDeCoのみ(退職金なしの年) → `dcYears`のみを使う(既存のまま、変更不要)
- 同年に両方受け取る場合 → `max(dcYears, sevYears)`で一本化(既存のまま、変更不要)

## 実装内容

1. `src/lib/helpers.ts`の`retirementTaxCalc`関数内、`yrs`の算出ロジックを、`severanceAmount > 0`だけでなく`idecoBalance > 0`も見て、上記3分岐になるよう修正する
2. 呼び出し側(`src/lib/simulate.ts`の本人・配偶者それぞれの`retirementTaxCalc`呼び出し箇所)に変更が必要か確認し、必要であれば対応する

## 実装前に確認してほしいこと(KENZO指定)

1. **`totalIdeco > 0`を「その年にiDeCoを受け取った」の判定として使って問題ないか**：ゼロ円受取や、残高はあるが今年の受取額が0円になるような特殊ケースが存在しないか確認すること。存在する場合、より適切な判定方法(例:受取フラグの別変数があるか)を検討すること
3. **`retirementTaxCalc`自体の責務の明確化**：この関数はすでに`idecoBalance`・`severanceAmount`の両方を引数として受け取っているため、「同年受取かどうか」の判定はこの関数内で完結できる設計になっている。呼び出し側(`simulate.ts`)で年数を決めて渡す設計にすべきか、関数内部で判定する設計にすべきか、現状のアーキテクチャ(呼び出し箇所が本人・配偶者の2箇所ある)を踏まえてどちらが適切か判断し、その判断根拠も報告に含めること

## 回帰テスト(KENZO指定・4ケース必須)

1. 退職金のみ(iDeCo受取なしの年に退職金を受け取るケース)
2. iDeCoのみ(退職金なしの年にiDeCo一時金を受け取るケース)
3. 同一年受取(退職金とiDeCo一時金を同じ年に受け取るケース。既存ロジックの`max(dcYears, sevYears)`が維持されることを確認)
4. 別年受取(今回の不具合ケース。本人:退職金55歳・iDeCo受取65歳。修正後、退職金の控除にdcYearsが混入しないことを確認)

上記4ケースについて、本人側・配偶者側の両方で確認すること(前回の調査で「本人固有の不具合ではなく関数自体に内在する欠陥」と判明しているため)。
