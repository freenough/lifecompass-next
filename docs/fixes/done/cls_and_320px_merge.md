## 1. マージ

1. `git status`で、変更が未追跡の`docs/fixes/active/`の指示書だけであることを確かめる。
2. `main`に切り替え、`git pull`で`origin/main`が`ad07e1f`であることを確かめる。違えば、**マージせず報告**。
3. `git merge --no-ff fix/cls-and-320px`。**メッセージはファイルにして`-F`で渡す**（`git merge -F -`は標準入力が読めない）。
   - 1行目の案：`Merge branch 'fix/cls-and-320px': CLS解消と320px幅の収まり`
   - 本文：3commit（`8ac6ff7`、`ebe8fdd`、`e0b151b`）の要点を、箇条書き3行。
4. マージ後、`git diff ad07e1f..HEAD`が、`git diff main..fix/cls-and-320px`（マージ前に取っておく）と**SHA-256で一致する**ことを確かめる（新規ファイル`HeroDemoChart.tsx`は内容のハッシュで）。
5. `git push origin main`。**mainのpushは1回。**
6. 報告：マージcommitのハッシュ、`git log --oneline -5`。

## 3. 本番確認

### 3-0. デプロイを待つ
- GitHubの公開API（curl）で、マージcommitのデプロイ状況が`success`になるまで待つ（`gh`は未インストール）。`success`になる前に本番を測らない。
- 本番URL：資産シミュレーターLP https://www.freenough.com/asset-simulator 、一人法人LP https://www.freenough.com/hitori-hojin 。

### 3-1. 測定の条件
- 広告・計測スクリプトは止める（遮断するのは`googlesyndication`と`googletagmanager`だけ）。乱数は、これまでの手順で固定する。
- 本番とローカルの**画素比較はしない**（フォントの描画が違う）。要素ごとの`getComputedStyle`・`getBoundingClientRect`の値と、目視で判定する。

### 3-3. 「枠が先に出て、下が動かない」ことの確認（目視の代わり）
資産シミュレーターLP、375px（と320px）で：
1. `requestAnimationFrame`で、**Heroの説明文・Hero CTA・その下のセクションの`getBoundingClientRect().top`を、最初の描画から5秒間、毎フレーム記録**する。**最大の変化量（px）**を報告する。（変更前は、約+354px動いていた）
2. 同じ画面のスクリーンショットを、**「JavaScript無効」「描画直後（約300ms）」「約1秒後」「4秒後」**の4枚撮り、Readで見て、**枠・「計算中…」・チャートが現れる様子を言葉で説明する。** 読み込み中の見た目に、不自然な点（空白の大きな隙間、文字の重なり、はみ出し）がないかを報告する。
3. KPI3つ（FIRE達成・資産寿命・MC破綻率）について、計算前と計算後で、KPIの行の**高さが変わらない**ことを実測する。

### 3-4. 320px幅の収まり（実測）
- 資産シミュレーターLP：Hero CTAの幅が272px、はみ出し0、`scrollWidth === innerWidth`。340 / 360 / 361 / 375pxで、第2段階の表と同じ値（304px、余白は360px以下で16px、361px以上で32px）。他の2つのCTAは、前後で同じ。
- 一人法人LP：「完全リタイア」が320pxで1行（340px以上も1行）。`CTA_BUTTON_CLASS`を使う3か所が、320pxで272px以下、はみ出し0。360〜362pxの既知の「図が本文幅を超える」状態（6.48 / 5.48 / 4.48px）が、前後で変わらない。
- **本番では、`getComputedStyle`で、変更後のクラスが効いているか**（パディング値が、360pxで16／24、361pxで32）を確かめる。

### 3-5. PC幅の見た目
- 資産シミュレーターLPと一人法人LPの、1024 / 1280pxの上部（Hero）のスクリーンショットを撮って目視し、**崩れ・はみ出し・重なりがないか**を報告する。画素比較はしない。

### 3-6. 他のページ（巻き込み確認）
- `CTA_BUTTON_CLASS`は一人法人LPの3か所だけ、`HeroDemo`は`/`だけで使われている（第1段階で確認）。念のため、**`/assets`と、ブログの1ページ**で、横あふれが出ていないか（320px・375px）を、読むだけで確かめる。

## 4. ブランチの削除（本番確認が受け入れを満たした場合だけ）

- **受け入れを満たさない項目があれば、削除せずに報告して止まる**（ブランチが復元用になる）。
- 満たした場合：
  - `git branch -d fix/cls-and-320px`、`git push origin --delete fix/cls-and-320px`（**`-D`は使わない**）。
  - **`git branch -a`と`git ls-remote --heads origin`で、消えたことを確かめて報告する。** 出力をそのまま貼る。
  - 復元用に、削除前のハッシュ（`e0b151b`）を報告に書く（`git branch <name> e0b151b`）。
- freenough-mainのブランチは、今回触っていない。念のため、`git branch -a`と`git ls-remote`で、作業ブランチがないことだけ確かめる（読むだけ）。
