## 1. 「今すぐ記録する」バナーが消えない不具合

### 1.0 現象

プロファイル「テストB」で、「保有資産」の記録履歴に**既に2026-09（今月）分の記録（885万円）が存在する**にもかかわらず、「今月はまだ記録していません。資産の推移を残しておきましょう。」バナーと「今すぐ記録する」ボタンが表示されたまま消えない。他のプロファイルでは同じ状況でも正しく消えている（未確認、可能性として報告）。

添付スクリーンショット（KENZOが実際に操作した画面）：記録日一覧に「2026-09：885万円」が表示されているのに、上部バナーが「今月はまだ記録していません」のまま。

### 1.1 調査してほしいこと

1. このバナー・ボタンの表示条件を判定しているコード（`AssetManagementPage.tsx`と思われるが、実際のファイル・関数を特定すること）を引用する
2. 「今月既に記録済みかどうか」の判定が、どのデータソース（`snapshots`＝個人の記録履歴か、別の何かか）・どんな比較ロジック（日付文字列の比較か、`Date`オブジェクトの比較か）で行われているかを確認する
3. 「プロファイルによって再現する・しない」という手がかりから、判定ロジックが特定のプロファイルのデータ構造（例：スナップショットの日付フォーマットの違い、`profileId`のフィルタ漏れ等）に依存していないか確認する。前回修正した「法人スナップショット配列だけを土台にする」パターンと類似の原因がないか、念のため確認すること
4. 実際に「テストB」のスナップショットデータ（`2026-09`のレコード）の`date`フィールドの実際の値（フォーマット）を確認し、判定ロジックが期待する形式と一致しているかを確認する

## 2. 計画の同名重複保存

### 2.0 現象

「計画を保存」フォームで、既存の計画と同じ名前を入力して保存すると、上書き確認なしにそのまま重複保存されてしまう（添付画像で「testp03」が個人のみ版・法人取崩込み版それぞれ2件ずつ、計4件重複しているのが実際に確認された）。他のプロファイル管理機能（資産管理ツールのプロファイル等）では、同名の場合に上書き確認のポップアップが出る。

### 2.1 調査してほしいこと

1. `PlanManagerPanel.tsx`の`handleSave()`（保存処理）が、既存の計画名との重複チェックを一切行っていないことを実コードで確認する
2. 他のプロファイル管理機能（例：資産管理ツールのプロファイル保存、`AssetManagerProfilePanel.tsx`等）で、同名時に上書き確認を行っている既存の実装を特定し、そのパターン（確認ダイアログの出し方、上書き判定の方法）を引用する。今回の修正でこのパターンをそのまま流用できるかを確認する
3. `savePlan()`（`src/lib/planSnapshot/storage.ts`と思われるが確認すること）が、名前の重複を許容する実装になっているか（一意性の制約が無いか）を確認する
