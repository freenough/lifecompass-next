# 調査指示書：FREENOUGH TOPページ UIアップデート（第一印象・崩れ/不揃いの整理）

作成日：2026-09-28
種別：**調査専用**（コード・設定・アセットの変更は一切行わない）
配置：`docs/fixes/active/investigation_top_page_ui_update.md`

---

## 0. 目的

FREENOUGHのTOPページ（ドメインルート）のUIアップデートに向けて、現状の構成と実測値を把握する。今回の改善の主眼は次の2点。

- **ブランドの第一印象**：見出し・理念ブロックの見せ方、ページ全体の締まり
- **崩れ・不揃いの整理**：2本柱ブロックのアイコン不統一・左右の揃え・ボタン幅、柱ブロック下の余白、フッターのリンク重複

本調査では**事実の収集のみ**を行う。修正案の作成・実装は行わない（方針はこの報告を見てから決める）。

---

## 1. 作業上の絶対ルール

1. **ファイルの作成・変更・削除を一切しない**（調査用スクリーンショットの保存先は後述の2.のみ）。調査開始時と終了時の`git status`を報告に含め、差分がないことを示す。
2. **コミット・push・ブランチ作成はしない。**
3. 覚えのない未commit変更が調査開始時にあった場合、中身に触れずそのまま報告する。
4. `tsconfig.tsbuildinfo`が書き換わった場合は元に戻し、戻したことを報告する。
5. 以下のロック対象ファイルは読むのみ（そもそも今回は全ファイル読むのみ）：`simulate.ts`・`analyze.ts`・`PortfolioPanel.tsx`・`simulatorStore.ts`・`profile.ts`・`blog.ts`・`blogTopics.ts`・`concerns.ts`・`ConcernCard.tsx`
6. **ブラウザでの実測時は、localhost以外の全ドメインへの通信を遮断する**（GA4・AdSense・アフィリエイトリンク等を含む）。クリック操作は原則行わない。
7. `localStorage.clear()`等の破壊的操作は行わない。必要になった場合は、対象オリジンが検証専用であることを確認・報告し、判別できなければ操作せずKENZOに確認する。
8. devサーバーを停止する場合は、ポートからPIDを特定して個別停止する（`taskkill /F /PID <番号>`等）。`taskkill /F /IM node.exe`等の一括終了は禁止。
9. `docs/fixes/active/`フォルダ自体は削除しない（指示書を`done/`へ移す場合も、フォルダは残す）。

---

## 2. スクリーンショットの保存先

- `.gitignore`で除外されているディレクトリがあればそこに保存し、パスを報告する。
- 該当がなければリポジトリ外（例：OSの一時フォルダ）に保存し、パスを報告する。リポジトリ内に新規ファイルを残さないこと。

## 3. 調査項目

### 3.1 TOPページの所在と構成

`lifecompass-next`は`basePath: '/asset-simulator'`のため、ドメインルート（TOP）を描画している箇所がどこかから確認する。

- TOPを描画しているリポジトリ・ファイルパス（別リポジトリ、rewrites、別アプリ等の可能性も含めて特定）
- TOPを構成するセクションとコンポーネントの一覧（ヘッダー／Hero見出し／理念ブロック／2本柱ブロック／フッター）と、それぞれのファイルパス・行番号
- 各セクションの文言がどこで定義されているか（JSX直書き・定数ファイル等）
- TOPで使われている色・フォントサイズ・余白のトークン（`globals.css`の`@theme`、CSS変数、Tailwindクラス）

### 3.2 ファーストビューの実測

以下のビューポートで、フルページと初期表示範囲のスクリーンショットを撮り、各要素の位置（上端y・下端y、px）を表にまとめる。

| 幅×高さ |
|---|
| 375×667 |
| 390×844 |
| 768×1024 |
| 1024×768 |
| 1280×720 |
| 1366×768 |
| 1440×900 |
| 1920×1080 |

計測する要素：
- Hero見出し（ブロック全体）
- 理念ブロック（グレー帯全体）
- 2本柱ブロック（見出し・ボタンそれぞれ）
- フッター上端

あわせて、各ビューポートで「2本柱のボタンが初期表示範囲に入っているか」をYes/Noで記録する。

### 3.3 Hero見出し・理念ブロック

- 見出しのフォントサイズ・ウェイト・行間・字間（clamp等の可変指定があれば各ビューポートでの計算値）
- 見出しの改行位置の制御方法（`<br>`、`text-wrap`、`word-break`、改行禁止指定等）と、各ビューポートでの実際の改行結果
- Hero・理念ブロックそれぞれの上下padding／margin（指定値と計算値）
- 理念ブロックの本文フォントサイズ・行間・段落間隔・最大幅

### 3.4 2本柱ブロック

**アイコン**
- 2つのアイコン（コンパス／ビル）のファイルパス・形式（SVG/PNG等）・元サイズ（SVGならviewBox）・表示サイズ
- コンパスアイコン周囲にうっすら見える四角が、画像自体に含まれる背景か、CSSによるものか
- 同じアイコンが他の場所（資産シミュレーターLP、一人法人LP、ヘッダー、OGP、favicon等）でも使われているか。使われている場合は使用箇所の一覧

**レイアウト**
- 2列を並べている方法（grid/flex、クラス、列幅、ギャップ）と、1列に切り替わる幅
- 1440×900で、左右それぞれの列について「アイコン左端・見出し左端・説明文左端・ボタン左端」のx座標を計測し、表にする（左右で揃え方が違うかどうかを数値で示す）
- 各列のテキスト揃え（text-align等）の指定
- 2つのボタンの幅・高さ・padding、幅が内容依存か固定か

**余白**
- 2本柱ブロックの下端からフッター上端までの距離と、その距離を生んでいる指定（padding、min-height、flex-grow等）

### 3.5 ヘッダー・フッター

- ヘッダー・フッターのコンポーネントファイルパス
- **それぞれがどのルートで描画されているか**（TOPと`/asset-simulator`配下・`/hitori-hojin`配下で同じコンポーネントか、TOPだけ別か）
- フッターの全リンクを、ブロックごと（「FIREを考える」列、「一人法人を考える」列、中段のリンク行、下段のリンク行、SNS等）に一覧化し、以下を表にまとめる
  - 表示テキスト
  - href
  - 実装方法（`next/link`／`<a>`、絶対URL定数使用の有無、`HITORI_HOJIN_SITE_URL`使用の有無）
  - 同じリンク先が他のブロックにも存在するか（重複の有無）
- ヘッダーのナビゲーションリンクも同じ形式で一覧化する
- 「シミュレーター」「資産シミュレーター」の表記が、それぞれハブLP（`/asset-simulator`）とアプリ本体（`/asset-simulator/app`）のどちらを指しているか、全リンクについて明記する

### 3.6 参考：既存LPとの共通要素

TOPの見た目を他LPと揃える判断材料として、以下を記録する（変更はしない）。

- 資産シミュレーターLP・一人法人LPのHeroで使われている、セクション余白・見出しサイズ・カード装飾（角丸・影・境界線）の指定と、共通化されたトークン（`--lp-*`等）の一覧
- TOPでそれらのトークンが使われているか、独自指定か
