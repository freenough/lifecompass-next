# 指示書:繰上返済(単発)対応 — ロジック実装(simulate.ts/helpers.ts)

**このセッションの役割:** 実装。ただし`simulate.ts`はロックファイルであり、今回は「一度きりの管理された例外」として変更を許可する。設計判断が必要な箇所に遭遇した場合は独断で進めず、いったん停止して報告すること。

**スコープ外(別指示書で対応):** `LifeEventTimeline.tsx`のモーダルUIへの繰上返済入力欄追加・試算表示・注記文修正は、本指示書のスコープ外。今回は`LifeEventTimeline.tsx`のローカル`calcMortgage`/`calcMortgageMonthly`重複解消(`helpers.ts`からのimportへの統一)のみ行う。

## 背景

住宅ローン+FIRE記事に続く新ツール企画(繰上返済 vs 投資比較ツール、第8弾候補)のため、`simulate.ts`のローン計算に繰上返済(単発)対応を追加する。事前調査(`investigation_mortgage_prepayment_calc.md`、完了済み)により以下が判明している。

- 正本の計算関数は`src/lib/helpers.ts:3-10`の`calcMortgage(principal, rate, termYears)`(元利均等返済の月次/年次返済額を返すクローズドフォーム)
- `simulate.ts:177-186`が毎年この関数を呼び、`evAge`〜`evAge + ev.years`の固定期間で加算しているだけ。残高(未返済元本)を年次で追跡する状態は存在しない
- `LifeEventTimeline.tsx:37-50`にローカル重複実装(`calcMortgage`/`calcMortgageMonthly`)があり、`helpers.ts`からimportしていない。UI表示専用で実計算には使われていないが、二重管理状態

## 実装要件

### 1. 残高計算関数の新設(両方式の共通前提)

`helpers.ts`に、繰上返済時点での未返済元本を求める関数を追加する。複利年金の残高公式によるクローズドフォームとし、ループでの月次シミュレーションにはしないこと(既存コードのスタイル・パフォーマンス方針に合わせる)。

関数名・シグネチャは実装者の判断で構わないが、以下を満たすこと。
- 入力:当初元本・金利・当初返済年数・経過年数(または経過月数)
- 出力:その時点の残高

### 2. 返済額軽減型の実装

繰上返済後、残存期間はそのまま(短縮しない)、残高から新しい月々返済額を`calcMortgage`で再計算する。既存の`calcMortgage`をそのまま呼び出せる設計であることを確認しながら実装すること。

### 3. 期間短縮型の実装

繰上返済後、月々返済額は変えず、新しい残存期間を逆算する。`calcMortgage`とは逆方向の式(返済額から期間を求める、対数を使うクローズドフォーム)を新設すること。

**バリデーション必須:** 「月々返済額 ≤ 利息のみ返済額」のケースは残高が減らず解が存在しない。この場合はエラーを返す、または期間短縮効果なしとして扱う設計とし、呼び出し元(UI側、次回指示書で対応)がハンドリングできる形にすること。

### 4. `simulate.ts`側の統合

住宅ローンイベントの新規フィールドとして、繰上返済年齢・繰上返済額・繰上返済方式(期間短縮型/返済額軽減型)を追加する。

**後方互換性が絶対条件:**
- 新規フィールドは全てoptional
- 未指定時は現行の`simulate.ts`の計算と完全に同一の結果を返すこと(1円単位で一致)
- `simulate.ts:177-186`のブロックを、繰上返済年齢以降で新しい返済額/新しい終了年齢に切り替わるよう書き換える。ループの終了条件が可変になる点に注意すること(調査報告で指摘済み)

### 5. `LifeEventTimeline.tsx`の重複解消

ローカル`calcMortgage`/`calcMortgageMonthly`(37-50行目)を削除し、`helpers.ts`からのimportに統一する。UI表示専用ロジックであり、simulate()への影響はないが、二重管理によるロジック不一致を防ぐため必須対応とする。

**今回はUIに繰上返済入力欄を追加しないため**、このコンポーネントの表示・機能自体に変更は生じない想定(importの統一のみ)。挙動が変わらないことを確認すること。
