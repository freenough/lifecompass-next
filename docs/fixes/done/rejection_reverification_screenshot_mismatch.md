# 差し戻し：再確認調査（証跡強化版）のスクリーンショットがキャプションと一致しない

作成日：2026-09-05
種別：**調査のみ（実装は行わない）。前回提出された`reverification_simulator_companystate_with_evidence.md`のフル報告を、証跡不備のため差し戻す**
関連：`reverification_simulator_companystate_with_evidence.md`（前回の再確認調査指示書）

## 0. 差し戻しの理由

前回提出されたフル報告（スクリーンショット7枚＋localStorageダンプ＋キャプション）を、KENZOとこのチャットで実際に画像を1枚ずつ確認したところ、**キャプションと実際の画像の中身が一致していない箇所が複数見つかった**。具体的には：

- 「画像2＝1節-B 対比用の資産管理ツール（URL: `/asset-simulator/assets`）」というキャプションだったが、実際の画像2は資産管理ツールではなく、**依然としてシミュレーター本体の法人ポートフォリオ画面**だった（グラフ凡例に「比例取崩」等シミュレーター側特有の表示があり、資産管理ツールの画面とは明らかに異なる）
- 「画像7＝手順8（『検証F』読込直後、現金分が500万円に復元）」というキャプションだったが、実際の画像7は**「資産管理」という全く別ページ**（保有資産・法人保有資産・予実比較グラフの画面）であり、検証対象である法人ポートフォリオの「現金分」入力欄自体がそもそも存在しない。今回の調査で最も重要な「読込直後に画面が正しく切り替わったか」を示す証拠として機能していない
- 画像3〜6も、キャプションの説明順序と画像内の値（現金分111万円／500万円）の対応関係が食い違っており、記載されている手順の順序通りに撮影されたか疑わしい

**「コードは正しいはずだから」という説明は前回同様受け取らない、と既に伝えた通り、今回は「証拠画像を出したこと」自体も、内容が対応していなければ意味がない。** キャプションを後から付ける方式では、この種の取り違えが起きることが今回証明された。撮影方法自体を変えて、再度実施すること。

## 1. 今回の必須ルール（前回との違い）

- **キャプションは後付けしない。** 各スクリーンショットを撮る**直前**に、「これから何のURL・どの手順を撮るか」を1行で明記し、その直後に撮影する。画像ファイル名または撮影直後のメッセージで、手順番号とURLを必ず紐づけること
- 撮影の順序を並べ替えない。手順1から手順9まで、実際に操作した順番のまま提出すること（後から並べ替えたり、近い状態のスクリーンショットを流用したりしない）
- 資産シミュレーター本体（`/asset-simulator/app`想定）と資産管理ツール（`/asset-simulator/assets`想定）を対比する画像は、**それぞれのブラウザのアドレスバー全体が写るように**スクリーンショットを撮ること（URLがキャプションだけでなく画像自体からも確認できるようにする）
- 各手順の画像は、**その手順で確認すべき対象（法人ポートフォリオの現金分入力欄など）が実際に画面内に写っていること**を、送信前に自分自身で見比べて確認すること。写っていない画像は撮り直すこと

## 2. 再実施する内容

`reverification_simulator_companystate_with_evidence.md`の2節（再現テスト手順1〜9）・3節（再レンダリング確認）を、1.のルールに従って**全て撮り直す**こと。手順自体の変更は不要（前回のテストシナリオ設計に問題があったわけではなく、証跡の取り方に問題があったため）。

- テストプロファイルは新規に作り直してよい（前回の「検証F」等が残っていれば削除してから）
- localStorageダンプは前回同様、各手順ごとに取得すること

- 調査のみ。修正は行わないこと
- `ProfileDrawer.tsx`・その他ロックファイルは変更しないこと
- テストデータは調査後に削除すること
