# 調査専用指示書 v2: Heroチャートのモバイル最適化＋Hero上部余白＋お悩みブロック左右余白

**本指示書は`investigation_hero_top_spacing_and_concern_block_spacing.md`(未着手)を差し替えるものです。上記ファイルは`docs/fixes/active/`から削除(またはdone/へ移動)し、本ファイルを使用してください。**

対象ブランチ: 前回の調査(`investigation_lp_mobile_first_view_hero_chart.md`、結果報告済み)の続き。`feature/lp-container-width`ブランチ、または新規ブランチで実施(判断は次フェーズ)

## 0. 前提・背景

前回の調査で、Heroチャートのモバイル見切れについて以下が判明済み:
- `min-height: 100dvh`は無効(コンテンツ自然高さがビューポートより大きいため)
- `py-16`→`py-6`相当の余白削減だけでは不十分
- 360px幅で見出しが3行に崩れる回帰バグを発見(別途対応予定)

さらにKENZOから実機(iPhone SE、Y!mobile回線、Safariツールバー展開時)のスクリーンショットが提供され、以下を確認:
- グラフ本体が「2.3億」の目盛り付近で見切れており、X軸ラベルは全く見えていない状態
- 前回報告の理論値(375×530想定)より実機の方がやや厳しい見切れ方

これを受けて、KENZOから新たに以下の相談があった:
1. Heroチャートのモバイル時の縦横比(高さ)を変更できないか
2. お悩みブロック(ツールセクション、見出し「かんたん計算ツール」)の**左右の余白**を圧縮したい(見出し〜1つ目のカードの縦の余白は対象外、現状維持でよい)

Hero上部余白の調査は前回指示書からそのまま引き継ぎ。**本指示書は調査専用**。方針決定・実装は次フェーズで行う(2フェーズ規律遵守)。

## 1. 調査目的

以下3点について、現状のCSS/実装を棚卸しし、変更した場合の実現可能性・副作用を確認した上で、比較候補パターンを複数提示する。

1. Heroチャートのモバイル時アスペクト比(高さ)の変更
2. Hero上部の余白圧縮
3. お悩みブロックの左右余白圧縮

## 2. 調査観点

### 2-1. Heroチャートのモバイル時アスペクト比変更

- 実機相当(375px幅、Safariツールバー展開時の実効高さ約530px)を基準に調査すること。理論値(375×667フル)のみでの確認は不可
- `HeroDemo.tsx`内の`CHART_HEIGHT = 300`(固定px、`ResponsiveContainer`の`height`にそのまま渡している)を、モバイル幅でのみ縮小する実装の実現可能性を確認
  - 案A: モバイル判定(メディアクエリ相当、またはJSでのwindow幅判定)で固定値を切り替える(例: モバイルは`CHART_HEIGHT = 220`)
  - 案B: 幅に対する比率(アスペクト比)で高さを算出する設計に変更する(`ResponsiveContainer`の`aspect`propの利用可否も含め確認)
- 高さを220px・250px・280pxの3パターン程度に縮小した場合、以下が破綻しないかスクリーンショットで確認
  - KPIバッジ3枠(FIRE達成/資産寿命/MC破綻率)の視認性・レイアウト崩れの有無
  - グラフ内のY軸目盛りラベル・凡例(FIREライン等)・データ線の視認性
  - X軸目盛り(年齢ラベル)が実機相当の実効高さ内に収まるか
- 高さ変更がデスクトップ表示に影響しないこと(モバイルのみのスコープであること)を確認

### 2-2. Hero上部余白

- 現状、ヘッダー下端からHero見出し上端までの合計空白(px)を、375×667・実機相当(375×530想定)・デスクトップ(1440px幅程度)それぞれで実測しスクリーンショットで記録すること
- Heroセクションの`py-16`(または該当クラス)が上下対称で設定されている箇所を`src/app/page.tsx`から特定
- 上のみを縮小する非対称パディング(例: `pt-6 pb-16`)にした場合、以下を確認すること
  - ヘッダーとHero見出しの間が詰まりすぎて窮屈に見えないか(モバイル・デスクトップ両方)
  - フルードタイポグラフィ(Hero見出しのclamp設定)やチャートカードとの相対位置に副作用が出ないか
- 上パディングを0px/16px(1rem)/24px(1.5rem)/32px(2rem)の4パターンで比較した際の見た目差分をスクリーンショットで記録

### 2-3. お悩みブロック(ツールセクション)の左右余白

- 対象: 見出し「かんたん計算ツール」を含むセクション(前回相談の「お悩みブロック」と同一、KENZO確認済み)
- **スコープ: 左右の余白のみ**。見出し〜1つ目のカードまでの縦の余白は他セクションと共通のため対象外、現状維持
- 現状の実装棚卸し
  - セクション全体のコンテナ左右padding(`px-*`)の現在値
  - カードグリッド自体に追加の左右marginがあればその値
  - 前回のコンテナ幅拡大(`Container`コンポーネント移行、対象7箇所)にこのセクションが含まれていたか確認。含まれていなければ旧来の`max-w-5xl px-6`のまま取り残されている可能性が高い
- 左右paddingを1〜2段階圧縮した候補値(例: `px-6`→`px-4`→`px-2`)でのスクリーンショット比較(モバイル375px基準)
  - カード内テキストが画面端に近づきすぎて窮屈にならないか確認
