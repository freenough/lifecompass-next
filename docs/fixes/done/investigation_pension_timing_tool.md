# 投資調査指示書:年金 繰上げ・繰下げ 比較シミュレーター(FREENOUGH Tools 第4弾候補)

## 背景・目的

FREENOUGH Toolsラインナップの第4弾候補として、公的年金の受給開始年齢
(繰上げ60歳〜繰下げ75歳)による年金額・損益分岐年齢を比較する単独ツールを
検討している。競合(LifePlan Lab `/tools/pension-timing`)を参考にしつつ、
FREENOUGH版は**計算結果を本体シミュレーターの年金入力欄(受給開始年齢・
年間受給額)に手動で転記し、他の資産・支出条件と合わせて詳細確認できる**
という導線を明確にCTAで案内する方針とする(自動転記は行わない。理由は
下記5参照)。

本ツールはfinance-core(積立・複利計算)とは全く異なる計算領域(公的年金の
増減率ルール)を扱うため、実装前に以下の調査を行い、設計方針を固める。

---

## 調査事項

### 1. 繰上げ・繰下げの計算式の確認(制度ルール)

- 繰下げ:1ヶ月当たり+0.7%、65歳から75歳まで(最大+84%、120ヶ月)
- 繰上げ:1ヶ月当たり-0.4%(1962年4月2日以降生まれ)/ -0.5%(1962年4月1日
  以前生まれ)、60歳から65歳まで(最大-24%、60ヶ月)
- 生年月日による繰上げ率の違いをどう入力させるか
  (生年月日そのものを入力させるか、「1962年4月2日以降生まれ」の該当有無を
  簡易選択にするか)を、Tools共通原則(入力少・即答)との兼ね合いで検討
- 老齢基礎年金・老齢厚生年金で、繰上げ・繰下げのルールが完全に同一か
  (原則同時請求である点も含む)を確認

### 2. financeCore.tsとの関係整理

- 既存のcalc関数群(`calcRequiredMonthlyContribution`・`calcAchievementAge`・
  `calcFutureValue`)は積立・複利計算領域であり、本ツールの計算(年金増減率・
  損益分岐年齢)とは性質が異なる。以下いずれの設計にすべきか判断:
  - (a) `financeCore.ts`に新規関数として追加
  - (b) 別ファイル(例:`pensionCore.ts`)に分離
- 既存の命名規則(`calc`プレフィックス、利率は%表記、境界値は`number | null`で
  意味を区別)を踏襲すること

### 3. 損益分岐年齢の計算ロジック確認

- LifePlan Lab方式:比較終了年齢(80/85/90/95/100歳)までの累計受給額を
  年齢ごとに積み上げ、基準(65歳受給)との交点を算出
- 端数・丸めルールの検討(第2弾`fire-age`はfloor切り捨てを採用した経緯
  [未到達を到達済みと誤表示するリスク回避]があるが、本ツールの損益分岐年齢は
  「得か損か」の目安であり第2弾とは性質が異なるため、四捨五入で問題ないか
  改めて判断すること)

### 4. 単位・出力形式の整合性確認

- 本体シミュレーターの年金入力欄:「年金開始年齢」(`ppAge`、60〜90歳)・
  「年間受給額」(`ppAmt`、万円/年)と、本ツールの出力単位が完全に一致する
  ことを確認(万円/年、整数または小数第1位までか)

### 5. CTA・導線設計の前提確認(重要、Product Spec前の共有事項)

- **方式B(手動転記)を確定方針とする。** 自動転記(URLパラメータ等での
  本体シミュレーターへの反映)は本体側の改修を伴い、得られる価値(2つの数値の
  転記の手間削減)に対してコストが見合わないと判断し不採用
- CTA文言には、単なる「本格シミュレーターへ」ではなく、**「この結果(年金
  開始年齢・年間受給額)を資産シミュレーターの年金入力欄にそのまま入力すると、
  他の資産状況・支出・NISA等と組み合わせた詳細なシミュレーションができます」**
  という趣旨を明確に案内する(第2弾`fire-age`のCTA文言パターン
  [限界の明示+本体誘導の一文]を踏襲した設計とする)
- 本体シミュレーターの年金ポップオーバー(`popPen`)が「年間受給額」を
  ねんきん定期便の見込額としている点との整合性(本ツールの出力もそのまま
  同じ形式の数値として使える設計にする)を確認

### 6. Tools共通原則との整合性チェック

- 入力を何項目に収められるか試算:
  (65歳時点の老齢基礎年金額・老齢厚生年金額・生年月日区分・比較終了年齢)の
  4項目で第1〜3弾(4〜5項目)と同水準に収まるか確認
- 30秒以内で結果表示・1画面完結の原則に合致するか

## 期待するアウトプット

- 計算式の実装方針(境界値ケース含む:60歳ちょうど、75歳ちょうど、
  生年月日境界の1962年4月1日/2日等)
- ファイル配置方針(`financeCore.ts`拡張 or 新規ファイル、理由付き)
- 検証スクリプト方針(`verify-pension-timing.js`想定:境界値+代表+ランダム、
  第1〜3弾と同水準の網羅性)
- CTA文言案(上記5の趣旨を反映した具体的な日本語文言、複数案)
- 入力項目の最終案(4項目に収まるか、収まらない場合の代替案)
