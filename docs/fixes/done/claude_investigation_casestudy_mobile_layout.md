# 調査指示：ケーススタディセクション モバイルレイアウト崩れの原因調査

作成日：2026-09-21
種別：**調査のみ（実装・修正は一切行わない）**
関連：`handoff_lp_grid_to_story_layouts.md`（前回セッション、ケーススタディの人物イラスト化・ストーリー形式レイアウト化を実装・本番マージ済み）

## 背景

前回セッションで、LPトップのケーススタディセクションを「2×2グリッド」から「縦に積む横長の帯（左右交互配置）」に変更し、本番マージ済み。PCでの見た目は意図通り（添付スクリーンショット参照：アバター＋タイトル＋名前・属性＋引用文が横並びの帯として整列し、右端に「公開中」バッジと「noteで読む→」リンクが揃って配置されている）。

しかし、KENZOがiPhone SE実機（Y!mobile回線、狭い画面幅）で確認したところ、モバイル表示のみ以下のような崩れが発生している：

- タイトル文言（「」で囲まれたセリフ）が画面幅いっぱいに大きな文字で折り返され、5行前後に及んでいる
- アバター（円形イラスト）が、本来テキストの左（または右）に並ぶはずが、折り返されたタイトルの上に重なるように配置されている
- 「公開中」バッジと「noteで読む→」リンクが、カードの縦方向の中央あたりに宙に浮いたような位置に表示され、本文テキストと重なって見える
- 1件目のカード（田中さん）と2件目のカード（山本さん）でバッジの左右位置が入れ替わっており（交互配置がモバイルでもそのまま適用されている様子）、いずれも本文と衝突している
- 山本さんの属性テキスト（「34歳・独身エンジニア」以降）が画面下端で見切れている（スクロールで続きが見える可能性はあるが、レイアウト自体が破綻している）

PC版の意図した見た目とモバイル版の実際の見た目を添付画像で比較できるようにしてある（PC: `FIREシミュレーター__FREENOUGH_資産シミュレーター.png`、モバイル: `1789969229439_image.png`）。

**このタスクは調査のみを目的とする。** 原因を特定した上で持ち帰り、KENZOとの設計チャットで修正方針（実装指示書）を確定させる。調査の過程で気づいても、その場での“ついで修正”は行わないこと。

## 調査1：ケーススタディセクションのコンポーネント構造とレスポンシブ対応の有無

**確認したいこと**
- ケーススタディセクションを構成しているコンポーネントファイルの特定（前回セッションの引き継ぎメモに記載の、左右交互配置・帯レイアウトを実装した箇所）
- レイアウトの実装方式（Flexbox / CSS Grid / どちらか）と、左右交互配置をどう出し分けているか（`nth-child`によるCSSの向き反転か、propsでの条件分岐か等）
- モバイル用のブレークポイント（`sm:` / `md:`等のTailwindクラス、もしくはメディアクエリ）が実装に存在するかどうか。存在する場合、どのブレークポイントで何が切り替わる設計になっているか
- **特に、テキスト（タイトル・名前属性・引用文）の折り返しによってカードの高さが可変になった場合に、アバターやバッジの位置が追従する設計になっているか、それとも高さが固定/想定される前提で絶対配置（`position: absolute`等）されているか**

**対象ファイル**
- ケーススタディセクション本体のコンポーネントファイル（ファイル名不明のため、LPトップページの構成ファイルから辿って特定すること。前回引き継ぎメモの「ワークストリーム2」を参照）
- 前回新規作成された`src/components/lp/PersonaAvatar.tsx`

**報告フォーマット**
- レイアウト実装方式について、該当コード抜粋（CSS/Tailwindクラスを含む）とともに説明
- アバター・バッジそれぞれの配置方法（flexの一部か、absoluteか）を明記
- モバイル用ブレークポイントの有無・内容を具体的に列挙

## 調査2：バッジ（公開中／近日公開 ＋ noteで読む→）の配置ロジック

**確認したいこと**
- バッジ＋リンクが、カードのどの要素を基準に配置されているか（親コンテナに対する絶対配置か、flexの`justify-content`/`align-self`による配置か）
- 左右交互配置のカードで、バッジ側の位置（左右）がどう決まっているか（アバターと同じ側か、逆側か、固定か）
- モバイル幅でバッジがテキストと重なって見える現象について、コード上の原因に心当たりがあるか（例：`position: absolute; top: 50%`のような、カードの高さがテキスト量で変わることを想定していない配置指定になっていないか）

**対象ファイル**
- 調査1と同一のコンポーネントファイル

**報告フォーマット**
- バッジの配置に使われているCSS/クラスの該当箇所を抜粋
- モバイル幅で重なりが起きる理屈を、コードの根拠とともに説明

## 調査3：実機相当での崩れの再現確認

**確認したいこと**
- ブラウザDevToolsでビューポート幅を375px程度（iPhone SE相当）に設定し、本番URL（またはローカル環境）のケーススタディセクションで、添付モバイルスクリーンショットと同様の崩れが再現するか
- 再現する場合、どの要素がどのCSSプロパティによって重なっているのか、DevToolsの要素インスペクタで特定する

**遵守事項**
- 本番相当の実データ環境を検証で操作しない（閲覧・インスペクトのみ）

**報告フォーマット**
- 再現有無
- 再現した場合、崩れの原因となっている具体的な要素とCSSプロパティ（インスペクタのスクリーンショット推奨）

## この調査結果の使い道

この3件の調査結果を持ち帰り、KENZOとの設計チャットで以下を確定させる：
- モバイル用レイアウトの修正方針（例：flex-directionをモバイルで縦積みに変更する、絶対配置をやめて通常フローに戻す、バッジの位置をタイトル直下等の固定位置に変更する、等）
- 左右交互配置をモバイルでも維持するか、モバイルでは統一レイアウト（アバター常に上/左固定など）にするかの意匠判断
- 修正範囲がケーススタディセクション単体で閉じるか、`PersonaAvatar.tsx`側の変更も必要か
