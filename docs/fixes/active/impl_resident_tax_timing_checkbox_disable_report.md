# 完了報告:社会保険料率上書き時の「40歳以上65歳未満」チェックボックスのグレーアウト

`docs/fixes/active/impl_resident_tax_timing_checkbox_disable.md` の実装。

## 修正内容(`ResidentTaxTimingForm.tsx`)

- `values.useSocialInsuranceRateOverride`が`true`の間、「40歳以上65歳未満(介護保険料を含む)」
  チェックボックスに`disabled`属性を付与し、視覚的にグレーアウトした
  (`text-slate-300 cursor-not-allowed`をラベルに、`disabled:cursor-not-allowed`を
  input要素に付与)。
- グレーアウト時、チェックボックスの直下に「社会保険料率を直接入力しているため、この項目は
  使用されません。」という一言を追加表示した。
- チェック状態(`values.isAge40OrOver`)自体は`onChange`ハンドラをそのまま残しており
  (disabled属性のみ付与)、非活性化時にstateをリセットする処理は一切追加していない。
  「社会保険料率が分かっている」のチェックを外せば、`disabled`が解除されて再び操作可能になり、
  かつチェック状態は非活性化前のまま保持される。
- 計算ロジック側(`residentTaxTiming.ts`)は無変更。既存の優先順位ロジック
  (`socialInsuranceRateOverride ?? (isAge40OrOver ? 15.4 : 14.6)`)がそのまま機能する
  (見た目のみの修正であることを`tsc`・`full-verify.js`両方がPASSすることで裏付け済み)。

## 検証結果

- `node scripts/full-verify.js`: 全ブロックPASS(計算ロジックを一切変更していないため、
  resident-tax-timing側の329件を含め、他ツールも含め全て無変更でPASS)
- `npx tsc --noEmit`: エラーなし
- 検証スクリプトへの追加項目なし(本修正はUIの見た目・操作性のみの変更であり、
  `calcResidentTaxTiming()`の入出力に一切影響しないため。この点は`full-verify.js`が
  329件全て無変更でPASSし続けることそのものが「計算結果に変化がないこと」の証跡になっている)

## ブラウザ実機確認(`/asset-simulator/tools/resident-tax-timing`)

1. 退職月5月・「40歳以上65歳未満」にチェックを入れた状態で、「社会保険料率が分かっている」に
   チェックを入れると:
   - 「40歳以上65歳未満」チェックボックスが即座にグレーアウトし、クリックしても状態が
     変化しない(`disabled`)ことをスクリーンショットで確認
   - チェックボックス自体は「チェック済み」の見た目のまま保持される(非表示にはならず、
     操作不能な状態で表示され続ける)
   - 直下に「社会保険料率を直接入力しているため、この項目は使用されません。」の注記が
     表示されることを確認
   - 社会保険料控除の実際の適用値が92万円(15.4%相当)→88万円(入力欄のデフォルト値14.6%相当)
     に変わり、`isAge40OrOver`ではなく`socialInsuranceRateOverride`が優先されていることを
     数値面でも確認(既存の優先順位ロジックそのものは今回変更していないため、この結果自体は
     前回セッション〈phase2〉時点から変わらない挙動)
2. 「社会保険料率が分かっている」のチェックを外すと:
   - 「40歳以上65歳未満」チェックボックスが再び操作可能な状態(グレーアウト解除)に戻ることを確認
   - チェック状態が非活性化前のまま(チェック済み)保持されていたことを確認(社会保険料控除の
     表示が92万円〈15.4%〉に戻り、`isAge40OrOver`の設定が生き続けていたことを裏付け)
   - グレーアウト解除に伴い、注記文言も消えることを確認
