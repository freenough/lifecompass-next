# 実装指示:resident-tax-timing UIコピー改善(初心者向けのわかりやすさ、ロジック変更なし)

## 目的
専門用語(特別徴収・普通徴収・波1・波2等)に不慣れな読者でも、このツールが何を計算しているか
直感的にわかるよう、UI文言のみを改善する。**計算ロジック(`residentTaxTiming.ts`)は一切変更しないこと。**
型定義・関数名・変数名も変更しないこと(あくまで画面表示の文言のみが対象)。

## 全体方針
以下の説明構造を軸に、UI各所の文言を調整する:

1. 退職すると住民税は「2つの波」でやってくる、という全体像を先に伝える
2. 波1=「退職前から進行中だった住民税の残り」、波2=「退職した年の所得をもとにした新しい住民税」、
   という区別を、専門用語より先に平易な言葉で説明する
3. 「特別徴収」「普通徴収」等の制度用語は、初出時に必ず平易な言い換え(給与天引き/自分で納付)を
   併記する
4. 「波1」「波2」という呼称はこのツール独自の説明用語であり、正式な税制用語ではない旨を
   どこかで一言断る

## 具体的な修正箇所

### 1. `ResidentTaxTimingTool.tsx` — 導入文の追加

現在の見出し直下の説明文(「退職月・退職前年の年収から、住民税がいつ・いくら発生するかを
試算します。」)の後に、以下の趣旨の1〜2文を追加すること:

「住民税は「前の年の所得」をもとに翌年課税される仕組みのため、退職すると、①退職前から
進行中だった住民税の残り と ②退職した年の所得をもとにした翌年の新しい住民税、という
2つのタイミングでお金が必要になります。」

### 2. `ResidentTaxTimingResult.tsx` — セクション見出しの言い換え

- 現在の見出し「今の住民税の残り({incomeBasisYearLabel}の所得基準)」を、
  「① 退職前から進行中の住民税の残り({incomeBasisYearLabel}の所得基準)」に変更
- 現在の見出し「退職翌年6月からの新規課税」を、
  「② 退職した年の所得をもとにした、翌年6月からの新しい住民税」に変更
- 上記2つの番号(①②)は、ヘッドライン直下に追加する内訳表示(P0-1で実装済みの
  「天引き想定」「自己納付想定」の内訳)とは別の軸であることが伝わるよう、視覚的に
  区別すること(内訳は「お金の出どころ」の軸、①②は「税金の発生タイミング」の軸)

### 3. `ResidentTaxTimingForm.tsx` — 用語の言い換え

- 一括/分割トグルのラベル「普通徴収で分割」「退職時に一括で納める」を、
  「自分で分割して納める(普通徴収)」「退職時にまとめて天引きしてもらう(一括徴収)」に変更
  (制度用語をカッコ書きで残しつつ、平易な言葉を主にする)

### 4. `ResidentTaxTimingResult.tsx` の「計算根拠を見る」アコーディオン — 用語注記の追加

アコーディオン内の説明文冒頭に、以下の一文を追加すること:
「なお、「①」「②」という呼び方はこのツール内でのわかりやすさのための呼称であり、
税法上の正式な用語ではありません(税法上は退職所得・給与所得等、より詳細な区分があります)。」

既存の説明文中の「特別徴収」「普通徴収」という語が初出する箇所には、直後に
「(給与天引き)」「(自分で納付)」という言い換えをカッコ書きで追加すること
(P0/P1指示で既に修正した文言を上書きしないよう、既存の文言に言い換えを追記する形で対応)

### 5. `ResidentTaxTimingComparisonTable.tsx` — キャプションの平易化

現在のキャプション文言(徴収区分をまたぐと所得基準の年が切り替わる、という説明)の
専門的な言い回しを、「3月退職と9月退職では、住民税の計算のもとになる年が違うため、
金額も変わります」程度の平易な表現に調整すること(内容は変更しない)。

- 完了報告書に、修正前後の主要文言差分を明記すること
