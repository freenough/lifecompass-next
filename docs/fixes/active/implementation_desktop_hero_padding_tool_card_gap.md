# 実装指示書: デスクトップHero上部余白(A案)＋ツールセクションのカード間余白圧縮(モバイル限定)

対象ブランチ: `feature/lp-container-width`(継続)

## 0. 前提

- 直前の調査(`investigation_desktop_hero_foldline_and_tool_card_gap.md`)の結果を受け、方針を確定した
- デスクトップHeroの「お悩み」見切れは、B案(`lg:pt-56`)だと1440×900で差別化セクションのテキストが切れる新たな問題が生じるため不採用。**A案(`lg:pt-24`)を採用**。1920×1080の実効高さ(Chrome込み970px相当)では見切れが24pxまで縮小することを許容範囲とする
- working treeは前回調査時点でクリーンな状態(コミット不要)

## 1. デスクトップHero上部余白(A案)

- `src/app/page.tsx`のHeroセクション、現状`className="pt-4 pb-16"`を`className="pt-4 lg:pt-24 pb-16"`に変更する
- モバイル(`lg:`未満)は`pt-4`のまま変更しないこと(現状の見た目を維持)
- `lg:pt-24`適用後、Hero自体が間延びして見えないか(見出し〜チャートカードの間隔バランス)をデスクトップで目視確認すること。調査時にこの観点は未確認のため、今回必ず確認すること

## 2. ツールセクションのカード間余白(モバイル限定)

- 対象: 「かんたん計算ツール」セクションのカードグリッド
- 列間の`gap-x-6`を、**モバイル(`lg:`未満)のみ**`gap-x-4`に変更する。デスクトップ(`lg:gap-x-8`)は現状のまま変更しないこと
- カード内部の`p-6`を、**モバイル(`lg:`未満)のみ**`p-4`に変更する。デスクトップは現状の`p-6`のまま変更しないこと
- 実装は`gap-x-4 lg:gap-x-8`、`p-4 lg:p-6`のようなレスポンシブクラスの明示的な出し分けで行うこと

## 3. 検証範囲

- デスクトップ: 1440×900・1920×1080(フル)・1920×970(Chrome控除近似)の3パターンで、Hero〜差別化セクション〜お悩みラベルの見切れ状況をスクリーンショットで確認
- モバイル: 375px幅で、ツールセクションのカード間隔・アイコン/タイトル/説明文の窮屈さがないことをスクリーンショットで確認
- ツールセクションのデスクトップ表示(`lg:`以上)に変化がないことを確認(前回のスクリーンショットと比較)

## 4. 証跡要件

- 1・2それぞれの変更前後のスクリーンショット(指定した解像度・幅で)
- 1920×970(Chrome控除近似)での実際の見切れpx数を報告に記載すること
- 変更したファイルパス・該当箇所のdiff

## 5. 安全ルール(再確認)

- コミット・pushは行わないこと。KENZOの明示的な指示を待つ
- devサーバーの停止は対象PIDを指定した個別停止のみ。全プロセス一括終了コマンドは使用禁止
- 完了報告にツールの内部ログ(シェルコマンド実行ログ等)やローカルファイルパスをそのまま貼らないこと
