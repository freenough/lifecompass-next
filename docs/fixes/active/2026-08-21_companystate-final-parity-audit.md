# 追加指示書：法人側UI・ロジックの個人側との完全一致（最終ラウンド）

作成日：2026-08-21

---

## 1. 背景

これまで複数回にわたり、法人側（CompanyState）のUI・挙動を個人側（`SimulatorForm.tsx`/`PortfolioPanel.tsx`）と揃える修正を行ってきたが、その都度「実は一致していない」という差異が見つかっている（利回り設定/MC設定のリンク挙動、PFカードの表示項目、モンテカルロ分析の指標数など）。

今回は、個別の指摘への対症療法ではなく、**個人側の実装ロジックを直接参照・追跡した上で、法人側を同じロジックで作り直す**ことと、**他に見落としている差異がないかの全体監査**を行う。これを今回のCompanyState UI仕上げの最終ラウンドとする。

---

## 2. 絶対に守ること（変更なし）

`simulate.ts` / `analyze.ts` / `types.ts` / `profile.ts` / `PortfolioPanel.tsx` / `blog.ts` / `blogTopics.ts` / `concerns.ts` は**読むだけ**、変更しないこと。`simulatorStore.ts`は既存の許可範囲（`extraEvents`関連）以外変更しないこと。

---

## 3. タスク

### 3.1 PFカードのμ表示 と 利回り設定/MC設定の手入力値、分離ロジックを個人側から正確に移植する

**まず調査すること**：`PortfolioPanel.tsx`（個人側、ロック対象・読むだけ）が、以下をどう実現しているかを正確に追跡する：

1. PFカード見出しのμ表示（`displayMu`）が、どの値を参照しているか。手入力トグル（NISA rW等）の状態に関わらず、資産クラス配分から常にライブ計算されている根拠となるコード箇所を特定する
2. 「利回り設定」セクションの手入力値（`rW`/`rR`等）が、どこに保持され、PFカード側の計算とどう独立しているか（データフロー上、両者が別の状態・別の計算経路であることを確認する）

**その上で実装すること**：法人側（`CorporatePortfolioPanel.tsx`・`portfolioMath.ts`・`corporateGrowth.ts`等）を、調査で確認した個人側と**同じデータフロー構造**になるよう修正する。具体的な期待挙動：

- PFカードのμ表示：手入力トグルの状態に関わらず、常に現在の資産クラス％配分から自動計算される（個人側と同じ「ライブの参考値」）
- 利回り設定・MC設定側の手入力値（実際の成長計算に使う実効値）：手入力ON中は、PFの資産クラス配分を変更しても影響を受けない独立値のまま（これは現状の挙動を維持する）

修正後、以下の操作をスクリーンショットで示すこと：
- 利回り設定側でμを手入力（ON）にした状態で、PFカードの資産クラス配分を変更する
- → PFカードのμ表示は変わるが、利回り設定側の数値は変わらないことを示す

### 3.2 個人側・法人側の他の差異がないか、全体監査を行う

`PortfolioPanel.tsx`（個人側）が持つ以下の機能・挙動それぞれについて、法人側（`CorporatePortfolioPanel.tsx`）の対応する実装と1つずつ突き合わせ、差異の有無を確認すること。差異があれば一覧化し、実装はせず報告すること（判断はこちらで行う）。

- 「①現在PFの比率を②積立期にコピー」ボタンの挙動
- 「③取崩期は②積立期と同じPFを使う」トグルの挙動（ONの時、②の変更が③に即座に反映されるか等）
- 「取崩期は積立期と同じ利回りを使う」トグルの挙動（3.1で扱った手入力値のsame-as-working同期）
- 「取崩期は積立期と同じ標準偏差を使う」トグルの挙動
- 資産クラス行の追加・削除・並び替え時の挙動
- その他、`PortfolioPanel.tsx`に存在するが法人側に対応する実装がない機能、または実装はあるが挙動が異なるもの

### 3.3 モンテカルロ分析「法人合算」バッジへのp10/p90追加

現状「破綻確率・中央値」の2指標のみ。個人単独側の「モンテカルロ分析」欄（破綻確率・p10・p50・p90の4指標）と情報量を揃え、`combined`側のp10・p90を算出・表示すること。
