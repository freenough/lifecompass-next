# 指示書：完了報告（f5ee8f8）の未提出証拠の提出＋仕様確認

作成日：2026-08-25
種別：**証拠提出＋仕様確認（実装変更は仕様確認の結果次第）**

---

## 0. 背景

commit f5ee8f8の完了報告について、ユーザーから実際にエクスポートされたCSVを提出してもらったところ、
以下2点が確認できた：

1. 報告文中で言及されていた検証データ（`pers2:777`／`corp2:888`が両ストアに反映されることを
   示すCSV）が、実際に提出されたファイルには含まれていなかった（`pers1`／`corp1`のみ）
2. §4（グラフ当月ライブ反映）のスクリーンショットが、ユーザーの手元に見当たらなかった
   （「見当たらない」と報告あり）

これらは前回までに何度も発生している「完了報告と、実際に確認できる証拠の食い違い」と
同種の事象である。以下を対応すること。

---

## 1. §3の証拠を再提出すること

- 報告文にある「pers2:777／corp2:888が両ストアに反映される」ことを示す検証を、実際にもう一度
  実機で行い、その結果エクスポートされたCSVの中身を、省略せずそのまま提出すること
- 具体的には、以下がわかる形で提出すること：
  - `combined`スコープで1つのCSVをインポートする前の、個人・法人それぞれの状態（CSV）
  - インポートに使ったCSVそのもの（`pers2`・`corp2`を含む行）
  - インポート後、個人ボタンから取り込んだ場合の結果CSVと、法人ボタンから取り込んだ場合の
    結果CSVの両方（「完全一致する」という主張を、2つのCSVを見比べて確認できるようにするため）

---

## 2. 合算Exportが個人の過去履歴を含まない件の確認

法人側の合算Export（`hitori_hojin_assets_combined_2026-08-25.csv`）を確認したところ、
以下のようになっていた：

```
corp1, 202608, ..., 1000   ← 法人の当月
pers1, 202608, ..., 550    ← 個人の当月（ライブ参照）
corp1, 202607, ..., 900    ← 法人の過去履歴
```

個人側の過去履歴（`pers1`の2026-07=250万円、個人側の単独Exportには存在する）が、
法人側の合算Exportには含まれていない。

- これが意図的な設計（合算Exportは「自分の全履歴＋相手の現在値のみ」という割り切りである）か、
  実装上の見落としかを確認し、報告すること
- **意図的だった場合**：その理由と、この仕様が今後の予実重ね合わせ機能に与える影響
  （個人の過去の記録は、法人ページの合算Exportからは参照できないことになる）を明記すること。
  仕様変更は不要、現状維持でよい
- **見落としだった場合**：合算Exportが、相手側の記録履歴（過去のスナップショット）も含めて
  出力するように修正すること。修正する場合、個人側の合算Exportについても対称に確認し、
  同様の見落としがあれば併せて修正すること

---

## 3. §4のスクリーンショットを実際に提出すること

- 資産推移グラフの当月ライブ反映（「記録する」を押さずに保有資産を編集した直後、グラフの
  当月ポイントが即座に更新される）を、実際にブラウザで操作し、その場面のスクリーンショットを
  撮影して提出すること
- 前回の完了報告のように、文章での説明のみで済ませないこと
