# 調査専用指示書: モバイルファーストビューでのHero/チャート見切れ調整

対象ブランチ: `feature/lp-container-width`の続き、または新規ブランチ(`feature/lp-mobile-first-view`等)は要判断のため本調査結果を踏まえて次フェーズで決定

## 0. 前提・背景

- 前回セッション(`handoff_lp_container_width_round.md`)にて、コンテナ幅拡大・Hero/資産管理ブロックのフォント/グラフサイズ調整・モバイル特徴リストのブロック単位中央寄せ・Hero見出しのフルードタイポグラフィ化を実施済み(本番未デプロイ)
- 今回新たに指摘された論点: **モバイル(iPhone SE等の小画面)で初期に画面を開いた際、Heroのチャートカードが画面下端で中途半端な位置で見切れている**。他サイトでよく見る「意図的に区切りの良い箇所まで見せて↓SCROLL等のスクロール誘導を添える」パターンにはなっていない
- 本指示書は**調査専用**。方針決定・実装は次フェーズで行う(2フェーズ規律遵守。方針未確定での実装着手は禁止)

## 1. 調査目的

現状のHeroセクション(見出し+チャートカード)が、主要なモバイル画面サイズでファーストビュー内にどう表示されているかを実測し、「区切りの良い位置で見切れる」ようにするための調整候補と、スクロール誘導UIの実装候補を洗い出す。

## 2. 調査観点

### 2-1. 現状の実測

- 対象URL: 本番相当のPreview環境(`feature/lp-container-width`ブランチのVercel Preview、またはローカルdev)の`/asset-simulator`
- 以下の画面幅×高さで、Heroセクションの見出し・チャートカードがどこまで見えているかスクリーンショットで記録すること
  - 375×667 (iPhone SE / 第2・3世代)
  - 390×844 (iPhone 12/13/14系)
  - 360×800 (Android標準的サイズの一例)
- ブラウザのアドレスバー等UIチェスト込みの実効表示高さ(`100dvh`相当)で確認すること。デベロッパーツールのデバイスモードだけでなく、可能なら実機かdvh基準のシミュレーションで確認する
- 各サイズで「チャートカードのどの位置で画面が切れているか」(カード上端から何pxの位置か、カード全体が見えているか)を記録

### 2-2. 現状のHero構造・スタイルの棚卸し

- Heroセクションの現在のDOM構造・使用しているCSS変数(`--lp-hero-hero-width`等、前回セッションで変数化した箇所)を確認
- 見出し・チャートカードそれぞれの高さが、現状どのように決まっているか(固定値/`clamp()`/コンテンツに依存 等)を整理
- Heroセクションに`min-height`やviewport単位(`vh`/`dvh`/`svh`)が使われている箇所があるか確認

### 2-3. 調整候補の技術的実現可能性の確認(実装はせず、可否のみ調査)

- チャートカードの下端がファーストビューの区切りの良い位置(カード全体、または見出し文言の途中ではなくカードの外枠)で切れるよう、Hero全体または見出し/チャートの高さをviewport基準で調整する方法の技術的な実現可能性
  - 例: Heroセクションに`min-height: 100dvh`相当を設定した場合の副作用(コンテンツが伸びすぎる/縮みすぎる端末幅の範囲)
  - 例: 前回導入した`--lp-hero-hero-width`と同様に、チャートカードの高さもCSS変数化して画面幅別に比較できるようにする場合の実装コスト
- スクロール誘導UI(「↓ もっと見る」等)を追加する場合の配置候補と、その際にHeroセクションの高さ計算に与える影響
- iPhone SE級(375px幅)だけ別扱いにする分岐(メディアクエリ等)を追加する場合の既存コードへの影響範囲

### 2-4. 参考: 他サイトのパターン整理(任意・簡易でよい)

- 「区切りの良い位置まで見せてスクロール誘導」パターンを採用している参考サイトが手元にあれば、実装方式(グラデーションフェード/明確なボタン/矢印アイコン+アニメーション 等)の傾向を簡単に整理

## 3. 証跡要件

- 上記2-1のスクリーンショット(各画面幅×高さ、現状のHero見切れ位置がわかるもの)
- 2-2で確認したDOM構造・CSS変数の該当箇所のコード引用(ファイルパス・行範囲)
- 2-3で確認した技術的実現可能性についての調査結果(コードを変更せず、可否と想定される副作用の記述のみ。実装はしないこと)
