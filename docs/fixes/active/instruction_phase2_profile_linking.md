# 実装指示：シミュレータープロファイルと資産管理ツールプロファイルの実リンク機能

作成日：2026-08-30
種別：**実装（新機能）**
関連：`instruction_phase2_profile_foundation.md`（`linkedSimulatorProfileId`の当初設計）／`instruction_phase2_ui_alignment.md`（リンク先指定UIが外れた経緯）／`instruction_phase2_ui_finalize.md`（直前の対応）

---

## 背景

一連のUI対応の過程で、「資産管理ツール側プロファイルの`linkedSimulatorProfileId`が、実際にはどこからも設定できず、切替の自動連動にも一切使われていない」ことが判明した。

このツールの目的の一つは**予実管理**（シミュレーターでの計画と、資産管理ツールでの実績・法人設定を突き合わせること）であり、その前提として「どのシミュレータープロファイルが、どの資産管理ツールプロファイル（保有資産・法人設定）に対応するか」が正しく紐づいている必要がある。今回、この紐づけを実際に機能させる。

**要件（KENZOとの設計協議で確定）**：
1. シミュレーターでリンク済みのプロファイルを読み込むと、対応する資産管理ツールプロファイル（保有資産・法人設定）に自動的に切り替わる（自動連動）
2. それとは別に、シミュレーター側の「法人資産」セクションに、資産管理ツールプロファイルを手動で選び直せるセレクターを設ける（新規シミュレーション作成時など、まだリンクが無い場合や、意図的に別プロファイルを使いたい場合のため）
3. リンクさせず、資産管理ツール側だけで個別にプロファイルを切り替える従来の運用も引き続き可能とする

---

## 1. `simulatorStore.ts`への最小限の追加：`currentProfileId`の保持

**背景（技術的制約の確認）**：調査済みの通り、シミュレーター側には「現在読み込み中のプロファイルID」を保持する仕組みがそもそも存在しない（`ProfileDrawer.tsx`の読込・保存は、値のコピーと名前一致判定だけで完結しており、IDを記憶しない設計）。`ProfileDrawer.tsx`自体は変更禁止のため、これを検知できる唯一の場所は`src/store/simulatorStore.ts`である。

**変更内容**：
- `useSimulatorStore`に`currentProfileId: number | null`を追加する（初期値は`loadInitialProfile()`が読み込んだプロファイルのID。調査1の通り、現状は配列の最後の要素を初期値として使っているため、そのプロファイルのIDを設定する）
- `loadProfile()`内で、読み込んだプロファイルのIDを`currentProfileId`に設定する
- `saveProfile()`内で、新規保存の場合は新しく発行されたID、上書き保存の場合はその上書き対象のIDを`currentProfileId`に設定する
- **`ProfileDrawer.tsx`自体は一切変更しない。** 上記はすべて`simulatorStore.ts`側のstate追加・既存関数内の追加代入のみで完結させること
- 既存の動作（読込・保存・削除等）の見た目・挙動は一切変えないこと。純粋な内部状態の追加のみ

---

## 2. 自動連動：シミュレーター側プロファイル読込→資産管理ツールプロファイルへの自動切替

- `currentProfileId`の変化を検知し（`useSimulatorStore.subscribe`等）、資産管理ツール側プロファイル一覧の中に`linkedSimulatorProfileId === currentProfileId`となるものが存在すれば、そのプロファイルへ自動的に切り替える
- **切替は、既存の未保存確認の仕組みをそのまま経由すること。** 現在の資産管理ツールプロファイル側に未保存の変更（`holdingsDirty`または`companyStateDirty`）がある場合は、無条件に切り替えず、`instruction_phase2_ui_finalize.md`で実装した確認ダイアログと同じ経路（確認→OKなら下書き破棄して切替、キャンセルなら切替中止）を通すこと。**自動連動だからといって、確認なしに切り替えたり保存したりする経路を新設しないこと**（これまでの安全策の方針を維持する）
- 該当するリンク先が資産管理ツール側に存在しない場合（`linkedSimulatorProfileId`が無い、またはリンク切れ）は、何もしない（現在アクティブな資産管理ツールプロファイルのまま）。エラー等は出さない

---

## 3. 手動選択：シミュレーター「法人資産」セクションへのプロファイルセレクター追加

- 現在、`法人資産（一人法人）`セクション冒頭にある静的テキスト「プロファイル：〇〇（資産管理ツールで選択中のプロファイルに連動します）」を、**資産管理ツールプロファイルを選択できるセレクター（`<select>`等）に置き換える**
- 選択肢は資産管理ツール側の保存済みプロファイル一覧（名前で表示）。現在アクティブなものを選択状態にする
- ユーザーがここで別のプロファイルを選ぶと：
  1. 2節と同じ未保存確認の経路を通した上で、資産管理ツール側プロファイルを実際に切り替える
  2. **現在のシミュレータープロファイル（`currentProfileId`）と、選んだ資産管理ツールプロファイルの`linkedSimulatorProfileId`を紐づける**（選ばれた資産管理ツールプロファイルの`linkedSimulatorProfileId`を`currentProfileId`の値に更新する）。これにより、次回このシミュレータープロファイルを読み込んだときに、2節の自動連動で同じ資産管理ツールプロファイルが呼ばれるようになる
- `currentProfileId`が`null`（今のシミュレーター実装上、通常は初期プロファイルが必ずあるため考えにくいが、念のため）の場合は、リンクの更新は行わず、資産管理ツールプロファイルの切替だけ実行する

## 4. 遵守事項

- ロックファイル（`types.ts`/`profile.ts`/`PortfolioPanel.tsx`/`simulate.ts`/`analyze.ts`/`montecarlo.ts`/`blog.ts`/`blogTopics.ts`/`concerns.ts`）への依存・変更は一切ゼロを維持すること
- **`ProfileDrawer.tsx`自体は一切変更しない。** 今回`simulatorStore.ts`への変更が初めて許可されるが、これはあくまで`currentProfileId`の保持という最小限の追加に限定し、既存のロジック・挙動を変更しないこと
- 資産管理ツール側の「新規保存」時に`linkedSimulatorProfileId`を設定するUIは、今回は復活させない（3節の手動選択セレクターが実質的にその役割を担うため）。判断に迷う場合は先に報告すること
- 「名前を変えて保存すると新規プロファイルが増える」という`ProfileDrawer.tsx`側の既存仕様により、リネームした場合は旧プロファイル側にリンクが残ったままになる。これは今回のスコープでは対応しない既知の制約として、完了報告に明記すること
- 既存テスト（`scripts/verify-*.js`、`full-verify.js`）が全てPASSすることを維持する。1〜3節の新機能に対する検証を追加すること
- 検証は本番相当の実データ環境を使わないこと
- 完了報告には必ず実際のコード抜粋・テスト結果・実機確認結果（スクリーンショット含む）を添付すること（文章のみの報告は不可）
