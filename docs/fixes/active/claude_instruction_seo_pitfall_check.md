# 指示書: SEO技術的落とし穴チェック(調査専用)

## 位置づけ

**これは調査専用の指示書です。実装・修正は行わないでください。**
調査結果をもとにKENZOが方針を決定し、必要であれば別途実装指示書を出します。
（ways-of-working.mdの2フェーズ規律に従う: 調査→結果確認・方針決定→実装、の順を厳守）

## 背景

外部の類似事例（Claude CodeでLPを作りSEO1位を獲得した記事）で、以下の技術的な落とし穴が報告されていました。
FREENOUGH（freenough-main / lifecompass-next 両リポジトリ）で同様の問題が発生していないか確認してください。

## 調査項目

### 1. サイトマップの lastmod が不正確になっていないか

**懸念**: `app/sitemap.ts` で各URLの `lastModified` を「ビルド時刻」や「デプロイ時刻」から動的に生成していると、実際にはコンテンツを変更していないページも「今日更新した」とGoogleに申告し続けることになり、更新頻度の信頼性を損なう。

**調査してほしいこと**:
- `freenough-main` と `lifecompass-next` それぞれの `app/sitemap.ts`（root-level app/sitemap.tsが両リポジトリに存在するはず）で、`lastModified` の値がどこから来ているか（`new Date()` のような固定でない動的値を使っていないか、記事ごとのfrontmatterの日付やgitのコミット日時など「実際にそのページが変更された日」を参照できているか）
- ブログ記事一覧を管理している箇所（`blog.ts`等、ロックファイル対象なので**読むだけ**）に、記事ごとの更新日フィールドが存在するかどうか
- 現在のsitemap.xmlを実際に取得し（本番URL）、複数URLの`lastmod`の値を目視確認し、不自然に全ページ同じ日付になっていないか

### 2. ブログ記事・OGP画像の形式確認

**懸念**: サムネイル/OGP画像がSVG形式だと、X（Twitter）やSlackなどのリンクプレビューで画像が表示されない場合がある。

**調査してほしいこと**:
- ブログ記事のOGP画像（`opengraph-image`やmetadata内の`images`指定）およびサムネイル画像が、実際にどのファイル形式（SVG/PNG/JPG等）で生成・配信されているか
- 画像がAI生成か静的アセットか、生成ロジックがある場合はどこにあるか
- 該当URLをOGPデバッグツール（例: Twitter Card Validator相当の確認手段があれば）や実際のプレビュー動作で確認できるか（ブラウザでの目視確認でも可）

### 3. 画像サイズ・初回表示の重さ

**懸念**: トップ画像やブログ内画像が過度に重いと表示速度が落ち、SEO・体感速度双方に悪影響。

**調査してほしいこと**:
- LPトップ（freenough.com）および資産シミュレーターハブページ（`/asset-simulator`）で使用されている画像のファイルサイズを一覧化（特に一番上に表示されるヒーロー画像等）
- 明らかに大きい（数百KB〜MB単位の）画像があれば、ファイル名とサイズを報告
- 画像フォーマットが最適化されているか（next/imageのようなNext.js標準の最適化機構を使っているか、素の`<img>`で配信していないか）

### 4. robots.ts / 構造化データの現状棚卸し（軽め）

**調査してほしいこと**（深追いはせず現状把握のみ）:
- `app/robots.ts`（両リポジトリ）の現在の設定内容をそのまま報告
- ブログ記事・トップページに構造化データ（JSON-LD、Article/Person/Organization schema等）が実装されているかどうかの有無のみ確認（実装されていなければ「未実装」と報告するだけでよい、この指示書では新規実装しない）
