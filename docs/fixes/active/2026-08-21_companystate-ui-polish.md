## 0. 前提：「破綻率変化」列の定義について（重要、4番の作業前に必読）

前回「破綻率変化列を個人単独主表示に戻す」と伝えた際、指示が曖昧だった。改めて定義を明確にする。

CompanyStateには、意味の異なる2種類の「破綻確率」が存在する：

| 名称 | 定義 |
|---|---|
| **`personalOnly`側の値** | 法人トグルON時は`extraEvents`（法人取崩の税引き後注入）込みで計算した、**個人口座（NISA/iDeCo/特定/現金）のみ**の破綻確率。KPIカードの「MC破綻確率」と同じ定義 |
| **`combined`側の値（法人合算）** | 個人口座の残高 ＋ **法人に残っている資産そのもの**、を合計した金額がゼロになるかで判定する破綻確率 |

この2つは全く別の指標であり、「個人単独」という言葉は前者（`personalOnly`）を指す。後者（`combined`）はあくまで補足バッジとして扱うこと。以下4番の対応は、この定義に基づいて行うこと。

**この2種類の数値（`personalOnly`＝法人から個人へ資金移動した後の個人資産、`combined`＝それに法人残存資産を加えた合計）は、法人トグルONの画面全体（KPIカード・グラフ・モンテカルロ分析欄・改善案インパクト比較を含む全て）に一貫して適用されるべき、共通の2軸である。今回の1〜4の修正は、現状バラバラになっているこの2軸の扱いを統一することが目的である。**

## 1. 法人PFへの直接μ・σ入力トグル追加

`CorporatePortfolioPanel.tsx`の①②③各フェーズ（現在／積立期／取崩期）に、個人側`SimulatorForm.tsx`のNISA/iDeCo/特定口座と同じ「トグルON＝μ・σを直接手入力できる」というUIパターンを追加すること。トグルOFF時は、これまで通り資産クラス％配分からの自動算出値を使う。

## 2. グラフの色分け修正

`AssetChart.tsx`（法人合算グラフ）にて、以下の色分け方針に修正すること：

- 「中央値」「合算(法人含む)中央値」は、どちらも個人資産推移の仲間の系列として、**同じ色系統（青系）でまとめる**
- 「FIREライン」は達成基準を示す参照線であり、資産推移の系列とは役割が異なるため、**別の色系統（例：アンバー系）に変更**し、青系の2系列と視覚的に区別できるようにすること

---

## 3. 「法人合算」バッジの統一

- 共通の小さなバッジ/チップコンポーネントを1つ新規作成し、「最終資産」カード・「MC破綻確率」カード・「モンテカルロ分析欄」の3箇所で使い回すこと
- 現状、「MC破綻確率」カードには法人合算の補足表示が無い（他2箇所には既にある）。これが意図した仕様か実装漏れかをまず確認し、実装漏れであれば追加すること

## 4. `ImpactTable`の「破綻率変化」列を`personalOnly`主表示に修正＋再検証

0章の定義に基づき、以下を実施すること：

- 「破綻率変化」列の主表示を、`combined`側の値ではなく**`personalOnly`側の値**（法人取崩の注入込み・個人口座のみの判定）に修正する。他の列（「最終資産差」）と同じ土俵の数値にする
- `combined`側の値は、3番で作成した共通バッジコンポーネントを使い、「破綻率変化」列に補足表示として添えること
- 現在の実装が既に`personalOnly`側を使っている場合（＝当方の理解が誤っている場合）は、修正せずその旨を報告すること
- 修正後、以前報告された「3施策すべてで破綻率変化が+0.0%だった」件について、`personalOnly`側の値で見た場合にも同じ現象が起きるか再検証すること。起きる場合は、前回の0.0%調査と同様の手法（1000試行中の生データ、枯渇試行数ベースの確認）で、計算上正しい結果か検証し、結果を報告すること

## 5. 検証要件（共通）

- `full-verify.js`/`tsc --noEmit`/`npm run build`を実行し、結果を報告すること
- ロックファイルの差分（前回から変化がないこと）を確認すること
- 実ブラウザで、1〜4それぞれの変更が意図通り反映されていることを確認し、スクリーンショットまたは具体的な確認手順・結果を報告すること
- **`combined`側（法人合算）の計算が、法人自身のμ・σ（①②③各フェーズのポートフォリオ設定）を使って毎年変動していることを確認すること**。具体的には、法人ポートフォリオのσを大きく変える（例：現状値→40%程度に変更）と、`combined`側の分布（p10-p90の幅）が明確に広がることを、生データまたはスクリーンショットで確認して報告すること。個人側と同じZスコアを共有しているが、振れ幅自体は法人自身のσでスケールされている（固定値で放置されていない）ことの確認が目的
