# 指示書: FAQ抽出のblog.ts統合、実現可能性調査(調査専用)

## 位置づけ

**これは調査専用の指示書です。実装・修正は行わないでください。**
FAQPage構造化データの抽出方式について、独立ユーティリティ（生Markdownへの正規表現）ではなく、`blog.ts`が既に使っている`remark`のAST（構文木）を活用する方式に切り替えられないかを検討しています。「既存のexport・型定義・挙動を一切変更せず、新しい関数を追加するだけで済むか」が最大の論点です。これが確認できれば、ロックファイル改修の「管理された例外」手続き（後方互換性確認・新規フィクスチャ追加・`full-verify.js`組み込み）を踏んだ上で、この方式への切り替えを検討します。

## 調査項目

### 1. `blog.ts`の現在のremarkパイプライン構成

- `blog.ts`が使っている`remark`関連のimport・プラグイン構成（`remark`, `remark-html`, `remark-gfm`等、使用しているものすべて）をそのまま報告してください
- 現在の実装が、Markdown文字列を直接HTML文字列に変換する一括処理（AST自体はコード内で明示的に扱っていない）なのか、それとも中間的にASTオブジェクトを保持・操作している箇所があるのか報告してください

### 2. 「よくある質問」セクションのAST構造の確認

- 実際に既存記事（例: `4percent-rule.md`など「よくある質問」セクションを含む1〜2ファイル）のMarkdownを、`blog.ts`と同じremarkプロセッサでASTにパースした結果を、コード内で一時的に出力（`console.log(JSON.stringify(ast, null, 2))`等、ファイルを書き換えずログ出力のみ）して構造を確認してください
- `**Q. ...**`の直後に空行がある場合とない場合で、生成されるAST上のノード構造（`paragraph`が分かれるか、`break`ノードが挟まるか等）がどう異なるか報告してください
- 質問部分の`strong`（太字）ノードと、回答部分の通常テキストノードを、AST走査でプログラム的に区別・抽出できそうか、所感を報告してください（実装はまだしない）

### 3. 新規関数追加のみで完結するかの確認

- `blog.ts`に、既存のexport（関数名・型定義）を一切変更せず、新しいexport関数（例: `extractFaqFromMarkdown(rawContent: string)`）を1つ追加するだけでFAQ抽出が実装できそうか、技術的な見立てを報告してください
- 既存の関数（記事一覧取得・記事詳細取得等）が、今回追加する新関数の処理と内部的に競合・干渉する可能性がないか確認してください（例: 同じMarkdownファイルを2回パースすることになるが、パフォーマンス上・処理順序上の問題がないか）

### 4. `blog.ts`の既存exportを使っている箇所の洗い出し（後方互換性確認の準備）

- `blog.ts`からexportされている関数・型を、現在どのファイルがimportして使っているか一覧化してください（`grep`等で機械的に洗い出して構いません）
- これは「新規関数を追加しても、既存の呼び出し元に影響が本当にないか」を確認するための事前準備です

### 5. `hitoriHojinBlog.ts`側の同様の調査

- `hitoriHojinBlog.ts`は`blog.ts`とは独立した実装とのことですが、remarkパイプラインの構成（`sanitize: true`のみで、`blog.ts`のようなカスタムschemaを持たない点は前回確認済み）を踏まえ、同様に新規関数追加のみでFAQ抽出が実装できそうか、`blog.ts`側と共通化できる部分があるか（例: AST走査ロジック自体は共有関数として切り出せるか）を報告してください

### 6. `full-verify.js`への組み込みコストの見立て

- 現在の`full-verify.js`パターン（`scripts/verify-*.js`）に、新規フィクスチャ（テスト用Markdownサンプル数パターン：空行あり/なし、A.プレフィックスあり/なし等）を追加してFAQ抽出のテストを組み込む場合、既存のテストパターンを踏襲してどの程度のコストで実装できそうか、既存の類似テストファイル（例: 前回の退職金計算ツールのテスト等）を参考に見立てを報告してください

## 完了報告のフォーマット

- 各項目について、該当ファイルパス・行番号、実際のコード・AST出力例を伴って報告してください
- 「新規関数追加のみで完結できそうか」について、Yes/Noと、Noの場合は具体的に何を変更する必要が生じそうかを明確に報告してください
- この指示書の範囲では実装は一切行わないでください（AST構造確認のための一時的なログ出力は可、ただしファイルへの変更は禁止）
- ロックファイル（`blog.ts`, `hitoriHojinBlog.ts`含む全ロックファイル）は読み取り・一時的なログ出力確認のみ、恒久的な変更は一切不可
