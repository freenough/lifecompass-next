# 調査専用指示書：法人MC実装・UI統合のための残り2点調査

作成日：2026-08-20

---

## 1. 背景・目的

CompanyStateの最終設計に向けて、以下2点の技術的事実確認が必要。

1. 個人側と法人側で「同じ年次市場ショックZスコア列」を共有し、それぞれのσでスケールしてMCを実行する方式を採用することが決まった。これを実現するには、`simulate()`の第4引数`shockZOverrides`を使って、外部から1000回分のZスコア系列を渡しながら`simulate()`を1000回呼び出し、法人側の成長計算も同じZスコア系列で行い、両者の試行ごとの結果をペアで合算する「MCの外側ループ」を新規に書く必要がある。この設計が技術的に成立するかを確認する
2. CompanyState（法人設定）の入力UIを、独立ページではなく、個人シミュレーター画面の左側「個人設定欄」の下部に、「法人資産を含める」トグルON時のみ表示する形で統合したい。統合先のファイルを特定し、ロック対象かどうかを確認する

**重要**：この調査は実装可否判断のための事前調査。実装するかどうか・どう実装するかはこのチャットで判断する。

---

## 2. 絶対にやってはいけないこと

- **実装・修正は一切行わないこと**。本指示書は調査専用
- ロックファイル（`simulate.ts`/`analyze.ts`/`types.ts`/`profile.ts`/`PortfolioPanel.tsx`/`simulatorStore.ts`/`blog.ts`/`blogTopics.ts`/`concerns.ts`）は**読むだけ**
- 独自に再実装したスクリプトで検証しないこと。既存のコードを読んで報告すること
- 「こう実装すべき」という提案・推奨は書かないこと。事実の報告に徹すること

---

## 3. 調査対象・確認事項

### 3.1 `shockZOverrides`を使った外部MCループの実現可能性

1. `simulate()`の第4引数`shockZOverrides: number[] | null`が、内部でどう使われているか（`simulate.ts`該当箇所を引用しつつ）追跡して報告する。具体的には：
   - 配列の各要素が「1年ごとのZスコア」という理解で合っているか
   - 配列の長さは、シミュレーション対象年数と一致している必要があるか（過不足時の挙動も含む）
   - このZスコアが、内部でどの資産クラス・どのσに対して、どう適用されているか（個人側の`calcAggregateSigma`で算出された単一のσに対して単純にZ×σとして使われているのか、それとも資産クラスごとに別の使われ方をしているのか）
2. 既存の`runMC()`（`montecarlo.ts`または該当ファイル）が、通常のMC実行時に`shockZOverrides`を使わず、内部でどうZスコアを生成しているか（乱数生成方式）を確認する。外部で生成したZスコア列を使う場合、既存の生成方式と統計的に同じ性質（正規分布、シード等）にする必要があるか、既存コードから読み取れる範囲で報告する
3. `simulate()`を1000回、外部ループから1回ずつ呼び出す場合の実行コスト（1回あたりの処理内容の重さ）について、既存の`runMC()`が内部で1000回ループしている実装と比較して、大きな性能差が生じそうな要因（例：`simulate()`呼び出し1回ごとに重い初期化処理が走る等）があれば報告する
4. `analyze()`は1000回の試行結果全体（`YearSnap[][]`等の集計前データ）を受け取れる構造か、それとも1試行分の`YearSnap[]`のみを想定した設計か確認する。法人側の合算結果を最終的にp10/p50/p90に集計する処理を、`analyze()`を再利用して行えるか、独自に集計処理を書く必要があるかの判断材料として報告する

### 3.2 個人設定欄（左パネル）の実装箇所

1. 添付画像（法人資産管理ツールの画面、および過去のCompanyState画面）ではなく、**個人シミュレーター本体（`/app`）の実際の画面**において、左側に表示されている「個人設定欄」（保有資産・ライフイベント・ポートフォリオ設定等をまとめたパネル、資産管理ツール画面の左パネルとは別物）が、どのファイルで実装されているか特定する
2. そのファイルが、指示書の対象ロックファイル一覧（`PortfolioPanel.tsx`含む）に含まれるか、それとも非ロックファイル（例：`app/page.tsx`内のレイアウト、または別の非ロックコンポーネント）かを明確に報告する
3. このパネル内に新しいセクション（法人設定、トグルON時のみ表示）を追加する場合、影響を受けそうな既存コードの範囲（レイアウトの折り込み方、スクロール領域の扱い等、UI構造上の制約があれば）を報告する
4. 「法人資産を含める」トグルの状態（ON/OFF）を保持する場所として、ロック対象の`simulatorStore.ts`に新しいstateを追加するのが自然か、それとも法人側の新規ストア（`companyStateStore`）側で持てるか、技術的な選択肢を列挙する（推奨は不要）
