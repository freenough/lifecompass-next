# 指示書: 著者プロフィール・構造化データ 現状調査(調査専用)

## 位置づけ

**これは調査専用の指示書です。実装・修正は行わないでください。**
先の「SEO技術的落とし穴チェック」で構造化データ(JSON-LD)が両リポジトリとも0件と判明しています。今回はその実装に向けた設計判断のための現状把握です。調査結果をもとにKENZOが方針を決定し、別途実装指示書を出します。
（ways-of-working.mdの2フェーズ規律に従う: 調査→結果確認・方針決定→実装、の順を厳守）

## 調査項目

### 1. 著者プロフィールページの有無

- `freenough-main`・`lifecompass-next`（`/asset-simulator`配下）・hitori-hojin配下それぞれに、著者・運営者を紹介するページ（`/about`, `/profile`, `/author`等の名称は問わない）が存在するか
- 存在する場合、そのページのURL・記載内容（名前・肩書き・SNSリンクの有無等）をそのまま報告
- 存在しない場合は「存在しない」と報告するのみでよい

### 2. 現状のmetadata実装の棚卸し

- 各リポジトリの`layout.tsx`（ルート・各セクション）で、Next.jsの`metadata`オブジェクトが現在どう構成されているか（`title`, `description`, `openGraph`, `twitter`, `metadataBase`等）をそのまま報告
- ブログ記事個別ページ（`src/app/blog/[slug]/page.tsx`等）で、記事ごとのmetadataがどのフィールド（タイトル・概要・公開日等）から動的生成されているか

### 3. 運営者情報（Organization相当）の所在確認

- サイト内に運営者情報・特定商取引法に基づく表記・プライバシーポリシー等のページが存在するか、あれば場所を報告
- 存在しない場合はその旨のみ報告（新設要否の判断はこの指示書の範囲外）

### 4. ブログ記事データ構造の確認（ロックファイルは読むだけ）

- `src/lib/blog.ts`・`src/lib/hitoriHojinBlog.ts`（**変更禁止、読み取りのみ**）で、各記事が保持しているフィールド一覧をそのまま列挙してください（例: `date`, `title`, `slug`, `eyecatch`, 著者名に相当するフィールドの有無等）
- Article構造化データを実装する場合に必要になりそうなフィールド（公開日・更新日・著者名・カテゴリ等）のうち、**現状データに存在しないもの**を明示してください（存在しないからといって新設の提案までは不要、事実の指摘のみ）

### 5. X・note.comとの紐付け状況

- サイト内の既存リンク（フッター、著者ページ等があれば）で、KENZO個人のX（旧Twitter）アカウント・note.comアカウントへのリンクが実装されているか
- リンクがある場合、そのURLと実装箇所を報告

### 6. hitori-hojin（一人法人）セクションの著者情報の扱い

- 一人法人セクションのブログ記事にも、資産シミュレーター側と同じ著者（KENZO）の情報が必要になる想定です。現状、一人法人側のページ・記事が資産シミュレーター側の著者情報・metadataと独立した実装になっているか、共通コンポーネントを共有しているかを確認して報告
