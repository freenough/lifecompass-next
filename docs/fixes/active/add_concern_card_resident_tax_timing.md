# 実装指示:concerns.ts への resident-tax-timing ツール用カード新規追加

## 背景
`src/data/concerns.ts`は「1ツール=1カード」の運用がほぼ徹底されているが、
`resident-tax-timing`ツールだけが対応するカードを持たない状態になっている
(前回の記事公開完了報告書で判明)。ちょうど関連記事(`taishoku-yokunen-juminzei`)も
公開済みのため、カード新規追加時に`articleUrl`も合わせて設定できる。

## 実装内容

### 1. 既存カードの構造確認
`src/data/concerns.ts`内の既存14件、特に`retirement-tax`・`retirement-ideco-timing`・
`pension-timing`など、同じ「退職前後」テーマのツールに対応するカードの構造
(フィールド構成、文言のトーン、`articleUrl`の設定有無)を確認し、同じパターンで
新規カードを作成すること。

### 2. 新規カードの作成
以下の要件で`resident-tax-timing`用のカードを追加すること:
- 悩み・不安を表す見出し文言:「退職後、住民税がいつ・いくらかかるか分からない」
  「退職翌年に住民税の請求が来ると聞いたが、いくらになるか不安」のような、
  既存カードの文言トーン(ユーザー目線の悩み表現)に合わせて作成すること
  (上記はたたき台であり、既存カードの文体パターンに厳密に合わせて調整すること)
- リンク先:`resident-tax-timing`ツール(`toolMetadata.ts`の該当エントリを参照)
- `articleUrl`:今回公開した`taishoku-yokunen-juminzei`記事のURLを設定すること
  (公開チェックリストの「新しい記事が公開されたら、対応するconcernカードに
  articleUrlを追加する」という既存の運用ルールに沿う対応)

### 3. 配置位置
既存14件の中で、テーマ的に近いカード(退職金・年金関連)の近くに配置すること
(配列内の並び順に既存の意図的な設計〈カテゴリ順等〉があれば、それに従うこと。
なければ末尾に追加でよい)

## 検証要件
- 新規カードが、既存カードと同じ表示形式でconcerns一覧ページに正しく表示されることを
  ブラウザ実機で確認すること
- カードのリンクをクリックし、`resident-tax-timing`ツールページに正しく遷移することを
  確認すること
- `articleUrl`のリンクが、公開済みの記事に正しく遷移することを確認すること
- `full-verify.js`全PASS・`tsc --noEmit`エラーなしを確認すること

## 禁止事項
- 既存13件のカードの内容・順序の変更(新規追加のみ)
- `docs/fixes/active/` フォルダの削除
