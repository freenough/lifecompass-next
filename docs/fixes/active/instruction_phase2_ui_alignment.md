# 実装指示：フェーズ2①改訂 — シミュレーター側UIとの体験統一（保存ボタン・プロファイル管理UI・ボタン配置）

関連：`instruction_phase2_profile_foundation.md`（フェーズ2①、実装・検証済みだがまだ未デプロイ）／`phase2_design_proposal_draft.md`

## 背景

フェーズ2①（プロファイル基盤・移行処理・CompanyState対応）は実装・検証済みだが、まだ本番デプロイ前。KENZOが実機で確認した結果、以下の点でシミュレーター本体（`ProfileDrawer`）とのUX一貫性に問題があると判断された。

1. 保有資産の追加・編集がその場で即座に確定してしまい、「今の操作がどのプロファイルに対して記録されているか」が画面から分かりにくい
2. プロファイル管理UI（①で新規作成した`AssetManagerProfilePanel.tsx`）が、シミュレーター側の`ProfileDrawer`と構成が大きく異なっており、同じアプリ内なのに画面によって操作体験が変わってしまっている
3. CSV/JSON関連ボタンの配置がシミュレーター側と揃っていない

**未デプロイの段階なので、①の実装済みコードを作り直す形で今回のうちに対応する。**

---

## 1. 保有資産編集を「ページ単位の明示保存」方式に変更

**現状**：保有資産の追加・編集・削除は、操作した瞬間に即座にlocalStorageへ書き込まれる（自動保存）。

**変更後**：
- 保有資産一覧の追加・編集・削除操作は、まず画面上の**作業中の状態（下書き）**として保持し、即座にはlocalStorageへ書き込まない
- ページに**「保存」ボタンを1つ**設置する。押すと、その時点の保有資産一覧全体を確定してlocalStorageに書き込む（シミュレーター本体の「入力してから保存」という体験に合わせる）
- 未保存の変更がある間は、画面上に分かりやすく「未保存の変更があります」といった表示を出す
- **ブラウザの標準的な離脱確認（`beforeunload`イベント）を実装し、未保存の変更がある状態でページを離れようとしたら警告を出す**（保存ボタン方式に伴うデータ消失リスクを緩和するため。これは必須）
- 保存ボタンを押した後は、「未保存の変更があります」表示が消え、保存完了が分かるフィードバック（トースト等）を出す
- **この「保存」ボタンの対象は、現在の保有資産一覧の編集のみ。** 既存の「記録する」ボタン（スナップショットを記録する操作）は、既にそれ自体が明示的な確定操作なので変更不要
- 個人・法人（「法人資産を含める」トグル）双方に同様に対応すること
- もし`CorporateSettingsSection.tsx`（法人設定、CompanyState編集）が現状フィールドごとの自動保存になっているなら、同じ考え方で同様の明示保存＋離脱警告に統一することが望ましい。ただし、既存のUIパターンを壊さない範囲で対応し、判断に迷う場合は先に報告すること

## 2. プロファイル管理UIをシミュレーターの`ProfileDrawer`と同じ構成に作り直す

シミュレーター側`ProfileDrawer`は、以下の構成・挙動になっている（KENZOが実機スクリーンショットで確認済み）：
- 名前入力欄が1つ
- ボタンが1つ：入力した名前が保存済みプロファイルの名前と一致すれば「上書き保存」、一致しなければ「新規保存」とボタンの表示が自動的に切り替わる
- その下に、共有・エクスポート・インポート関連のボタン群
- 一番下に保存済みプロファイルの一覧（各行に「読込」「削除」リンク）

**資産管理ツール側の`AssetManagerProfilePanel.tsx`を、同じ構成・同じ挙動に作り直す：**

- 名前入力欄を1つに統一
- ボタンを1つにし、入力した名前が既存プロファイルの名前と一致するかどうかで「新規保存」「上書き保存」を自動的に切り替える
- **「新規保存」を押した場合**：新しいプロファイルを作成し、**現在アクティブなプロファイルの保有資産・CompanyStateを、そのまま新プロファイルの初期データとしてコピーする**（今画面に表示されている内容を、新しい名前のプロファイルとして保存する、というシミュレーターと同じ体験にする）。作成後は自動的にその新プロファイルに切り替える
- **「上書き保存」を押した場合**：現在アクティブなプロファイルの名前・生年月日・リンク先といった**プロファイル自体のメタ情報**を更新する（保有資産自体は1節の「保存」ボタンで別途確定されるため、ここで重複して扱わない）
- 一覧に保存済みプロファイルを表示し、「読込」（切替）・「削除」を提供する。削除・リンク切れ・リンク解除の仕様は`instruction_phase2_profile_foundation.md`の既存仕様（カスケード削除、`remainingProfiles[0]`ルール、リンク切れ表示、明示的なリンク解除操作）をそのまま維持すること

## 3. 常時表示の「現在のプロファイル」インジケーター

- プロファイル管理パネル（ドロワー）を閉じていても、資産管理ツールのメイン画面のどこかに「現在のプロファイル：〇〇」という表示を常に出す
- これにより、ドロワーを開かなくても、今どのプロファイルに対して操作しているかが常に分かるようにする

## 4. CSV/JSON等のボタン配置をシミュレーター側と揃える

シミュレーター側`ProfileDrawer`のボタン並び順（実機スクリーンショットで確認済み）：
名前欄 → 保存ボタン（新規保存/上書き保存の自動切替） → URLで共有 → JSONでエクスポート → JSONをインポート → 保存済みプロファイル一覧

資産管理ツールには「URLで共有」に相当する機能は無い（個人の実データを扱うため、共有機能自体を実装しない）一方、シミュレーター側には無い「CSV」機能（月次のスナップショット履歴の編集用）が存在する。これを踏まえ、**資産管理ツール側の並び順を以下に明確に指定する**：

**名前欄 → 保存ボタン（新規保存/上書き保存の自動切替） → CSVでエクスポート → CSVをインポート → JSONでエクスポート → JSONをインポート → 保存済みプロファイル一覧**

CSVをJSONより上に配置する理由：CSV＝月次編集（比較的よく使う操作）、JSON＝完全バックアップ（たまに使う操作）という役割の違いがあるため、使用頻度が高い方を上に置く。この並び順・グルーピングを厳密に実装すること（実装側の裁量に委ねず、この順序通りに配置する）。
