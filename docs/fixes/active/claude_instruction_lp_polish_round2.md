# 実装指示：お悩みカード修正／資産管理ツールブロックのダーク化実験／ケーススタディ左固定統一

作成日：2026-09-21
種別：**実装（複数箇所の小〜中規模修正）**
関連：3者(Claude/ChatGPT/Gemini)によるLPレビューを踏まえた設計チャットでの決定事項

---

## 背景

LP全体のレビュー（ChatGPT・Gemini・このチャット）を踏まえ、KENZOとの設計チャットで以下5点の対応方針が確定した。アイコン・イラストのテイスト統一（円形枠アイコン vs 裸アイコンの不一致）と「未来は1本ではない」ダークセクションの新設は、**今回は対象外（別途検討）**。

---

## 1. 「お悩み」カードの調整

### アイコンを削除する

- 各カード上部にあるアイコン（現状使っていない場合はこの項目はスキップしてよい。前回提案のサンプルバッジも今回は追加しない）を削除し、質問文の見出しをそのまま視覚的なアンカーとする

### ボタンの見た目を「常時visibleな薄い塗り」に変更する

- 現状、「60秒で試算する」「詳しく試算する」ボタンはホバー時のみ薄い色が付く実装になっている。タッチデバイス（スマホ・タブレット）にはホバーが存在せず、常にテキストリンクと見分けがつきにくいという問題がある
- ボタンの背景色を、**ホバーの有無に関わらず常時**、`bg-sub`（globals.cssで定義済みの薄いグレー背景トークン）を適用する
- 文字色は`--color-accent`（#334155）を使う
- 枠線は既存の`border`トークンを使い、細く残す
- **新しい色を追加で定義しないこと**。既存の`bg-sub`/`border`/`--color-accent`トークンのみで構成する
- ヒーローの「今すぐシミュレーションする→」（濃紺塗りつぶし）とは明確に格が異なる、控えめなボタンにすることが目的。間違って濃紺塗りつぶしにしないこと

### コピーの誤りを修正する

- 「今のペースで資産は足りる?」カードの説明文「今の積立ペースなら**何歳でFIRE達成**できるか分かります」は、このツールが実際に計算しているのは「目標資産額への到達年齢」であり、「FIRE達成」という表現は不正確。**「今の積立ペースなら何歳で目標資産に到達できるか分かります」**（またはこれに準ずる正確な表現）に修正すること
- 残り3枚（「55歳で辞めても生活できる?」「年金は繰上げ・繰下げどっちが得?」「資産は何年持つ?」）の説明文についても、同様に「FIRE」と「目標資産到達」「資産寿命」「破綻確率」等の概念を混同している箇所がないか確認し、あれば同様に修正すること。修正箇所は完了報告に一覧で示すこと
- アイコン削除・ボタン配色変更後、モバイル幅・デスクトップ幅の両方でレイアウト崩れ（ボタンとテキストリンクの間隔等）がないことを確認すること

## 2. セクションラベルの文字色を濃くする

- 「— お悩み」「— FIREガイド」「— ケーススタディ」等、各セクション見出しの上にある小さいラベルテキストの文字色が薄く、可読性が低い
- コントラスト比を上げること（既存のslateスケールの中で、現在より1〜2段階濃い色に変更する程度でよい。新しい色を追加定義する必要はない）
- LPトップの全セクションで同じラベルパターンが使われているはずなので、1箇所だけでなく該当箇所すべてに反映すること

## 3. 「毎月の資産を、記録する。」ブロックを、切り替え可能な形でダークゾーン化する実験

**これは実験的な変更として位置づける。効果が薄い・見た目がしっくりこない場合はすぐ元に戻せる実装にすること。**

- 対象は`AssetManagementPromoSection.tsx`（前回までのセッションで進捗カード化・ドーナツ実装を行ったブロック）
- **現状の白いカード（左の見出し・説明文・箇条書き・CTAボタン、右のKPI3枠＋ドーナツを含む、白背景・角丸・枠線のブロック全体）は内部を一切変更しない。** テキスト色・ボタン色・ドーナツ配色・KPIバッジ配色、すべて現状のまま
- 変更するのは、**このカードの外側、セクション全体を囲っているページ背景色のみ**。現状の薄いグレー背景（または白背景）を、**Slate 600〜700程度の濃さのグレー系**に変更する。具体的には、既存の`--color-accent`（#334155、Tailwindのslate-700相当）をそのまま背景色として再利用すること（新しい色を追加定義しない）。CTA・フッターで使われている、より深いトーンの濃紺とは明確に区別できる濃さであることを確認すること（それより明るい必要がある場合はslate-600、#475569を使ってもよい）
- **背景色は画面幅いっぱい（フルブリード）に塗ること。** 他のセクション（「お悩み」等の薄いグレー背景）と同様に、背景は画面端から端まで、中身のカードだけが`max-w-5xl`のコンテナ幅に収まる構造にすること。背景色を内側のコンテナ要素にだけ適用すると、左右に元の背景色の余白が残ってしまうため注意すること
- **コンテナの`max-w-5xl`自体は変更しないこと。** 前回、カード幅を広げる際に誤ってコンテナの最大幅（`max-w-5xl`→`max-w-6xl`）まで変更してしまい、前後セクションと左右余白がズレる事故があった。今回は背景色の変更のみで、コンテナ幅・カード幅（`lg:w-[420px]`等）は一切変更しないこと
- 結果として、「暗い背景の上に、今まで通りの白いカードが浮かんでいる」という見た目になる。カードそのものの意匠は一切いじらないため、配色調整のコストが実質ゼロになる
- **実装方法**：ライト/ダークの切り替えを、1つのクラス名またはdata属性（例：セクションのルート要素に`data-theme="dark"`を付与し、その背景色だけをCSSで上書きする）だけで行える構造にすること。KENZOが「やっぱり戻したい」となった場合、そのクラス名/属性を1箇所外すだけで元の背景色に戻せるようにすること
- カードの余白（背景との間の余白）が窮屈にならないよう、暗い背景の面積が十分に見える形で調整すること
- モバイル幅・デスクトップ幅の両方で確認すること

## 4. ケーススタディのアバター配置を左固定に統一する

- 現状、`i % 2`によってアバター（人物イラスト）の左右位置がカードごとに交互になっているが、名前・タイトル・引用文といったテキスト自体は常に左詰めのままで、"完全な鏡写し"にはなっていない。この中途半端さが「揃っていない」印象を与えている
- **アバターの位置を全カード左固定に統一し、交互配置ロジック（`i % 2`によるavatar側の反転）を削除する**
- テキスト側の配置・順序は変更しない（現状のまま）
- バッジ（「公開中」「noteで読む→」等）の位置についても、アバターと連動して反転していた場合は同様に固定側に統一すること
- モバイル幅（前回のモバイルレイアウト修正が生きていることを確認しつつ）・デスクトップ幅の両方で確認すること

## 遵守事項

- ロックファイル（`types.ts`/`profile.ts`/`PortfolioPanel.tsx`/`simulate.ts`/`analyze.ts`/`montecarlo.ts`/`blog.ts`/`blogTopics.ts`/`concerns.ts`/`ConcernCard.tsx`）への依存・変更は一切ゼロを維持すること
- 3節（ダークゾーン化）は特に主観判断を伴う実験的変更のため、既存の`feature/lp-asset-allocation-demo`ブランチとは別に、専用ブランチ（例：`feature/lp-asset-dark-experiment`）で作業すること。1・2・4節（お悩み・ラベル・ケーススタディ）は別の変更なので、混在させず適切に分けること（同一ブランチでまとめてよいが、コミット単位は分けること）
- 新しい色・デザイントークンを追加で定義しないこと。既存のトークン（`bg-sub`/`border`/`--color-accent`/slateスケール）の範囲で対応すること。3節の背景色も新規定義ではなく既存の`--color-accent`（またはslate-600）の再利用とする
- コミット・push・Vercel Preview作成は、KENZOの確認・指示を受けるまで行わないこと
- 完了報告には、各項目ごとに実際のコード抜粋・実機確認結果（スクリーンショット）を添付すること
