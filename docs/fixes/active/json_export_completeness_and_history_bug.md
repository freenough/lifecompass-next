# 実装指示書：JSON Export/Importの完全性確認・過去月断面バグの調査修正

作成日：2026-08-26
種別：**調査＋修正（重要度：高）**
前提：`simplify_csv_scope_and_fix_graph_history_bug.md`（CSV・グラフ・前回記録比カード・
資産配分変化テーブルの過去月断面バグ修正）完了後の追加調査・修正

---

## 0. 背景

CSV・3つの表示コンポーネント（グラフ／前回記録比カード／資産配分変化テーブル）は、
「法人スナップショット自身が持つ`personalHoldings`／`totalPersonalAmount`という
表示用の古いコピー」を参照していたことが原因の過去月断面バグを修正済み。

JSON Export/Importについては、この一連の修正の対象に含まれていなかった。ユーザーからの
指摘を受け、以下2点を確認・対応する。

---

## 1. JSON Exportに同じ過去月断面バグが残っていないか調査すること

- 現在のJSON Export関数が、`HojinAssetSnapshot[]`をそのまま（生の状態で）書き出している場合、
  各スナップショットが内部に持つ`personalHoldings`／`totalPersonalAmount`は、CSVで既に
  修正済みの「記録タイミングによって歯抜けになりうる表示用コピー」のままである可能性が高い
- 調査し、この推測が正しいか確認すること。正しければ、CSV Export（`exportToCsv`、
  `followup_evidence_request_f5ee8f8.md`2章の修正）と同じ考え方で、JSON Exportに含める
  スナップショットの`personalHoldings`相当のデータも、個人ストア自身の真の記録履歴
  （`assetManagement/storage.ts`の`loadSnapshots()`）から該当年月を引いて補完・上書きする形に
  修正すること
- JSON Importについても、取り込んだデータの扱いが同じ考え方に沿っているか確認し、
  ズレがあれば併せて修正すること

---

## 2. JSON Exportに不足しているデータを洗い出し、対応すること

JSONは「完全バックアップ」とUI上で謳っているが、以下がExportペイロードに含まれているかを
確認すること：

- 設定値：目標資産額（個人・法人それぞれ）、個人化想定比率
- 資産移転ヘルパー（法人→個人）の移転履歴ログ（`hojinTransferLog`）

含まれていない場合、以下のいずれかで対応すること（判断に迷う場合は、実装前に方針を報告すること）：

- **含める場合**：ExportペイロードにこれらのフィールドをJSON Import時に復元可能な形で追加する。
  Import時は、既存の設定値・ログを上書きするか、マージするかを明確にし、確認ダイアログで
  「設定値・移転ログも上書きされます」等、影響範囲をユーザーに明示すること
- **含めない場合**：「完全バックアップ」というUI文言を、実態に即した表現
  （例：「保有資産・記録履歴の完全バックアップ（設定値・移転ログは含みません）」）に修正すること

---

## 3. 他にCSVとJSONで扱いが異なる項目がないか、最終確認すること

上記1・2以外に、CSVとJSONで出力・取り込みの範囲が異なる項目がないか、ひととおり確認し、
発見があれば報告すること（ユーザーからの指摘は「移転ヘルパーの入力値のみが差分では」という
仮説だったが、実際には複数の差分があると考えられるため、網羅的に確認すること）。

---

## 6. 完了報告時に必要なもの

- 1章：調査結果（原因があったか、無かったか）。修正した場合は、修正前後のJSON Exportの中身
  （過去月の個人分が正しく含まれるようになったことがわかる形で、省略なしで提示すること）
- 2章：不足していたデータの洗い出し結果と対応方針。実装した場合は、修正後のJSON Exportの
