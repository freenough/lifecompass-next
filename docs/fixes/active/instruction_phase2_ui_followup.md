## 背景

前回の完了報告に対するレビューで、以下3点の確認・追加対応が必要と判断した。

1. `CorporateSettingsSection.tsx`（CompanyState編集）を自動保存のまま据え置いた理由（「同じフォーム内の他フィールドが自動保存方式だから」）について、実際にそうなのか確認が必要
2. `beforeunload`はブラウザレベルの離脱（タブを閉じる・リロード・別サイトへ移動）でしか機能せず、Next.jsのクライアントサイド遷移（ヘッダーの`<Link>`等）では警告が出ないという既知の制約が報告された。**これは今回のうちに対応する**
3. 一覧に追加された「名前変更」機能が、名前欄＋上書き保存フローと重複していないか確認する

## 1. 確認：シミュレーター本体の他フィールドの保存タイミング

前回の報告は「シミュレーター本体ページの他の全フィールド（現在年齢・NISA残高等）が一貫して自動保存方式である」という前提で、CompanyStateだけを自動保存のまま据え置く判断をしている。しかし、シミュレーター本体の`ProfileDrawer`は「フォームを自由に編集し、明示的に保存ボタン（新規保存/上書き保存）を押すまでlocalStorageには書き込まれない」という設計だったはず（`handleSave`が呼ばれて初めて`saveProfile()`が実行され、`lifeCompassProfiles`に書き込まれる）。

**まず、以下を実コードで確認すること：**
- `useSimulatorStore`および各入力フィールドの実装を確認し、現在年齢・NISA残高等の入力値が、`ProfileDrawer`の保存ボタンを押すまで本当に一切localStorageへ書き込まれないかを確認する

**確認結果に応じて、以下のいずれかで対応する：**

- **「保存ボタンを押すまで書き込まれない」が正しい場合**：CompanyStateだけが自動保存されている状態は、他フィールドとむしろ**矛盾**している（一貫していない側はCompanyStateの方）。`CorporateSettingsSection.tsx`を、`instruction_phase2_ui_alignment.md`1節と同じパターン（下書き状態管理・専用の保存ボタン・離脱警告）に変更すること。CompanyStateは`hojinCompanyState`という別ストアで管理されており`ProfileDrawer`の保存ボタンとは連動できないため、資産管理ツール側の現在プロファイルに紐づく形で、この編集画面専用の保存ボタン・下書き状態・離脱警告（2節の仕組みを利用）を新設すること
- **「他フィールドも何らかの形で自動保存されている」ことが判明した場合**：その保存先・タイミングを具体的なコード箇所とともに報告した上で、CompanyStateを自動保存のままにするかどうかは実装せず先に報告し、判断を仰ぐこと

## 2. SPA内遷移でも未保存警告を出す（今回対応・必須）

**要件**
- ヘッダーコンポーネント全体を大きく作り替えることは避けつつ、以下の方式で対応する：
  1. 「未保存の変更があるか」を示す軽量な共有state（React Context等、例：`UnsavedChangesContext`）を新設し、アプリ全体からアクセス可能にする
  2. 資産管理ツールページ（および1節の対応が必要ならCompanyState編集画面も）は、未保存の変更がある間、このフラグをtrueにする
  3. ヘッダーのナビゲーションリンク（`<Link>`コンポーネント等）に、クリック時にこのフラグを確認し、trueなら確認ダイアログ（`confirm()`等）で警告してから遷移を許可する、という**最小限のガード**を追加する
  4. ヘッダー自体のレイアウト・デザイン・他の挙動は変更しない。既存のリンクに数行のクリックハンドラを追加する程度の変更に留めること
- 資産管理ツール（および1節でCompanyStateも対象になった場合はそちらも）以外のページでこのフラグをtrueにする箇所は無いため、他ページの挙動に影響が出ないことを確認すること
- 実機で、保有資産を編集した状態（未保存）でヘッダーの他ページへのリンクをクリックし、警告が表示されること・キャンセルすればページに留まり下書きが保持されることを確認すること

## 3. 確認：一覧の「名前変更」機能について

- 前回追加された一覧の「名前変更」機能について、追加した経緯を説明すること
- 名前欄に入力して「上書き保存」を押すことでも名前は変更できるはずだが、この2つの経路が重複し、ユーザーにとって分かりにくくなっていないか確認し報告すること
- 重複していて紛らわしいと判断される場合は、一覧の「名前変更」を削除し、名前欄＋上書き保存の1経路に統一すること（判断に迷う場合は実装せず先に報告し、KENZOの判断を仰ぐこと）
