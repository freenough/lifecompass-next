# 実装指示:給与所得控除テーブルへの令和8・9年分特例(74万円)の年度対応実装

## 背景
`calcSalaryIncomeDeduction()`(現状は令和7年度改正版=最低保障額65万円で固定)について、
令和8年度税制改正により、令和8年・9年分の所得(住民税では令和9年度・令和10年度分)に
最低保障額74万円の時限特例が適用されることが、国税庁一次資料(令和8年5月付Q&A、
`https://www.nta.go.jp/users/gensen/2026kiso/pdf/0026005-024.pdf`)で確認された。
確認済みの正確な数値表は以下の通り(令和8年・9年分限定):

| 給与収入 | 給与所得の金額 |
|---|---|
| 69万1,000円未満 | (対象外、下記「190万円までの区分」参照) |
| 69万1,000円以上74万1,000円未満 | 0円 |
| 74万1,000円以上219万1,000円未満 | 収入金額 − 74万円 |
| 219万1,000円以上219万3,000円未満 | 145万1,000円 |
| 219万3,000円以上219万6,000円未満 | 145万3,000円 |
| 219万6,000円以上220万円未満 | 145万6,000円 |
| 220万円以上 | 従来通り「収入金額×30%+80,000円」等の既存の速算表(令和7年度版と同一) |

**220万円ちょうどで、上記の「収入−74万円」方式と、既存の速算表(30%+8万円)が
正確に一致することを確認済み(どちらでも146万円になる)。この境界より上の区分
(360万円・660万円・850万円の各区分)は、令和7年度版から変更がないことも確認済み。**

**重要な制約:令和10年分以降(特例終了後の恒久額69万円)の詳細な境界値は、
今回のセッションでは一次情報での裏付けが取れていない。この部分は実装しないこと。**

## 実装方針

### 1. `calcSalaryIncomeDeduction()` の年度対応化
- 関数シグネチャに、対象となる所得年(暦年)を受け取る引数を追加すること
  (例:`calcSalaryIncomeDeduction(incomeYen: number, incomeYear: number): number`)
- 令和7年分(2025年)以前:現行の65万円ベースのロジックをそのまま使用
- **令和8年分・令和9年分(2026年・2027年)**:上記で確認した74万円特例のテーブルを実装すること。
  69万1,000円未満の区分については、令和7年度版の「190万円まで:65万円」ロジックを
  流用してよいか、あるいはこの範囲にも別の特例があるかを、実装前に国税庁の同資料内
  (69万1,000円未満に関する記載がないか)を再確認すること
- **令和10年分(2028年)以降**:一次情報が未確認のため、**今回は実装しないこと**。
  暫定措置として、令和9年分と同じ74万円テーブルをそのまま使い続けるのではなく、
  関数が令和10年分以降の年を受け取った場合は、既知の情報(69万円が恒久的な最低保障額に
  なることは確認済み)に基づき、190万円までの区分を69万円に置き換えた上で、
  200万円台の境界値は「不明」であることを示す形にすること(例えば、69万円区分の上限を
  一旦190万円のまま据え置く保守的な近似とし、コード内コメントで
  「令和10年分以降の正確な境界値は未確認。一次情報が確認でき次第、別途修正が必要」
  と明記すること)

### 2. 波1・波2それぞれで参照する所得年の決定
- 波2(`calcNextYearTax()`):退職年(`retirementMonth`から逆算できる、入力時点で明示的な
  年の入力はないため、`new Date().getFullYear()`を用いて「今年退職する」という前提で
  所得年を決定してよいか、確認の上で実装すること。ツールの性質上、常に「今」使われる
  ことを想定した設計で問題ない
- 波1(`calcCurrentYearTax()`):`incomeBasisYearLabel`(前々年/退職前年)に応じて、
  対応する暦年を算出し、その年を`calcSalaryIncomeDeduction()`に渡すこと

### 3. `calcSalaryDeductionApproxMaxError()` への影響
- この関数(別表第五との近似誤差上限)も年度によって値が変わりうるか検討すること。
  ただし前回の調査(`betsuhyo5-extraction/investigation_report.md`)は令和7年度版のみを
  対象にしていたため、令和8・9年度版の別表第五との誤差については未検証である。
  今回は「令和7年度版のみ検証済み」という前提を崩さないよう、令和8・9年分については
  この誤差上限表示を一時的に非表示にするか、「この年度については別表第五との誤差は
  未検証」という注記に置き換えること(検証していない数値を確定値のように見せないため)

## 検証要件
- 令和8年・9年分の課税所得計算について、上記の表に基づきPython Decimal等で検算し、
  完了報告書に記載すること
- 特に境界値(69万1,000円・74万1,000円・219万1,000円・219万3,000円・219万6,000円・220万円)
  での挙動を`verify-resident-tax-timing-tool.js`に追加すること
- 令和7年分の既存の計算結果に影響がないこと(回帰なし)を確認すること
- `full-verify.js`全PASS・`tsc --noEmit`エラーなしを確認すること
- 完了報告書に、令和10年分以降が未実装のままであることと、その理由(一次情報未確認)を
  明記すること

- 「204万円」等、今回のセッションで裏付けが取れていない数値をコードに使用すること
