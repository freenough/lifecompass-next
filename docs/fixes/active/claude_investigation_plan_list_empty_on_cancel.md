# 調査依頼：計画の同名上書き確認でキャンセルすると、一覧表示が0件になる不具合

作成日：2026-09-03
種別：**調査のみ（修正は行わない）**
関連：`claude_instruction_banner_and_duplicate_plan_fix.md`（本タスクの実装）

---

## 0. 現象

「計画を保存」で既存計画と同名を入力し、上書き確認ダイアログでキャンセルを選択すると：

- **localStorage側（`listPlans()`で直接確認）**：対象計画の`id`・`createdAt`・件数はすべて保存前と不変。ストレージは正しく「何もしていない」状態を保っている
- **画面の「保存済み計画」一覧側**：キャンセル前は1件表示されていたのに、キャンセル直後は「まだ計画が保存されていません」（0件）という空状態表示に変わる

ストレージが変化していないにもかかわらず、画面表示だけが空になっている。これは今回追加した重複チェック・確認ダイアログのロジックが、意図せず画面表示用のstateに影響を与えている可能性が高い。

## 1. 調査してほしいこと

1. `PlanManagerPanel.tsx`の`handleSave()`内で、今回追加した重複チェック（`listPlans(currentProfileId)`の呼び出し、`window.confirm()`、キャンセル時のreturn）の実コードを改めて引用する
2. 保存済み計画の一覧を画面に表示している`plans`（または同等のstate/prop）が、どこで・どのタイミングで更新されるか（`onPlansChanged`・`onSaved`等のコールバック、または別のstate管理）を確認する
3. キャンセル時に`return`する分岐より**前**に、意図せず一覧側のstateを更新・クリアするコードが実行されていないか（例：`listPlans()`の戻り値を、重複チェック用の一時変数ではなく、誤って画面表示用のstateにそのままsetしてしまっている等）を確認する
4. もし該当箇所が見つからない場合、`listPlans()`自体の実装（`src/lib/planSnapshot/storage.ts`）に、呼び出すたびに何らかの副作用（他のstateやキャッシュを書き換える等）が無いかを確認する
