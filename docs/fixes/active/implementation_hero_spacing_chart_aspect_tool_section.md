# 実装指示書: Hero上部余白・チャートアスペクト比・ツールセクション左右余白

対象ブランチ: `feature/lp-container-width`(継続)。別ブランチが必要と判断した場合はKENZOに確認してから切ること

## 0. 前提

- 直前の調査(`investigation_hero_chart_aspect_top_spacing_concern_block_v2.md`)の結果報告を受け、KENZO・Claudeで方針を確定した
- **作業開始前に必須**: 調査時の未コミット変更(報告にあった2ファイル)を`git status`で確認し、実装対象と異なる一時的な変更であれば`git checkout`等で元に戻してから着手すること。working treeがcleanな状態でこの指示書の作業を開始する

## 1. Heroチャートのモバイル時アスペクト比変更

- `src/components/lp/HeroDemo.tsx`の`CHART_HEIGHT = 300`固定pxを、**Tailwindの`aspect-*`ユーティリティをブレークポイントで出し分ける方式(調査報告の案B)**に変更する
  - モバイル: 高さ約220px相当のアスペクト比
  - デスクトップ(`lg:`以上): 現状の300px相当を維持し、見た目に変化がないこと
- `ResponsiveContainer`の`height`は`"100%"`とし、親要素の高さをCSS(`aspect-*`)で制御する形に変更
- JS側の`matchMedia`等によるモバイル判定は使わない(案Bを採用するため)

## 2. Hero上部余白

- Heroセクションの`py-16`を`pt-4 pb-16`(非対称)に変更する
- `pb-16`(下側)は現状のまま変更しない

## 3. Heroチャートカード内部の微調整(可能な範囲で)

- カード内`pb-3`→`pb-1`
- KPIバッジ3枠とグラフの間の`mt-2`を可能な範囲で圧縮(例: `mt-1`)
- 目的は実機相当(375×530)でのキャプション下端のはみ出しをできるだけ減らすこと。ゼロにする必要はなく、無理に詰めてKPIバッジやグラフが窮屈にならない範囲で行うこと
- この微調整の結果、実機相当でどこまで改善したか(はみ出しpx数)を完了報告に記載すること

## 4. ツールセクション(「かんたん計算ツール」)左右余白

- 前回のコンテナ幅拡大で`Container`コンポーネントに移行済みの当該セクションについて、左右paddingを`px-6`→`px-2`に変更する
- カード内部の`p-6`はそのまま維持(変更しない)

## 5. 検証範囲

- モバイル: 375×530(実機相当、Safariツールバー展開時を想定)、375×667(フル)、390×844、360×800(見出し折り返し確認も含む)
- デスクトップ: 1440px幅程度で、チャート高さ・Hero上部余白・ツールセクション余白のいずれも意図せぬ変化がないことを確認
- ツールセクションは`px-2`まで縮めた際、カードのテキストが画面端に近づきすぎて窮屈に見えないか確認(前回調査でp-6により実質32px確保されることは確認済みだが、実装後の見た目でも再確認)
