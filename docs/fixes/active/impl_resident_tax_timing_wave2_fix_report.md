`docs/fixes/active/impl_resident_tax_timing_wave2_fix.md` の実装。

## 修正内容

### 1. `calcNextYearTax()`(`src/lib/tax/residentTaxTiming.ts`)
`retirementMonth <= 5`で分岐を追加した。

- **6〜12月退職(現状維持)**:`estimatedRetirementYearIncome = priorYearIncome/12×retirementMonth
  + postRetirementIncome`、`incomeYear = retirementYear`。分岐追加以外、既存ロジックは
  一切変更していない。
- **1〜5月退職(新規)**:`priorYearIncome`をそのまま使用(月割りしない)。
  `postRetirementIncome`は加算しない。`incomeYear = retirementYear - 1`。

新しい計算ロジックを重複実装しないという指示に従い、年間税額の算出は波1(`calcCurrentYearTax()`)
と全く同じ低レベル関数群(`calcSalaryIncomeDeduction`・`calcSocialInsuranceDeduction`・
`calcTaxableSalaryIncome`・`calcAdjustmentDeduction`・`calcIncomeTaxPartWithAdjustment`)を
そのまま呼び出す形にした(波1側の`calcAnnualResidentTax()`が内部で呼んでいるのと同一の関数群)。
分岐したのは「収入の合成方法(`estimatedRetirementYearIncome`)」と「基準年
(`incomeYear`)」の2点のみで、税額計算そのもののロジックは1箇所も複製していない。

### 2. UI文言の出し分け(`ResidentTaxTimingResult.tsx`)
- セクション見出し「②」を`input.retirementMonth <= 5`で分岐:
  - 6〜12月退職:「退職した年の所得をもとにした、翌年6月からの新しい住民税」(現状維持)
  - 1〜5月退職:「退職前年の所得をもとにした、今年6月からの新しい住民税」
- `assumptionNotes`(`residentTaxTiming.ts`側で生成)も同様に分岐:
  - 1〜5月退職:「今年6月からの新規課税は、退職前年の年収をそのまま使用しています(退職月が
    1〜5月のため、前年は年間を通じて在職していたと仮定しています)。」(新規)
  - 6〜12月退職:「退職前の給与は前年の年収を月割りした仮定値です。賞与の時期により実際の所得
    とは差が生じます。」(現状維持)
  - 「退職翌年6月からの新規課税は、自己納付(普通徴収)を前提に試算しています」の発火条件に
    `retirementMonth >= 6`(`!isEarlyYearRetirement`)を追加。1〜5月退職では
    `postRetirementIncome`の値に関わらずこの注記を出さない。
- 「計算根拠を見る」アコーディオン内の②の説明文も、同じ条件でテキストを出し分けた
  (1〜5月退職向けに、「進行中の住民税年度(①)が終わる5月の直後、今年6月から新しい住民税
  年度が始まるため、②は『翌年』ではなく『今年』の6月から発生します」という補足を追加)。

### 3. 比較表(`ResidentTaxTimingComparisonTable.tsx`)
- 列見出しを「翌年6月〜」→「②(新しい住民税)」に変更(退職月グループによって開始時期が

修正前後の②の値が一致する構造的な理由も確認した:1〜5月退職グループは、修正後は
「前年まるまる1年分」を基準にするため月に依らず金額が同一になる(1月退職と5月退職で
②が完全に同額)。さらに、220万円を超える収入帯(本ツールが扱う400〜800万円は全て該当)では
給与所得控除が年に依存しないため、修正後の1〜5月退職の②は、偶然にも6〜12月退職グループの
12月退職の②(`priorYearIncome/12×12+0=priorYearIncomeそのもの`に帰着するため)と同額になる
(例:600万円のケースでは1月・5月・12月退職いずれも②=307,800円)。これは意図した設計上の
恒等式ではなく、「上位区分では年による給与所得控除の差がない」という既存の別の性質からくる
副次的な一致であることを完了報告書に明記しておく(検証スクリプトのコメントにも同様の注記を残した)。

## 独立検算(Python Decimal相当の整数演算による手計算)

600万円・5月退職の②(修正後):
- 給与所得控除(2025年表・360万超660万以下:×20%+44万)= 1,640,000円 → 給与所得4,360,000円
- 社会保険料控除(14.6%)= floor(6,000,000×0.146) = 876,000円
- 課税所得 = 4,360,000 − 876,000 − 430,000(住民税基礎控除) = **3,054,000円**
- 市民税 floor(3,054,000×0.06/100)×100 = 183,200円、県民税 floor(3,054,000×0.04/100)×100 = 122,100円
- 所得割(調整前)= 305,300円 → 調整控除2,500円(課税所得>200万円のためmax(2,500,負の値))
- 所得割(調整後)= 302,800円 → 年間税額 = 302,800 + 5,000(均等割) = **307,800円**

本番コード出力(`nextYearTax.total`)と桁単位まで完全一致した。この計算は、直前のセッション
(`impl_resident_tax_timing_phase2_report.md`)で600万円・9月退職の波1について既に独立検算済みの
計算過程と全く同じ数値(同じincomeYear=2025・同じpriorYearIncome=6,000,000を使うため)であり、
既存の検算結果の再利用としても整合性が取れている。

## 残課題(今回のスコープ外・参考情報)

- `retirementYearIncomeOverride`(「退職年の実際の給与収入がわかっている」)は、1〜5月退職では

  は、フォーム入力前の一般的な説明であり、退職月によって出し分けることは指示書の対象に
  含まれていなかったため変更していない。1〜5月退職の場合はこの一般説明とも実態がズレるため、
  将来的な文言調整の余地がある。
