## チェックリスト

### [ ] 1. PFカード見出しのσ表示を削除

現状：「法人資産（投資分）μ: 2.7% ／ σ: 6.4%」のようにσまで表示されている。
対応：カード見出しはμのみにする（個人側と同じ）。下部の灰色サマリーボックスは対象外（4番を参照）。

### [ ] 2. `copyCurrentToWorking`の手入力フィールド混入を修正

現状：①→②の比率コピー時、`useManual`/`manualMu`/`manualSigma`等の手入力系フィールドもコピーされてしまう。
対応：%配分のみコピーし、手入力系フィールドには一切触れないよう修正（個人側と同じ設計）。

### [ ] 3. 「取崩期は積立期と同じ利回り/標準偏差を使う」独立トグルの追加

現状：法人側にこの2つのチェックボックス自体が存在しない（`retirementSameAsWorking`という%配分同期トグルのみ）。
対応：個人側の`rateSameAsWorking`/`sigmaSameAsWorking`と同じく、%配分の同期とは独立した2つのトグルを追加。OFFにした瞬間、その時点の積立期側の実効値を取崩期側にシードしてから手動モードに切り替える処理も実装する。

### [ ] 4. 灰色サマリーボックスの参照値、個人側実装との整合性を再調査・再確認

現状：法人側の灰色ボックス（「μ/σ X% / Y%」）は`getEffectivePhaseMetrics`（手入力優先）を参照している。一方、以前の調査報告では、個人側の`calcAggregateMu`/`calcAggregateSigma`（「全口座集計」欄の計算元）は`pfManualFlags`を一切参照しないと報告されていた。この2つの報告は矛盾している。

対応（実装の前に、必ず以下の確認を行うこと）：
1. `calcAggregateMu`/`calcAggregateSigma`の実装を該当行を引用しながら再確認する
2. 個人側の「全口座集計」欄の表示が、手入力トグルをON/OFFした際に実際に変化するかどうかを、ブラウザ操作で確認する
3. 2の結果が「変化しない（PF値のみを参照）」であれば、法人側の灰色ボックスも同じ挙動に修正する（手入力を無視した集計値に変更）
4. 2の結果が「変化する（手入力を反映する）」であれば、根拠となるコードを示した上でその旨を報告し、法人側は現状のままでよいと報告する

**前回、確認なしの説明で「妥当」と誤って承認してしまった経緯があるため、今回は必ずコード・実機確認の根拠を示すこと。**

### [ ] 5. `ImpactTable`「最終資産差」列を差分表示・ラベル統一に修正

現状：添付画像で「法人合算後: 5.1億円」のように**絶対額**が表示されている。
対応：
- 列の定義（最終資産の**差分**）に合わせ、絶対額ではなく差分を表示する
- ラベルは他箇所（「破綻率変化」列は既に「法人合算」表記になっている）と同じ「法人合算」に統一する（「法人合算後」ではない）

この項目は過去2回指示済みだが未反映だった。**なぜ反映されなかったのか（指示の見落とし、別の修正で上書きされた等）の原因も報告すること。**
