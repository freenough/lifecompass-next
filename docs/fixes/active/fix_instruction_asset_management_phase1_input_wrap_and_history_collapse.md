## 1. 【バグ修正】保有資産カードの入力行が折り返してしまう

デスクトップの左サイドバーで保有資産の件数が増え、サイドバーに縦スクロールバーが表示される状態になると、各入力行（保有者／資産クラス／金額／削除ボタン）の横幅が狭まり、削除（✕）ボタンだけが次の行に折り返されてしまう不具合が確認された。

### 1.1 対応内容

- 入力行のレイアウトを、スクロールバーの出現有無に関わらず折り返さないように修正すること
- 対応方法の例（実装しやすい方法でよい）：
  - 各行の入力欄に`flex-shrink`の調整を行い、削除ボタンを含めた行全体が`flex-nowrap`で確実に横並びを維持するようにする
  - スクロールバー分の幅を考慮したレイアウト（`scrollbar-gutter`の指定、またはサイドバーのpadding調整）を行う
  - 必要であれば、資産クラスの選択肢（ドロップダウン）の最小幅を見直し、狭い横幅でも崩れないようにする
- 対象は`AssetHoldingCard.tsx`の入力行コンポーネント

### 1.2 検証

- 保有資産の件数を増やしてサイドバーにスクロールバーが表示される状態を作り、すべてのカテゴリカードの入力行で削除ボタンが折り返さないことを確認する
- デスクトップ幅・やや狭いウィンドウ幅の両方で確認する

## 2. 資産推移の記録履歴を折りたたみ表示に変更

「資産推移」セクションの記録日一覧（テーブル）は、記録件数が増えるほど縦に伸び続ける（上限24件）。テーブル部分を折りたたみ表示に変更する。

### 2.1 仕様

- **折れ線グラフは常時表示のまま**とする（変更なし）
- **テーブル（記録日一覧）は、初期状態で直近3〜5件のみ表示**する
- テーブル下部に「すべて表示」等のリンク／ボタンを配置し、押すと全件（最大24件）が展開される
- 一度展開した後、「閉じる」等で再び直近数件のみの表示に戻せるようにする
- 件数がもともと3〜5件以下の場合は、「すべて表示」ボタン自体を表示しない（展開する意味がないため）

### 2.2 実装対象

- `AssetSnapshotHistory.tsx`

### 2.3 検証

- スナップショットが多数（10件以上）ある状態で、テーブルが初期状態で直近数件のみ表示され、「すべて表示」で全件展開されることを確認する
- 折れ線グラフ自体は件数に関わらず常に表示されていることを確認する
- スナップショットが3〜5件以下の場合、「すべて表示」ボタンが表示されないことを確認する
